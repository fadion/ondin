# App chrome (§9.1 UI chrome, §9.2 Layout)

How `ondin-app` draws its window and panels: the toolkit choice, the shared widget rules in `ui.rs`, the module map, and the layers tree and inspector behaviour. The edit flow is in `app-dataflow.md`, the dashboard in `library.md`.

## 9.1 UI chrome

### Toolkit

- **egui, via eframe.** gpui was evaluated and parked: it renders through its own backends rather than wgpu, so embedding the Vello-on-wgpu canvas would need cross-API texture sharing or a per-frame CPU readback. egui composites a wgpu canvas trivially (Vello renders to a texture, egui draws it through a paint callback).
- egui is a medium-term commitment. The boundary rule (no egui types in core, render, export or mcp) is what keeps a later migration survivable.
- eframe rather than raw winit + egui-winit + egui-wgpu: it owns only the window, wgpu device and event loop, imposes no canvas cost, and swapping back changes only `main.rs`. eframe 0.35: the `App` method is `ui(&mut self, &mut egui::Ui, &mut Frame)`, and panels are `egui::Panel::left(..)` shown into a `Ui`.

### Theme (`theme.rs`)

- **Two palettes, dark and light.** `theme::color::Theme { Dark, Light }` picks a `Palette`; the current theme is a thread-local, since the UI paints on one thread and a test that switches theme cannot reach one running beside it.
- **Chrome colours are read through functions, canvas marks are constants.** The `palette!` macro gives every palette field an accessor of its name (`color::bg()`, `card()`, `field()`, `hover()`, `accent_700()`, `warn()`, …); the text tiers are `theme::text::strong()`, `muted()`, `dim()`, `faint()`, `disabled()` and `off()` (a hidden, locked or inapplicable row, a step above `faint()`). Derived: `text_a(alpha)`, `accent_a(alpha)`, `divider()`, `unsaved()`, and `by_theme(dark, light)` for a colour too local for the palette. The canvas marks — `SELECT` and its alpha tiers, `GRID_GAP`, `SPACING_*`, `KEY`, `COMPONENT*`, `BADGE`/`BADGE_INK`, `MEASURE`/`MEASURE_INK`, `POINT` — stay `const` in both themes: they sit on artwork, not on the chrome. Where the selection colours chrome text (a selected layer's name and glyph, the drop host's, the library's drop hint) it is `select_ink()`, `SELECT` in dark and a deepened blue in light. Ink on a fixed black wash (present mode's counter and page chip, a library card's *Kit* and mark chips) is `on_scrim(ink)`, the ink's dark-theme value in either theme, since the wash does not change. A colour chip's hairline is `ui::swatch_hairline()`, white at 30% in dark and black at 30% in light. A component set's resting outline lies on the page and takes its ink from the page ground (`canvas::set_outline`). A page with no colour of its own is drawn on `color::canvas()` (dark 23,23,24, the headless `DEFAULT_CANVAS_BACKGROUND`; light 238,238,240), so an untouched page follows the theme; a picked colour is the document's and stays whatever the theme. Text drawn straight on the page (`canvas::ground_text`) takes its ink from the resolved ground's luminance, not from the theme.
- **Ramp steps are named by role, counting away from the ground:** 900 is the subtle accent ground, 100 the ink on it, and `accent()` is the 500. In light, `accent_900()` is a pale tint and `accent_100()` a dark blue. `danger_*` and `saved_*` follow the same rule. A mark on a *solid* accent fill (a switch's or slider's knob) is `on_accent()`, near-white in both themes.
- **Light grounds** are the text mixed toward white, lighter as they rise; a field, a hover or a recessed tab sits below its ground rather than above. Hues are deepened to hold contrast on white.
- **Light ink gain:** in light, `text_a` scales alpha by `LIGHT_INK_GAIN` (1.2), because dark ink on a light ground reads fainter than light on dark at the same alpha. The gained alpha stops at `LIGHT_INK_CAP` (230), short of opaque, so `strong()` stays a step under `text()`. `every_ink_reads_on_every_ground_in_both_themes` holds a contrast floor for every ink over every ground in both palettes, and for the selection ink and the scrim inks on their grounds.
- **Preference:** `Prefs::theme` is `ThemePref { System, Dark, Light }`, stored lowercase, default Dark so an install from before keeps its look. `theme::follow` runs first in `OndinApp::frame_body`, every frame, resolving System against `ctx.system_theme()` (dark when unknown); on a change it calls `theme::apply`, which sets the palette and reinstalls egui's style (`dark_mode` follows), and `frame_body` restyles its root `Ui`, which copied the old style before the pass began. `OndinApp::new` runs `follow` once on the stored preference, so the first frame opens in it. Both screens' Settings modals open on the same *Appearance* section (`settings::theme_section`), a System/Dark/Light segmented control; while either modal is open the chrome previews the draft's pick, Cancel reverts and Save writes it.

### Icons (`theme::icon`)

- **The app draws every icon from its own font**, `assets/fonts/OndinIcons.ttf` (family *Ondin Icons*), which `theme::install` registers as the `ondin-icons` family; `theme::icon_text` and `theme::icon_font` set a glyph in it. Each `theme::icon` constant holds a Private Use Area codepoint.
- **The source is `assets/icons/glyphs.json`**: per icon, its name (the constant in lower kebab, `FOLDER_SIMPLE` → `folder-simple`), its codepoint and SVG path data on a 16-unit grid — `stroke` (a centreline stroked at 1 unit, round caps and joins), optional `fill`, optional `cut` (stroked the same way and taken out of the fill), optional `transform`. `assets/icons/build_font.py` builds the TTF from it (fontTools and skia-pathops; run in WSL, as its header says). A changed glyph means a rebuilt font.
- **Drawing rules:**
  - 16 px grid, 1 px margin: everything inside 14×14.
  - One stroke, 1 px, round caps and joins, centred on a half pixel so a straight line covers one pixel row at 100%. A drawing that turns on a single stem uses the 7.5 axis.
  - Keylines: square 12, circle 13.
  - Fill marks state: a main component (`HEXAGON_FILL`), a locked layer (`LOCK_SIMPLE_FILL`), the filled half of a pair, a boolean's result.
  - A pair is one drawing turned or mirrored: `FLIP_HORIZONTAL`/`FLIP_VERTICAL`, the four `CORNER_*` per-corner-radius glyphs (a dotted box whose one rounded corner is solid, turned into each corner). Filled twins mark state: `HEXAGON_FILL`, `LOCK_SIMPLE_FILL`. The canvas cursors are not icons: `cursor.rs` draws its own (`tools.md`, *Canvas cursors*).
- **Two tests hold the font to the constants.** `theme::tests::the_glyph_source_names_every_icon_at_its_codepoint` pins `glyphs.json` to `icon::ALL`, name and codepoint; `every_named_icon_has_a_glyph_behind_it` lays out every entry of `icon::ALL` and requires ink that differs from the missing-glyph box, since a wrong codepoint or an unrebuilt font lays out fine and draws nothing.

### Shared rules

- **One hairline per control, resolved against its own ground** (§15 D386). `theme::color::field_border()` is 8% text over `field()`; `card_border()` is 8% over `card()`, for strokes enclosing a card ground. They differ on purpose (brighter ground, brighter border). Every control's ground is `field()` with `field_border()`, the `ui::segmented` track included; a lit segment cell is `text_a(33)` over it. Sliders, switches and the Align row's buttons carry no hairline.
- **One hover ground, `theme::color::hover()`**, read by `theme::install`'s `w.hovered` fills, `ui::icon_button_padded`, `ui::button_face`, a segment cell, `inspector::template_cell`, `ui::menu_head`, `ui::menu_row` (so a menu and a dropdown's list hover alike) and `ui::list_row_ground`. Every list row lit or hovered paints `list_row_ground` (lit at a segment cell's `text_a(33)`): the pages list, the variables browser's rows (lit while their menu is open), the kit picker, the history list's hover, the dashboard's lists, Version history's rows (`ui::list_row_fill`: an opened row and the body it opens are one block in the hover, its corners at the block's ends, and a compared row stays in the hover, since the lit fill would bury the rail); the layers tree's hover tint is `hover()` too. A selection that wears the accent (the layers tree, History's current step, a picked dashboard file) keeps it. Change it in one place. Hover changes a control's fill and ink, never its hairline: a dropdown's face hovers as a button's does, since an accent ring on whatever is under the pointer would make accent mean hover.
- **One set of control states** (`ui::FieldButton`, and the theme's `widgets` for egui's own):
  - *Rest:* `field()`, `field_border()`. A command's word or glyph is `text::muted()`; a value (a field's number or text, a dropdown's choice) is `color::text()`.
  - *Hover:* `hover()` fill, `color::text()` ink, the hairline unchanged.
  - *Open* (a dropdown whose list is up): the hover face with an `accent_700()` hairline, which ties the list to its field.
  - *On* (latched: a toggle, a flip, Overlay): `accent_900()`, `accent_700()` hairline, `accent_200()` ink; `accent_800()` under the pointer.
  - *Primary* (a surface's one main action: a dialog's confirm, *New file*, *Publish*): `accent()` fill and hairline, `accent_ink()` ink, `accent_400()` under the pointer. On is a state; Primary is an action, so they look different.
  - *Danger:* `danger_900()`, `danger_700()`, `danger_200()`; it stays quieter than Primary, so a destructive confirm is never the loudest button.
  - *Disabled:* `FieldButton::Disabled` keeps the resting ground with `text::disabled()` ink and no hover; a control disabled through its `Ui` (`ui::disable_unless`) fades whole, ground included, at egui's disabled opacity. Either is the Disabled state.
  - Icon buttons without a ground (`ui::icon_button*`: the rail, the top bar, card heads) are their own family and keep their own active state.
- **An action with other ways to do it is `ui::split_button`**: one `button_face`, Primary while available, a hairline before a caret end; its word has a `label_button`'s ink and `ui::LABEL_BUTTON_PAD_X` of air, so it reads as the primary `settings::text_button` beside it. Which end the click landed on decides between the action and the caret's menu. Unavailable, it is an ordinary face with the word dimmed and the caret still live.
- **A chip that carries a note is `ui::label_button_noted`**, sized by `label_button_noted_w`: a `label_button`'s word, then the note in `ui::SMALL_PT` mono `text::faint()`, never the accent. A property holding interaction-state ties uses it on its value chips for `rest` or the tied selector.
- **A switch that carries a note is `ui::switch_row_noted`**: a `switch_row` with the note in `text::faint()` after its label, at the label's size — a count of what the switch would act on, kept while it is off so the reader sees what is left (Clean up's rules), or what turning it on brings (Settings' icon sets and photo services: the licence, or the key a service needs). A note too long for the row is cut with an ellipsis 12pt short of the switch, the whole note its tooltip.
- **A panel the rail's foot opens is `ui::rail_popup`**: an `Area` holding `Tab`, on `ui::card_frame` padded `ui::RAIL_POPUP_PAD` (12), a fixed height whose bottom-left is `OndinApp::rail_popup_anchor(button)`: 8pt right of the rail, bottom-aligned with the panel's own button, or the canvas's bottom-left with the toolbar hidden. The foot reads, top to bottom, *Assets*, *Styles and variables*, *Insert components*; the three share the place and opening one closes the others.
- **A hover card beside a browsing panel wears `ui::hover_card_frame`**: raised, a faint hairline, a 6pt corner — the insert picker's and the assets browser's, one ground. Both place it with `ui::rail_hover_card` (beside the panel at the row's top, `ui::RAIL_CARD_W` wide, never taking the pointer) and time it with `ui::Resting` (`ui::RAIL_CARD_DELAY` of rest, a frame asked for when it is due).
- **A secret typed in is `ui::secret_field`**: a `text_field` masked unless shown, with an eye / eye-slash button at its end that flips it, its two tooltips the caller's. It sets its own gap before the eye, so it stays the width it is given whatever spacing its caller runs. The Figma import's token and Settings' photo keys use it.
- **A menu's row that opens a list beside it is `ui::submenu_row`**, `label ▸`, lit while its list is open (a keyboard highlight handed to it wins); in a menu of check rows it is `ui::submenu_check_row`. The list is `ui::flyout(id, row, w)…show(ctx, (rows, seps), add)`, a `menu_frame` card placed by `flyout_place`, whose `.pad` matches the padding of the menu it hangs from and whose `.order` (`Tooltip` by default, over a popup) keeps it above that menu; `show` answers the card's response for the caller's click-outside and pointer-inside tests. Drawn from inside a popup's closure, a pick closes both. The caller keeps the row's rect while open, opens it on the row's hover or click and closes it when another row is hovered. The Variants card's *State ▸*, the View menu's *Panels ▸*, the Variables browser's *Move to ▸* and the context menu's submenus all use them.
- **A popup over the canvas hangs from `ui::canvas_popup_area`**: centred on the canvas, `ui::CANVAS_POPUP_TOP` under its top edge, on `settings::card_frame`, at most `ui::canvas_popup_room` tall, a scrolling list capped at `ui::CANVAS_POPUP_LIST_H`. The command palette, batch rename, Clean up, Fill with content, tokens import, the trace card and Colour review hang there. Every card among them is `settings::canvas_card`: the frame without a margin, its width, `Tab` held, and either a clear-backdrop modal (`CardHold::Modal`) or the canvas left live (`CardHold::Open`). Rows inset by `settings::CANVAS_CARD_PAD`. `settings::card_head` is the title row (`card_head_noted` with a dim note after the title: tokens import's file), and `settings::card_foot` the note-and-buttons footer. `card_foot_with` gives the footer its own left side (tokens import's *Keep this file linked* and refusal).
- **One of a list chosen is a lit row with a check**, `ui::list_row_ground` lit on the chosen row and an `icon::CHECK` on it (the pages list, the variable picker): never a radio, and the whole row takes the click. A row that can be left out carries `ui::paint_tick_box` (`ui::tick_box`'s box, without its label) and fades its words by `ui::UNTICKED_FADE` while unticked: tokens import's rows, Colour review's members. Where the rows carry boxes, the chosen one wears its act's glyph in the box column instead of a check, which would read as one more tick (Colour review's target, `icon::ARROWS_MERGE`).
- **A ticked row inside a popover is `ui::tick_row`**: `paint_tick_box` at the menu inset, a `RowMark` (glyph or colour chip) in the menu glyph's column, the name at `SMALL_PT`, a faint `RowTail` on the right (words, or two chips with an arrow), one `MENU_ROW_H` row on `list_row_ground` under the pointer. `Tick::Open` senses a click and fades an unticked row by `UNTICKED_FADE`; `Tick::Fixed` is ticked and faded by `TICK_FIXED_FADE`, for what comes with the rest and is not the user's to change (the kit update review); `Tick::Dead` is a dead box with its words faded by `TICK_DEAD_FADE`, for a row that cannot be taken, its reason the row's tooltip (a locked layer in *Bind other uses*).
- **A row naming a variable without binding anything draws `panels::binding::capsule`**, the binding chip's resting capsule.
- **A chord the user reads goes through `input::keys`** where it is shown, bare or inside a sentence (`input::key_name` for one keycap): it is written as spelled on Windows and Linux and in a Mac menu's symbols on macOS (⇧⌘Z). The shared painters already do it (`ui::menu_row`'s accelerator, `palette::chip`, the cheatsheet's keycaps, the status line); a tooltip or card sentence wraps its own text. Stored text keeps the `Ctrl+…` spelling, which tests compare. A name the user wrote (a page, a file, a layer) goes into a status message in “curly quotes”, which `keys` leaves as typed (*Undo · on “Ctrl+K menu”*, *Imported “logo.svg” — 1 layer*).
- **A chord is bound and spelled in one place.** A key plus exact modifiers is a row of `input::BINDINGS`; a label showing it takes `Item::spec`'s accelerator or `input::accel(action)`, never a string of its own. Only a chord read in code is spelled by hand, beside its `Item`.
- **A variable collection wears `icon::DATABASE`** (U+F015, a cylinder) wherever one is named: the browser's picker and its menu, a search's or list's collection headers, *Move to ▸*, the `+` menu's *New collection*. **A variable's scope wears `icon::TARGET`** (U+F016, concentric circles round a dot): *Scope…* and every door to it. `STACK` was not reused for collections: it already means *Arrange ▸*. **An interaction state wears `icon::HAND_POINTING`** (U+F017, a hand, index finger raised) wherever one appears: a value chip's *State ▸* row on the Variants card, and its undo steps. **The assets browser wears `icon::ASSETS`** (U+F05A, a picture card over another; not `IMAGE`, which is *Place image…*): its rail button, palette row and *Insert icon* step. **A credit wears `icon::QUOTES`** (U+F05C, a pair of quotation marks): *Credits…* in the Document menu and the palette. **A service the network cannot reach wears `icon::WIFI_SLASH`** (U+F05B, the arcs struck through): the assets browser's empty states.
- **Two gates hold the standard.** `clippy.toml` refuses egui's raw control constructors (`TextEdit::singleline`, `DragValue::new`, `Button::new`, `Ui::button`, `Ui::checkbox`, `Checkbox::new`, `Slider::new`, `Ui::radio`, …) outside `ui.rs`; a site that needs one carries `#[expect(clippy::disallowed_methods, reason = "…")]`, so each exception is named. `control_audit` measures what clippy cannot see, a hand-painted ground: it renders the inspector (a rectangle, a text layer, a flex frame), the stroke, effect and type popovers, Settings, Find, Batch rename, Clean up, Fill with content, Colour review, Repeat around origin, Blend shapes, the warp card, the trace card, a component set's Variants card, the variables browser and its *Scope…* popover, the tokens import review, the top bar's tokens pill, the vision simulation's bar, a compare (its bar and changes card), Version history's footer, the path bar's Clean up card, the assets browser (empty, with an icon set ready, and on the photos tab with a service on) and the Credits card headlessly, in both themes, takes every painted rect that a clickable widget fills, a segment track holds or that spans a taller click band at its middle (a list row's ground), and requires its height, corner, fill and hairline to come from the standard, then hovers each one and checks the hover state. A menu row paints no ground at rest, so a popup menu is swept (`swept`): each row it adds is hovered and its ground must be a list row's height and corner in `menu_row`'s hover, no hairline; a value chip's popup and its *State ▸* flyout are, the flyout's rows also as wide as the popup's, and so are Colour review's rows, the compare card's and Version history's (at their own height). A new surface joins its list by hand.
- **A `TextEdit` composed into a row wears `ui::edit_frame`**, made for the row's content height. Its padding is even and the edit is stretched over a box of that height, so the edit takes a press anywhere on the row and its line sits on the row's centre, where the labels and glyphs beside it centre. Whole-point padding alone leaves a fractional line off by half a point. In a row, the edit goes in through `EditFrame::add` / `show`; an edit `put` or `place`d over its own box takes `EditFrame::on`. `TextEdit::min_size` cannot do this: egui reads only its width. The one exception is the inspector card head's name, a heading edited in place: it stays `Frame::NONE`, one line tall, centred by its row, and its typing edge is drawn from that line.
- **Control type and glyphs are the primitive's, not the caller's.** Text in a control is `ui::CONTROL_PT` (12). A glyph in a 28 control is `ui::CONTROL_GLYPH_PT` (15), the remove × included; the dropdown chevron is `ui::COMBO_CHEVRON_PT` (13). A field button takes no glyph size, so a card cannot pick 14 where the next one picked 15.
- **One type scale and one set of inks.** Every text size in the chrome is a role in `ui.rs`: `EYEBROW_PT` 9.5 (small-caps eyebrows), `CAPTION_PT` 10.5 (captions, counts, badges, accelerators, canvas pills), `SMALL_PT` 11.5 (notes, menu rows, secondary list text), `CONTROL_PT` 12 (also `BODY_PT`, egui's `Body`: tooltips and unsized labels), `HEAD_PT` 13 (a surface's lead line: the inspector's layer name, the tab's document path, the palette's query), `TITLE_PT` 14 and `HEADING_PT` 17 (a screen's heading). Every text ink is a `theme::text` tier. A role's size given a name of its own is spelled from the scale (`const NAME_PT: f32 = ui::HEAD_PT`); a size off the scale for a reason of its own (the contrast ratio's 15, the rulers' 7.5) keeps its literal in a local constant with a `// text-size:` comment giving the reason. `tests/text_scale.rs` scans the source outside `ui.rs` and `theme.rs` and refuses a literal size in a `FontId` or `RichText::size`, a local `const` holding a literal that such a call takes as its size, a tier spelled as its alpha, and an off-tier alpha within the statement of a text call. It does not read a size computed from a role (`ROLE + 1.0`) or an ink put in a `let` several lines before its text. Text on a ground of its own (an accent chip, a canvas pill) keeps its ink with a `// text-ink:` comment giving the reason.
- **Hairlines land on the device grid.** `ui::hairline_on_pixel_centre` (parity of `floor(width × ppp)`) is the shared predicate; `ui::hairline_in_column` takes the nearest position of that parity (used by `ui::rule`, `inspector::popup_rule`, `settings::section`); `rulers::snap_across_axis` shares the predicate but rounds (guides; the pixel grid's `grid_ink::on_line` picks the same pixels for its one-device-pixel lines). The predicate is shared, the base is not; swapping bases moves ink by up to a device pixel.
- **One control height: `ui::CONTROL_H` = 28**, in cards, popovers, dialogs and the dashboard. `ui::segmented` cells use `SEGMENT_CELL_H` (28 minus the track's padding). The one second scale is `ui::Scale::Toolbar`, for the bars laid over the canvas (Compare, Contrast) and the top bar's pills: `ui::TOOLBAR_H` 24, segment cells 20, glyphs 14, words 11.5. Deliberately shorter: swatch chips, badges, the layers tree's 26pt rows, and a `ui::inline_edit` rename, which takes the height of the row or card it lies over (`control_audit` exempts it by its bare field ground at `BUTTON_R`).
- **One rhythm, set by the Transform card:** `ui::CARD_COL_GAP` 7 (X beside Y), `ui::CARD_ROW_GAP` 9 (X/Y above W/H). In popovers `ui::SECTION_LABEL_GAP` (5) binds a small-caps eyebrow to its control; `POPOVER_SECTION_GAP` = `CARD_ROW_GAP`. The column gap is spelled twice per row (`item_spacing.x` and the `(available_width() - GAP) / 2.0` split); both must move together or the last control wraps. Export list rows are the one exception (row plus size caption at 3, next unit at 6).
- **Colour lives in `Hsv` (`ui.rs`)**, never egui colour types (premultiplied 8-bit and `Hsva` lose RGB at low alpha). `color_to_egui` is one-way, for painting.
- **Chrome never sets `CursorIcon::PointingHand`** and shows no I-beam over labels (`style.interaction.selectable_labels = false`). Cursors change only to mean something: `Grab` on a paint row's grip, `ResizeHorizontal` on the layers edge, scrub strips and gradient stop handles, and over the canvas the cursors `cursor.rs` draws. A `TextEdit` keeps its own I-beam. Nothing ever withdraws a cursor: egui takes `PlatformOutput` each frame, so the last writer wins and writing `Default` erases an earlier claim.
- **Every `ComboBox` owes `.icon(ui::combo_chevron)`** (`icon::CARET_DOWN`, 13pt, `text::dim()`, state-independent); `Style` has no field for it. Closed state is a `ui::glyph_and_text` or `ui::combo_text` job (explicit size and colour), never a bare string. Check: count `ComboBox::from_id_salt` against `.icon(ui::combo_chevron)`.
- **List rows are one height, `ui::MENU_ROW_H` (24)**, in a dropdown's list and in a menu alike, whether or not the row has a glyph and shortcut column. `ui::menu_rows` sets the rows' padding itself and zeroes their `bg_stroke`, so a hovered or selected row has a resting row's geometry; a `ComboBox` list is built from the global style, not the face's scope, so a caller cannot set that padding for it. A dropdown's list is as tall as its rows up to
  `ui::DROPDOWN_MAX_H` (twelve rows and the 6pt gaps between them, the theme's `combo_height`), then scrolls; only a list that
  wants another cap sets `ComboBox::height`. Rows hover at radius 4. Groups in a list are parted by one separator, `ui::menu_sep`: `text_a(26)`, 5 above and 4 below.
- **Every menu casts one shadow, `ui::MENU_SHADOW`**: `ui::menu_frame` wears it, and `theme::install` sets it as egui's `popup_shadow`, so a `ComboBox`'s list and a tooltip match a menu rather than egui's darker, tighter default. A menu's card is padded `ui::MENU_PAD` (5), egui's own popup menus too (`menu_margin`), so a `ui::flyout` beside any of them matches; a popover's is `ui::POPOVER_PAD` (11).
- **A card floating over everything is `ui::card_frame()`**: the card's fill, a `color::divider()` hairline, a 10pt corner and a deeper shadow than a menu's. The popups over the canvas, the modals (`settings::card_frame` is it), Find, the variables browser, the insert picker and the assets browser wear it; it keeps `ui::SCREEN_MARGIN` (12) from the screen's edge. Its sections part with `ui::card_rule`, a 1pt `divider()` hairline on the device grid, as the Pages and History pane dividers do; a menu's groups part with `ui::menu_sep`.
- **A colour that is a preference is a `PaintSlot::Pref`**, drawn with the inspector's own row (`single_paint_row`) and edited by the same picker. Every slot verb diverts it (`pref_scoped`) into the open Settings form's draft, so it is staged like every other Settings row and makes no undo step. The picker opens beside a modal card with `open_picker_beside`, stays above it while it serves a `Pref` slot, and takes Escape before the card does.
- **One close ×, `ui::close_button`**: an 18pt box (`ui::CLOSE_BUTTON_W`), a 13pt glyph, the tooltip *Close*, on every popover, dialog and canvas card. Escape closes them all, so the tooltip does not name it. A row's remove × and a bar's buttons are other controls.
- **A popover with no control to lead it is headed by `ui::popover_head`**: its name as a `ui::eyebrow`, the `ui::close_button` against the right margin (*Export settings*, *Repeat around origin*, *Blend shapes*).
- **A list with nothing to show says so with `ui::empty_note`**: one `SMALL_PT` line in `text::dim()` at the rows' inset, no closing period.
- **A whole surface with nothing in it is `ui::empty_state`**: an optional glyph (`ui::EMPTY_GLYPH_PT`), a `CONTROL_PT` heading in `text::strong()` and a `SMALL_PT` `text::dim()` line saying how to fill it, centred, with room below for a button (the variables browser, the insert picker, the assets browser). Its lines stand 10pt apart, the heading pulled 4pt toward its line, set by `empty_state` itself so a panel laid out with no item spacing reads the same; a button sits 12pt under the line. The caller sets the air above. Version history lays the same sizes and inks along its rail.
- **A row of buttons at the foot of a dialog or popover is `settings::footer_buttons`** (a dialog: `FOOTER_GAP` above) **or `settings::footer_row`** (a popover: its own gap): right-aligned, the way out first and the commit rightmost, and laid left to right so `Tab` reaches them in that order. A disabled commit that owes its reason a tooltip is `settings::footer_row_noted`.
- **A painter-drawn eyebrow is `ui::paint_eyebrow`**, `ui::eyebrow`'s capitals, size and ink, for the surfaces that paint their heads.
- **A word on a coloured pill over the canvas is `ui::canvas_pill`** (the size badge, a measure, a spacing value, the pivot's name, the crop's *Done*, the drop label): `BADGE_PT` in `ui::pill_ink(hue)`, `ui::PILL_PAD` (7×3), 4pt corners. Each caller keeps its own placement; `ui::canvas_pill_size` sizes one before it is placed. A measure's pill is the one narrower one (`ui::canvas_pill_padded` with `measure::PILL_PAD`, 4×2): it sits centred on the line it measures.
- **A before-and-after split's divider is `ui::split_handle`**: a 2pt accent line with a 14×36 accent grip at its middle wearing the drag grip's six dots (`DOTS_SIX_VERTICAL`, the paint rows' grip) in `color::accent_ink`. Only a press within `ui::SPLIT_REACH` (12) of the line takes it, and a right-click mid-drag puts it back. Compare's Swipe and the trace card's preview draw it.
- **A checked menu row is `ui::MenuRow::checked`.** With a glyph, the glyph turns accent; with none (`MenuRow::new("", label)`, or `ui::menu_check`), `icon::CHECK` takes the glyph column when on, and on or off the label sits at `ui::MENU_LABEL_X`, so a menu of them keeps one column: the View and Snap menus, the tabs overflow list, the flex words, a collection dropdown, *Move to ▸*. A menu with nothing to tick (Tools) leaves the column out: its rows are bare, labels at the row's 8pt inset. Such a menu is as wide as its widest row and never under its floor: `ui::menu_check_width` over its labels, or `ui::menu_check_accel_width` over `(label, accel)` pairs when rows show chords, with `ticks` saying whether the column is there, measured as `menu_row` lays them.
- **Words in a menu row's chord column that are not a chord are `ui::MenuRow::note`**: the accelerator's place and `text::faint()` ink, never read through `input::keys`, and ignored beside an `accel` (Fill with content's kind lists, each kind's sample; the Credits card's layer names). `menu_row` cuts its tail, note or accelerator, with an ellipsis at half the label's room, so a note built from the user's text cannot eat the label; a cut note puts *label · note* in the row's tooltip.
- **Every reset of one thing offers its push on a right-click, `ui::reset_push_menu`**: the reset, then *Push … to main* (`icon::PUSH_TO_MAIN`, U+F05D, an arrow rising into a hexagon outline; not `ARROW_UP_RIGHT`, go to main, nor `UPLOAD_SIMPLE`, publish). A card header's, a field mark's (`mark_menu`), a marked label's (`component::label_mark`), a ghost row's; an overridden dropdown's list carries *Push to main* as its second row. A picked push sets `ui::request_push`, and the reset door asks `ui::take_push` whether to commit the push instead. A hover chip or a ↺ click stays the reset alone: a push reaches every instance (`components.md`, *Push to main*).
- **A sentence inside a menu is `ui::menu_note`** (a confirmation saying what goes): wrapped, muted, inset 8 on both sides as a row's glyph is. A row with a tick box in its glyph's place sets its label at `ui::MENU_LABEL_X`, a menu row's label column.
- **A control that does not apply is shown and disabled, never removed** (removing one shifts every field beside it, and an early-returning card shifts everything below). Shapes: `ui::FieldButton::Disabled`, `ui::HeadAction::inert`, a dimmed `HeadAction::toggle`; each carries its reason in a tooltip. Dimming is paint only, so the call site must re-test `.clicked()`. Tooltips on disabled things: `on_disabled_hover_text` where a `Response` exists, else an explicit `Sense::empty()` claimant allocated after the disabled scope (hover is granted to a zero-sense widget that sits above the top interactive one). Nested gates use `ui::disable_unless` (`Ui::disable` multiplies opacity). Ink uses `ui::resting_ink` so disabled-over-disabled does not compound. `ui::segmented_enabled` / `segmented_tipped` give per-cell enabled state and tooltips; a disabled cell senses `Sense::hover()` (not a tab stop). The colour picker's *Gradient* tab is shown disabled for a slot that cannot hold a gradient.
- **One search field, `ui::search_box`**, in a panel, a dialog and at the head of a dropdown's list alike: the field ground, a faint magnifier, and once it holds text a clear ✕ that the edit stops short of, so the pointer over it is an arrow and it hovers on `hover()`. The ✕ empties the field, keeps the keyboard there and reports a change; it is no tab stop. The command palette's field is its own scale and is not one.
- **Two kinds of focus.** *Typing focus* says where keys go and shows whenever a text entry holds focus, however it got it: an `accent_700()` hairline on the field's own edge, on every text entry (value, text, search, rename) alike, but for a name typed over in place: a layer's or a page's row renames through `ui::label_edit`, `ui::inline_edit` without ground or edge, so the name itself turns editable where it sat and only the caret and selection show. A card's rename (a document, a version) keeps `inline_edit`'s field. *Keyboard focus* is `:focus-visible`: an accent hairline outside the focused control, shown only after `Tab` moved the focus and put away by any pointer press, so a click never rings a button (a click does not focus one either). It is painted once a frame for whatever holds the focus, by `ui::KeyboardFocus` (made at the top of `OndinApp::frame_body`, painting as it drops), on the control's own layer and cut where the control is; no control paints its own, and a text entry never wears it, its typing edge saying the same. A scroll area holding tab stops ends its content with `ui::keep_focus_in_view`.
- **An open surface holds `Tab`.** Every popover, dialog and card over the canvas calls `ui::hold_tab` in its body (`settings::card` does for its cards): the first `Tab` after it opens focuses its first control and `Shift+Tab` its last, and the focus wraps at either end rather than leaving for the panels behind. The topmost open one holds, and only while nothing is focused, the focus is on it, or it is a modal: a focus in the panels walks the panels past an open card (Find, Colour review). The held `Tab` is moved at the top of the frame, over last frame's stops, so the control it lands on sees `gained_focus` and a field selects its text. A text session's or a path's `Tab` stays the canvas's while no control has the focus. `Escape` puts the ring away, as a pointer press does. A control that resets from the keys (a ↺, a list row's reset) stays a stop while it holds the focus, and a card head's reset chip hands the focus to the head, so the reset does not drop it. A card whose `Enter` applies it reads that `Enter` through `ui::card_enter` — with nothing focused or in a text entry — and only when no control acted this frame: on a focused button or box `Enter` is that control's click, so a focused *Cancel* cancels.
- **Every control is a tab stop, in the order it is laid out**, and `Enter` or `Space` on a focused one acts as a click does (egui's own; the canvas leaves `Space` alone while a control holds the keyboard, `canvas::space_down`). A control shown only under the pointer (a reset chip, a row's buttons) is shown while it or its row holds the focus too, and registered on the frame `Tab` leaves the row, or it cannot be the next stop. The list behind a control (a split button's caret, a tool group's flyout) opens on `Alt+↓` (`ui::list_key`), and `Shift+F10` is a right-click on the focused control, rewritten as one in `App::raw_input_hook` (`ui::menu_key_as_right_click`), so every right-click menu needs no keyboard door of its own; a control scrolled out of view or under another surface is left alone, since the press would land on whatever shows there. The ring is cut only on a side where the control itself is cut by its clip. The keys are listed in `shortcuts.md` §8d. A control that moves a value with the arrows (a slider, the picker's plane and tracks, a gradient stop, a layers row's fold) takes them with `ui::arrow_keys`, which keeps egui from moving the focus to the neighbour that way: a hundredth of the range a press, a tenth with `Shift`; a value's step commits at once, the steps of one run one undo step, so a save or an undo while the control holds the focus sees them. Such a control reads a pointer press as a value with the primary button only (`ui::primary_press_pos`), so a right-click, `Shift+F10`'s included, moves nothing. A focused row renames on `F2` or `Ctrl+R` (`ui::rename_key`), the keys rename has everywhere. Nothing that no key can use is a stop: grips and dividers sense `Sense::DRAG`, a row's ground under its own controls `Sense::CLICK`. The search box's ✕ stays no stop: selecting the text and deleting it does the same.

### Value fields

- **A `ui::value_field` is one box**: the prefix is a measurement and galley painted into a strip reserved beside the number (cursor advanced with `add_space(inset)`; `DragValue` sized `full - inset` with `button_padding.x` zero), not a widget laid out ahead of it. `Prefix::Text` is 13pt. The number sits beside its prefix (`Align::Min`); a metered field uses `Align::Max`.
- **A field is the width its caller gave it, whatever it holds.** egui grows a `DragValue` to its text, so the number is laid out in a child clipped to its box and the row advances by the box alone; a number too long for it is cut at the edge, its press with it.
- **No typed or scrubbed number reaches past `ui::FIELD_LIMIT`** (±1,000,000): `Scrub::whole` starts there and `Scrub::range` clamps both bounds into it, so `0..=f64::MAX` means "not negative"; a bound chip's retype (`binding.rs`) and a number variable's cell (`variables::parse_cell`) clamp the same. Far past it, a curve's extent overflows vello's GPU buffers and the canvas draws an empty frame. Canvas gestures, MCP and a loaded file are not held to it.
- **A metered field** (`ui::value_field_metered`) says how far a value has gone with a wash under its number, by its `ui::Meter`: `Signed` for an offset either way from a neutral middle (from the centre, over a zero tick), `Amount` for a `0..=1` amount with no opposite (from the left edge across the whole field). Pick by the value's range, never draw a dead half.
- **The whole field scrubs, prefix included.** `value_field` owns its number (`value: &mut N`, plus a `ui::Scrub`); a second claimant, `ui.interact` over the strip, applies the pointer delta at the field's speed. The strip's id is `ui.auto_id_with("prefix-scrub")`, never `ui.id().with(..)`. Its response is unioned into the number's so callers and the edit valve see one control. The strip shows the plain arrow when it is an instance override's reset. Written back only on a real change.
- **Sense flags:** the strip is `Sense::CLICK | Sense::DRAG`, spelled as bitflags because the constructors add `FOCUSABLE`, so a scrub strip is no tab stop; a marked field's strip adds `FOCUSABLE`, its ↺ being the stop before the number (shown while focused, `Enter` resets). A clickable unit is `Sense::click()`, the stop after the number. Grips and pane dividers are `Sense::DRAG`: no key can drag them. Read `Sense`'s flags, not its constructors' names.
- **`ui::strip_drag_value_chrome`** strips the two faces of a `DragValue` on foreign chrome. The width goes, the *colour* of `selection.stroke` stays (it also tints selected glyphs; a transparent stroke makes selected digits invisible).
- **Sensitivity:** `ui::SCRUB_SCALE` through `ui::scrub(base)`. `Scrub::whole(base)` settles drags to integers, `Scrub::fine(base, decimals)` to a stated few (line height, star inner ratio); `.range(r)` clamps after rounding; an inverted range is swapped and a NaN bound falls back to the field limit. Typing is never rounded. Integral by nature: X/Y/W/H, rotation, skew, radii, side count, opacity %, font size, guide position, stroke weights, dashes, mitre.
- **A range bounds gestures and keystrokes; it never rewrites stored values.** All numeric helpers set `clamp_existing_to_range(false)` (egui's default rewrites an out-of-range stored value and reports it as a user edit). The picker's angle and radial CX/CY fields are `ui::value_field`s like the inspector's, so they inherit it. Applies to the Type panel, the Layout grid fields and the image card's Scale.
- **Typed arithmetic:** `expr::eval` parses every numeric field (`+ - * /`, brackets, sign; evaluated once, not stored). No identifiers, no functions (`min`/`max`/`avg`/`round` declined: every operand a field sees is a literal; the real want is a *reference*, which belongs to the Luau design in `vm.md`). Superset of egui's parser (space thousands separator, U+2212 minus). A trailing unit is dropped, except typography's `Length` (`Px | Em`) where `expr::eval_in(text, Unit)` rejects a token written in a different unit. Half-typed and non-finite results are rejected, leaving the value alone. Recursion depth is bounded at 64 in `unary` (a stack overflow is not a panic and would lose the unsaved document).
- **Precision is pinned per field**, never derived from drag speed (egui's `auto_decimals` printed 15 decimals at zero speed): `ui::number(n)` as a `custom_formatter` (trims zeros) or `max_decimals`. Single- and multi-selection twin fields must use the same spelling. `Scrub`'s `decimals` is a different thing (where a drag settles).
- **Scrub wrap:** a scrub reaching the window edge teleports the cursor (`ui::wrap_scrub`, x axis only). The artefact delta is spent on a zero speed (`ui::scrub_speed_for`); `Wrap` recognises it by size (more than half the requested jump), not timing.
- **"An edit is happening" is not answered by value fields.** The chrome retreat asks the transaction (`Transaction::changes_ink`) at the committer.
- Clicking a text field selects all (`ui::select_all_on_focus`, applied after the field runs). Operator glyph shape changes while typing are Inter's `calt`; nothing to fix.

### Window, icon, updates

- **App icon is two artefacts:** `icons/icon.png` (512) passed to `ViewportBuilder::with_icon` for the taskbar/Alt-Tab (winit registers `hIcon: 0`), and `icons/icon.ico` compiled into the exe by `build.rs` via `winresource` (also sets `ProductName`/`FileDescription` "Ondin"). A build-script failure is fatal. `icons/icon-1024.png` feeds the macOS `.icns`; `icons/icon-64.png` is the brand mark (`ui::logo`, texture kept in egui temp memory): the library tab's glyph, and the library top bar's 26pt mark with the name 12pt from it. The editor's top bar has no mark; the library tab is the way back.
- **Own title bar on Windows and Linux** (`chrome.rs`): the tab strip is the title bar. It lays `caption_buttons`, `drag_strip` (empty parts move the window; double-click maximises via `ui::double_clicked`) and, over the window, `resize_zones` (twelve `Order::Foreground` areas: four edges plus two arms per corner; none while maximised). The top bars below it are plain bars (`app::top_bar_frame`). `chrome::above_modal`, the last call of each screen's frame, relays zones, strip and buttons over a modal's backdrop (not by `move_to_top` on the zones; egui orders same-pass raises by age). macOS keeps system decorations under a transparent title bar; the strip starts `leading_inset` (72pt) in, clear of the traffic lights, which `traffic_lights::place` centres on the tab strip (`tabs::STRIP_H / 2`, 18pt down) every frame, since AppKit lays them out again on a resize; in full screen they are left to AppKit. Host differences are decided once in `chrome::Host::current`; the rest ask a `chrome::Chrome` capability. The drag strip arms itself on the press; chrome never takes keyboard focus (`POINTER_ONLY`). Focus mode hides the tab strip and the top bar; `focus_strip` returns a 32pt strip of caption buttons when the pointer reaches the top edge. Present mode draws neither.
- **The tab strip** (`tabs::tab_strip`, panel `tab-strip`, `tabs::STRIP_H` 36pt) sits above both screens' top bars; the model is in `library.md`. The library's tab comes first: the brand mark on a 40pt tab with a ground of its own, since a bare mark is judged against the taller strip and reads low. Tabs are 29pt tall, standing on the strip's foot so the front one joins the top bar, with 7pt top corners; the `+` and the caret are 30pt tabs of their own beside them, lifted on hover and while the caret's list is open; 200pt wide, shrinking together to 96pt, past which a caret lists every open document (front ticked, unsaved dotted) and the strip scrolls only as far as keeps the front tab visible (`strip_layout`, `scroll_to_show`). The front tab takes `color::topbar()`; a tab behind and a hovered one have grounds of their own a step above the strip's (`tab_behind()`, `tab_lifted()` over `tab_strip()`). A pinned tab shows a pin (`icon::PUSH_PIN`) and has no close box; any other shows the × when in front or hovered, else the unsaved dot; a shared kit wears `icon::PACKAGE`, an unreadable file a warning glyph and a red ring, a file being read pulses (`ui::pulse_alpha`). A tab whose name had to be cut wears `Project / Document` as its tooltip; a whole name wears none, as it already says it. A drag reorders, on the tab's own side of the pinned run; a middle-click closes an unpinned tab; a right-click opens the tab menu (`context-menus.md` §6.9), which the library's tab, `+` and the caret lack; `+` makes a new document in the project in front, as `Ctrl+N` does. Room beside the caption buttons stays empty (`DRAG_ROOM`) so the window can always be dragged. Strip widgets sense the pointer only, never keyboard focus, as a system title bar is not in the Tab order. The inspector column starts below strip and top bar.
- **Self-update (Velopack):** checks GitHub Releases at startup and every three hours, downloads silently, and offers *Restart to update* in a chip beside Settings (5pt, `app::TOP_GAP`). `ONDIN_NO_UPDATE_CHECK` disables it. Portable archives, `.deb`/`.rpm` and cargo builds never check. The restart goes through the close request (unsaved work is asked about); Velopack's updater is launched only from `on_exit`, because once launched it applies after 60 s regardless. The chip refuses while another Ondin process runs (`instances`, counted at click and at exit). Nothing is applied at startup. Every launch the hook sees logs to `config_dir()/ondin/ondin.log`. §5.4a's network rule governs the font source only. Identity values (pack id, channels, `chrome::APP_ID`) are permanent (§4 invariant 12).
- **Opening a document from the OS:** `ondin <file>` opens it in a tab in front (`main::names_a_document`: a `.ondin` name or any existing file, made absolute; anything else stays *unknown command*), over `reopen_last`, through `open_path`, so it becomes `last_document` and a failure is reported on the library. It is a GUI launch for the Velopack hook. A double-click runs the same: on Windows the install and update hooks write a per-user `Ondin.Document` file type (`file_type::register`; uninstall removes it, and `.ondin`'s default only while it is still ours); on Linux the desktop entry takes `%f` with `MimeType=application/x-ondin`, declared by `packaging/linux/io.github.fadion.Ondin.mime.xml`; on macOS the bundle's `Info.plist` (`packaging/macos`, built into `Ondin.app` by `build-app.sh`, which `vpk` packs as it is) exports `io.github.fadion.Ondin.document` (`.ondin`, `application/x-ondin`, conforming to `public.json`) and claims it as Editor and Owner. macOS sends the open as an `odoc` Apple Event (Finder, the Dock icon, `open`), which winit 0.30 does not pass on, so `open_event` takes it from `NSAppleEventManager` and queues the paths. At launch the first queued path is the `open` argument when the command line gave none; the rest, and any that come later, open through `open_path` on either screen in the first frame no modal is up. So on macOS a double-click while Ondin runs goes to the running window; on Windows and Linux each launch is its own process.

`EditorSession` holds no GPU state on purpose: it is unit-testable without a device, `ondin serve` (§8.2) needs the same state without a window, and §8.3's op queue plugs in there. `canvas.rs` borrows `session.render_inputs()` and owns everything device-shaped.

### Panels and the inspector

- The top bar, layers pane and tool rail are `egui::Panel`s (they reserve space). The **inspector is an `egui::Area` of independent cards drawn after the canvas**: artwork runs to the window edge, the canvas viewport is the full remaining window, and gaps between cards are live canvas (so aiming at a panel never deselects). An `Area`'s `Ui` has `max_rect` equal to its own last-frame size, so a nested `ScrollArea` converges on a tiny box; `inspector_panel` re-establishes the column rect explicitly.
- **Inspector hold** (§15 D999): because the inspector and layers panel draw after the canvas, a click that changes selection would draw the new selection's cards the same frame and drop a typed field's edit. `inspector_panel` holds the selection it drew (`OndinApp::inspector_hold`) while a widget on its own `Area` layer has focus and the live selection differs (and the held layers all exist), then commits to the layer being edited. A popover field holds nothing, except a value chip's rename, which asks (`variants::hold_inspector`) and commits on close (`Escape` cancels). The frames between are the commit, not a lag.
- Neither the layers tree nor the inspector draws a scrollbar (`ScrollBarVisibility::AlwaysHidden`); scrolling still works, both ways in the tree. Popovers keep theirs.- **Card headers:** the whole header row toggles, and a collapsed card is its whole header, both skipping the action corner (`ui::CARD_MARGIN_X`, `HEAD_ACTION_W`, `HEAD_ACTION_PAD`). The two targets are mutually exclusive (`ui::section_head` takes a `sense` flag; `inspector::panel` passes `open`) or both take the press. The `+` is a 20pt glyph with a 40×32 sense rect (`ui::icon_button_padded` senses the padded rect, allocates the unsensed box).
- **Pane section headers** (Pages, Layers) are `ui::fold_head`, not `section_head`: one press target over just the caret and the eyebrow, never the full width, and both brighten `text::faint()` → `muted()` on hover, with no hover ground. They are placed by ink, not layout box: the eyebrow's capitals centred on the row, the caret `FOLD_CARET_LIFT` (2 pt) above that line, since a chevron centred by its ink reads low. `fold_head` answers the eyebrow's baseline, for text set beside it.
- **A fold headed by a name** (a variable group, a kit in the picker or the update popover, a token-import group) paints its caret with `ui::fold_caret`: `FOLD_CARET_PT` (11 pt), left-aligned at the row's x and centred on its line, no lift, as nothing in capitals sits beside it.
- **Fill/Stroke panels are open when they hold paint, closed when empty,** asserted on a new subject and on the transition only (so a manual toggle wins within one selection). `OndinApp::synced_selection` (one map keyed by panel title) notices the subject moved and is read once per frame by `inspector_paint_panels`; `paint_auto_collapsed` records already-collapsed panels; the logic is the free fns `sync_paint_collapse` / `open_paint_panel`.
- **Cards are salted by which card they are, not where** (`inspector::panel` pushes the title; `identity_card` one shared salt). `identity_glyph` nudges `CIRCLE` down a point so the swapped glyph does not step.
- **`paint.rs`** holds most rules for how an edit rewrites a brush (kind switching keeps stops and reframes the geometry on the box, opacity scales a ramp, a linear gradient is stored as its two free ends and the angle field turns the line about its middle at its length, `with_linear_angle`, reframing only a zero-length line on the box as CSS frames an angle) but not all: what a colour field reads is one parser (`colour_text`), but the typed colour's alpha and unchanged-write rules live in `inspector::paint_hex_field` and the picker's `colour_text_field`/`write_slot_rgb` (shared with the eyedropper) separately, and the panels have disagreed. Gradient accessors speak the shape's space (forward through `GradientBrush::transform`, writers back through its inverse); a writer that inverts checks `build::affine_is_invertible` and returns the brush untouched for a collapsed space. `with_radial_axes` writes the ellipse as a circle under the transform, but two equal square axes as a plain circle under the identity, so a round gradient stays one CSS can say; a focal offset is kept relative to the outer circle. `PaintSlot` names what is painted, including slots with no node: `Canvas`, `Guide`, `Selection(PaintTarget, usize)`, `SelectionAll(PaintTarget)`, `TextDecoration`, `GroupColor([u8;4])`, `GroupGradient(PaintAt)`. Each slot declares whether it takes gradients and alpha; the alpha slider is absent where unsupported, the *Gradient* tab is present and disabled. `Canvas` and `Guide` answer false to both. `PaintKind::GRADIENTS` (Linear, Radial, Sweep labelled *Angular*) is the kind chip's menu and `is_gradient`'s answer; `PaintKind::Image` is no picker kind. Every geometry writer returns a brush of another kind unchanged.
- **Arrangement lives in `build.rs`** (align, distribute, tidy up, z-order, and a loose selection's spacing handles: `arrangement`, `respaced`, `reordered`, `offsets`). The app owns only which box align uses: the key layer's box, else the selection union, else (single layer) the container's box. `build::sorted_along` keeps leftmost leftmost; with overlap the leading edges are spaced evenly (span is `max(trailing) - min(leading)`). `build::distribute_spacing` takes the key as an argument (it holds still; others pack around it; two layers suffice); `build::gaps_along` returns every gap from boxes (the panel feeds `session::preview_world_bounds`; `OndinApp::spacing_tx` reads the committed tree). Z-order restacks each parent independently against the order previous ops leave; a one-step move swaps with the nearest unselected neighbour and adjacent runs move as a unit; `build::restacked` walks from the far end.

### Layers tree

- **Drawn front-to-back:** `flatten` walks each child list reversed; indices stay model indices, so `layers::resolve_drop` mirrors it (top of a container's list is `child_count`). The rows, the Shift-click range and the drop hint all read that one `FlatTree`.
- **Only the rows in view take a widget or ink; the tree is flattened once per change.** `flat_rows` walks the page into `FlatTree`, keyed on the session revision, the page, the search and the stamp of `Folds` (the folded set, restamped only when it changes, so a selection change that unfolds nothing rebuilds nothing), so a frame does no document walk; a Shift-click's range reads the same rows. `tree_rows` allocates the whole column in one piece and places every row's `TreeRow` by arithmetic, since the guides and the drop hint read the whole list, then runs `layers_row` only for the rows crossing the clip. A row's widget id is its layer's (`row_id`), not the layout's next auto id, which would shift with the first row in view and drop a held drag. Out of view, the row being renamed is still painted, or its field would lose focus unseen, and a dragged row still takes its widget. The topmost selected row is scrolled to wherever it is. `tree_guide_segments` works out runs only for the rows crossing the clip, over a one-pass parent index (`guide_parents`), and skips a run outside the clip before dashing it, a dash being one shape. Pinned by `only_the_rows_in_view_are_painted`, `only_the_rows_in_view_take_a_widget` and `a_row_being_renamed_keeps_its_field_out_of_view`.
- **A hovered row outlines its layer on the canvas** (`OndinApp::layers_hover`, drawn by the canvas with the History pane's hover), in the canvas hover outline's stroke, so a layer can be found in a dense layout from its row. Not for a selected row, which has the selection's frame already, nor during a row drag.
- **A focused row answers the keys for its own controls** (`layers::row_keys`): `→` opens a folded group and `←` folds an open one, `Ctrl+Shift+H` and `Ctrl+Shift+L` hide and lock that row, `F2` or `Ctrl+R` renames it, `Delete` deletes the selection when the row is in it and the row alone otherwise (the focus going to the nearest row whose layer is left, below first), `Enter` selects it as a click does, and the eye and lock show while it holds the focus. `↑`/`↓` move the focus a row: the tree does it after the walk (`OndinApp::layers_focus_step`), registering and scrolling to the next row, which may be out of view, and the focused row keeps drawing out of view as the renamed one does.
- **A row's resting badge gives way to the eye and lock on hover.** A worded one (a frame's size, a folded set's count) ends at the row's edge, short of a resting eye; a glyph one (mask, bound, a subtract's base, a mirrored path) is centred on the lock's x, so the lock replaces it in place (`a_glyph_badge_rests_where_the_lock_shows`).
- **Row controls (caret, eye, lock) are painted, not widgets.** `layers::RowTargets::at` answers both "what is under the pointer" and "what did the press hit" (`CONTROL_HIT` band), so what lights is what a click acts on. A hovered control paints `text::strong()`. The row's tint, eye, lock, size badge and component mark are pinned to the tree's viewport, not the row: `layers_row` paints them on a band, the viewport inset by `TREE_PAD_X` (`OndinApp::layers_view_x`, set before the scroll area each frame), and `RowTargets` takes those x's. Not the content's clip rect, which egui widens by `clip_rect_margin` once the area scrolls sideways, and not the band's overlap with the row, whose end can stop a few points short of the view at full scroll; either moved the controls at the end of the scroll.
- **Names are laid out whole, never truncated; the tree scrolls sideways to the rest** (`app::layers_panel`'s `ScrollArea::both()`, Shift+wheel, which egui reads as horizontal). Cutting a name to the room left of the controls squeezed deep rows to a few characters. The rows are as wide as the widest row in view needs: `layers_row` measures each painted row's name end, plus a hovered row's eye and lock room (`name_limit` with both, no badge, so hovering does not change the width), into `OndinApp::layers_tree_w`; `layers_tree` resets it each frame and the scroll area lays out the next frame's rows at exactly that width, so the scroll reaches no further than the longest name in view, and scrolling down to shallower rows brings the view back left. A floor of offset plus view, to stop that, let a fast inertial fling hold the view past every name, since the furthest the scroll could reach was read off where it already was. A name that runs on under the controls (`name_end > name_right`) is covered by `cover_row_end`: the row's own opaque ground (`row_ground`, `color::panel()` under the `row_tint` of a dragged, selected or hovered row) from `COVER_PAD` (6pt) before `name_right` to the band's right, rounded there as the tint is, faded in over `NAME_FADE` (24pt) before that, the fade reaching a point into the solid so its anti-aliased edge shows no seam. Limits: the tree guides are painted after the walk and so over the cover, and a resting badge wider than eye and lock can sit over a name's last characters at full scroll. Pinned by `a_long_frame_name_is_whole_and_scrolls_under_its_size`.
- **A row whose picture cannot be drawn wears its glyph in `theme::color::warn()`** (`layers::picture_missing`, asked of the decode cache; counts visible fills and strokes). **A row with a picture draws a 16pt thumbnail** at the glyph's x (`layers::picture_of`: first visible fill only, frame ground included), rounded by the tessellator (`THUMB_RADIUS` 3; the chip is masked at 4). Dimmed rows take 40%: a locked or hidden layer's, and a slice's (knife glyph), which never shows; `layers::thumb_tint` composes dimming with the picture's alpha. `thumbs::ImageThumbs` (on `OndinApp`) is the chrome-owned texture cache: 2 ms per-pass budget, one upload per pass, `request_repaint` on deferral, sweeps (`KEEP_PASSES` 3) because keys carry scrubbable floats.
- **Drag shows exactly one mark:** a `color::SELECT` line where the layer lands, or an outline round the destination container, never both and one line per boundary. Painted once after the walk (`OndinApp::drop_hint`), boundaries named by screen position (`layers::boundary_y`: `n` rows, `n + 1` boundaries). The tree keeps its line; porting the paint panels' live-reorder idiom is a decided non-goal (D306). The line sits mid-gap (`drop_line_y`), 2pt (`DROP_LINE_PT`), snapped to device pixels; the container outline stays 1pt.
- **Panel width:** default 300, user-resizable 210–600 (`default_size` then `size_range`, order matters; the closure calls `ui.set_min_width(ui.available_width())` or the panel collapses to the minimum), width written to `prefs.json` when the drag ends. `MIN_W` is derived from the row walk. Edge highlight waits 200 ms (`app::EDGE_DWELL`), the resize cursor does not. The inspector column does not resize (decided). Indent is `layers::INDENT` 31pt; 22 was tried and declined.
- **Drop follows the indent** (`layers::depth_range`): a gap between rows is a run of insertion levels; shallowest is the depth of the row below (hard floor), deepest the row above's (or the floor if deeper). No row records whether it is open and `depth_range` must not ask. The level is a displacement from the grab (`depth_asked_for`, from `LayerDrag::grab`), held with hysteresis (`STICK` 0.65 of an indent); the unclamped `level` is what `LayerDrag::level` stores. The line draws at the chosen level's column.
- **The destination container lights its name and glyph in `color::SELECT`** (`LayerDrag::lit`, copied from `target` at the top of the frame; paint only, a frame behind by necessity). It outranks selection and dimming. The dashed outline alternative was tried and removed.
- **Drag guards:** nothing is read unless the primary button is down *or released this frame* (`primary_down() || primary_released()`), otherwise the drag is cleared; a stranded drag (panel hidden mid-drag) must die. The drag ends on the primary button only; secondary cancels via `cancel_gesture`.
- **The tree scrolls to a selection it did not make** (`sync_tree_to_selection`, `layers_synced_selection`), instantly (`ScrollAnimation::none()`) and vertically only: `scroll_to_selected_row` checks and asks for the row's y-range across the clip's x-range, since the row's whole box would jump the view sideways each time. Three in-walk doors that change selection (click, right-click, `drag_started()` `set_one`) each owe the line, or picking a partly visible row scrolls under the pointer.
- **Spring-load** (`OndinApp::spring_load`, `layers::SPRING_SECS` 1 s): resting on the "inside" zone of a collapsed group opens it; passing `None` restarts the wait; the `request_repaint_after` is the whole timing.
- **`layers::resolve_drop`:** one level in from the row above means inside it at the end of its list; otherwise `ancestor_at_depth` gives the node whose slot is the answer. The no-cycle check (`build::can_parent`) is on the destination parent. `drop_spot` bounds the pointer on the right only, and picks the first row the pointer has not passed the bottom of.
- **Structure guides** (`layers::tree_guide_segments`, `Prefs::tree_guides`, on by default): dashed trunks per open ancestor branch, a connector, and an elbow, 1.5 on / 2.5 off at 8.5% text. Every run starts with a dash; `ELBOW_CLEAR` and `layers::elbow_y` (snapped) keep junctions closed. Runs are computed after the walk from `TreeRow`s (the drop hint reads the same list); a trunk whose branch has closed is not drawn. Hover lights the parent's trunk down to the hovered row's elbow; a selected row lights the same path in `color::SELECT` (main/instance hexagons stay `text::strong()`). Precedence is `layers::GuideInk`: hover beats selection run by run; a selected row under the pointer keeps blue. `layers::caret_column` is the one function for column x.
- **The section folds** (`Prefs::layers_folded`, persisted): the pane keeps its width and hides the tree, the search field and the header's collapse-all and search buttons, so a shared screen shows no layer names. *Rename* (`rename_selection`) unfolds it. Private mode folds it over the preference without writing it (`app-canvas-chrome.md`).
- **Fold button** reads the room (`tree_is_all_collapsed` / `toggle_collapse_all`, both via `tree_containers`). A top-level row reserves caret room whether or not it has one (`caret_room = has_children || depth == 1`).

### Pages (`pages.rs`)

- **The current page** is `EditorSession::page`, always one of the document's pages (§5.5). Switching is a view change, never an edit and never saved in the file: no history step, no dirty flag. Every door goes through `OndinApp::go_to_page`, which finishes a live text edit, then `switch_page` parks this page's camera and selection for the sitting and brings back the ones the other page was left with; `page_changed` drops gesture and panel state naming the other page's layers, and frames a page shown for the first time this sitting (`take_first_visit`). `keep_page` moves off a page an edit took away, to the first page.
- **Where a document opens.** The library remembers per machine, by document id, the page each document was left on (`library::cache::LocalIndex::last_page`) and where its camera was (`last_view`: page, centre, zoom); both are local because a view change never goes into the file. `adopt_opened` goes back to that page (`reopen_last_page`) and, when the view was recorded on that same page, to that camera (`reopen_last_view`). Otherwise it sets `EditorSession::home_pending`, and the canvas's next frame, once it has measured itself, runs `home_camera`: 100%, the page's topmost top-level frame (leftmost among equal tops) centred across the canvas with its top `HOME_MARGIN` (100pt) below the canvas's top; a page without a frame is fitted whole, an empty page gets the default camera. `remember_view` records page and camera as a document leaves the front (`park_active`, `discard_tab`, and `on_exit` for the tab in front), and nothing while `home_pending` is set: that camera is one the user never saw.
- **A selection never spans pages** (`Selection::retain_existing(doc, page)` drops layers not on the page). The canvas, the layers tree, *Select all*, layer search, the rulers and guides and snapping all act on the current page. A paste lands on it; a copied layer's parent, or a guide's frame, on another page falls back to the current page's root.
- **Undo and redo follow their step**: when none of the step's subjects (`Transaction::subjects`, read off `History::next_undo`/`next_redo` before it runs) is on the current page, the app goes to the page the first of them is on now, else was on, selects those there, and the status reads *Undo · on ‹page›*.
- **The Pages section** heads the layers pane, shown even with one page: a fold header (*PAGES*), the current page's name while folded (on the eyebrow's baseline, truncated with an ellipsis before the `+`), and `+` (*New page*); then one row per page, the current one checked, a draft tagged *Draft*, and while comparing with a version an ochre count of the page's changed layers, with the compared pages the document lacks listed dimmed after its own (`app-compare.md`). A click switches; a double-click renames in place (Enter or a press elsewhere keeps the name, Escape the old one); a drag reorders, drawing the layer tree's insertion line (`MovePage`); a right-click opens the page menu (`context-menus.md` §6.8) without switching; layer rows dropped on another page's row move the selection there. The list fits six rows, then scrolls; its divider drags the height. Fold and height are preferences (`pages_folded`, `pages_height`); private mode folds it over the preference without writing it.
- **The verbs**, shared by the section, the page menu, the keyboard and the palette:
  - *New page*: the lowest free `Page N`, at the end, on the current page's ground, made current with its name open. Adding and naming are one undo step (`commit_into_last`, over `History::fold_into_last`).
  - *Next page* / *Previous page* (`Ctrl+PageDown` / `Ctrl+PageUp`, `Action::StepPage`) stop at either end.
  - *Duplicate page*, *Draft* and *Delete page* as `context-menus.md` §6.8 gives them. The copy *Duplicate page* makes opens its name like *New page*'s, in the same undo step. *Delete page* deletes an empty page at once and asks first for one with layers (`page_delete_confirmation`: *Delete page?*, *Cancel* and *Delete* in danger red; `Escape`, the backdrop and ✕ cancel). Deleting the current page lands on the one above it (below it, for the first); the status line counts the instances detached.
  - *Move to page* (`move_selection_to_page`): the selection to the top of the other page, in order, at the same place on the canvas (every page shares one origin); it leaves the selection and the view stays. One undo step.

### History (`panels/history.rs`)

- **Where:** a section docked at the foot of the layers pane, below Layers. *View › Panels › History* (`ViewSwitch::History`, *Show history* in the palette, `prefs.view.history`): not on the canvas menu, off by default, no chord; turning it on also shows the layers pane. Focus mode hides it with the pane; private mode hides it, its steps carrying layer names.
- **Rows, oldest first:** *Opened* or *New document* (the document as opened), or *Earlier* with a clock glyph when the history was resumed from an earlier session (`EditorSession::resumed_history`; the state before the oldest kept step, not the document as opened), then one row per step (`History::done` then `undone`) reading `Label · Subject +n · Page` beside the step's glyph (`StepNote`, §5.8); the page is named when it is not the page in view and the subject is not the page itself. Short of room, the subject is cut first, down to ` · …`, then the page (`history::share`). On the right, a *Saved* pill marks the row whose state is on disk (`EditorSession::saved_step`) and a sparkle an MCP step, its tooltip naming the client and tool. The current row is accent-tinted and the rows after it (the redo stack) dimmed; the list keeps the current row in view.
- **Click jumps** (`OndinApp::jump_history` → `EditorSession::jump_to`, plus what an undo drops). The click aims at the row's step by serial, found after a live text session is finished, since that commit drops the redo rows; a row it dropped jumps nowhere. The jump undoes or redoes as many steps as it takes in one go, following only the last step to its page as `Ctrl+Z` does. A jump is not a step. A step that fails stops it on the last one that applied (*Undid n of m steps — the next one failed: …*); otherwise *Undid 5 steps · Ctrl+Y to redo* or *Redid 2 steps*, plus *· on ‹page›* when it followed. A new edit drops the dimmed rows without warning, as after `Ctrl+Z`.
- **Hover** outlines the step's layers that are on this page and still exist, in the canvas hover outline's stroke; it never switches page or selection.
- **`saved_step`**: `Some(None)` is the document as opened, `Some(Some(serial))` the state just after that step, `None` no state in the history (never saved, or restored from a crash). Set by `mark_saved` and a successful `finish_save`, cleared by `mark_unsaved` and by an edit folded into the saved step (a run or `fold_into_last` changes the document under the same serial), reset by `adopt_document`. `resume_history` sets it to the top step: the file on disk is that state.
- **The history outlives the session** for a document the library has filed: it is kept with each save and resumed on open (§9.5, *Undo history*).
- **The divider drags freely** (`prefs.history_height`, the section's height with its header, default 240), capped only by the Layers header: History may be taller than its list and Layers as short as its header, unlike the Pages divider's cap at content height. Folded (`prefs.history_folded`), the header drops to the pane's foot and names the current step, plus *N ahead* when stepped back.

## Traps

- `LIGHT_INK_GAIN` must stay a linear factor on alpha: `text::disabled()` is matched to `Ui::disable` halving `muted()`, and a curve would part the two routes to disabled in light. `ui::tests::unavailable_and_switched_off_are_different_greys` pins the match in dark only.
- `ui::value_field`'s column gap exists in two places (`item_spacing.x` and the width split); change both.
- A hairline's predicate and base are separate; do not merge `hairline_in_column` and `snap_across_axis`.
- `MENU_ROW_H` is a floor; it only equals the row height while padding keeps natural height below it.
- Disabled dimming is paint only; the click must be re-tested. The only guard on the canvas ground is the glyph colour.
- Several of these invariants (every `ComboBox` chevron, every numeric field's precision pin, `clamp_existing_to_range(false)`, the `lost_focus` rules in `app-dataflow.md`) are enforced by nothing but review or a grep.
- `layers::depth_range` and `TreeRow::closed` must not be conflated; a collapsed container takes drops only through its own outline.
- Layers tree: the drag-state guard must be asked what it says on the release frame; egui clears `pointer.down` on that frame.
- Layers tree width: never derive it from the scroll offset (a floor of offset plus view, say): the width then bounds the scroll by the scroll itself, and a fling runs past every name. `a_long_frame_name_is_whole_and_scrolls_under_its_size` pins it. The measure counts eye and lock whether or not the row is hovered, or a hover would change the width; no test pins that.
- Cursor claims go through two APIs (`Context::set_cursor_icon`, `Response::on_hover_cursor`); grep both.
- Ask where a widget is, or which layer it is on, with `ui::widget_rect`, never `Context::read_response`: in egui 0.35 building a `Response` surrenders the widget's focus on a frame whose click landed elsewhere, so the inspector hold reading the focused field that way dropped a page name field opened by the `+`. Pinned by `pages::tests::a_page_added_by_its_button_arrives_focused`.
- `home_pending` lives on `EditorSession`, not `OndinApp`, so a tab parked before its first frame is still homed when it comes forward; and `remember_view` must return while it is set, or a tab parked unseen records a camera the user never saw and reopens on it next time. The return is pinned by `pages::tests::a_document_opens_on_its_first_frame_then_where_it_was_left`.
- `open_event` registers its `odoc` handler when `NSApplicationWillFinishLaunchingNotification` is posted, never directly in `install`: AppKit installs its own handlers just before that notification, so only one registered there wins, and a cold launch's event still comes after it. No test pins this; only a Mac shows it.
