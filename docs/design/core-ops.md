# Core operations: transforms, ops, builders, history, Resolved, queries

How a document changes and how it is read back: transform and resize rules (§5.6), the operation set and `apply` (§5.7), composite builders (§5.7a), generated layer names (§5.7b), history (§5.8), the derived `Resolved` layer (§5.9) and queries (§5.10). The data model is in `core-model.md`.

### 5.6 Transform & resize semantics (Figma baseline)

- `transform` carries translation, rotation, skew and flip, **not scale**. A layer's size is one number in one place (its geometry), or a stroke thickens when its group is resized. Skew is admitted because it has no geometry field to live in. Container layout (§5.3c) refines this to a *specified* size and a *used* size derived in `Resolved` and never saved; scale stays out of the transform.
- Interactive resize edits *geometry* (`SetGeometry`: rect/ellipse size, path points scaled, text box size); stroke widths and children are unaffected.
- **Text:** a resize moves the text **box**, never the font size, and may not change which `TextSizing` (Auto / AutoHeight / Fixed) a layer is in. `tools::scale_geometry` (shared by group resize, selection resize and skew) hands text to `tools::scaled_text_sizing` ahead of the generic path and returns.
  - A **railed** text answers first: `TextSizing` is inert on a rail, so the arm edits the rail via `tools::railed_resize` (shared with `resize_to_handle`; the two derive their boxes differently, `anchored_box` over `Resolved` vs `tools::railed_box`).
  - **Off a rail**, each axis scales exactly when the user authors it: `Auto` nothing, `AutoHeight` only its wrap width, `Fixed` both. The transform half is the caller's.
  - Answering first is load-bearing: `tools::resizable_size` reports `Size::ZERO` for auto text and `(w, 0)` for auto-height, and the `max(1.0)` floor would convert them to `Fixed(1×1)`. The early return concerns the box only: under the Scale tool auto text still takes the new **font size** (`tools::scale_scalars` runs ahead of it).
  - `railed_resize` must be handed the type the transaction will *leave* (`tools::kind_to_solve_against` applies the gesture's photographic factor to the four text scopes, at both rail doors), or the solve converges on the old font. The translation holding the corner still is read off `Handle::anchored` of both boxes, not the box origin (right only for `BottomRight`). The solve is exact on placement, close on extent.
- **Dragging a text layer's own handle authors its box.** `tools::resize_to_handle` always gives the dragged width; a side handle owns one axis (`Handle::anchored`), so dragging the right edge of auto-width text yields `AutoHeight`, while a corner or top/bottom handle authors the height → `Fixed`. `Fixed` stays fixed under a side drag.
- **The inspector's W and H are the same gesture**: `tools::resized_text_sizing` takes the new size and one boolean (does this number author the height); W no, H yes, W with the proportion lock is a corner. The fields read `query::local_box`.
- Every door starts from the stored mode at the extents it is drawn (`tools::gesture_text_sizing`); the used kind is not enough, since a flex/grid-stretched text is drawn `Fixed` whatever it stores, and reading that broke auto-width labels in stretching columns.
- **Group resize** recurses geometry edits into children (`tools::resize_group`, one transaction): each descendant's position and each leaf's geometry scale; the group's own transform is untouched. **Exact at every angle**, including rotated children scaled non-uniformly: `tools::split_geometry_scale` carries the node through the scale and splits the result with `build::Basis::exact` (rotation/skew/flip into the transform, residual diagonal into geometry). RQ is exact only for **invertible** matrices; `Basis::exact` answers `None` for rank-1 or sub-`DEGENERATE` bases and every caller **refuses per node** (that member stays put, the rest proceeds; `tools::scaled_about` does the same for overflow). Multi-selection resize (`tools::resize_selection`) uses the same mechanism.
  - **A group with `display` set** goes through `resize_geometry` (`tools::resize_layer` routes it): it writes its box (`LayoutItem.width`/`height` in px via `build::sized_flex_item`, which also stops growth) and reflows; under the Scale tool it also recurses into contents.
  - **A frame inside a resized group** is a box and a container: a resize sets its box and leaves contents pinned; the Scale tool scales contents too (`tools::scale_subtree`, descendants only). A frame scaled directly takes its box alone.
- **A leaf whose geometry is its shape** (`Line`/`Path`: no authored size, no children) scales that geometry (`tools::resize_geometry`). `scale_geometry` works about the node's origin, so the transform takes the correction `anchor·(1 − S)`, split by `split_geometry_scale`, which keeps a handle-mirror as a flip. Routing is structural, spelled once in `tools::resize_layer`, which `canvas::resize_tx` and the inspector W/H both call. Only a `Path` arrives in practice; a lone `Line` has endpoint handles (`tools::move_line_end`).
- **A handle dragged past its anchor flips the shape; the flip is the sign of the scale factor.** `tools::resize_factors` hands `scale_along` a signed distance (only the magnitude clamped); a negative factor reaches `split_geometry_scale`, which puts the reflection in `Orientation::mirror`. A childless leaf with an authored size (`Rect`, `Text`, image-filled) goes through `tools::resized_box` (extent `(at - held).abs()`), which **reports** the crossing; `resize_to_handle` composes a reflection about the new box's centre. The crossing test is a sign comparison against `span - 2·held`, not `at < held` (`Handle::Left` holds the right edge). Alt is the same with the centre as anchor. Type on a rail is the exception (`on_path_flip` on `NodeKind::Text`).
- **Split on the node's LOCAL transform**, after projecting back through the parent, never on the world matrix (that wraps the parent's basis round the outside and puts scale back). A **world** basis can hold scale (sheared parent × turned child); anything reading one back must carry that residual.
- Skew is asked for directly: `Ctrl`-dragging a side of the selection box, and the inspector's Skew field (§9.4). Plain resize never produces one.
- **The Scale tool (`K`) does not multiply the transform.** `tools::Scaling` is `Geometry` (all of the above) or `Photographic` (same recursion plus `tools::scale_scalars`, which multiplies stroke widths, dash patterns, per-side widths, corner radii and font size by the geometric mean of the two box factors; §9.4).
- **Scoped guides (§5.5) scale by the axis factor, not the mean** (`tools::scaled_guides`, called from `scale_scalars` behind the `Scaling` fork): a plain resize leaves a guide's absolute offset, a photographic scale multiplies it (vertical by x, horizontal by y). Gate on the `Scaling` fork, not on the mean being ≠ 1 (a photographic `(2.0, 0.5)` has mean ≈ 1 and must still scale guides).
- **Layout lengths scale per axis too** (`tools::scaled_layout`, same fork): flex padding left/right and column gap by x, top/bottom and row gap by y, for frames and groups; a grid's px tracks likewise (`%` and `fr` tracks are shares).

### 5.7 Operations

```rust
pub enum Operation {
    // ids are minted by the caller (TransactionBuilder + IdSource) and carried in the op:
    CreateNode  { id, parent, index, kind: NodeKind, transform: Option<Affine>, name: Option<String> }, // None: numbered — §5.7b
    DeleteNode  { id },                       // removes subtree
    InsertSubtree { nodes: Vec<Node>, parent, index },   // paste / duplicate / import / undo-of-delete
    Reparent    { id, new_parent, index },
    Reorder     { id, index },
    SetTransform{ id, transform },
    SetGeometry { id, geometry: GeometryPatch }, // size, corner radii, path, line end, text sizing
    SetText     { id, content, spans: CharSpans, para_spans: ParaSpans },
    SetTextStyle{ id, style: TextStyle, spans: Option<CharSpans> },         // character defaults
    SetTextSpans{ id, spans },                  // character overrides, content untouched
    SetParagraphStyle { id, paragraph, spans: Option<ParaSpans> },          // paragraph defaults
    SetParagraphSpans { id, spans },
    SetBlockStyle{ id, block: BlockStyle },     // vertical align, trim, overflow, max lines
    SetName, SetVisible, SetLocked,
    SetProportionsLocked { id, locked },        // resize holds ratio; not SetLocked
    SetPivot    { id, pivot: Option<Pivot> },
    SetOpacity  { id, opacity: f32 },
    SetClip     { id, clip },                   // frames; an inert flag may sit elsewhere
    SetMask     { id, mask },                   // ONE node, not a run; WrongKindForOp on a kind that
                                                // cannot mask; ArtboardPlacement if its subtree holds a frame
    SetMaskMode { id, mode },                   // writable on a non-mask; changes_ink true there too
    SetFillRule { id, rule },                   // own op (a property of no one kind); changes_ink true; absorb refuses it (§6.2)
    SetFills    { id, fills: Vec<Keyed<Fill>> },
    SetStrokes  { id, strokes: Vec<Keyed<Stroke>> },  // a bound width's binding rides in the item
    SetEffects  { id, effects: Vec<Keyed<Effect>> }, // whole stack; gated on Root only (not takes_paint);
                                                // the one paint-adjacent op that changes ink OUTSIDE its layer
    SetExports  { id, exports },                // whole list; no kind gate; changes_ink false
    SetLayoutGrids { id, grids },               // drawn over a frame, never in it; changes_ink false
    SetInsets   { id, insets },                 // whole set; refused NonFinite; changes_ink true
    SetDisplay  { id, display: Option<Display> }, // whole layout; refused NonFinite / BadLayout; changes_ink true
    SetLayoutItem { id, item: LayoutItem },     // whole set; BadLayout for line 0, span 0, negatives;
                                                // dirties the PARENT too (an item's properties move siblings)
    SetComponent { id, component }, SetLink { id, link }, SetSwap { id, swap },
                                                // invert to old value; changes_ink false; component::check runs after the last op
    SetVariantSet { id, set }, SetVariant { id, values }, SetProperties { id, props },
                                                // invert to old value; no ink; held by variant::check inside component::check
    SetMode { id, mode }, SetCornerVars, SetSpacingVars, SetVisibleVar, SetSizeVars, SetTextVars, SetOpacityVar,
                                                // binding-only ops: the field alone; the binding verb writes the literal beside it
    AddImage, RemoveImage, OpenVault, CloseVault, SetOrigin,   // image table, vault, provenance
    // variables table (no node named; variable::check after the last op):
    AddVariable, RemoveVariable (refused while bound), SetVariable, SetKitModes, SetVariableName, SetVariableCell,
    AddMode (with every variable's cell), RemoveMode (refused while a frame uses it at the transaction's end; inverts to AddMode carrying the column), SetModeName,
    // (a mode moves as RemoveMode + AddMode of the same id: variable::move_mode_ops)
    // styles table (no node named; style::check after the last op):
    AddStyle, RemoveStyle (refused while bound), SetStyleName, SetStyleValue, SetStyleOrigin,
    SetFillStyle, SetStrokeStyle, SetEffectsStyle, SetTypeStyle, SetLayoutStyle, // binding alone; style::settle writes the values; no ink
    // ops with no node (the ground and guides belong to the document, §5.5):
    SetCanvasBackground { background },
    AddGuide { guide }, RemoveGuide { id }, SetGuidePosition { id, position }, SetGuideColor { id, color },
    SetGuideScope { id, owner: Option<NodeId>, position },  // both, or neither
}

pub struct Transaction(pub Vec<Operation>);   // applied atomically = one undo entry
pub struct ApplyOutcome { pub inverse: Transaction, pub dirty: DirtySet }

pub enum OpError {
    NoSuchNode, DuplicateId, InvalidParent, WouldCycle, IndexOutOfRange, BadOpacity, BadExportSpec,
    BadLayout, WrongKindForOp, ArtboardPlacement, MalformedSubtree, TooDeep, NonFinite, CannotModifyRoot,
    EmptyGeometry, BooleanAbandoned,   // empty is the user's to fix; abandoned is not
    NoSuchGuide, DuplicateGuide, BadGuideOwner,
    DuplicateItemId, BadLink,          // checked after the last op
    NoSuchVariable, DuplicateVariable, NoSuchMode, DuplicateMode, Variables(VarRule), /* ... */
}
```

- **`apply` is atomic**: validate every op against staged state; on any error mutate nothing. It does `let mut working = self.clone()`, a whole-document clone per commit, undo and redo: O(nodes) with a small constant, **and it must stay that way**. `ImageSource::Embedded` holds an `Arc<[u8]>` so the image table clones as a refcount bump (a `Vec<u8>` cost 10.2 ms per nudge at 60 MB). Anything else large added to `Document` owes the same question.
- The inverse is computed from pre-state: `SetTransform` captures the old transform; `DeleteNode` inverts to an `InsertSubtree` of the captured nodes with their **original ids** at the original position.
- **The dirty set names the nodes the ops wrote; descendant expansion belongs to `Resolved::update`** (§5.9). Enumerating a subtree in the op left `update` unable to tell why a node was dirty (a nudged group of twenty texts re-shaped all twenty). Four ops still dirty a subtree: `SetClip`, `SetMask`, `SetMaskMode` (they change how everything below is drawn) and `SetGeometry` on a frame (changes the children's clip). Structural ops (`InsertSubtree`, `DeleteNode`, `Reparent` for both parents) enumerate what they touch. Everything else inserts the node it wrote and its parent where the parent's union bounds move. **Variables-table ops write no node**: those that can change what a binding reads (variable added, removed or rewritten, a cell, a mode added/removed, a kit's modes) dirty **every node that reads a variable** (`Document::bound_nodes`, a scan), because bound corners' used kind lives in `Resolved` and `update` returns early on an empty set. `SetModeName` does too while the document holds a kit (an unmapped kit mode is matched to a document mode by name); `SetVariableName` dirties nothing.
- Ids ride inside ops, so replaying a transaction anywhere gives the same result (multiplayer, §12); `apply` allocates none. `CreateNode { name: None }` is the one field resolved against the destination; diverged replicas agree on structure and ids and may differ on the string.
- **`SetText` carries both span lists** because a span is a byte range into the content; the string alone would misplace every override past the edit. Styling without editing is `SetTextSpans` / `SetParagraphSpans`, so undoing "make this bold" cannot restore different text.
- **The two *style* ops carry an optional span list; only their inverses fill it.** Setting defaults re-states overrides against them (`Spans::restated`), dropping a span that became an echo. `None` asks for that re-statement (every forward caller); `Some` installs exactly that list (an undo restoring a dropped span).
- `SetCanvasBackground` has no node id, is infallible, dirties nothing, inverts to the previous colour.
- **The guide ops** dirty nothing (a guide is not rendered) but validate: `AddGuide` refuses an existing id, the other four a missing one (`DuplicateGuide`/`NoSuchGuide`). `RemoveGuide` inverts to an `AddGuide` carrying the whole guide. **`SetGuideScope` moves owner and position together** because `position` is read in the owner's space; it inverts to itself with the old pair (one undo step per cross-frame drag).
- **Op order in a delete transaction is load-bearing:** `apply` inverts by reversing, so deleting a frame before removing its guides inverts to `[AddGuide, InsertSubtree]`, re-adding a guide to an owner not there yet, which fails the undo. Guides first (`build::guides_of`, `app.rs::delete_selection`). The guide-owner post-condition runs after the last op and before `*self = working`, over the whole guide list, so frame-then-guides is legal forward but breaks undo.
- **`SetExports` bounds what it stores** (`BadExportSpec`): a scale that cannot be a size, or `quality` outside `1..=100` (`document::export_spec_is_usable`, same rule as `ExportScale::from_label` and the CLI parse). The loader instead **drops** the row.
- **`SetDisplay`/`SetLayoutItem` refuse values CSS refuses** (`BadLayout`): negative track, `minmax()` with an `fr` minimum, `repeat(0, …)`, empty repeat, grid line 0, `span 0`, negative padding/gap/grow/shrink/size/limit/basis. Nothing is dropped at load; `container::style_of` lays around a bad stored value. The check is against what the node holds (`is_valid_over`): a refused part an edit carries forward unchanged is tolerated, and history steps are not checked (`apply_restoring`, §5.8), or a file's bad value could not be undone to or edited around.
- **`Operation::changes_ink`** is whether applying it changes what is *drawn*; `Transaction::changes_ink` is *any* op. The chrome-only ops answer `false`: `SetName`, `SetLocked`, `SetProportionsLocked`, `SetPivot`, `SetExports`, `SetLayoutGrids`, the five guide ops, `SetComponent`, `SetLink`, `SetSwap`, `SetVariantSet`, `SetVariant`, `SetProperties`, `OpenVault`/`CloseVault`, `SetOrigin`, `AddVariable`, `RemoveVariable`, `SetVariableName`, and the styles table and bindings (`AddStyle`, `RemoveStyle`, `SetStyleName`, `SetStyleValue`, `SetStyleOrigin`, `SetFillStyle`, `SetStrokeStyle`, `SetEffectsStyle`, `SetTypeStyle`, `SetLayoutStyle`). `SetModeName` answers `true`: a document mode's name is the kit mapping's fallback match. Every `false` op but the vault pair and `SetOrigin` (which `absorb` refuses) is a no-op in `RenderOverrides::absorb` (§6.2), and **the two lists part the other way too**: `absorb` also no-ops ops that change ink with no override to carry them — `AddImage | RemoveImage` ("cannot preview") and the variables table's `AddMode`, `RemoveMode`, `SetModeName`, `SetVariable`, `SetKitModes`. `absorb`'s no-ops are invisible to `EditorSession::has_gesture_preview` (`!overrides.is_empty() && …`) and so to `cancel_gesture`'s gate; derive any repair list from `absorb`, not `changes_ink`. The `match` is wildcard-free so a new op stops the build; `op::changes_ink_tests::only_the_chrome_operations_change_no_ink` pins the whole `false` arm. Caller: the selection chrome's edit-time hide (§9.4).
- **`Operation::changes_nothing(&self, doc)`** asks whether applying it would leave the document as is; `Transaction::changes_nothing` is *all* ops (a Hide over a mixed selection is one `SetVisible` per layer, some no-ops). Asking each op against the current document is sound because if every predecessor changes nothing, that is the document it would see. Wildcard-free `match`; **`false` is the safe answer** (a wrong `true` silently drops an edit; a wrong `false` costs one pointless undo step). A missing subject and the kind gates answer `false`, so a failing commit still fails and reports. Equality is of the value written (`-0.0 == 0.0`, `NaN` equals nothing, so non-finite ops still reach `NonFinite`). An empty transaction answers `false` (the committer's question, §9.3). Caller: `EditorSession::commit_inner`.
- Grouping/ungrouping are composite transactions (§5.7a), not ops. Validation rejects: cycles, a frame parented by a shape or with a boolean or mask above it, out-of-range indices, unknown/duplicate ids, malformed subtrees, opacity out of range, ops on an unsupporting `NodeKind`.
- **`InsertSubtree` validates the whole subtree**: every parent/child pair through `CreateNode`'s kind rules; no second `Root`; no node listed as a child twice; **every node reachable from the subtree root** (a walk, not a count, since counts balance on a cycle); depth after attaching ≤ `io::MAX_TREE_DEPTH` (`TooDeep`, measured against the destination parent's depth so it is absolute); no frame under a boolean or mask, whether the barrier is above or inside the subtree; opacities in range; and the per-node field loop (`build::brush_is_finite`, geometry, transform, pivot, effects; invariant 8). It is the funnel for paste, undo-of-delete, import (`io::clip`) and MCP writes, and payloads arrive as OS-clipboard text no earlier guard has seen.

### 5.7a Composite builders & the world-space facade (`build.rs`)

Users and agents think in world space and whole intents; the model stores local transforms and primitive ops. `build.rs` is the single translation layer, in core because the UI, MCP write tools and the command line (§13) need identical projections.

```rust

```

Two properties every builder upholds:

- **A structural edit must not move anything on screen.** Plain `Reparent` keeps the local transform and teleports by the parent difference; `group`, `ungroup` and `reparent_preserving_world` re-project. A layer a layout places is not where its stored values say (an in-flow item's stored transform is where it returns to on leaving; a stretched item's stored size is not its drawn size), so every door that takes a layer out of a layout (`group`, `frame`, `boolean`, `mask`, `ungroup`) writes it where it is drawn first (`baked`: used transform and kind, plus the drawn size of a container with its own layout). Two moves are the layout's answer and kept: masking a pair in a flow moves it whole into the first slot, and *Display → none* on a laid group that is itself an item changes the box its parent places.
- **An edit applies to a node exactly once.** A selection containing a group and something inside it must not move the inner node twice: `outermost` filters covered descendants, and every multi-node transform builder routes through it.

Further rules:

- **A builder dissolving several containers simulates rather than concatenates.** `ungroup_all` runs `ungroup` over a `Document` clone advanced by each transaction as built (and a `Resolved` advanced incrementally), because `ungroup` reads the container's index among its parent's children and later containers see child lists already changed. Concatenating against the original puts the second container's children at stale indices while every world position is still right, so position assertions cannot see it. The clone is skipped for a single container. `layers::plan_layer_move` and `insert_subtrees` follow the same rule.
- **`subtree_nodes` vs `outermost`.** `outermost` alone is wrong for a colour (a group has no paint); members are reduced to outermost, then each subtree walked in full, in deterministic pre-order (children pushed in reverse) so op lists replay identically (§12). Roots are ordered by `all_in_document_order` when more than one. `set_opacity_all` takes `outermost` (opacity composes down the tree); `set_corner_radius_all` takes the subtree (a radius does not compose).
- `OPACITY_AGREEMENT` and `RADIUS_AGREEMENT` say how near two values must be for a readout to call them one (opacity prints as `{v:.0}%`; a radius is in document units). The panel's `_shown` twins read them.
- **`colors_in`** is the census behind Group Colors and the picker's document-palette chips. The scope is the caller's: a single selected container is the box the question is asked *about*, so the panel passes its children (§9.4). **Solids only** (what `recolor` acts on, by exact RGBA bytes). **`gradients_in`** is its twin over the leftover paints, keyed by the whole `Brush` (stops *and* geometry). Both wrap one private `census(doc, ids, key)` so they agree on which paints and layers and in what order. `ColorUse` carries `uses` (paint slots) and `nodes` (distinct layers, document order); a row names the node the paint sits on, never its container. **Hidden paints are counted** so a recolour doesn't resurrect the old colour when toggled back.
- **`PaintAt { node, target, index }`** (`Copy + Eq`) locates a paint: two lists and an index on every kind. `census` keeps the first place each entry was met. `paint_at` answers `None` when the place is gone (the signal for a slot to close). `repaint` changes every use of a whole brush; it is not a generalisation of `recolor` (two keys, two match rules).
- **`paint_targets`: a group is organisation, a frame is a thing.** A paint edit passes through groups and the root to shapes, and stops **at** a frame, taking the frame as target (a fill over a frame colours the frame, not its contents). A frame inside a frame is not reached. `subtree_nodes` is the census scope ("what colours are in here" includes frame contents). A frame's fills are its fill list, so `shared_*`, `set_*` and `edit_*` treat a frame exactly as a rectangle and no verb needs a frame case.
- **`Properties`** (fills, strokes, the effect stack, the drawn opacity and its `opacity_var`, plus `carried` variables, `drawn_fills`/`drawn_strokes`, `drawn_widths` and `drawn_effect_numbers` for bound values) is the payload behind *Copy/Paste properties*. Position, size, rotation, name, pivot, lock and geometry (a corner radius lives in `NodeKind`) are excluded. `properties_of` refuses a group (an empty appearance would *clear* whatever it lands on). `paste_properties` composes `set_fills_all`, `set_strokes_all`, `set_effects_all` and `set_opacity_all`, the last two on outermost targets only (effects and opacity composite down the tree, so a group takes the shadow, not its children); each skips targets that already agree, so a no-change paste is an empty transaction. The clipboard outlives a document switch, so `Properties` carries each bound variable's name and kind and each paint, stroke width, effect number and the opacity as drawn; `paste_properties` keeps, rebinds through `variable::rebind` or detaches to the drawn value, and the app's status names which, including a bound paint, width, effect number or opacity on the target that the paste replaces.
- **`shared_fills`/`shared_strokes` share the whole list, not the first brush**, compared by value through `item::same_values` (two layers given the same fill separately carry different item ids). The returned list is the first target's, ids and all: an anchor to retarget from, never a list to write verbatim. Writes: an edit of the shared list → `retarget_*_all` (maps each item through the anchor to the target's own; an added row gets one id on every target); a wholesale replacement (*Paste properties*, the mixed row's clear) → `set_*_all` (each target's ids kept by position); one row in place → `edit_*_at_all`.
- **Any disagreement is `Mixed`; the only empty panel is one where nothing in scope is painted.** An unpainted target among painted ones must not read as "No stroke". `shared_over_*` fold a getter over every paint of every target; a target with no paint disagrees with every value (absence is a value). A mixed row writes with `edit_*_all`, preserving each target's list length, order and untouched properties.
- Every builder emits **one** transaction (invariant 5) and skips no-op writes, so an unedited field blur produces nothing.
- **`Basis` and `Orientation`:** `transform` may carry reflection and skew (§5.6); `atan2(b, a)` is wrong for both. `Basis::of` is the single decomposition (`Orientation::of` = `Basis::of(t).orientation`). The split is RQ by Gram–Schmidt: every **invertible** 2×2 factors uniquely as `R(θ) · skewX(k) · mirror · diag(sx, sy)`, which lets a world-space edit be pushed onto a node whatever its parents did. `Basis::of` is total and lossy (for reporting: a collapsed node reads 0°, not blank); `Basis::exact` is partial and exact (`None` for rank-1 or sub-`DEGENERATE`; for rewriting). `scale` is the non-negative residual; the reflection stays in `Orientation::mirror`. `skew` is radians in `(-π/2, π/2)` with SVG/CSS `skewX` semantics (matrix coefficient `tan(skew)`; a 25° skew emits `matrix(1 0 0.4663 1 …)`). `R(θ)·FLIP_Y` and `R(θ+π)·FLIP_X` are the same reflection, so `of` reports the axis leaving the smaller angle (flipping an upright layer must not read −180°). The inspector's rewrites guard on `exact`: `inspector::multi_angle_tx` refuses a member with no exact split, and the skew field of `inspector::inspector_transform` withholds the write when `Basis::exact` is `None` while still showing the lossy reading.

### 5.7b Layer names (`naming.rs`)

Four things generate a name: creation, duplication, a boolean's label following an operation change (§9.4), and an image layer's `"Image N"`. Everything else is the user typing. The app owns names it generated; the user owns names they typed.

- **`CreateNode { name: None }`** is resolved by `Document::op_create` through `naming::created_name` against `Document::child_names(parent, except)`. Every generated name carries a number, the first included ("Rectangle 1"). The number is the **first free** one, not max+1, read from names present; no stored counter. Numbering is **per parent**. The sibling scan makes a bulk create Θ(n²), recorded in `roadmap.md` under *Per-edit cost*. `naming::free_name` wraps to 1 at `u32::MAX` (a copy's `from` is parsed from user text; overflow would panic in debug and yield `Rectangle 0` in release).
- **A builder wanting a specific name passes `Some`.** In core only `build::flatten`/`build::outline`/`build::outline_stroke` (carrying the layer's own name, and "‹layer› stroke" for each stroke path; `flatten`'s union arm numbers against surviving siblings). Everything else passes `None`, including the starter document. The app adds one: `canvas::image_layer_name` before `tools::create_image` (an image is a Rect, so `None` would number it as one). `"Image"` is deliberately not in `GENERATED_NAMES` (the inverse of `default_name`).
- **A duplicate keeps a typed name and increments a numbered one**, decided from the string by `naming::copy_name`. `build::CopyNames` accumulates answers (several copies in one transaction can't see each other in the document) and emits `SetName` for the copied root only. Both copy paths use it: `insert_subtrees` (paste, `Ctrl+D`) and the Alt-drag's `canvas::clone_tx`.
- **Strict vs loose tests stay separate.** `naming::generated_stem`/`is_boolean_label` ("is this a string we would have written") gate `build::set_boolean_op` overwriting a name; `copy_name` only asks whether it looks numbered (a false positive is benign).
- **`naming::usable`** trims, answers `None` when empty, and turns interior whitespace characters into a single space (runs not collapsed). `svg_in::element_name` uses it, so `None` → `op_create` generates a name. Both rename fields refuse empty names but still hand-roll `trim`/`is_empty`; this is where the rule is written, not yet the only place it is enforced.
- **Uniqueness is never load-bearing.** Everything looks up by `NodeId`; reparenting into a parent holding the same name renames nothing. This is why the SVG writer puts names in `data-name` and never `id` (§7): `id` must be a unique XML `Name`, "Rectangle 1" is neither.

### 5.8 History

```rust
pub struct History { undo: Vec<Transaction>, redo: Vec<Transaction>, run: Option<Shape> }
```

- `commit(doc, tx)`: `out = doc.apply(&tx)?; undo.push(out.inverse); redo.clear();`. `undo`/`redo` pop, apply, push the returned inverse to the other stack; a step that fails to apply goes back on the stack it came from, since `apply` changed nothing and dropping it would lose what it holds. Both apply through `Document::apply_restoring` (`apply` with `BadLayout` and the blur cap stood down, since a step writes back only values the document held, including a file's CSS-refused layout value); every other check stands.
- **`redo.clear()` on commit** stops a redo applying to a document that has moved on (commit A, undo, commit B, redo would re-write stale values).
- **`run` is the merge window** for `commit_into_run`: the **shape** of the last commit, one `Operation::shape_key` per op = variant + the *field* where the payload names one + subject. Merge is refused unless shapes are equal (keeping the older inverse restores both edits only if the second overwrote exactly what the first did). The field matters: `SetGeometry`'s payload is a field selector, so a size edit and a corner-radius edit on one node must not merge. `shape_key` is not `Operation::overwrites` (which is `None` for every guide op; `SetGuidePosition` keys a run here, so a held arrow key on a guide is one undo step).
- **No structural command can use the run:** `shape` needs `overwrites()` on every op, `None` for `Reparent`, `DeleteNode`, `CreateNode`. Ungroup, paste and image drop must fold their parts into one transaction *before* committing (§9.3).
- **A run ends on** a plain `commit`, `end_run()` (the caller's half), and **any undo or redo** (an undo that left the shape standing lets the next edit fold into the step before the undone one and discard its own inverse; a redo with nothing to redo still ends the run).
- History lives in core and is shared by app and MCP: one timeline. Depth is unlimited; `DeleteNode` inverses hold full subtrees, so a size cap is a parked future knob.

### 5.9 Resolved (derived layer)

```rust
pub struct Resolved {
    world: FxHashMap<NodeId, Affine>,
    world_bounds: FxHashMap<NodeId, Rect>,   // stroke-expanded, world space — the box you EDIT
    ink_bounds: FxHashMap<NodeId, Rect>,     // world_bounds grown by the effect stack — what is DRAWN
    inner_ink: FxHashMap<NodeId, Rect>,      // ink_bounds before this node's own effects escape
    text: FxHashMap<NodeId, TextLayout>,     // parley layouts, invalidated via DirtySet
    boolean: FxHashMap<NodeId, BezPath>,     // combined outline per Boolean node, its own local space
    failed: FxHashSet<NodeId>,               // booleans whose arithmetic was abandoned
    index: rstar::RTree<BoundsEntry>,        // leaves = paintable nodes
    used: FxHashMap<NodeId, Used>,           // SPARSE: only where layout moves/resizes a node, or bindings apply
    text_memo: FxHashMap<NodeId, TextMemo>,  // layout pass's text measurements, across commits
}
impl Resolved {
    pub fn rebuild(doc: &Document) -> Self;
    pub fn update(&mut self, doc: &Document, dirty: &DirtySet);
    pub fn used_local(&self, doc, id) -> Option<Affine>;   pub fn used_kind(&self, doc, id) -> Option<&NodeKind>;
    pub fn used_local_of(&self, node: &Node) -> Affine;    pub fn used_kind_of(&self, node: &Node) -> &NodeKind; // node MUST be doc's own
    pub fn used_frame(&self, id) -> Option<Size>;          // a group WITH a layout's box
    pub fn remembered_text_box / remembered_text_widths / remembered_text_baseline;  // preview reads of text_memo
    pub fn ink_bounds(&self, id) -> Option<Rect>;
    pub fn text_layout(&self, id) -> Option<&TextLayout>;
    pub fn invalidate_text(&mut self, doc: &Document);
    pub fn mask_path(&self, doc: &Document, id: NodeId) -> Option<BezPath>; // in the PARENT's space
}
```

- **The maps each answer a different question.** `world_bounds` is the editing box (selection outline, inspector W/H, snapping, rulers, marquee, R-tree); `ink_bounds` is what is drawn; `inner_ink` is what an effect *layer* must hold before its own padding, the only one a caller with a different effect stack (the preview path) can use (sizing from `ink_bounds` clipped the blur being scrubbed). `failed` sits beside `boolean` so "no entry" can't mean both "correctly empty intersection" and "upstream panic". Adding a map is a decision: `update` must keep every one equal to `rebuild`, and `ondin-core/tests/resolve.rs`'s `assert_resolved_matches_rebuild` compares only `world`, `world_bounds`, `ink_bounds`, `text`, `used_local`/`used_kind`/`used_frame`; `boolean`, `inner_ink` and `failed` are outside it. `text_memo` must not be compared (a cache of what the pass asked for, not a derived answer).
- **`used` is sparse and read only through `used_local`/`used_kind`**, which return the node's own `transform()`/`kind()` where there is no entry. A document with no layout and no bindings holds nothing here; the goldens staying byte-identical check that. Entries come from: layout (insets-pinned layers, flex/grid items, `Used::frame` for a laid group); a bound width/height (`resolve::with_bound_size`); a bound text's content/family (kind at the variables' strings); and bound corners (`resolve::with_bound_corners`, resolved radii put into the used kind after layout, keeping layout's size). A reader of the document's kind sees a bound corner's literal 0. `build::keep_corner_bindings` keeps a bound corner bound when an edit writes what it **draws** (used radius) or its **own literal**; anything else detaches (a typed 0 is the literal and detaches nothing, a stated price).
  - `used_local_of`/`used_kind_of` serve callers with a `&Node` and no document (SVG writer helpers); the node must be this document's own (map keyed by id; a captured copy or ghost would be answered with the original's layout).
  - **Draw, measure, hit-test and edit from those two.** A pinned layer's stored transform is not where it is drawn, so `build::keep_insets` turns a placement written for a pinned layer into its insets at the commit seam. A used kind is always the same variant as the document's, so a `match` on kind may read either.
  - `resolve::used_geometry` places a child of an `Artboard` with authored insets via `container::place` against the frame's **used** size, and children of a group with a layout (`resolve::frame_box`); `place_node` runs `container::lay_out` at each layout root and in-flow items take slot and size from it. Everything else answers `None`. `ondin-export/tests/insets.rs` proves a used geometry reaches render and export (a pinned document written byte-for-byte as its baked twin).
- No `FontContext` is threaded through: `core::text` owns a thread-local parley engine; layouts carry the exact `peniko::FontData` so the renderer draws glyphs straight from it.
- **`update` consumes `DirtySet` in this order:** (1) sort the affected set parents-first; (2) recompute the **used** entries over the subtree expansion; (3) re-shape the **dirty** nodes' text; (4) recompute world transforms parents-first from used locals; (5) recompute bounds children-first, propagating to the root. A deleted node drops its entry in every map. The sort precedes the used pass because a pinned child is placed against its frame's used size and that entry must be fresh. `rebuild` fills `used` whole before its pre-order walk, because the walk shapes text at the used kind and composes used locals.
  - **The text pass does not run over the subtree expansion**: a descendant's world transform depends on a dirty ancestor but its text layout does not (`text::layout` reads only the node's own used kind). `core::text::shapes()` is the counter that makes this assertable (identical layouts and a green differential can't see it). Layout is the one door past this rule: text in flow wraps at its container's available width and is shaped at its used kind, so `update` records which used entries actually *changed* and re-shapes the text among them the dirty set didn't already cover. The layout pass measures text at several widths on every commit at every layout root under the chain root, so measurements are kept across commits in `text_memo` (per text node: box and first baseline at each sizing asked, and content widths); `update` drops every dirty id's entries before the pass, fonts arriving dirty every text node, and every **bound** text's entries are dropped on each pass (its content and family read the variables table and mode in force, and `SetMode` dirties only its frame). So a commit that re-lays a chain re-measures every bound text in it; kept (21 ms at 200 bound labels) rather than tracing which edit reached which bound text. The memo is moved into a `RefCell` for the length of a pass and put back.
  - **The expansion starts from each dirty node's `container::chain_root`** (under flex an item moves when a neighbour grows, so a change re-lays the chain from the topmost container above it; the first hop counts for a child that just left the flow). The chain runs through a group or boolean with no layout, an atomic box its contents resize.
- **The affected set carries each node's depth and the sort caches its key.** `collect_subtree` records depth as it descends (`FxHashMap<NodeId, usize>`); the sort is `sort_by_cached_key` over a lookup. Both halves are load-bearing: a key walking the parent chain on every comparison made the incremental path 4.8× the full `rebuild` at depth 20 and 47× at depth 200 (cost scales with **depth**, not node count). `rebuild` needs no sort.
- **The text cache is load-bearing.** Bounds, hit-testing and the scene walk all read it; without it every text node re-shapes several times per frame. **Font arrival invalidates it, only for a font the document names** (layouts computed before a download used the fallback face): the app gates `invalidate_text` on `FontPoll::touches` against `OndinApp::document_families()` (the picker registers preview faces for families merely scrolled past). `invalidate_text` itself is whole-document.
- **Bounds:** local bounds per kind in `geometry.rs`, expanded by half stroke width plus miter allowance. A bounds function's `None` means *no measurable extent*: `world_bounds_of_parts`/`world_bounds_of_path` pass through `geometry::measurable`, requiring the rect to be **ordered and finite** (either test alone passes bad boxes: a `NaN` transform gives an inverted rect; an overflowing finite affine gives an ordered infinite one). Such a node is out of the index, the cull and zoom-to-selection. `transform_rect` stays total; the failed-boolean placeholder box goes through `measurable` too. The rule is stated twice (the writer guards what it stores, `resolve::build_index` guards what it accepts) because `world_bounds` derives from geometry as well as transforms, and `rstar`'s `AABB::from_corners` normalises an inverted rect to the maximal box, making the node a candidate for every query forever.
  - `ink_bounds` overflow: `effect::escaped` uses `f64::hypot` for the ellipse-mapped radius (the squared form overflowed at ~1e154); where the answer really overflows, both ink stores end `.and_then(geometry::measurable)` so a non-number bound becomes an *absence*. `stack_escape` computes the layer-blur deviation fold overflow-safely (divide by the largest deviation, sum squares ≤ 1, multiply back), and `escaped` answers the unbounded rect for an escape whose insets are not all finite. A non-finite escape written directly is guarded at the operation (`build::effect_is_finite` at `SetEffects` and `InsertSubtree`, invariant 8): `escaped` splits insets into offset and radius so an infinite escape gives `inf − inf = NaN` and `f64::min` returns the other operand, leaving the box unchanged. Derived infinite escapes from finite fields (radius past ~2.7e154) are the dangerous case: an infinite box makes everything draw; the *unchanged* box makes the cull drop artwork that is on screen. **Too small is the one error these bounds may not make**; a non-number is an absence.
- **`mask_path` is the outline a mask clips with, in its parent's space** (handed to `push_layer` under the parent's world transform, or into a `<clipPath>` beside the parent's `<g>`). `Shape` mode only (an alpha mask has no geometry). Arms are `boolean::operand_of`'s plus `Text` (glyph outlines; a boolean deliberately lacks that arm); a `Group`/`Root` contributes the **union** of its children. `None` means *masks nothing* (hidden mask, empty text, empty group, cancelled boolean), never "clip everything away". Filled non-zero.
- **A masked layer keeps its own world bounds; its *container* gets only what the mask lets through.** `world_bounds` is never reduced by a clip (conservative, and the box you drag by), but `resolve_subtree`/`recompute_bounds` clip each masked child's contribution to the box the governing mask **clips with** (`resolve::mask_extent`, arm-for-arm with `mask_path`; `query::mask_extent_local` is its local twin; `query::local_box` mirrors it or handles and snapping disagree). A mask **group** narrows its own box by its inner mask, while `mask_path` skips the inner mask and clips with the un-narrowed union; the helper follows `mask_path`. **The mask itself contributes nothing to the union** (it lends the clip, not its rectangle): five arms (`recompute_bounds` box and ink, `resolve_subtree` box and ink, `query::local_box`). A group whose only child is a mask has no box at all.
- **`ink_bounds` is the second bounds cache and the split is the point.** `world_bounds` must not move when a shadow changes (softening a blur would grow the reported height; snaps would catch on a shadow edge). `ink_bounds` is that box grown by `effect::stack_escape` at **every level of the subtree** (from children's *ink*, so an ancestor remembers a deep shadow). **Export** frames from it (`ondin_export::extent`, §7) and the SVG writer's filter region starts from it (padded for inner shadows, §7). They are equal for nearly all nodes, hence a second map. A masked child's ink contribution is clipped to the mask's **ink** extent (`mask_extent` over `ink_bounds`; a blurred mask passes ink beyond its outline). `stack_escape` composes per §6.4 stage (a drop shadow's silhouette is cut from the already-blurred layer), not as a union of per-effect escapes; the box is also the buffer (`grow_to_escape` ends `device_ink.intersect(grown)`), so under-estimating shows as a ruled edge across the shadow. **Culling reads `ink_bounds`** (`scene::paint_node`, §6.3).
  - **Containers starting from their children's ink:** a group and the root always; a frame only when it does **not** clip (box ∪ children's ink; a clipping frame keeps its box). Both passes carry the arm (`recompute_bounds`, `resolve_subtree`). Without it a group holding a non-clipping card culled the card's overflow whenever the card's box was off screen.
- **Property test:** `update` after any op sequence ≡ `rebuild`, for transforms, bounds and text layouts, over randomized sequences including text creation/restyling, `SetMask`, `SetEffects`, card frames (clipping or not) under groups, a second run authoring `SetDisplay`/`SetLayoutItem`/`SetInsets` and comparing `used_frame`, a third drawing grids half the time, and a fourth in `ondin-core/tests/variables.rs` (`incremental_update_equals_rebuild_over_random_variable_ops`) kept apart so earlier runs draw what they always did. The fourth authors corner, gap/padding, visibility and W/H binds and detaches, cell edits, modes added and removed, frame modes and reparents across frames, with undos between; it authors no `SetVariable`, `SetKitModes`, `SetModeName` or kit modes, and no stroke-width, effect, opacity or text binding. It guards a change to either implementation but is **silent about whether the rule they agree on is right** (both passes once narrowed by the mask's own box, identically, and it stayed green).
- Known cost: `update` rebuilds the whole R-tree (`build_index`, `RTree::bulk_load`) rather than patching; first thing to fix as node counts grow (§14).
- **Variables reach this layer through the used geometry alone** (§5.3f). A bound paint is resolved off the document on every frame; a bound corner is a used-kind entry; a bound gap/padding and a bound visibility taking an item out of its flow reach it as the placements the layout views lay with them resolved (`resolved_display`, `shown`). A variable's edit targets no node, so every table op that can change what a binding reads dirties every node reading a variable (`Document::bound_nodes`), and a frame's `SetMode` dirties the frame (whose subtree `update` already takes).

### 5.10 Queries

```rust
pub fn hit_test(res, doc, p: Point, slop: f64) -> Vec<NodeId>;
pub fn nodes_in_view(res, view: Rect) -> Vec<NodeId>;
pub fn bounds(res, id) -> Option<Rect>;      // world AABB, from Resolved
pub fn local_box(doc, res, id) -> Option<Rect>;
pub fn pivot_world(doc, res, id) -> Option<Point>;
pub fn group_chain(doc, id, inside: Option<NodeId>) -> Vec<NodeId>;
pub fn is_within(doc, id, ancestor) -> bool;
pub fn is_effectively_locked(doc, id) -> bool;   // this node, or any ancestor
```

- **`hit_test`** = R-tree candidates → **exact geometric test** (point-in-path for fills, distance ≤ half-width for strokes, glyph-box for text), topmost-first, respecting visible/locked, which are read **through ancestors** (`is_effectively_interactable`). Exact tests live in `geometry.rs`, at the node's **used** kind: `geometry::contains_local(node, paint, kind, p, text, slop)` takes kind and paint apart from the node (which still supplies the fill rule); `hit_test` hands it `Document::resolved_paint`'s paint so a bound stroke width reaches by its number, not its literal 0.
- **`is_effectively_locked`** is `pub` because the whole app needs it. **A locked group locks its contents.** Everything that refuses an *edit* asks this, and so does the one label that explains the refusal (`canvas::draw_size_badge`'s padlock). The lock control itself and its label must not (they write the node's own flag; asking would offer *Unlock* on an unlocked layer). A node the document doesn't hold answers `true` (refusal, not licence). It is **locked alone, not visibility**: hidden-but-unlocked layers are editable.
- **`slop`** is a picking allowance in **world** units, spent by **every kind**: each arm of `geometry::contains_local` adds it to the ink's reach (`stroke_expansion + slop`) as an outward band. A stroked shape with no fill has no interior and is grabbed by its outline; `Text` honours it too. The caller supplies it because only it knows zoom: `canvas::pick_slop = PICK_SLOP_PX / points_per_world` (**points** per world unit, not `camera.zoom`, which is device pixels, or the band shrinks at 150%/200% display scale). `0.0` means exactly. It widens the **candidate query** as well as the exact test (a horizontal line's cached bounds are zero-height).
- **Masking answers the hit test at both ends** (`query::masked_away`). A **mask is never hit** (it paints nothing; a click there belongs to what it lets through; it stays selectable from the layers panel and by marquee, which use bounds). **Masked content is hit only inside its mask**; every ancestor is asked (a mask two levels up clips just as surely). `outline_at` asks the same function, last (behind cheap rejections, since it walks ancestors and asks `mask_path`), so the Text tool doesn't offer a mask as a rail.
- **`outline_at`** rejects each segment by its own control hull first (`query::seg_hull`): a Bézier lies inside its control-point hull, so a hull farther than the allowance cannot hold the nearest point and the quintic root-find is skipped. The hull is used rather than `PathSeg::bounding_box()` (itself a root-find; measured half as good). A reject may only be too generous. `canvas::rail_at` asks it for hover and again for click.
- **`bounds` vs `local_box`** are not interchangeable. `bounds` is the axis-aligned world region (culling, snapping, marquee). `local_box` is the node's own rectangle in its own space (selection outline, resize handles, and the box resize tools edit *from*); on a rotated node `bounds` is a box the shape doesn't have. It is the **used** box (children placed by used locals). **A group with a layout is its box** (`Resolved::used_frame`, padding included). Any other container unions its children through their transforms, each masked child clipped to what its governing mask clips with (`query::mask_extent_local`, working in the node's own space to avoid an inverse per child; this is what makes a group's box rotate with it). `bounds` is a map lookup; `local_box` is a subtree walk, and the chrome asks it six times per frame (`EditorSession::preview_pivot_in(id, box_)` lets the pivot and handles share one box). A cache on `Resolved` is declined: it would answer only the resting frame (`session::preview_local_box` re-walks whenever an override is live, i.e. every frame of a gesture), so six uncached walks per frame is the design.
- **`pivot_world`** = `local_box` composed with the node's `Pivot` and world transform: the point a rotation or mirror should hold still. It lives here (a question, not a builder); `build::flip` and the inspector's quarter-turn buttons both ask it, so neither picks a different point from the canvas marker.
- **`hit_test` always returns a leaf** (groups aren't indexed, §5.9). Turning that leaf into the node a click should *select* is a separate step; `group_chain` is the tree walk: the unbroken run of group-like ancestors, outermost first (the policy atop it is the app's, §9.4, but MCP `select` needs the same answer). **A frame between groups is a rung** (a card in a row is part of the row). Frames above the outermost group are trimmed (a top-level frame's contents stay directly clickable) unless the walk stopped at `inside`; asked of `inside` itself the answer is `[]` (a stepped-into frame is clicked on its background). **An instance root ends the trim like a group** whatever its kind (§5.3d), so a frame instance is a rung. The app also *subtracts* before walking up: `canvas::pick_leaf` drops any frame with children and no group above it (not one that is an instance or sits inside one). That is a picking policy; `hit_test` still reports the frame honestly.

## Traps

- **Two defences against scale in the transform:** split on the LOCAL transform, never the world matrix, or the parent's basis puts scale back by another route.
- `Basis::of` (total, lossy, for reading) vs `Basis::exact` (partial, for rewriting): rank-1 bases have no exact split; callers must refuse per node.
- A photographic scale must gate guide/layout scaling on the `Scaling` fork, not on the mean factor differing from 1.
- Railed text: solve against the type the transaction will leave, and pin the corner the *handle* holds, not the box origin.
- In a delete transaction, guide removal must precede the frame deletion or the inverse (applied reversed) fails.
- `changes_ink`'s `false` arm and `absorb`'s no-ops are different lists, parting both ways (the vault pair and `SetOrigin`; the image pair and the ink-changing table ops); `has_gesture_preview` can't see `absorb`'s no-ops.
- `ungroup_all` must simulate on an advancing clone; concatenated transactions put children at stale indices while world positions still look right.
- `update` must not re-shape text over the subtree expansion except for used entries that actually changed; `text_memo` entries of bound texts must be dropped each pass.
- `sort_by_cached_key` plus recorded depth in `collect_subtree` are both required; either alone leaves `update` slower than `rebuild`.
- A bound corner/width literal is 0: readers using the document's kind instead of the used kind see 0; edits from the used kind must go through `keep_corner_bindings`.
- Bounds may be too large but never too small; a non-finite bound is stored as an absence, not an infinite or unchanged box.
- `used_*_of(node)` requires the document's own node; a copy is answered with the original's layout.
- The `update == rebuild` property test guards both implementations agreeing, not the rule being right.
