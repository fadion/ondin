# 7. ondin-export

The export crate: SVG, PDF, PNG, JPEG, WebP, code export (HTML/CSS, React, Vue), the Penpot and Sketch files, the MCP snapshot, the export plan and the CLI. It also documents the SVG writer's mirror, the `svg_in` reader, where the two meet.

## 7. ondin-export

### SVG writer

- API: `svg_with(doc, res, origins: &[NodeId], ExportText) -> Export`; `svg_of_reported` is it with live text, `svg_of(...) -> String` keeps only the markup; `svg(doc, res, page, artboard: Option<NodeId>)` exports one page whole or one artboard.
- **Text** is live by default: one `<text>` per line, one `<tspan>` per run, re-shaped by the viewer. `text::export_lines` cuts a style run where the face drawing it changes (`ExportRun::face`, the family the drawing face's own file gives it, set only when it is not the style's family). Only the PDF's SVG names those faces (`svg_linking`'s `faces`, `Defs::faces`), one `<tspan>` per cut in its face's family (`run_attrs(style, face)`); the SVG anyone exports, and the code export's, join neighbouring runs of one style back into one `<tspan>` in the document's family (`svg::tspans`), which a viewer falls back from by itself and which reads back with no family change per cut. `ExportText::Outlines` (an `ExportSpec` field, so a saved row and `--outlines` both reach it) writes instead the glyph outlines our layout drew, in the scene walk's text order (`emit_outlined_text`): each run a `<path>` in its own colour or once per fill, the strokes along the whole outline (`write_element` takes the outline as a boolean's result), then the decoration bands (`scene::decoration_path`, warped on a rail). An outlined rail writes no `<textPath>` and no rail def, and outlined text earns none of the text reports below.
- **`Export`** is the writer's side of `svg_in::Import`'s `skipped`/`approximated`: `svg`, plus `approximated` (the picture differs) and `round_trip` (picture right, re-reading gives a different document). The export card and *Copy as SVG* word both through one helper.
- **Selections**: the viewBox is the union of the origins' bounds (`crate::extent`, shared with the PNG writer, unions `ink_bounds` not `world_bounds` so a drop shadow is not cropped). Each subtree is emitted under its **parent's** world transform (`emit_node` composes `outer * res.used_local_of(node)`, the *used* local; passing the origin's own world applies it twice). Caller order is kept (output is byte-stable and SVG has no z-index). Nothing is deduplicated; the caller filters with `build::in_document_order` (`outermost` plus document order).
- **A spec's file** is `svg::svg_spec(doc, res, node, spec)`, the one writer of an `ExportSpec`'s SVG (`plan::render` and the panel's preview both call it). It frames the layer as `ExportSpec::view` says: under `SvgView::Frame` a frame on its own world box whatever its artwork reaches (`svg::frame_view`), so a 24×24 icon frame writes `0 0 24 24`; any other layer, and every layer under `SvgView::Artwork`, on its ink (`crate::extent`); a slice on its box. `pad_square` grows that box about its centre to a square. The box's corner is written at `0 0`, the drawing shifted with it, so the file says nothing of where the layer sits. The spec's SVG settings are SVG-only and kept, inert, under other formats, as `quality` is:
  - **`colour`**: under `SvgColour::CurrentColor` every solid fill and stroke, a text run's own colour and text's default black are written `currentColor`, the alpha kept as `fill-opacity`/`stroke-opacity` (`solid_attr`), so the file takes its colour from the page. Gradients, pictures and shadows keep their colours. `Export::merged` counts the distinct RGB solids it stood in for, which the export card names.
  - **`strokes`**: under `SvgStrokes::Outline` each visible stroke is a filled `<path>` of the ink `build::stroke_ink` gives, sides, dashes and alignment included (the ink *Outline stroke* makes), so it never rides the shape's own element; the document is untouched.
  - **`precision`**: decimal places of lengths and coordinates, 0 to `MAX_PRECISION` (4), default 2. Unitless numbers (opacities, stop offsets, colour matrices and tone curves, the miter limit, a text path's start offset) always keep four through `svg::fmt_unit`, since their error scales with what they multiply. A transform's coefficients (`svg::fmt_matrix`) keep seven significant digits of its largest scale term, never fewer than four places: a large picture's pattern scale multiplies thousands of pixels. Every other door (*Copy as SVG*, code export, the PDF's SVG) writes four.
- **Structure**: groups and artboards become nested `<g>` with local transform and opacity (group opacity is only correct on a `<g>`); shapes use local coordinates; a clipping artboard gets a `clipPath`. A frame's clip, fill and stroke and a rect's element all come from `svg::box_shape`: a `<rect>` (with `rx` for one circular radius), else the rounded outline as a `<path>`. An ellipse cut by its arc, a spiral and an arc are each a `<path>` of their outline; gradients are real `<linearGradient>`/`<radialGradient>` defs. `gradientTransform` is omitted at identity; the stop list is written clamped monotonic on a copy.
- A **sweep** gradient has no SVG 1.1 form and is approximated as a `<radialGradient>`: centre from the brush, radius from the node's box to its farthest corner, pulled back through the brush transform (`cx`/`cy`/`r` are read before `gradientTransform`). The call is gated on the kind because it asks `paint_frame` for a box.
- **Credits** (§5.3) go in one `<metadata><credits xmlns="https://github.com/fadion/ondin/credits">` block at the top of the file, before `<defs>`: one `<credit>` per line `credit::credits_in` gives for the origins, its sentence as text and `layers` (the layer names), `licence` and, when present, `source`, `author` and `licence-url` as attributes (`credits_metadata`). Nothing when no layer carries one. At the top rather than on each element, since a shape can be several elements and a wrapping `<g>` would read back as a group. Every door through `svg_framed` writes it — a file, *Copy as SVG*, a spec's file, the PDF's SVG — except code export's inline pictures (`svg_at_zero`, `Style::credits` off): their page carries the credits as a comment, a `<credits>` element is not one JSX knows, and the markup is hashed to pair variants. Every credit is written, `required` or not.
- **Model-completeness gate**: everything the model expresses must round-trip to valid SVG, and anything it can only approximate must be reported, not silently substituted.

#### Masks

- A **shape mask** is `<clipPath id="mask-{id}">` plus a `<g clip-path="url(#mask-...)">` wrapping the run of siblings above it; it emits no element of its own (the markup shape of `scene::MaskRun`). No transform and no `clip-rule` (defaults match the canvas). A mask whose path is `None` wraps nothing.
- An **alpha or luminance mask** is `<mask id maskUnits="userSpaceOnUse" style="mask-type:alpha|luminance">` holding the layer's own markup, with `<g mask="url(#...)">` over the run. `mask-type` is written for both modes; for alpha it is load-bearing (SVG defaults to luminance). It is written as the CSS property, not the attribute, for support. PDF export inherits both through usvg.
- The ink arm has a `doc.shown` guard: a hidden mask must not erase the run (an ink mask laying no ink does erase, which is correct). No emptiness test, matching the canvas.
- The `<mask>` region is written explicitly, as the mask's own `ink_bounds` mapped into the referencing node's local space and inflated a tenth. The default `-10%..120%` is relative to the viewport in the current (possibly transformed) user space and loses artwork under a scaled group. A mask with no ink keeps the absent region. `<clipPath>` takes no region.

#### Effects

- An effect stack is **one `<filter id="fx-{id}">`** and a `<g filter="url(#fx-...)">` wrapping everything the node emits (§5.3a, §6.4). Properties that are load-bearing:
  - The region is explicit, `filterUnits="userSpaceOnUse"`, from `Resolved::ink_bounds` mapped into the wrapper's space, **then padded for inner shadows** (`svg::inner_working_pad` = `reach(blur) + |spread| + |offset|` over visible inner shadows, uniform). Outside the region every primitive is transparent black, so with the layer's ink as the region the alpha-inverting `feComponentTransfer tableValues="1 0"` has nothing to invert from and a rect/frame/image/text inner shadow drew nothing. A filter's working region and the layer's ink bounds are two quantities.
  - The wrapper sits outside the clip (SVG applies `filter` before `clip-path` on one element), which is also the only position that works for multi-element output (`emit_stacked`). It carries no transform, so the region is in the node's parent's space (what `effect_region` composes for).
  - A `<filter>` with no primitives renders its element as nothing, so a stack that is all off or all neutral emits no filter; an attribute-less `<feOffset/>` is the shortest "unchanged".
  - The graph is built in the same two stages as the CPU pass (§6.4); every filter carries `color-interpolation-filters="sRGB"`.
- **A background blur is left out and reported approximated** (*a background blur, left out*, `report_node`): SVG has no backdrop, since no viewer implemented `BackgroundImage`. PDF inherits the note through the SVG.
- `ondin_core::svg_in::effects_of` reads a `<filter>` back as an effect stack (shadow chain drop or inner, lone `<feDropShadow>`, lone `<feGaussianBlur>`, `<feMerge>` as assembly, bare `<feOffset/>` as an **empty** stack, not a skip). Stack order is document order; `feMerge` lists results differently so is not used for order. A `Filters` row's `feColorMatrix` is written but not invertible (brightness and contrast scale the same channels), so such a stack is skipped whole and reported.

#### Blend modes

- A node that composites through a blend layer on the canvas (§6.2) is wrapped in an outermost `<g style="mix-blend-mode:X">`, or `<g style="isolation:isolate">` for an isolating Normal and for a page or top-level frame holding a blended layer (a mode or a shadow's). It sits outside the filter wrapper, as the blend layer sits outside the effect layer, so a layer's shadow blends with it. `svg::blend_decl` makes the scene's decision again and is shared with the code export. SVG has all sixteen modes, so a layer's mode is not reported.
- **A shadow's own mode is drawn Normal and reported** (*a shadow's blend mode, drawn normal*, `report_node`): a `<filter>` reads only its own element, never what lies beneath, so the mode has nothing to blend with there. PDF inherits the note through the SVG. The reader reads every shadow as Normal; the writer never writes an `feBlend` for one.

#### Reporting

- Known inexact features are reported to the user: sweep as radial, shadow spread as a square kernel, a shadow's blend mode as Normal, type on a rail (glyph placement is the viewer's), a crop past the picture's edge (`crops_past_picture`), a flipped rail as a reversed path, an image fill as a `<pattern>`, and a run's variation axes, OpenType features, baseline shift or language. The four text properties are written on the run's `<tspan>` (`svg::run_attrs`): axes and features as CSS in `style`, the shift as `baseline-shift` (a `dy` would make the `<tspan>` positioned, and the reader would split it into a node of its own), the language as `xml:lang`. Those after the crop are **round-trip** losses, not approximations (the picture is identical), and the report keeps the two lists apart.
- The report is read off the node in `emit_node` under the visibility guard, **not** in `collect_defs` (which has no visibility guard, an unreferenced def being harmless). The shadow arm checks that spread is nonzero, the effect visible and `effect_region` answerable, so it never warns about markup absent from the file. `ondin-export/tests/fidelity.rs` pairs every reported claim with the markup that caused it. `svg_roundtrip.rs` binds the writer only for tests that call `svg_of`; a test on hand-written markup binds nothing.

#### Names, numbers and the reader

- A layer's **name** goes in `data-name` (`name_attr`, written at the leaf in `emit_shape`, the container `<g>` in `emit_node` (the outer one in the split-clip case), and `emit_stacked`'s `<g>`), not `id`: `id` shares a namespace with the synthesised `grad-`/`img-`/`clip-`/`mask-`/`fx-` ids, so a layer named `clip-601d_2` would shadow a real `<clipPath>`. Unnamed writes nothing. The reader prefers `data-name` and falls back to `id` (Illustrator and Inkscape put layer identity there), going through `naming::usable` (§5.7b): blank or all-space names fall through to numbering.
- `svg::fmt` is the single number formatter. Its places are a thread-local, `PRECISION`, which `svg_framed` sets for one pass through `PrecisionScope` (clamped to `MAX_PRECISION`, put back on drop, a panic included): `fmt` is reached from too many places to take a parameter. Trailing zeros are trimmed only after a decimal point, so at 0 places 19.7 is `20`. A non-finite number floors to `0` (a non-`<number>` makes the whole file unparseable). A floored `<filter>` region has no area and renders the element as nothing, so a **singular world transform writes no filter** (artwork exports unfiltered, as `ScenePainter::push_effect_layer` does). The predicate is `build::affine_is_invertible`, not a relative-epsilon determinant test that could never fire at large coordinates.
- **PDF import** (`pdf_in`) has no reader of its own: `hayro-svg` draws each page as SVG and `svg_in` reads it, so a PDF's fills, strokes, gradients, clips and pictures take the SVG paths. Text arrives as glyph outlines, since a PDF places glyphs rather than setting paragraphs; `hayro-svg` writes a `<use>` per glyph, which `pdf_in::merged_glyphs` joins into one `<path>` named *Text* per run of one paint on one line, splicing each run's span so the rest of the markup is kept byte for byte. A stroked run's width and dashes are in the `<use>`'s units, so they are scaled with the outline (`stroke_scaled`); under a transform that is not a similarity no one width redraws the stroke, and those glyphs stay `<use>`s. `hayro-svg` draws a shading as a `<pattern>` holding one gradient-filled shape; `pdf_in::unwrapped_shadings` splices each such pattern into that gradient under the pattern's id, the pattern's and the shape's transforms folded into `gradientTransform`, since `svg_in` reads no pattern. A tiling pattern, and a shading clipped to its `/BBox` (whose bare gradient would paint the whole shape), stay patterns, skipped and reported.
- **What a page may cost is measured before it is drawn.** `hayro-svg` rasterises a function-based or mesh shading, and a gradient SVG cannot express, at the filled shape's box at one pixel per point, without a cap, and decodes each picture at its declared size; a shape far off the page asks for any size and the allocation failure aborts the process. `pdf_in::page_cost` interprets the page onto a device that only adds those sizes up (a mesh's triangles at the device pixels hayro samples them at), and a page past `MAX_SHADING_PIXELS` (64 million: a full-bleed mesh on an 8,000-point artboard) or `MAX_PICTURE_PIXELS` (256 million: ten 24-megapixel photos), one whose patterns, soft masks or Type 3 glyphs nest past the eight levels the walk follows (`hayro-svg` follows fifty), and every page after the pages read reach four times either budget together (`MAX_DOCUMENT_PIXELS`, since each page's drawing crosses back to the app and its pictures are decoded there) is left out, counted in `PdfImport::too_large` and reported as *N pages too large to draw*; a PDF with no page left is refused (`PdfInError::TooLarge`). The app's doors, and the child process the app runs `pdf_in::import` in as the guard for what this measure misses, are in `app-image-editing.md`.
- **Reader behaviour** (`svg_in`) that bears on round-trip:
  - Style cascade follows CSS's invalid-declaration rule: an unparseable `fill`/`stroke` leaves the inherited paint. Three meanings share `None`: `none` and `transparent` mean unpainted; an unresolvable `url(#...)` is a valid declaration with a dead reference, unpainted (so a missing image does not become opaque black). `!important` is stripped in `declaration` (no important tier exists).
  - `svg_in::Css` reads compounds of type, class, id and `*` joined by descendant and child combinators. It refuses `+`/`~` (sibling order), `:pseudo` (state) and `[attr]`, reported once per sheet. A selector list is read member by member (`.a, rect:hover` still paints `.a`, as Chromium).
  - A `<style>` is all its text children joined (`svg_in::style_sheets`, built in `import` above the `Builder` it is handed, because `Css` rules borrow it). `roxmltree`'s `text()` returns only the first child and lost sheets with a leading comment.
  - A paint that is genuinely unreadable is reported via a fourth flag beside `Css::complex`, `Gradients::patterns` and `Gradients::resampled`; it is a `Cell` (a fact about elements, set while the gradient table is borrowed) and a `skip`, not an `approximate`.
  - `stdDeviation="0"` is a value, not a refusal: a lone zero blur is an identity primitive like bare `<feOffset/>`; negative is refused. `shadow_chain`'s "neither moved nor softened" test is on values, not presence (a zeroed offset plus zeroed blur is not a chain). `flood-color="currentColor"` resolves against the referencing element's `color`.
  - A `<text>`'s own `opacity`, `display`/`visibility` and `filter` reach every run it splits into (positioned `<tspan>` becomes its own node). Opacity multiplies, hiding is either-or, and for `filter` the run's own wins where stated.
  - `mix-blend-mode` and `isolation` are read from a style, an attribute or CSS (`BlendMode::from_css`), an inner `<tspan>` taking the outer element's. The writer's blend wrapper comes back as a group carrying the mode, as an effect's `<g filter>` does; `isolation:isolate` alone sets Normal, which isolates a group. A keyword the model lacks is reported approximated, *mix-blend-mode X (drawn normal)*.
  - A `<tspan>` is read at any depth, content flattened to one piece per text node carrying the innermost element's resolved style.
  - Text whitespace collapses to XML's four characters (`XML_SPACE`: space, tab, CR, LF), not Unicode's set (no-break and ideographic spaces must survive). `text_node`'s two trims share the constant; `lead` re-bases span byte ranges onto the trimmed string.
  - A duplicate id is **first-wins** in all three id maps (`ids`, `clips` (clipPath and mask), `by_id`), as browsers do.
  - A `<clipPath>` imports as a `Shape` mask and a `<mask>` as a `Luminance` one, SVG's own meaning and exact, or as `Alpha` when its `mask-type` (attribute, style or sheet) says alpha (`svg_in::masked`). A PDF soft mask written as a luminance `<mask>` reads exactly through the same path.

#### Paint emission

- A shape with at most one fill and one centred whole-outline stroke is **one plain element** with `fill`/`stroke` attributes. Anything else goes to `emit_stacked`: a `<g>` carrying the node's transform and opacity, then one element per visible paint in §6.3 order, strokes with `fill="none"`. Transform and opacity move to the group so the paints share one user space (also the `clipPath` space) and fade together. `write_element` is the single per-kind element writer both paths share. `fill-rule` rides with the fill through `with_fill_rule` on both arms (an `Exclude` given an aligned stroke once exported non-zero, a union).
- Non-plain shapes:
  - **Non-centred stroke**: `align_clip`, a `<clipPath>` plus double-width stroke, per stroke (`sa-<node>-<i>`; the id carries the paint's own index). An outside clip's outer ring carries the canvas's mitre allowance (`effective_sides(...).max_width(s.width) * miter_limit`); the two must agree.
  - **Per-side stroke**: one `<path>` per edge from `geometry::side_path`, sharing one alignment `clipPath`. `plain` requires `effective_sides(...).is_all()`.
  - **Fitted dash on a multi-subpath path**: one `<path>` per subpath, each with its own `stroke-dasharray` (`plain` requires `dash_fit_pieces(...).is_none()`).
  - **Frame border**: painted over contents and outside the frame's clip, so a frame with both becomes two `<g>`s (outer transform and opacity, inner `clip-path`) with the border `<rect>` between them, only when both are present.
  - **Text stroke** rides the `<text>` element (re-shapeable); an aligned one is clipped against `ondin_core::text::outline`.
- `stroke-dasharray` carries the resolved pattern (SVG cannot express a zero-length dot or fit-to-corners). `stroke-miterlimit` is emitted only for Miter joins with limit != 4 (SVG's and kurbo's default). Gradient slot names carry the paint index (`grad-<node>-fill-0`, `-stroke-1`), even when there is one paint.
- **Known divergence**: past `scene::lay_stroke`'s gate the canvas fills an expanded outline while this writer hands `stroke-width` to the consumer, so a very wide stroke (e.g. 309pt on a 200x120 shape) is only as correct as the viewer.
- **`Defs`** is insertion-ordered (byte stability, goldens) and deduped through a set, not a scan of the `Vec` (a scan was O(D^2) and 87% of export time at 16,000 defs). Ids are a `DefKey` newtype whose equality is counted under `cfg(test)`; `def_count_tests` bounds 2,000 defs below 2,000 comparisons (a timed ratio measured the machine).
- **Image fill** is a `<pattern>` (a paint server, through `Defs`, `image_id` spelled like `gradient_id`; `paint_attr` names it). The tile is the source's intrinsic pixel box; the whole framing is one `patternTransform`, omitted at identity via `matrix_attr`. A pattern repeats where the canvas pads with the edge pixels; that differs only where a pad-extended framing's picture box does not cover the frame — a hand-edited crop outside `0..1` — and is reported as an approximation (Fit's letterbox is clipped, so it does not count). Inside the pattern is a `<use>` of one shared `<image id="pix-<hash>">` per distinct `ImageId`, written once in `<defs>` and carrying `ImageEntry::href` (data URI, or a link's path as written). Per-node `<pattern>` stays (its transform is the node's framing); `opacity` and `filter` sit on the `<use>`; no `width`/`height` on the `<use>`. An **adjusted** picture gets a `<filter>` on the `<use>` (never on the pattern): `feColorMatrix` and `feComponentTransfer` straight from `ImageAdjust::pipeline`, each only where not identity, no `feFuncA`, sRGB interpolation, region pinned to the element's own box (the default 10% bleed would show between tiles). Unadjusted emits no filter. A letterboxing picture forces stacking (the clip belongs to one paint). The framing frame mirrors the walk: an artboard's own box, a text node's layout bounds, otherwise the outline's bounding box.
- An image fill the table cannot answer for exports as the **missing-image placeholder** (`emit_missing`, off `ondin_core::missing_placeholder`, with `clipPath` `mi-<node>-<slot>`), never as a dangling `url(#...)`, and forces stacking. A stroke with an unanswerable image writes `none` (the canvas draws nothing). A frame's ground is an ordinary fill and goes through the same path.
- **Two-walk gate**: `ondin-export/tests/two_walks.rs` compares the *ink set* (which nodes each walk puts paint down for, through a unique solid colour per node) between this emitter and the scene walk (§4 invariant 11). The two recorded divergences were of that kind.
- **Variables** arrive as resolved values: each node's paint is taken through `paint_box::node_paint` (`Document::resolved_paint` in the mode in force there, then gradients mapped onto the box layout draws, as the canvas does, §6.2) in `collect_defs` and both emitters; helpers read only literal brushes; a bound corner arrives as `rx` through the used kind. Paint is presentation attributes; `style` appears only for an ink mask's `mask-type` and a blend wrapper's `mix-blend-mode` or `isolation`.

### Code export

- One core (`code::walk`) builds the element tree and an emitter prints it. Classes are slugged from the layer name, the kind's name standing in, a numeric suffix on repeats within a file or on a text style's class. The pipeline is separate from `ExportSpec` -> `plan` -> `PlannedFile` and asks the SVG and PNG writers for what CSS cannot draw (§15 D1098). Three emitters, one signature (`doc, res, origins -> CodeExport`); every zip ends with `tokens.css` (only when the page reads a variable), `text-styles.css` (only when a text wears a text style), `assets/` (PNG fallbacks and picture files) and `report.txt`:

  | Emitter | Files before the shared tail |
  | --- | --- |
  | `code::html::html_of` | `index.html` (links `tokens.css`, then `text-styles.css`, before `styles.css`) and a `<slug>.html` per other page, one `styles.css` with the reset. Every instance is written out as its layers. |
  | `code::react::react_of` | `App.tsx` and `App.module.css` (the page), a `<Name>.tsx` and `<Name>.module.css` per other page, `base.css` (the reset: border-box, `body` margin 0), `components/<Name>.tsx` and `components/<Name>.module.css`. Pictures in JSX are imported as bindings; inline SVG is rewritten as JSX (`code::jsx`: attributes camel-cased where React aliases the name, any other left hyphenated, which React sets as written; `style` objects; text as string expressions). |
  | `code::vue::vue_of` | `App.vue`, a `<Name>.vue` per other page, `base.css`, `components/<Name>.vue` (`<script setup lang="ts">`, `withDefaults(defineProps<…>())`, `<style scoped>`). Text the template compiler would change — a run of whitespace, a tab, a space at an edge (it condenses them), `{{` — is an interpolated string literal, in inline SVG too, never `v-pre`, which would void a `v-if` or `:class` on its element; an `img` `src` starts `./` or `../` so Vue's compiler imports it. |

  Every `.tsx` and `.vue` file imports `base.css` (and `tokens.css`), then `text-styles.css` when its tree wears a text style, before its component imports and its module CSS; CSS `url()`s are written `./assets/` or `../assets/` from the file, as a bundler resolves them.
- **Credits** (§5.3) of the exported layers open the page's file as a comment, one `credit::credits_in` line each (the plain line, then ` — ` and the source address when there is one): `<!-- Credits … -->` under `index.html`'s doctype and at the top of `App.vue`, `/* Credits … */` at the top of `App.tsx` (`Target::write_credits`). A line is escaped for its comment (`--` and `*/` broken apart). Nothing when no layer carries one.
- **A layer's HTML element** (`Node::element`, `core-model.md`) is its tag (`Walk::element_of`, `Walk::write_element`); Automatic is the tier's own, below. Nothing is guessed from names. Each element takes what makes it draw as the `div` it replaces, ahead of the layer's own declarations so they win (`reset_first`):

  | Element | Written with |
  | --- | --- |
  | Button | `type="button"` and `BUTTON_RESET` (margin, padding, border, background, font, color, text-align), without `font` when the text wears a text style's class, whose face `font` would undo; phrasing content inside |
  | Link | `href` when set; `LINK_RESET` (color, text-decoration) |
  | List | `ul` with `list-style: none`, margin and padding 0; a child written as a plain box becomes its `li`, any other (an element of its own, a picture, a use) is wrapped in an `li` with `display: contents` (`Walk::items`) |
  | Heading | margin 0; phrasing content inside |

  **Phrasing content** (`phrasing`): inside a button or a heading every box becomes a `span`, `display: block` where it set no display, since those elements hold only phrasing content. An element HTML refuses where the layer now sits (`element::refusal` holds only when it is set; a later move can break it) is written as Automatic and listed in `elements`: anything inside a button, a button or link inside another, a second main, the main inside any other element (HTML lets it sit only in plain boxes), a header or footer inside another. So is an element on a layer drawn as a picture, which keeps its tag and leaves the page's main to a later layer. A use keeps the elements its component wrote, so a use inside a button, or a use of a component whose root is a button or a link inside either, is reported under `approximated` as invalid HTML. The walk counts one main per page and per component file; in React and Vue a component renders into its page, so a page's main beside a use holding one writes two, unreported; the menu allows one per top-level frame, so several frames exported onto one page write the first and report the rest; each variant's tree of a set may hold its own. A component's root takes its element in its own file (`Walk::component`), and a use takes none, so it is never wrapped twice; a marked set's root is written by `as_element` (below), its element still barring what may sit inside it. React and Vue write the same elements.
- **Components** (React and Vue; `walk::page(.., components: true)`): an instance root whose main is a CSS-tier layer becomes a use of a component made from the main, or from the set when the main is a variant, named PascalCase from the main's or set's name, unique in the export ignoring case (two names differing in case are one file on NTFS and APFS), with `App`, `Component` and `ComponentType` reserved (the page, and the types React and Vue import) and a Windows device name taking a `Component` suffix (a kit's folder, `Kit`).
  - **A set is one component.** Each variant property is a string-union prop defaulting to the default variant's value (`kit::default_variant`, the topmost, then leftmost), but for the interaction state's, which has none (below). Each other variant's tree is drawn under its values (`if (size === "Large") return …`; `v-if`/`v-else-if`), the default's last as the fallback for any other values. Variants sharing their values are written once, and an instance of a later one is inlined. The default's tree is walked first, so its classes take the plain names; classes are unique across the trees.
  - **The trees are merged where they can be** (`code::merge`). `merge::pair` first keys every other tree's layers to their counterparts in the default's (`Element::key`), under a paired parent: by lineage key, whichever side recorded it, else by name path, as the model pairs a variant's layers; a layer whose counterpart another took gets a key of its own; a text's paragraphs and runs match by place. Variants join the merge one at a time: a variant that would break it keeps its own tree and the rest still merge (`Merged { bodies, apart }`), exact and not reported. A tree merges when every matched element is the same but for its declarations — tag, attributes, text, uses and arguments, an inline SVG equal but for its class and with equal rules — and every layer list comes in an order each tree keeps (two layers ordered each way round keep that variant apart). Each element wears the default's class or, under the variants whose rule differs, that variant's class (one per distinct rule, worn under any of their values): `className={size === "Large" ? styles["label-2"] : styles.label}`, `:class="size === 'Large' ? … : …"`. A layer only some variants draw is shown under them (`{size === "Large" && (…)}`, `v-if`), or, when the default draws it, under all but the variants that do not (`!(size === "Large")`), since the default's tree is drawn for any values no other tree is; variants never share values, so their conditions never overlap. A boolean property's guard joins it with `&&`. Each rule is whole and exactly one applies, rather than a base rule and a modifier: a modifier's two classes would tie a use's doubled class on the root, and the use's placement must win.
  - **A marked set's interaction states are CSS** (`code::states`; the model is `components.md`, *Interaction states*). The variants that are no state merge as above; each state variant is diffed against its rest variant's view of the merged tree (rest: the same values of every other property) and written as rules on the elements' classes, in the order hover, focus-visible, active, disabled, so a later state wins a declaration two change. Each rule applies live on the root, never while a value is forced, and forced by its value: `.root:hover:not([data-state]):not(:disabled) .el, .root[data-state="Value"] .el {…}`.

    | State | Live on the root |
    | --- | --- |
    | Hover | `:hover:not([data-state])`, then `:not(:disabled)` on a Button, `:not([aria-disabled="true"])` on a Link or Plain |
    | Focus | `:focus-visible:not([data-state])` after the root's class twice, and `outline: none`: the state draws its own focus, never the browser's ring too |
    | Pressed | `:active:not([data-state])`, then the same as Hover |
    | Disabled | `:disabled` on a Button, `[aria-disabled="true"]` on a Link or Plain, after the root's class three times |

    Every live selector weighs four classes (`dom::Live::live_selector`), the root's class repeated to pad the lighter ones, so where two states apply at once — hover and focus, focus on a disabled Link — source order decides, as the order above means.

    - Only changed declarations are written; one rest has and the state lacks is `unset` (`display` is `revert`). A layer only the state draws is added with `display: none` and shown by the rule; one only rest draws is hidden by it. **A layer drawn another way than rest's counterpart is a swap** (`merge::same_drawing` refuses it: another tag, a picture whose markup differs, another use or arguments, another binding): rest's is hidden and the state's added and shown, so a recoloured vector icon still pairs. Rules name elements by class index (`dom::StateStyle`), so Vue's class renames carry; where variants sharing a root class need different state rules, the root takes a class per variant (`split_roots`).
    - **Placement and size are never written on the root** (`states::PLACEMENT`), since a use's must win: a state changing them is reported approximated (*the root is 2 px larger than at rest; drawn at rest's size and place*).
    - A state that does not line up with rest (no rest variant, other text, another order: `variant::unpaired_states`' reasons) keeps its own tree behind the prop alone, reported approximated (*Button · Large, Pressed: “Label” moves before “Bg”, so :active is written only behind the `state` prop*). A rest variant kept apart from the merge says so with the merge's reason (*Large, Default does not merge with the other variants (…)*).
    - **The root** is written as its roots' element (`variant::root_element`, read as Button, Link or Plain; `walk::as_element`): Button a `<button type="button">` with `BUTTON_RESET` before its own declarations, so they override it, and phrasing content inside, so its inner frames are `span`s; Link an `<a>` (`LINK_RESET`) with the default root's `href` (`Live::href`); Plain a `div tabindex="0"`, or the roots' own element when it is one other than Button or Link (a `nav`), written by `write_element` as an unmarked root is, (`tabIndex={0}` in React, whose types refuse the HTML spelling). A root drawn as a picture stays one. Interactive content cannot nest, so a root holding a use of an interactive component is written as Plain, reported.
    - **The prop stays, for forcing a state.** It has no default: unset, the browser decides; an instance at rest passes none, and any other value forces. The forced `data-state` holds the value's exact name, since two values may differ only by case. A `disabled` boolean prop is added; the root carries `data-state={state === "Default" ? undefined : state}` — rest's value passed is no forcing, so the live states keep working — and `disabled={disabled || state === "Disabled"}` (or `aria-disabled`). React's props interface `extends Omit<ComponentPropsWithoutRef<"button">, …>` over the named props and spreads `...rest` onto the root before its own attributes (`rest2` where a prop is named `rest`); Vue binds `:data-state` and `:disabled`/`:aria-disabled`, attrs falling through. A base-tree condition reads the prop through `dom::state_prop`: rest holds for any value but a plain (untied) one, so a forced state still draws from rest's tree.
    - Plain HTML writes the page as drawn and says so in one line when it holds a marked set. `html_of_components` reads the state prop as the frameworks do (`dom::term_holds`), writes a use's forced `data-state` and `disabled` as plain attributes (`Live::drawn_attrs`) and holds the states' rules.
    - Toggle states (`:checked`, `aria-pressed`) are not built.
  - **A swap property is a component prop** when every slot it is bound to shows one main, as a use that sets nothing: React types it `ComponentType<{ className?: string }>` and destructures it into a capitalised binding (`icon: IconSlot = Star`, the walk keeping `IconSlot` off every component name); Vue types it `Component` with a factory default (`() => Star`) and draws `<component :is="icon">`. The slot keeps its placement class, so whatever component is passed sits where the slot does. A use passes a swapped main's component (`icon={Heart}`, `:icon="Heart"`), which is then written too; a swap to a main no use can show inlines the instance.
  - **A shown nested instance's parameters are forwarded** (*Shown from nested*): every parameter of the slot's component — its variant, its properties, its own forwarded ones — becomes the outer component's, named for the slot (`buttonLabel`, `buttonSize`), with no default, and the slot passes each on with its own value standing in when the slot sets one (`label={buttonLabel ?? "OK"}`). The slot's value can differ per variant of a set, so no single default would hold; `undefined` reaches the inner component as unset, which draws its own default. Vue declares each forwarded prop's default as `undefined`, because Vue casts an absent boolean with no default to `false`. Slots are matched across a set's variants and an instance's copies by name path, as the model matches them (`variant::ShownNested::key`); a path whose slots show different components, or a slot a swap property also chooses, is not forwarded. A shown copy switched to another variant of its set is a forwarded variant value; switched to another component it is an override.
  - A component's parameters are one list (`Walk::params`: variant properties, properties, forwarded ones), read the same way on any instance (`Walk::read`); what a use passes is where the instance's value differs from what the component draws unset (`Walk::differences`), and the fields an instance may differ in are those the parameters read (`Walk::fields`).
  - Boolean and text properties become typed optional props defaulting to the main's values, named camelCase; a word strict code reserves (ES modules are strict: `private`, `interface`, `eval` too) or `styles`, the CSS module's binding, gets a `Prop` suffix, and `className`, `key`, `ref` and `children` are taken. A picture's import binding is snake_case (`card_box_png`), which no prop or component name is. A boolean shows its bound layers (`{prop && (…)}`, `v-if`); a text property replaces the bound text's content with the value in its first paragraph's style, reported approximated when the main's text has runs or more than one paragraph. A use passes only values that differ from the default.
  - The component root is `position: relative` at the main's own size; the use carries the instance's placement and size in a rule naming its class twice (`.card.card`), so it outranks the root's own rule whichever stylesheet loads last. React's root joins a `className` prop; Vue's takes the class by fallthrough. A use whose root sets a mode its main does not, or at an export origin under a non-default mode, sits in a `display: contents` wrapper carrying `data-mode`, since a use writes no attributes of its own. A use whose visibility varies by mode sits in one shown by the visibility token, `display: var(--x, contents)`: a `display` in the use's doubled-class rule would override the root's own flex or grid.
  - In Vue a used component's root also carries its user's scope and its user's class, so classes are settled in two passes: `vue::avoid` renames any class in a file equal to a root class of a component the file uses, then `vue::keep_uses_apart` renames a use's class that is any class of the used file (except that file's root class when it has one tree, which the root wears anyway). Neither renames a class onto a worn text style's, which is global.
  - An instance is **written out as its layers** when, anywhere up its chain of copies to the main, it differs in anything but the fields its component's parameters read and its root's visibility, size and mode: any other override, a removed or reordered child, a local layer, any other swap, or a root mode other than the main's when the main sets one, which the component's root carries (*"inlined because of overrides; make it a property to keep the link"*). Instances of a main, or any variant of its set, drawn as a picture are inlined too, with their own reason, as are those whose main draws a property's layer inside a picture (a use cannot reach into one; a boolean on the picture itself shows its element) and those drawn in another mode than their main's while the main's pictures, strokes, effects, visibility or content read a variable that varies: a component is written once, in its main's mode, and `var()` carries a mode only into CSS values.
  - **A kit's components** are written from its vault mains into `components/<Kit>/`, the folder named PascalCase for the kit (`Origin::name` on the vault top, else the kit's name in the variable table, else *Kit*), unique per kit; imports between folders are written relative (`code::relative`). The vault is never resolved, so the walk runs on `kit::as_placed` with every vault top moved to the first page and resolved there, which leaves the page's own layers where they are; without it a kit main's text has no layout and its automatic line height would be `normal`.
- **`CodeExport`** carries five lists, kept apart as `Export`'s are: `approximated` (the page draws differently from the canvas; this list is the contract), `positioned` (draws right, but as fixed positions or a picture: a group without `display`, a layer written as SVG), `inlined` (instances written out as layers, empty for plain HTML), `states` (one line per marked set, *Button: Hover and Pressed written as :hover and :active; `state` forces one*) and `elements` (layers written as another element than they set, and why). `report.txt` opens with *Interaction states:*, then the other lists under their headings, `elements` last under *Written as another element than set:*; the app shows no states report of its own.
- **Variables are custom properties** (`code::tokens`). A bound field is written as `var()`. Fill, stroke, effect and layout styles are already folded into each layer, so they arrive resolved with their variables kept as `var()`; text styles are classes (below).
  - **A visibility bound to a variable that varies is a token**: a boolean is `initial` (true) or `none` (false), read as `display: var(--x, <own display>)` (`Tokens::shown`). `initial` is the guaranteed-invalid value, so the fallback, the layer's own display, wins. The layer is written whatever it shows in the mode drawn.
  - **A text content that varies by mode** (`tokens::varies`) is written once per distinct value, each in a `span` wrapper read as `display: var(--<var>-<mode>, contents)` (`Tokens::shown_in`). That hidden token, shared by every text of the variable, is declared in each mode block of its collection: `initial` where the mode holds that value, `none` elsewhere. This holds for a document string with a literal cell in every mode of its collection (`tokens::strings_by_mode`) whose text no component text property replaces; a kit's string or one with an alias, whose value another collection's mode can decide, is written for one mode and reported approximated.
  - **A string scoped to flex families alone is written bare as its CSS keyword** (`Tokens::keywords`), and a bound direction or wrap is `flex-direction: var(--x)` / `flex-wrap: var(--x)`, with `align-content` written whenever the wrap is bound. Bound to a string scoped wider, they are written for one mode and reported approximated.
  - **`tokens.css`** declares every variable read plus every alias target they reach in any mode, and the hidden tokens that show a text per mode, nothing else, in one block per mode per collection. **The collection picked by width is the window's**: its default on `:root`, each other mode in `@media (min-width: Npx) { :root {…} }`, then each mode's `[data-mode…]` block after every media block, so a frame pinned to a mode wins over the window. Any other collection's default mode's block is `:root, [data-mode="<default>"]`, since a frame can set the default inside one set to another; each other mode is `[data-mode="…"]`. **Every block declares every token of its collection, aliases included**: a custom property's `var()` is substituted on the element declaring it, so an alias declared only on `:root` keeps the default's value in a `[data-mode]` subtree (measured in Chrome). For the same reason a block also redeclares every alias of another collection that names one target in all its own modes and reaches a variable of this one; an alias whose target differs by mode cannot be redeclared by a block that does not know that mode, and is reported (`Tokens::unfollowed`). A kit's variable is declared in the blocks of the document collection its kit collection maps from, in the column that mode maps to (`Variables::kit_mode_at`); a kit's own modes get a block of that kit's variables, redeclaring every document alias that names one, on `[data-mode~="…"]`, since a frame may set a kit mode beside a document mode. With two or more collections the selectors are `[data-mode~="…"]`, since a frame names every mode it sets in one attribute; with one they stay `[data-mode="…"]`.
  - **Names**: `--` plus the slugged path (`brand/500` → `--brand-500`); a kit's prefixed with its kit's name, the document's own left unsuffixed on a collision. Mode values are slugged likewise, each one word, unique across collections. A frame that sets modes carries `data-mode`, every mode it sets as a word (`Tokens::modes_attr`); an export origin under an ancestor setting a non-default mode carries that mode's beside its own, for every collection the origin does not set itself, since each collection inherits on its own.
  - **A frame that picks its mode by width is a page filling the window**, so the media blocks read the window's width as the canvas reads the frame's: the page root is `width: 100%` with `min-height` its height, the frame `left: 0; width: 100%`. A picture in it is drawn in the frame's width mode, which the window cannot change, so one reading a variable another width resolves otherwise, and not under a layer pinning that collection's mode, is reported (`Walk::picture_follows_width`). Exported beside other origins, each such frame is a page of its own (`walk::page`, `Page::others`); the other origins keep the first page, and with none the first such frame does. Each other page is named from its frame, unique against the first page and the components: HTML `<slug>.html` (`<slug>-page.html` for a Windows device name; every page sharing the one `styles.css`), React `<Name>.tsx` and `<Name>.module.css`, Vue `<Name>.vue`, beside `App`.
  - **A frame's width queries are container queries.** Its element carries `data-query` (`Tokens::query_attr`): one word per query, `‹component›-‹collection›` (a kit collection by its name, or the kit's for its only one), shared by every frame querying that collection at the same widths. A kit collection's blocks declare the kit's variables in that kit mode's column. After every collection's blocks `tokens.css` writes, per word (`Tokens::query_blocks`): `[data-query~="…"] { container-type: inline-size }`; the narrowest mode's block on `:where([data-query~="…"]) > *`; each other mode's under `@container (min-width: Npx)`, which reads the content box as the canvas's pick does; then each mode's pin, `:where([data-pin~="…"] > [data-query~="…"]) > *, :where([data-mode~="…"][data-query~="…"]) > *`, last so a pin wins. Every one is `:where()`, of no weight, so source order alone ranks them and a child pinning its own mode keeps it, the nearer pin winning as on the canvas; equal widths resolve to the later mode, as `query_mode` does. The children are the selector because a container never queries itself, as on the canvas. A pin on the frame itself, or on a use's own `display: contents` mode wrapper, beats the query; a use of a main with width queries marks its own pin `data-pin` beside `data-mode` (`Walk::instance`), while a mode inherited from around, on a wrapper or any ancestor, carries no `data-pin` and loses to the query, as on the canvas. No test draws it in a browser.
  - **Numbers are unitless; the use site adds the unit**: `calc(var(--x) * 1px)` for gaps, padding and shadow offsets, `max(0px, …)` where the model floors at 0 (size, a size limit, stroke width, corner radius, blur), `calc(var(--x) / 100)` for opacity (a percentage, clamped by CSS as by the model). A bound blur is `calc(<floored px> * 0.5)`, the deviation. A bound colour under a fill `%` is `color-mix(in srgb, var(--c) N%, transparent)`; a bound family is `var(--f), sans-serif`, the token a quoted string. A bound type number takes its literal's unit, held to the model's range: `font-size` `max(1px, calc(var * 1px))`, `font-weight` `clamp(1, round(var), 1000)`, `line-height` `max(0, calc(var / 100))` for a `%` literal else floored px, `letter-spacing` and a paragraph's `margin-top` `calc(var * 0.01em)` for `%` else px; a paragraph with a spacing of its own writes that instead. With a size bound, corner radii clamp to `calc(min(W, H) / 2)` over the size expressions, and a replaced flow item's `min-width`/`min-height` follow it.
- **Text styles are global classes** in `text-styles.css`, written only when a text wears one (`Page::text_styles`, `code::finish`).
  - **Names**: `walk::page` names every text style of the document up front, in id order, `text-` and the slugged name (*Heading/Large* → `text-heading-large`), and every file's classes start with those taken (`Classes::reserving`), so a layer named *Text Heading Large* is `text-heading-large-2` whichever is met first.
  - **The class** is made when a CSS-tier text bound to the style is first met (`Walk::text_class`): the style's face (`face`), an automatic line height as the px that first user was laid at. The file holds one rule per worn style, in the order first met. The text wears the class before its own: `class="text-x title"`; in JSX `` className={`text-x ${styles.title}`} ``, alternatives and a component root's `className` inside the template; in Vue a static `class` beside `:class` when the element has alternatives.
  - **The text's own rule leaves out what the class makes** (`TextClass::own`, in `Element::css`): each declaration the class makes with the same value is dropped, and a property the class declares and the text does not is set back to `normal`. Whatever the text sets otherwise, a line height laid at another px included, stays and wins, as its stylesheet loads after `text-styles.css`. The element's declarations stay whole in the tree, since merges and interaction states compare what is drawn; only the printed rule is trimmed.
  - Colour is no part of a text style, so it stays on the text's own rule. A run's `span` writes only what differs from the text's face, so runs take no class.
  - *Copy as CSS* wears no class (below). `code_text_styles.rs` pins the emitters; `code_fidelity.rs`'s `text_styles_match_the_canvas` draws the page.
- **Three tiers per layer**, the first that draws it exactly, judged on the layer's own features (its children choose their own; `Walk::css_blocker`):
  1. CSS on a `div` (or the element the layer sets): frames, groups, rects, ellipses and text (a `p` per paragraph, a `span` per run that needs one).
  2. The subtree as inline SVG through `svg::svg_at_zero`: other kinds (a spiral as "a spiral"), masks, an ellipse cut by its arc and an `Arc` (both "an arc, which CSS cannot draw", rather than the whole ellipse reported approximated), and paint or effects with no CSS form below. **A picture's markup says nothing of where it sits**: its `viewBox` starts at 0 0 (the element is placed by CSS), and its def ids are renamed for its content (`walk::content_ids`: the layer's place in the picture and an FNV-1a hash of the markup). The same picture in two variants therefore writes the same markup and pairs in a merge or a state, while two different pictures keep ids of their own in the page's one id space. **A path or line its insets stretch** (`walk::stretching_holder`) is a `div` the insets place, holding the picture with its geometry box as the `viewBox` on each stretched axis, `width`/`height: 100%`, `preserveAspectRatio="none"`, `overflow: visible` and `vector-effect="non-scaling-stroke"` on its shapes, so it stretches in the browser as on the canvas; an axis it does not stretch on keeps the ink as its view at its px size. One drawn turned, skewed or scaled is written at its drawn size and reported. **A pinned plain group or boolean** (`layout.md`, *A plain group pinned in a box*) is placed by its insets like any pinned layer, its box its drawn contents' (`Resolved::contents_box`, `walk::shared_box`); every layer inside it, through nested plain groups, is placed as `Place::Share`: `left`/`top`/`width`/`height` as percentages of that box, a picture filling its share as a stretched path does. A turned, skewed or scaled layer takes its unturned box's share and keeps its transform's linear part, turning about its centre as on the canvas; text's box takes its share and its type keeps its size, as on the canvas. One with no extent is written at its drawn place and reported. A picture drawn turned, skewed or scaled in the world (a path in a turned group, or under an import's `viewBox` scale) is not stretched, as above.
  3. A 2× PNG through `png::raster_of` when the SVG writer itself reports an approximation; reported as approximated. A raster with the same bytes as one already written reuses its file, so the same picture pairs across variants here too.
- **Placement**: every element is positioned (`relative` in a flow, `absolute` out of one) so siblings paint in tree order. An out-of-flow layer gets `left`/`top` at its slot (`container::slot_of`) and its linear transform as a `matrix()` about the box centre, CSS's default `transform-origin`; a group without a layout has no box and turns about its origin. Insets inside a frame or a laid-out container are written as `left`/`right`/`top`/`bottom` in their own units. Auto margins between two insets are placed as core places them (`walk::margined_axis`): one pushes the box against the far inset, written as that inset alone, and two centre it as the midpoint with `translate: -50%`, because CSS's own auto margins leave a box that overflows its insets at the start one — and a chart's label or pie, centred on a point between two insets that meet, always overflows. Flex and grid are written under the model's names, `Start`/`End` as `flex-start`/`flex-end`. A frame without a layout writes a typed px or percentage size as the layout reads it, else its own box. A flow item that is neither text nor a laid-out container gets `min-width`/`min-height` of its own size, so the layout does not squeeze it below it as it would an empty `div` — except on an axis sized as a percentage, which follows its parent down.
- **A chart** (`charts.md`) is written as the frames it is: its flex and grid as CSS, its marks by their percentage insets, its paths as stretching pictures, so the page resizes it as the canvas does. The chart frame takes `role="img"` and an `aria-label` of its name, and each of its children `aria-hidden="true"`, which hides the parts under them. `code_charts.rs` pins the markup and `code_fidelity.rs`'s `charts_reflow_as_the_canvas_does` draws flattened, resized charts.
- **CSS forms**, measured in headless Chrome against the CPU renderer:
  - **Strokes**: an all-sides stroke is an `outline` (which follows `border-radius`) offset by −w inside, −w/2 centred, 0 outside. On a frame with children the part inside the box goes on a last child over the whole box (`pointer-events: none`), since an element's own outline paints under its positioned children and the canvas strokes a frame over them; a clipping frame keeps the part outside the box on itself, where the last child would be clipped, so a centred stroke splits at the edge. An outline's square corners are mitred, so a centred or outside stroke with any square corner goes to SVG unless mitred with a limit of at least √2. An ellipse's stroke is CSS only on a circle: an outline offsets the radii, which is not an ellipse's parallel curve. A per-side stroke is `border`s only when inside, square-cornered and on a layer with no children: through a rounded corner CSS tapers one width into the next where the canvas splits the arc. One solid, undashed stroke at most.
  - **Gradients**: linear (pad or repeat) at any angle under any affine; a concentric, growing radial under an axis-aligned transform; a sweep as a non-repeating `conic-gradient` under a rotation and uniform scale. Reflect, a focal or shrinking radial and non-sRGB interpolation go to SVG. The tier is judged and written on the paint as drawn (`paint_box::node_paint`, in `css_blocker` and `paint`), so a box stretched by layout is judged with its stretch.
  - **Image fills** (`code::image`) are `background` layers framed off `ImageRef::framing`: Fill `center / cover no-repeat`, Fit `center / contain no-repeat`, Crop and Tile an exact px position and size, `no-repeat` and `repeat`. Quality Low sets `image-rendering: pixelated` on the element, so a layer whose pictures disagree on it goes to SVG. Under per-side borders the element gets `background-origin: border-box`, since the canvas frames the picture on the whole box. A missing or linked picture, colour adjustments, a fill under 100% (a CSS background layer has no opacity) and a crop past the picture's edge (the canvas stretches the edge pixels) go to SVG; the last is reported there and so becomes a PNG.
  - **Picture files** are `assets/<slug of the image id>.<ext>`, one per image and orientation, shared by fills: the original encoded bytes, or, for a turned or mirrored picture (`ImageOrient`), the decoded picture mirrored then turned clockwise by quarters, written as PNG with `-r<quarters>[m]` in the name. A GIF is written as PNG too, since the canvas draws its first frame and a browser would animate it. Inline SVG links its pictures to these files rather than embedding them (`svg::svg_linking`, the upright file, its pattern turning it), so layers sharing a picture share one file; React imports it as a binding and Vue links it from the file.
  - **Effects** are one `filter`: blurs, then the drop shadow, each at `effect::deviation` (radius × 0.5). Only one drop shadow, with zero spread, since CSS chains `drop-shadow()`s; spread, inner shadows and colour filters go to SVG. So does a drop shadow with a blend mode (`drop-shadow()` has none), where the SVG writer's report makes it a PNG.
  - **A background blur** is `backdrop-filter: blur(<deviation>)` (bound, `blur(calc(var * 0.5))`) on a rect, ellipse or frame. `css_blocker` refuses it on a group or text (*a background blur on a group or on type*: CSS shows it through the element's box, the canvas through the outline) and beside any other visible effect (*a background blur with another effect*: an element's `filter` applies over its filtered backdrop too, where the canvas leaves the backdrop out of the layer's effects). A refused layer goes to SVG, whose report makes it a PNG.
  - **Blend modes** are `mix-blend-mode` or `isolation: isolate` on the element, from `svg::blend_decl`, at every tier. A clipping frame holding a blended layer takes `isolation: isolate` beside `overflow: hidden`, which makes no stacking context while the canvas's clip layer isolates; the page's root element takes it when anything on the page blends, as the canvas isolates the page. A tier-2 `<svg>` or tier-3 `<img>` carries it on itself too: it is drawn alone, so a mode written only inside it would blend with nothing of the page.
  - **Corner radii**, a frame's or a rect's, are `border-radius` clamped per corner to half the short side, so CSS's proportional scaling never applies. Smoothing is written circular and reported approximated.
  - **Text** is CSS with at most one fill, solid, and no stroke, off a path; otherwise SVG. An automatic line height is written as the px the canvas laid (`TextLayout::line_height`), because `normal` reads a different metrics table per browser and platform; a run of another size or font under it is reported, as are line limits, box trim, hanging indents and list markers. Fonts are named, never shipped.
    - **Case** is written into the content with core's `text::cased_text`, never as `text-transform`, whose rules differ (`capitalize` keeps capitals, `ß` uppercases to `SS`). A text property's value arrives uncased, so it takes `text-transform`, reported.
    - **Decorations and baseline shift are a run's**, on the run's own `span` (`Walk::run`): CSS draws a decoration on the box carrying it and no descendant can take it off, so a node's underline on its element would survive a run without one. An underline and a strikethrough on one run nest, the underline outside. A decoration is the longhands: the colour, a px thickness or `from-font`, an underline's offset negated (the model's is up from the baseline) or `text-underline-position: from-font`, `text-decoration-skip-ink: none`. Chrome snaps a band to whole pixels, which the bar allows for. A dashed, dotted or wavy style, and a strikethrough's offset, have no matching form and are reported. A baseline shift is `position: relative; top`, which moves the ink and not the line, as the model does; `vertical-align` would grow the line box.
    - **Paragraphs** write the model's wrap (`pre` for no wrap), `word-break`, `overflow-wrap` and, for a justified paragraph, `text-align-last` (`center`, `right`: the model translates the last line). The model's direction only resolves `Start` and `End` (`left`/`right` when explicit); the base direction is the shaper's, so right-to-left content is reported, as are optical margins and an ellipsis that fires (CSS's `text-overflow` never fires on wrapping text).
- **Fidelity bar**: `ondin-export/tests/code_fidelity.rs` screenshots each fixture's page in headless Chrome through `code::fidelity`, which `ondin check code` also runs (`ONDIN_BROWSER`, else the usual install paths; skipped with a note when none is found, failing when `CI` is set) and compares it with `png::raster_of` by mean channel error per 8×8 cell over white. Text fixtures are compared after two passes of a 3×3 box blur (three for component pages, where a use puts its text at any x) at a lower limit, decorations at a looser one since Chrome snaps a band to whole pixels, with the bundled Inter given to the page. A fixture must report nothing approximated. It drives `html_of`, and `html::html_of_components` for the walk's component branch, which React and Vue alone reach: that page draws each use as the tree its component chooses for the use's arguments, standing in for a bundler. The frameworks' own syntax has no browser test.

### Design tokens (DTCG)

- `dtcg::tokens(doc, mode) -> dtcg::Tokens` writes the document's own variables and styles as a W3C Design Tokens (2025.10) `tokens.json`, with `notes` for anything left out or changed. Kit variables are not written; an alias to one is written resolved, in the mode each value is written for, and noted once. Its doors are `ondin tokens export` and *Export tokens…* (the variables browser's `+` menu, the palette). `dtcg_in` reads such a file back (*Reading it back*, below); how a read file lands on the document, and a linked file, are `styles-variables.md`, *Design tokens*.
- **Paths**: a slash name is nested groups, and an alias is a `{a.b}` reference. A token whose path is also a group is that group's `$root`, and is referenced as `{a.$root}`, since the format refuses a reference to a group. `.`, `{`, `}` and a leading `$` become `_`, with a note, for variables and styles alike. A variable whose legal path another already holds is numbered (`a_b_2`), noted, so an alias to either keeps its meaning.
- **Modes**: one mode's values are the `$value`s (the default mode unless asked for another; an asked mode sets `$value` for its own collection only, every other collection writing its default), and every mode's value, with the variable's id, sits under `$extensions["io.github.fadion.ondin"]`, keyed by the mode's name (numbered, `Dark 2`, when an earlier mode of its collection has the same name, noted). A one-collection document's root extension lists the modes (with that `key` where it differs from the name, and each mode's `minWidth` in a collection picked by width), names the `$value` mode (`valueMode`) and holds the string and boolean variables, which have no DTCG type; with styles it also names their group (`styles`).
- **Collections**: a document with two or more writes each as a top-level group named after it (made legal, numbered on a clash, never `styles`, noted when changed), whose extension carries `collection: {id, name, modes: [{id, name, key?, minWidth?}], valueMode}` and that collection's string and boolean `variables`. A one-collection document writes as above, so its files are unchanged. A loose (string or boolean) alias to another collection's variable names that collection.
- **A number's type is its scope's when it has one** (`dtcg::scope_type`): lengths only make a px `dimension`, weight only `fontWeight`, anything else `number`. An unscoped number is typed by what it binds (`number_reads`): lengths alone (sizes, radii, gaps, padding, limits, stroke widths, effect numbers, px type lengths) make a px `dimension`, a font weight alone makes `fontWeight`, and anything else (opacity, em lengths, a mix, nothing) makes `number`; so a document with no scopes exports as it did. A scoped number's reads are seeded from its scope before an alias and its target pool their reads both ways, since the format gives them one type. **An alias declares the type of the token its reference ends at** (`Writer::type_of` follows the chain, and a chain that cycles across modes ends at the cycle's lowest id, so every token of one cycle declares one type; `own_type` is the scope's or reads'), since a DTCG reference must resolve to a token of its own type: an alias scoped apart from its target is written in the target's type and noted, which leaves the editor free to alias across scopes. A token has one type, so a variable whose modes alias tokens of different types takes the first aliasing mode's, and the clash is noted. The scope itself rides in the token's extension (`scope`, a list of field names) and in a loose variable's entry.
- **Styles** go under `styles` (the first free of `ondin-styles`, `ondin-styles-2`, … if a variable group already takes that name), with one group per slot:
  - **Fill** is one visible fill: a `color` (a reference when it is bound at full opacity) or a `gradient` (stops only, noted).
  - **Stroke** is one solid stroke, written as a `border`.
  - **Effects** made only of shadows become a `shadow` (an inner one is `inset`). The blur number carries over unchanged, since the model's blur is CSS's blur radius. A shadow's blend mode has no DTCG field, so it is left out, noted.
  - A border's width and a shadow's numbers are `dimension` slots: a variable bound there is a reference only when its token is a `dimension`; otherwise its value is written in px, noted.
  - **Type** becomes `typography`. An em letter spacing becomes px at the style's size, and an Auto line height becomes 1.2, noted. Italic, word spacing, decorations, case, baseline shift, features and variable axes have no place in the token and are left out, noted.
  - **Layout**, a layer or background blur, a filter, an image fill and several fills have no DTCG form; the style is left out and noted.
- **Reading it back**: `dtcg_in::parse(text) -> Result<File, Refusal>` reads any DTCG `tokens.json`, in the file's own key order (its own JSON type: `serde_json`'s map sorts, and the review lists groups as the file does). It refuses what is not a JSON object, a file holding no token, a token whose `$type` neither it, a group nor a reference supplies, and any value it cannot read, giving the first reason and its dotted path. A group's `$type` is inherited, `$root` is the group's own token, and a reference `{a.b}` drops a trailing `$root`.
  - **Only what has a home is read.** `color`, `dimension` (px, rem at 16 px; a string such as `"12px"` or a bare number too), `number`, `fontWeight` (a number or the format's weight names), `fontFamily` (a list's first) and, leniently, `string` and `boolean` become variables; `typography` a text style, `shadow` an effects style, `gradient` a fill style. In the styles group the extension names (`styles` when unnamed; only in a file carrying the extension), the slot subgroups `fill`, `stroke`, `effect` and `type` take colour or gradient, border, shadow and typography as that slot's style. Anything else (`cubicBezier`, `duration`, a border outside that group) is left out and listed (`File::left_out`). The extension's string and boolean variables are read back.
  - **Modes**: the extension's list, each mode's values under its `key` and its `minWidth` read beside it. `$value` belongs to `valueMode` (else the first mode) and wins over that mode's extension value, because code edits `$value`. A file without the extension is one unnamed mode. A top-level group whose extension carries `collection` is read as that collection, its own modes and `valueMode` governing its tokens.

### Penpot file

- `penpot::export(doc, res, name) -> io::Result<PenpotExport>` writes the whole document, every page, as a `.penpot` file in Penpot 2's third export format, the one `penpot_in` reads: a zip of JSON, `manifest.json` first, then `files/<file>.json`, one JSON per page and per shape, `colors/`, `typographies/`, `components/`, and pictures as `media/` entries naming stored `objects/`. The file says data `version` 67 (Penpot 2.18's) and lists no migrations, so Penpot applies only its later repairs; its features are `components/v2` and `fdata/shape-data-type`. Ids are UUIDs derived from node ids, so the same document writes the same bytes. `PenpotExport::approximated` lists what Penpot draws differently or not at all, deduplicated, in the order met. Penpot 2.18 imports the file, draws it as Ondin does, and its own re-export reads back through `penpot_in`.
- **Placement.** Every Penpot shape is in page space. A box shape (board, rect, circle, text) is its unturned box turned, skewed or mirrored about its centre by `transform`, the node's scale folded into the box. Arcs (an ellipse's or an `Arc`), spirals, polygons, stars, lines and paths are paths baked into page space; a boolean is a `bool` carrying its computed outline as content beside its operands.
- **Kinds.** Frame → board (a clip is `showContent` false); rect and whole ellipse → rect and circle; group → group, an empty one left out; a group with a layout → a board, since Penpot has layout on boards only (reported). Text → a content tree, one paragraph per line break and a leaf per style run, plus `positionData` from Ondin's own layout (`text::line_runs`): Penpot draws each run at Ondin's place and stretched to its width, and a viewer shows the text without waiting for the workspace to set it again. `line_runs` shapes the text again, so the app's export worker registers the layouts' faces (`Resolved::text_fonts`) first.
- **Masks.** Each mask's run of siblings becomes a masked group whose first shape is the mask; an alpha or luminance mask is drawn as a shape mask and reported. A hidden mask is a hidden layer and masks nothing.
- **Library.** Colour variables → library colours at the default mode's value; a fill bound to one names it only where the node draws that value, since a node in another mode draws another colour. Text styles → typographies; a run names one only while it still sets in it. Other modes, and number and text variables (written as values), are reported.
- **Components.** A main outside the vault → a component with `mainInstance`; each layer of a copy names its main's layer (`shapeRef`), and `touched` lists the groups `reset::overrides` finds overridden, so Penpot's sync keeps the overrides. A copy with layers of its own or a swap, or whose main is in the vault, is written as plain layers and reported. Variants are separate components, reported.
- **Layout.** Flex → Penpot flex: direction, wrap, justify, align, gap, padding; item sizing fix, auto or fill (a frame hugs only at `fit-content`, a laid group unless it has a typed size, text by its sizing mode; grow fills the main axis; a stretch fills the cross axis only where no size is typed, as CSS's does), px min and max, align-self; a layer with insets is `layoutItemAbsolute`. Grid is reported and left at drawn positions. Outside a flex layout, insets become constraints (`left`/`right`/`leftright`/`center`/`scale`, `top`/`bottom`/`topbottom`). Penpot resizes a group's children by their own constraints, so a layer inside a pinned plain group or boolean, through nested plain groups (`scales_with_group`), is `scale` on both axes, as Ondin scales it.
- **Effects.** Shadows; one layer blur, its value the deviation (radius × `BLUR_DEVIATION`); one background blur under its own `backgroundBlur` key at the radius, which Penpot halves itself. A second blur of a kind and colour filters are left out, reported.
- **Export settings** → `exports`, one `{type, scale, suffix}` per row: the format's keyword (`png`, `jpeg`, `webp`, `svg`, `pdf`), the multiplier, and the suffix Ondin names the file with (`ExportSpec::effective_suffix`, so an untyped 2× row writes `@2x`). A width or height becomes the multiplier it asks for on the box Ondin's own export frames (`plan::framed_box`: the ink, so a shadow counts), 1× for a layer with none. Penpot has no place for a prefix, a background, or a quality, trim, square pad, outlined text or SVG setting that would act (`plan::acting_extras`); each is left out, and every one of these is reported.
- **Reported besides:** slices, hidden fills, layout grids and guides (all left out), linked or missing pictures (left out), corner smoothing, dash offsets and multi-dash patterns, non-miter joins, per-side strokes, angular gradients (written linear), two-point radials, repeating gradients, picture fit, tile, crop, adjustments and orientation, a shadow's blend mode, text on a path, OpenType features and axes, word spacing, baseline shift, percent sizes, reversed wrap and baseline alignment.

### Sketch file

- `sketch::export(doc, res, name) -> io::Result<SketchExport>` writes the whole document, every page, as a `.sketch` file, the format `sketch_in` reads: a zip of `document.json`, `meta.json` (format version 146, compatibility version 99), `user.json`, one `pages/<id>.json` per page and pictures under `images/`, shaped to `@sketch-hq/sketch-file-format` 6.5's schema, which closes every class. Ids are upper-case UUIDs derived from node ids (`stable_id::uuid`, which the Penpot writer shares), so the same document writes the same bytes. `SketchExport::approximated` lists what Sketch draws differently or not at all, deduplicated, in the order met. The rich fixture and the golden document validate against the schema and read back through `sketch_in` render as the originals; no file has been opened in Sketch itself.
- **Placement.** A layer is its frame in its parent's space, turned (Sketch's rotation runs counter-clockwise) and flipped about its centre, the node's scale folded into the frame; a skew is dropped, reported. Paths, booleans and groups are written in their container's space, unturned, a group's transform folded into its layers. A layer's insets are its resizing constraint (a pinned edge or size clears its bit; a percentage leaves the axis free); a layer inside a pinned plain group or boolean, through nested plain groups (`scales_with_group`), pins nothing, since Sketch resizes a group's layers by their own constraints and Ondin scales them by their shares, and `sketch_in` pins the group again.
- **Kinds.** Sketch allows an artboard only at a page's top. A frame there, unturned and unscaled, → artboard, which always clips (a frame that does not is reported); one solid fill with no stroke, radius or effect is its background colour, any other paint a rect at the bottom of its layers. Any other frame → a group led by a rect carrying its paint (radii, fills, borders), that rect a clipping mask when the frame clips; reported. The paint rect never carries the frame's opacity, blend or effects: the group, artboard or symbol instance it leads does, so Sketch applies them once. Rect → rectangle with per-corner radii; a rect's or a frame's corner smoothing is Sketch's smooth corners (reported); whole ellipse → oval; arcs (an ellipse's or an `Arc`), spirals, polygons, stars, lines and paths → shape path, one of several subpaths a shape group of its parts, winding from the fill rule: under even-odd each later part joins by difference, under non-zero by union where it winds the first part's way and by difference where it winds against it; boolean → shape group of its operands' outlines under the op; group → group, an empty one left out; slice → slice. Export settings → export options, named by suffix or prefix (both set: the suffix, reported); the suffix is the one Ondin names the file with (`ExportSpec::effective_suffix`), so an untyped 2× row is named `@2x`. A background, and a quality, trim, square pad, outlined text or SVG setting that would act (`plan::acting_extras`), are left out and reported.
- **Text** → an attributed string, runs at UTF-16 offsets: the PostScript name (`sketch::postscript`, the inverse of `sketch_in::font_face`), colour, kerning, line height as minimum and maximum line height, alignment, underline, strikethrough, upper and lower case; title case is written as typed, reported. `textBehaviour` follows the sizing mode.
- **Masks.** Sketch's mask chain means what Ondin's does. An outline mask's fills, borders, shadows and blur are turned off, since Ondin's mask paints nothing; alpha → `clippingMaskMode` 1; luminance is written as alpha, reported. A hidden mask masks nothing.
- **Components.** Sketch allows a symbol master only at a page's top, so every main outside the vault is a master on an added *Symbols* page, stacked one under another, and a symbol instance stands where the main was; a main whose whole paint is one solid fill shows it as the master's background in its instances. A copy is a symbol instance with `stringValue` overrides for its text, each override path running through the nested copies the master writes as instances (a nested copy written plain holds its layers under their own ids). A string override carries no runs, so a copy whose text differs from its main's in its runs, or that differs in anything else (other overrides, layers of its own, a swap), or whose main is not written, is written as plain layers, reported. Variants are separate symbols, reported.
- **Library.** Colour variables → shared swatches at the default mode's value; a fill names its swatch only where it draws that colour. Text styles → shared text styles; a text names one while its first run still sets in it. Other modes, number and text variables, and fill, border and effect styles are written as values, reported.
- **Effects.** Shadows and inner shadows; one blur, a layer blur (type 0) or a background blur (type 3). A second blur and colour filters are left out, reported.
- **Reported besides:** auto layout (kept at drawn positions), layout grids and guides (left out), turned slices, export backgrounds, borders differing in dashes, caps or joins (drawn as the first), dash offsets, per-side borders, picture borders, repeating gradients, two-point radials, angular gradients off centre or turned, cropped pictures, picture adjustments and orientation, linked or missing pictures (left out), a shadow's blend mode, text in more than one colour or not solid, outlined text, text on a path, OpenType features and axes, word spacing and baseline shift.

### PDF

- `pdf::pdf_of(doc, res, origins, ExportText) -> Option<pdf::Export>` is our SVG (`svg_with`) parsed by `usvg` and drawn by `krilla` through `krilla-svg`: one page framed as the SVG frames it, **a point per world unit**, the same bytes for the same document. `None` when the subject has nothing to frame (as the SVG and PNG refuse it) or the converter refuses the markup. One file per spec, as every format. The converter reads only our own `data:` pictures: a linked picture's path is never opened, since a received document chooses it (a UNC path would open an SMB session), and it draws as missing. A run whose family had no face when its layout was shaped (`TextLayout::absent`, read where the layout was made: the export worker's engine holds only the faces layouts drew from, so it cannot tell a missing family from one that drew no character) is drawn in the face that drew it on the canvas, which its `<tspan>` names, and noted *X, which is not available, drawn in Y* with that face when it is Inter or one of the family's stand-ins (`pdf::stands_in_for`: a script's fallback draws what the family lacks either way) (`pdf::approximations`, so the export card shows it too; the text is shaped again only when some run's family is absent, since the card reads it on every edit). `pdf::select_font` is the backstop for a family the database still has no face of: its first stand-in with a face there (`fallback_fonts::stand_ins`), else Inter, with the same note; usvg's own lookup would leave the run out.
- `pdf::pdf_pages(doc, res, &[(name, origins)], ExportText)` is several such pages in one PDF, each at its own size, and `pdf_of` is its one-page case. A page with a name gets a bookmark (the PDF outline) of that name. The outline is written only when some page has a name, so a one-page export's bytes do not change. The notes are every page's, deduplicated. The doors are *Export frames as one PDF…* and `--pdf --frames`.
- **Why this converter**: `svg2pdf` pins `usvg` 0.45, which ignores `font-variation-settings`, so a variable face (Inter, the default) would embed at its default weight. `usvg` 0.47 maps `font-weight` onto `wght` and `krilla` embeds the instance it asked for. An SVG-free writer straight from the scene was the other road: exact glyphs, but a third writer and our own rasterizing of effects.
- **Live text** (*Embedded fonts*) is shaped again by `usvg`, from a font database holding exactly the font files our layouts used (`fonts_used`, fallbacks included), with `Inter` as its fallback family as in core and **a glyph fallback kept to the run's own family** (`pdf::same_family_fallback`): each run names the face that drew it, so it fills its own characters, and every face the line used is embedded. One family's subset files (Fontsource's `latin` and `latin-ext`, or a stand-in's) all name themselves alike, so the database files each face under its file's alias as well (`svg::face_alias`, blob id and face index), a run is cut wherever its file changes (`ExportRun::file`), and its `font-family` names that alias ahead of the family: the lookup finds the very file the canvas drew from. usvg's glyph fallback cannot stand in for that, since it stops at the first character no face of the family has (another family's character earlier on the line), so it is left for text no glyph run covers. Another family's face is never reached, since usvg redraws a whole line in a fallback that covers all of it. The subsets are embedded with a `ToUnicode` map, so the text selects and searches. Line breaks, baselines and the face per run are ours, placement along a line is the converter's. `usvg` reads `font-feature-settings` without shaping with it. **Outlines** are the SVG's outlined text and embed no font.
- A blend mode is a real PDF blend graphics state (`/BM`), which `usvg` and `krilla` carry from the SVG's `mix-blend-mode`, not pixels (`tests/pdf.rs` checks `/BM/Multiply`).
- A `<filter>` (an effect, a picture's adjustments) has no PDF form: `krilla-svg` rasterizes it at `FILTER_SCALE` (4, 288 dpi), capped at 5000 px a side, so a layer past 1250 units comes out coarser. A filter on a frame or group rasterizes everything inside it, text included (not selectable, no font), and the note says so. Live text's underlines and strikethroughs are the font's plain line in a PDF (no colour, thickness, style, offset or skip-ink), noted.
- **Reporting**: `pdf::Export::approximated` is the SVG's `approximated` plus the conversion's own (an effect or a picture's adjustments drawn as pixels; OpenType features on live text). The SVG's round-trip list does not apply, a PDF never being read back. `pdf::approximated` answers the same without converting, for the export card. Rasterizing our SVG with `resvg` (the same `usvg` read) against `png::raster_of` over the golden document agrees everywhere but antialiasing, so the conversion is faithful to what the SVG says.

### Raster

- **PNG**: `png(doc, res, vp, page) -> Vec<u8>` via `VelloCpuRenderer` and a PNG encoder; no GPU. It shares the scene walk, so placeholders are ink on the pixels. Shapes, backgrounds, images and text all rasterize (`ScenePainter::draw_text`, `cpu.rs`).
- **PNG of a selection**: `png_of(doc, res, origins) -> Option<Vec<u8>>` walks from each origin through `scene::build_of`. Ancestor clipping does not travel and nothing behind is painted (so a selection exports on transparency). 1:1, one device pixel per world unit. It is a shortcut with no production caller (the panel, CLI and goldens use `RasterOpts`); nothing will warn about it since the crate is a library.
- **JPEG**: `jpeg::encode_rgba8(rgba, w, h, quality)`, no renderer of its own; all pixels come from `png::raster_of`. Alpha is dropped, not flattened: the matte is the export's background, decided in `plan` and composited before the encoder.
- **WebP**: `webp::encode_rgba8(rgba, w, h)`, lossless (VP8L), alpha kept, pixels likewise from `png::raster_of`. `image`'s WebP encoder writes nothing else and a lossy one would mean libwebp, a C dependency, so a WebP spec has no quality and the panel's quality field is JPEG's alone.
- **Finishing**: `png::raster_of(doc, res, origins, RasterOpts)`. `RasterOpts` is the *resolved* spec: **scale**, optional **background** (under the artwork), **trim**, **pad-to-square**. Resolution (e.g. `Background::Frame`, `Width(512)`) needs the tree/box and happens in `plan`. Steps run **trim, then pad, then composite**: trim reads alpha (a background first would make it a no-op), pad before trim would be trimmed away, compositing last covers art and padding in one pass.
- **Size cap**: per side `png::MAX_RASTER_SIDE` = 511 x 128 = 65408 (both factors are vello's and private), emphatically not `u16::MAX`, the value vello panics on. The cap is applied to the **scale**, not each axis (independent clamping squashes aspect). The number lives in `ondin-render`; `png::MAX_RASTER_SIDE` is an alias (the font picker's `rasterize_glyph_run` shares it). Two tests re-measure it against the dependency (`a_raster_at_the_cap_renders_on_either_axis`, `cpu::preview_tests::a_strip_too_big_for_the_backend_is_refused_rather_than_truncated`). Finishing steps widen before multiplying (`png::square_bytes` in `usize`; `u32` wrapped at 32768). WebP holds less: `webp::MAX_SIDE` = 16383, libwebp's limit (`image` encodes 16384 but cannot read it back), and `plan` caps a WebP spec's scale to it the same way and reports the row `clamped`.

### Plan

`plan(doc, res, subjects, PlanOptions) -> Vec<PlannedFile>` is the one place a saved `ExportSpec` (§5.3) is interpreted: scale becomes a multiplier against a layer's box, `Background::Frame` a colour by walking to the enclosing artboard, a layer name a filename sanitized for the strictest filesystem. The spec's `prefix` and the layer name are **composed before sanitizing**, so `/` means one thing across the whole path.

- `PlannedFile` carries the pixel size the panel shows and a `clamped` flag. `raster_size(doc, …)` and `raster_opts` measure the box the render frames (`framed_box`): `ink_bounds` (the box `extent` frames) for a layer, so rows predict file size for layers with effects and `Width(512)` resolves against the framed box, and a slice's own box for a slice.
- **A slice exports a region of its page** (`plan::slice_region`): its world box (axis-aligned), drawn through by its page's top-level layers. What falls outside is cut by the frame, and every slice draws nothing, so the subjects are the whole page rather than what the box overlaps. `render` frames the file on that box: `png::raster_region` (a viewport on it, through `raster_framed`, which `raster_of` shares), `svg::svg_spec` (the box is the `viewBox`), `pdf::pdf_region` (through `pdf_framed`, which `pdf_pages` shares). `raster_opts` turns `trim` off for a slice, since its box is the point of it. Its file is named after the slice as any layer's is; `Background::Frame` walks from the slice to its enclosing frame. A slice itself is skipped by every writer (`svg::emit_node`, `code::walk::node`, the scene walk), so it never appears in its own or any other export.
- A subject with no specs of its own plans `PlanOptions::unset`, `None` (nothing) unless a door sets it; *Export all frames* sets a 1× PNG.
- `render(doc, res, file)` returns bytes; `zip(files)` packs a set. Nothing here touches the filesystem (app and CLI do). `encode(raster, spec)` is the one place a raster becomes bytes for a spec, shared by `render` and the panel's preview, which rasterizes once to both encode and draw.
- **No two files in a plan share a name**: `ExportSpec::effective_suffix` separates specs on one layer (typed suffix, else the scale's marker), and a case-insensitive ` (2)` de-collision (`de_collide`) catches same-name layers and duplicated layers (which carry their specs). This covers names *inside one plan* only; a file already in the destination is replaced by whichever writer runs.
- The doors that write with no dialog owe a count: the panel's *folder* arm (`Exported 4 files (2 replaced) -> ...`), the CLI's `--all` (`wrote 4 files to ... (2 replaced)`) and its one-off export (`wrote design.zip (replaced)`). *File* and *Archive* destinations were named in a save dialog, so are exempt.
- `folders_from_names` reads `/` in a layer name as a folder separator, **off by default** (it changes what a name means).
- **A component set can export each variant as its own file** (`ExportSpec::each_variant`, inert on any other layer; `plan::variant_files`). The set's name is the folder and each variant's values, joined by `-`, are its file's stem, both lower-cased with spaces as `-`, the spec's prefix in front and its suffix behind (`icons/arrow-left-24.svg`); the files follow the order of the values in the set's properties, and two variants holding the same values de-collide as any two files do. Each planned file renders its variant, so every format and every door (the panel, `--all`, re-export on save) gets the folder.

### CLI

- `ondin export <file> [--svg|--pdf|--png|--json|--html|--react|--vue|--penpot|--sketch] [--outlines] [--scale <n>|--width <px>|--height <px>] [--page <name|n>] [-o out]` runs headless, no GPU, on one page: `--page` names it by number from 1 or exact name, and unasked it is the first page that is not a draft (the first page when every one is). `--json` describes every page and `--penpot` and `--sketch` write every page as a Penpot or Sketch file (their notes on stderr), so all three refuse `--page` (`ExportFormat::whole_document`). `--outlines` writes an SVG's or a PDF's text as outlines and is refused elsewhere and on `--all`, where each spec carries its own. `--pdf` prints what it drew differently on stderr. `--pdf --frames` writes one PDF with a page per visible top-level frame of the page, each bookmarked with the frame's name, and fails when there is none. `--frames` is refused anywhere but a one-off `--pdf`. `--html`, `--react` and `--vue` write the code export of the page's top-level layers as a zip, and a count line on stderr when the report is not empty. `ondin export <file> --all [--scale-override <2x|512w|512h>] [--folders] [--page <name|n>] [-o dir]` runs the **document's own** export settings (every layer carrying any, but a hidden slice: `build::exported_in_bulk`, as the panel's *Export all*) on every page that is not a draft, or on the one page `--page` names, draft or not, in every format they name; it is a different command, so `--all --png` is refused. The one-off command has no JPEG or WebP flag.
- On Windows a release `ondin.exe` is GUI-subsystem with no console, so the CLI is reached through the console twin `ondin.com` beside it, which runs `ondin.exe` with its own standard handles. It exits with the child's code whole (no clamp to a byte) and puts the child in a kill-on-close job object so Ctrl+C ends the export. A non-Unicode argument is refused with exit 2.
- One document: a second positional is refused naming both files. `-o` takes a filename and refuses an argument beginning with `-` (otherwise `-o --png` swallowed the format flag and wrote SVG into a file named `--png`).
- With no `-o` it writes into the folder holding the `.ondin` (`.` only if no parent). An `-o` naming the document itself is refused.
- **Exit 1 when no file is produced** (gate is on the rendered set, not on "has settings": a raster spec over an empty group writes nothing and must fail; an SVG spec always writes a file and exits 0).
- Size flags are the panel's three questions (`ExportScale` variants). They are **refused** on every format but `--png` and on `--all`, and only one at a time (the same flag twice is refused; `--png --svg` takes the last, since formats have an obvious ordering). The derived output name is not decorated with `@2x`. `Width`/`Height` resolve against the box the render frames.
- `--scale-override` (for `--all`) *overrules* a size the document carries; the file still decides which layers export and at what formats. It parses the row vocabulary via `ExportScale::from_label` (`2x`, `512w`, `512h`, bare number = `x`). It lives in `PlanOptions`, because the scale is half the filename through `ExportScale::marker`. Specs that become identical under an override collapse to one file; the dedupe runs only under an override.
- When `viewport_at`'s cap reduces a size the command says so on stderr, in the spec's vocabulary (`200000w`, not `655.350x`).
- **`ondin render`** (`render_cli`) makes many files from one document, into `-o` as a folder, with `export`'s format and size flags (`--png`, the default, or `--svg`; one size flag, PNG only):
  - `ondin render <file> --component <name> --data <rows.csv> [--name-by <column>]` places an instance of the component — a main that is not a variant, or a set, which starts at its first variant — and renders it once per data row. The header names properties as the inspector shows them, exactly or, when that finds one, ignoring case: a variant property switches the variant, and a text, boolean (`true/false`, `yes/no`, `on/off`, `1/0`) or instance-swap property (a component's name) sets its value. An empty cell keeps the default; a column matching nothing warns once on stderr and is skipped; a cell that does not read for its property, a combination no variant has, or a row with more cells than the header fails the run naming row and column, before anything is written. Files are `{component}-{row}`, the row number zero-padded to the row count, or the `--name-by` cell, sanitized, with plan's ` (2)` de-collision.
  - `ondin render <file> --all-modes [--page <name|n>]` renders every top-level frame of the pages that are not drafts, or of the one page named, once per mode of every collection in which it is shown (`Document::shown`, so a visibility variable decides per mode), as `{frame}-{mode}`; each mode is set alone over the frame's own set (`variable::with_mode`), other collections left as the frame sets them. A document with no modes fails, as does one with no frame shown in any mode. Rows: a header with no rows is refused; a line break inside a quoted cell is one `\n` whatever the file's line endings, and a lone `\r` ends a row; variant and swap cells are trimmed like the headers; a `--name-by` cell gives at most 200 characters of the file name. Every frame door (*Export all frames…*, `--pdf --frames`) asks `shown`, not the literal `visible`.
  - Every edit goes through an `EditorSession` commit, so a row settles exactly as the inspector's edit would, and is undone after its render. The CSV reader is ours (RFC 4180 quoting, CRLF, a byte-order mark; a semicolon separator when the header has semicolons and no commas), not a dependency. The same write and report as `--all`: everything is rendered before anything is written, `(n replaced)` and `(n skipped)` are counted, and exit 1 when nothing is produced.
- `ondin diff <a> <b> [--json]` reports what changed from `a` to `b` (`ondin_core::diff`), by page and then by layer in Layers-panel order (`+` added, `-` removed, `~` changed), then what belongs to no page (variables, modes, styles, guides, images, the library block, a kit publish). Exit codes are `diff(1)`'s: 0 same, 1 different, 2 unreadable; the text prints nothing when they are the same, `--json` writes the structure either way. Everything is matched by **id**, so a rename is a rename and a layer raised past three siblings is the one reported (siblings outside the longest common order). Values are compared through the saved form, so a field added to the model is compared without being listed; a key the file skips at its default reads as that default. A number changes at 0.01 or more in its own unit (float noise below it, any real move above), a colour when its hex or alpha percentage does; values print as the inspector shows them (two decimals, `#RRGGBB`, bound ids as the variable's or style's name). A layer reads as its trail from the page's top level, an instance root marked `(instance)`, so a copy's override reads under its instance; a change a copy shares with the layer it was copied from is reported once, on that layer. An added or removed layer is one line counting the layers that came or went with it; a layer that was there before and moved into an added one is still listed, under it. A later collection's modes read by name, and the first collection's own name and widths read under *collection “name”*. A tokens link is one line for being made, dropped or moved to another file, and one for its file applied again, never a line per token.
- `ondin check contrast <file> [--page <name|n>] [--aaa|--apca] [--non-text]` (`contrast::check_with`) measures every shown text layer of the page against what is drawn behind it. The canvas's contrast check mode runs the same measurement (`app-canvas-chrome.md`).
- `ondin check code <file> [--page <name|n>]` (`code::fidelity::check_export`) opens the page's HTML export in a headless browser (`fidelity::browser`, as the fidelity bar finds one) with the bundled Inter given to it, and holds the screenshot to `png::raster_of`, so what did not translate is reported rather than left to drift. A cell past the bar's shape limit is put down to the topmost layer whose ink box holds the cell's worst pixel, a text box only where that pixel is its type. Text is judged by placement and colour instead: within its box, ink is what differs from the commonest colour, the page's counting within `fidelity::INK_REACH` (3 px) of the canvas's, and past it only in the canvas type's solid colour (within `MAX_INK_COLOUR_ERROR`), so a layer of another colour drifting under the box's empty part stays that layer's while type the page adds (a line `max_lines` would have cut) is the text's; more than a tenth of either image's ink lying over a pixel from the other's is a drift (`fidelity::misplaced_ink`), and so is the solid ink's colour differing past `MAX_INK_COLOUR_ERROR` (`fidelity::ink_colour_error`). A cell limit cannot tell a line set wrong from Chrome drawing light type on a dark fill heavier, which a pixel's allowance absorbs. Ink spilling past a text box is put down to what is drawn there. The page's mean, held to `MAX_MEAN_ERROR`, leaves out the pixels within one of type ink, whose antialiasing it would otherwise read as drift. It prints each drifted layer, then the export's own approximated entries as `noted`; exit 0 when the page holds, 1 when it drifts (the page, `cpu.png` and `shot.png` kept in a temp folder it names), 2 when the document cannot be read or no browser is found.
  - **Measuring:** the layer's box is rendered at 2× through the CPU renderer (`render_subtrees_with`, through `RenderOverrides`), over the page ground — its own colour, else `Options::default_ground`, else `DEFAULT_CANVAS_BACKGROUND`; the app passes its theme canvas, so a theme switch changes the options and re-measures: once with the layer at zero opacity, the backdrop (not hidden, which would take it out of an auto layout and slide its siblings into its place); once each with its fills, strokes and runs painted white and black, whose difference is the layer's coverage at any backdrop; and, when it has several colours, once as it is. The pixels covered at least half as much as the most covered are its glyph cores, so ink the colour of its backdrop is measured, at 1 : 1. At each core, the colour drawn there is the layer's colour whose drawing best matches that pixel, and what it draws is worked out from the two inks' renders, so an ancestor's opacity counts once whether or not it also fades the backdrop. That colour is measured against the backdrop pixel with WCAG 2's ratio. A text layer's score is its worst core's; a non-text mark's is its best colour's at that colour's worst core, since a mark needs one part that stands out (a white box with a dark border reads by its border). A layer that covers no pixel (clipped away, covered, fully transparent) is not reported; a mask is never measured. The box is drawn at a lower scale when it would pass 4 megapixels or `MAX_RASTER_SIDE` on a side.
  - **Colours:** they come from the runs' own colours, else the top visible fill, else black when the text has no visible fill or stroke. A fill that is not one solid colour skips the layer, naming the gradient or picture. So does a mode that mixes rather than covers, on the layer or a layer it is drawn inside (*is blended with what is beneath it*): the drawn colour is worked out source-over, which a mode replaces.
  - **Thresholds:** AA is 4.5 : 1, or 3 : 1 for large text (24 px, or 18.66 px from weight 700, each run at the layer's world scale, the strictest run's threshold the layer's); AAA is 7 and 4.5. `--apca` scores APCA-W3's |Lc| instead, at the Bronze simple-mode levels: 75 for body text, 60 from 24 px or 16 px at weight 700, 45 from 36 px or 24 px at weight 700.
  - **Non-text:** `--non-text` also measures shown shapes whose shorter side is under 24 world units (icons, borders, dividers), their visible solid fills and strokes, at 3 : 1 (Lc 30 under APCA). A larger shape is a surface and is not measured; a boolean is one shape, its operands not marks of their own.
  - **Modes:** each collection with two or more modes that a variable reads — one of its own, or a kit's that maps from it — is checked in each of its modes, one collection at a time (`contrast::Prepared::new`), with top-level frames that set none of that collection drawn in it and every other collection as the page sets it, and the layers to measure are chosen in each mode, so one shown only in Dark is measured there. Each mode's worst sample (the ink, how it is drawn, the backdrop it was found at, and the threshold that mode's sizes ask) is kept on the finding for the canvas's fix card. Each mode is held to its own threshold; the finding reports the mode furthest below its threshold, or least above it.
  - **Where it lives:** the scores, the findings and the fixes are `ondin_core::contrast`, which
    `ondin_export::contrast` re-exports; only the measuring needs the renderer, and
    `contrast::Measurer` lends it to core as a `contrast::Probe` (the `fix_contrast` verb's).
  - **Fixes** (`contrast::nearest`, `contrast::passing_variables`): the nearest passing colour keeps the ink's OKLCH hue and chroma and moves only its lightness, to the closest value that passes every mode's worst backdrop at that mode's threshold with a small margin, giving up chroma only at the gamut's edge. The passing variables are the colour variables whose value in each mode passes there, nearest the ink in OKLab first.
  - **Output and exit codes:** failures and skips print one line each, scores rounded down as the canvas's badges write them (`Level::format`), then a count. Exit 0 when all pass, 1 when any fails, 2 when the file cannot be read.
- `ondin merge <base> <ours> <theirs> [-o out]` is a three-way merge (`ondin_core::merge`), written over `ours` unless `-o` says otherwise. Exit codes: 0 clean, 1 with conflicts, 2 when a file cannot be read. That is git's merge-driver protocol: `.gitattributes` gets `*.ondin merge=ondin`, and git config gets `merge.ondin.driver = ondin merge %O %A %B`.
  - **How it merges:** the three saved forms, each migrated to the current schema, are merged as JSON. A value one side changed takes that side. An object merges key by key, except a one-key object whose key differs between the sides (an enum that switched variant), which is one value, and the keys that are one value together: a text's `content` with its `spans` and `para_spans` (byte ranges into it), a path's outline with its per-anchor `corner_radii`. A list of records with an `id` (layers, pages, guides, styles, variables, list items) merges record by record. A list of ids (`children`, a property's `bound` and `preferred`, a variant property's `values`) merges as an ordered set (`merge_order`): the order of the side that reordered the ids all three hold, ours' when neither did, less the other side's removals, with the other side's additions after the id they follow (last when only additions follow them). Any other list of strings that kept its length (a variant's values, one per property) merges place by place. Any other list is one value. An image record the merged document still uses is kept, whichever side removed it, since the loader admits a reference to a missing picture. An empty base (git's `%O` for a file both branches added) merges two ways: what one side alone holds arrives, and every value the sides hold differently is a conflict.
  - **Conflicts:** where both sides changed one value differently, or both reordered one list differently, ours wins and the place is listed on stderr. A record removed by one side and changed by the other is kept. The result must load; if it does not (a layer moved under two different parents, or deleted on one side and edited on the other), ours is kept whole and the reason is listed. The output is re-saved canonically.
- `ondin run <script.json> [--in <file.ondin>] -o <out.ondin>` commits a script of registry verbs
  (`verbs::run_script`, `core-ops.md` *The verb registry*) against `--in`, or a new document, and
  writes the result atomically. It prints a line per step that made something (`step 1: <id>`, a
  node's wire form or `add_image`'s image id), and exits 1 naming the step and the parameter when
  one is refused. Its pictures are hashed and sized as an import's are (`import_files::Pictures`).
- `ondin tokens export <file> [--mode <name>] [-o tokens.json]` writes `dtcg::tokens` to `-o`, or to stdout without one, with each note on stderr. A `--mode` the document does not have is refused, naming the modes it has; one it has sets `$value` for its own collection only.

### In the app

- **Code export** is a one-shot of the selection, never a saved setting: regenerated code overwrites whatever was edited in it, so nothing earns a place on the layer. Its door is `Action::ExportCode(code::Target)` (*Export as HTML / React / Vue…*, one zip through a save dialog seeded with the layer's name made a file name by `plan::sanitize_segment`, then generated, zipped and written on an export worker as the other exports are, the report's counts on the status line), with no chord, no context-menu row and no panel row: the command palette's *Export as HTML… / React… / Vue…* rows are its GUI door (dim with nothing selected), beside the CLI.
- **The Penpot and Sketch files** are one-shots of the whole document, through `Action::ExportEditable(EditableFormat)` (`OndinApp::export_editable`), `EditableFormat` holding `Penpot` and `Sketch`: the palette's *Export as Penpot file…* and *Export as Sketch file…* rows are their only GUI doors, with no chord and no menu row. A save dialog seeded with the document's name, then the file written on an export worker from a copy of the committed document; the status line says *Exported Penpot file* (or *Sketch file*), or adds *— drawn differently: …* with the writer's notes.
- **Copy as CSS** (`code::css_of`, layer context menu and palette) puts each selected layer on the clipboard as text, in document order under a `/* name */` comment, the way *Copy as PNG* takes a container with its contents. A leaf layer (text included, whose paragraphs are not layers) is its bare declarations, to paste into a rule; a layer with children is the walk's rules for its whole subtree, class selectors and all. The layer's own `position`/`left`/`top` are dropped (each layer is walked as its own page, so they would always read as the origin); its children keep theirs, so a container is written `position: relative` to be what they measure from. Pictures stay `url("assets/…")`, which the clipboard does not carry. A lone solid background, which the walk writes as `linear-gradient(c, c)` so fills can stack, is collapsed to `c`; variables stay `var(--…)`. The clipboard carries no `text-styles.css`, so a text wears no text style's class and keeps its whole face.
- **Copy as PNG** at 1× and 2× (`OndinApp::copy_as_png(scale)`) puts raw RGBA on the clipboard through arboard, transparent, from `png::raster_of`; the status line gives the pixel size. The raster is rendered on a worker from a copy of the committed document and handed to the clipboard at the end of the frame it lands on (`poll_png_copy`); a second copy replaces one still rendering, any text copied meanwhile (an `OutputCommand::CopyText` that frame: a layer copy, Copy as SVG or CSS, a field) drops it rather than be overwritten by it, and with the clipboard out of reach nothing is rendered.
- **A slice on the clipboard is its region** (`app::copy_subject`): a lone selected slice copies as PNG and SVG what its Export row writes (`plan::slice_region` through `png::raster_region` / `svg::svg_region`), and *Copy as CSS* refuses it with a reason, a slice being no layer. A slice among other layers is left out of their copy, since it draws nothing.
- The image export door for a layer is the inspector's **Export** panel (§9.4), editing the layer's own `exports` list. The one-off *Export as...* and its `Ctrl+Shift+E` were removed (it asked everything on every use and remembered nothing). `Ctrl+Shift+E` is unbound but not free: plain `Ctrl+E` is *Flatten*, whose binding row holds Ctrl alone, and `a_stray_shift_on_ctrl_e_does_nothing_rather_than_flattening` holds that a stray Shift does not reach it. `scene::build_of` stands (Copy as PNG, the panel, CLI, goldens).
- **Destination follows file count**: one file gets a save dialog with a name; several get a folder; *Export as ZIP* appears when there is more than one file. A planned path is folder and name: with `folders_from_names`, `save_dialog_target` sends the folder half to `set_directory` and the name to `set_file_name` (only if the folder exists); the write side creates the folder for both destinations.
- *Export all* (`Ctrl+Alt+E` and a canvas-menu row) re-runs every layer on every page that is not a draft into the last folder with no dialog after the first time. Every layer means nesting included: a spec on a nested layer is a deliberate instruction. Panel (`exportable_layers`) and CLI ask one predicate, `build::exported_in_bulk`: the layer carries export settings and is not a hidden slice, by its own eye or an ancestor's (`Document::shown_through`). Hiding a slice switches it off; any other hidden layer with settings still exports, its settings being the instruction. Both collect through `build::all_in_document_order` (document ordering without `outermost`); the *selection* door (`export_subjects`) keeps `outermost` so a group and its picked child do not plan the child twice. The sort supplies the order; `exportable_layers` collects in any order.
- *Export all frames…* (canvas menu and palette, dim with no frame on the canvas) plans every visible top-level frame of the current page (`exported_frames`; nested frames are not included) with `PlanOptions::unset` a 1× PNG: a frame's own rows when it has any, else that PNG. It goes through the panel's `run_export`, so one file gets a save dialog and several a folder.
- **Image exports render and write on a worker** (`write_export` → `deliver`, through `crate::job::Job`), so a slow PDF or a large PNG never freezes the window. The worker gets a copy of the committed document and its `Resolved`, so the files are what was on screen when the export was asked for, whatever is edited meanwhile. It registers the faces that `Resolved`'s text layouts drew from (`Resolved::text_fonts`) before it writes, since the text engine is per-thread and SVG and PDF shape live text again; the contrast check's worker does the same. While any runs, the status bar carries *Exporting ‹file›…* (or *Exporting N exports…*) with *Cancel* beside its messages (`OndinApp::exporting`, `RunningExport`), the bar interactable only then; a report names its file when it wrote one (*Exported “Ko-padel — Home.png”*), the count otherwise, when `poll_exports` sees it land, which it polls before the library's, a loading tab's and present mode's early returns; a report landing while another document is in front starts with the asking file's name. Several may render at once, but each writes only after every export asked before it has (`ExportTurns`), so two re-exports on save leave the later save's files. Quitting waits for every export that will still write (`drain_exports` in `on_exit`), so no file is left torn. **Closing a tab does not stop its exports; *Cancel* does** (`cancel_exports`): it sets each running export's flag (`ExportFlags`), which the worker reads before each render and again when it claims the write after its turn (`begin_write`), so nothing not yet being written is written. A render under way cannot be interrupted and finishes unwritten; the cancelled job stays in `exports` until it does and its landing says nothing, but quitting waits only for one that had claimed its write. *Export frames as one PDF…* runs on the same worker. The dialogs stay on the UI thread, before the worker starts.
- *Export frames, all pages…* (canvas menu and palette, offered only when there is more than one page) plans every page that is not a draft as *Export all frames…* plans one, each into a folder named after the page (a slash in the name becomes `-`, a repeated name is numbered); the status line counts the draft pages left out (`all_pages_frames_plan`).
- *Export frames as one PDF…* (canvas menu and palette, dim with no frame on the canvas) writes the frames *Export all frames…* takes as one PDF, a page and a bookmark each, named after the frame (`frames_pdf_pages`). The frames' own export rows play no part. It saves through a dialog seeded with the document's name, and the text is live.

### Snapshot (AI handoff / MCP projection)

`snapshot(doc, res) -> Snapshot`, serde-serializable and **distinct from the save schema**. It describes every page: `Snapshot::pages` lists them in order (`id`, `name`, `ground` as `#rrggbb` through `Document::ground`, so a page with no colour of its own reports the default, `draft`, `mode` by id), each page's root is also a node of kind `Root`, and every node names its `page`. Node content: id, kind, name, page, local and world transform, world bounds, paint summary (gradients as kind and stops; images by content-hash id, framing mode, alpha, non-rest adjustments), full text style, children ids, artboard membership, and a `warnings` list (missing font families). A chart frame carries `chart` (`ChartSummary`: kind and variant as the Chart card names them, the table's header as `{ id, name, numeric }` and its row count but no cells, the mapping by column id in the form `set_chart` takes, each series column's name, visibility and own colour, and whether it is linked), and each node under it its `role` (`"Bar"`, `"TickLabel"`), the `PartRole` its chart keeps it by.

- `snapshot_version` is currently **17**. Bump when a reader who does not know the field would misdescribe the page, or when an untouched document's snapshot changes bytes (a consumer diffing snapshots reads the version first):

| Version | Change |
| --- | --- |
| 3 | Text attribute model |
| 4 | Image detail |
| 5 | Image adjustments |
| 6 | `NodeSnapshot::mask` (reported for every node like `clip`, so untouched documents change bytes) |
| 7 | `mask_mode` (string `"Shape"`/`"Alpha"`, so adding a mode does not shift an integer discriminant; owned because the type is `Deserialize`) |
| 8 | `effects`: visible entries in compositing order, skipped when empty, string `kind`, **authored** numbers (a blur's radius, not the gaussian deviation) |
| 9 | A frame's ground leaves `Geometry::Artboard` and is an ordinary entry in `fills` |
| 10 | A gradient's `opacity` |
| 11 | Numbers platforms disagree about, written at the SVG writer's four places (`geometry.svg`, `local_transform`, `world_transform`, `world_bounds`); no key moves |
| 12 | Pages: `pages` replaces `root`, and every `NodeSnapshot` carries `page` |
| 13 | The `"slice"` kind and `Geometry::Slice { width, height }` |
| 14 | `NodeSnapshot::blend`, the menu label (`"Multiply"`, `"Pass through"`), absent at the kind's default; `EffectSummary::blend`, a shadow's, absent at Normal |
| 15 | The `"spiral"` and `"arc"` kinds, `Geometry::Spiral { width, height, turns }` and `Geometry::Arc { end_x, end_y, sweep }` |
| 16 | `PaintSummary::Image::duotone`: the dark and light ends as `#rrggbb`, present while the duotone amount is above zero |
| 17 | `NodeSnapshot::chart` on a chart frame and `NodeSnapshot::role` on each of its parts, both absent elsewhere |

- `local_transform` and `geometry` are **used** values (§5.3 layout), not what the user set; `world_transform`/`world_bounds` come from `Resolved`. A local an agent computes from these and writes back is a used value saved as typed. Whether the snapshot also carries specified values is MCP-work's question.
- `NodeSnapshot::pivot` is skipped when unset and reports the **resolved local point** (fraction resolved against `local_box`). It is the one derived field: a node with no measurable box falls to `Rect::ZERO`, so its fraction reports `[0, 0]`. Additive, no bump. `pivot` is not rounded.
- `mask_mode`'s `"Luminance"` joined version 7's strings with no bump, which is why the field is a string.
- `NodeSnapshot::element` (the tag, `"nav"`, `"h2"`) and `href` (only while the element is a Link with an address) are absent otherwise. Additive, no bump: an untouched document keeps its bytes, and neither changes what is drawn.
- Shape fields absent at their default are additive, no bump: `Geometry::Ellipse::arc` (absent at the default 0 · 360 · 0), `Artboard::corner_radii` (absent when square) and `corner_smoothing` on a frame, rect, polygon or star.
- `name` is usually distinguishing (numbered generated names, §5.7b) but **not unique**; `id`, `parent` and `children` sit beside it for disambiguation.

### Deliberate absences

A page's ground and the guides are in neither SVG nor PNG, and the guides are not in the snapshot (which reports each page's ground only as page data, never as artwork): the ground is the surface behind and around frames, and a guide is scaffolding. Both are document state (§5.5), not exported state. Guides are never in the scene walk (§9.4), so no export path can emit one.

## Traps

- Image markup has no gate: the §11 golden holds no image and `svg_in` has no `<pattern>` handling. Check changes in a browser: export, hand-rewrite a copy into the new shape, serve both over HTTP, draw to canvases, difference the pixels.
- A filter's region and the layer's ink bounds differ for inner shadows; the pad is not slack.
- `mask-type: alpha` (on the reader's side too: without it a `<mask>` imports as luminance) and explicit mask/filter regions are all load-bearing; the markup is well-formed in every wrong version.
- Report claims from `emit_node` under the visibility guard, never from `collect_defs`.
- Do not use `id` for layer names (collides with synthesised ids).
- Do not turn `Defs` into a map (byte order) or its membership into a scan (quadratic).
- Raster finishing order trim -> pad -> composite is the meaning of each step.
- The PDF's SVG names each run's face and its converter has no glyph fallback; the two hold together. usvg 0.47 shapes a text chunk's whole text in each span's face, the first span's the base, and when a fallback face covers every character of it, replaces all the base's glyphs, so Inter text with kana in a Japanese subset face (which covers Latin) would come out wholly in that face, embedding only it. Turning `select_fallback` back on, or not passing `faces: true`, brings it back. `a_pdf_embeds_the_fallback_face_its_script_was_drawn_in` (app, `#[ignore]`, network) pins it.
- A snapshot change that alters bytes needs a bump even if it adds no key; two stale version numbers have sat in prose before.
- `all_in_document_order` vs `in_document_order`: the first keeps nested exporting layers, the second filters to outermost.
- Code export writes an all-sides stroke as an `outline`, not a `border` (a border sits only inside the box), and a frame's on a last child, not on the frame (its children would cover it); an automatic line height as px, not `normal`; case into the content, not as `text-transform`; decorations on runs, not on the text's element; a baseline shift as `position: relative`, not `vertical-align`; and a picture under per-side borders with `background-origin: border-box`, not the default padding box. The obvious CSS for each draws wrong; the fixtures in `code_fidelity.rs` (`strokes_…`, `a_frame_stroke_…`, `text_…`, `baseline_shift_and_case_…`, `image_fills_…`) cover them, and only where a browser is found.
- `tokens.css` redeclares aliases in every mode block of their collection and gives each collection's default block `[data-mode="<default>"]` beside `:root`. Each looks redundant; without the first a dark subtree's alias keeps the light value, without the second a default-mode frame nested in another mode reads the outer mode. `variables_match_the_canvas_in_every_mode` pins both.
- The collection picked by width writes its `[data-mode]` blocks after every `@media` block: `:root` and an attribute selector weigh the same, so source order decides, and a pin written before a media block loses to the window. No test pins a frame pinned inside one picked by width. A true boolean is `initial`, not `block`, so `display`'s fallback restores the layer's own display; `a_frame_picked_by_width_matches_the_canvas_at_each_width` draws it.
- A component use's rule names its class twice and Vue's `vue::avoid` renames the user's classes that equal a used component's root class. Without the first the use's placement loses to the root's own rule when the component's stylesheet loads later; without the second a Vue user's scoped rule reaches the child's root. `vue::keep_uses_apart` is the same trap the other way: the use's class lands on the child's root, where the child's own rule for that class would reach it (a use named *Large* drawing the *Small* variant). `a_vue_page_never_shares_a_class_with_a_component_root_it_uses` and `a_set_is_one_component_choosing_its_variant_by_a_union_prop` pin the renamings; `component_uses_match_the_canvas` draws the doubling's placement.
- A text's element keeps its whole face in the tree and only `Element::css` trims what its text style's class makes. Trimmed in the tree, a merge or a state would compare what is printed rather than what is drawn. A merged element's alternatives wear its class too, so `merge::merged` keeps the class only where every variant's text wears the same one, and writes each rule whole otherwise. `TextClass::own`'s `normal` reset covers a text whose face lacks a declaration its class makes. `html_writes_a_class_per_text_style_used` pins the trim and `a_set_whose_texts_differ_in_style_wears_no_class` the merge.
- An element's reset goes ahead of the layer's own declarations (`reset_first`), since `font` after `font-size` would undo it (`a_buttons_resets_come_first`). A text written as a Button that wears a text style's class leaves `font` out of the reset altogether: the element's own rule loads after `text-styles.css`, so `font: inherit` there would undo the class's face. No test pins the second.
