# Kits: shared component libraries

Covers §5.3e: a kit is a document marked as one whose published components other documents vendor into a hidden vault, with an insert picker, publishing, updates and *Make local*. Components themselves (links, overrides, variants, swap) are §5.3d.

## 5.3e Kits

**Terms.** A *Kit* is a document whose components others use. *Library* stays the dashboard's collection (§5.11a, §9.6). A component whose main lives in a kit is a *kit component*; an instance of one names its source as "Atlas kit".

**A kit is a document marked as one** (document menu, *Make this a kit*; nothing is shared until the first publish). Its changes reach other documents only when it publishes; saving only saves. A kit keeps only its last publish: version number, date, note, and a frozen copy of each published main or set. Consumers vendor from that, never from the working document. Neither marking nor publishing is undoable (outward acts, like Save and Export); the date is stamped by the user's publish, so §5.11a's no-clock rule holds.

**Vendoring.** Using a component from kit L in document D copies L's published main into D as a hidden, read-only *vendored kit main* (the whole set for a variant, plus every kit main it nests, transitively) and records provenance: L's `meta.id`, the main's node id in L, the published version. D's instances link to that copy exactly as to any main of D, so everything in §5.3d (`link`, propagation, value-compared overrides, `component::check`, swap, variants, properties) runs unchanged. D stays self-contained: it opens, renders and exports with L deleted or offline. Images travel as a cross-document paste carries them (§15 D280).

**The vault** is another parentless `Root` beside D's pages, never a page itself (`Document::vault`, named *Kits*). Its nodes live in `Document.nodes`, so the component passes, which look up by id, need nothing new. It is outside every page's tree, so every walk from a page skips it (render, `Resolved::rebuild`, exports, snapshot, layers panel, cover, zoom-to-fit, *Select all*); React and Vue code export reads it on purpose, through `kit::as_placed`, to write a kit's mains as components (export.md, *Code export*); a reader that forgets fails safe. Explicit guards: the loader's reachability walk from every page and the vault; `kit::check` in `apply` and the loader; `Resolved::update` dropping a dirtied vault node as if deleted; `Selection::retain_existing` and `select_main` in the app; `RenderOverrides::absorb` refusing the vault's two operations. A reader that iterates the node map rather than walking from a page does meet the vault (`swap::options`, `component::instances_of`, which must leave it out so *Select all instances* and counts ignore nested vault copies).

**Origin.** Each vendored node gets its own `NodeId` in D and records its source in `Node::origin` (kit `meta.id`, node in L's published state, version); a vault main's top node also records the kit's name so an unfindable kit can still be named. Reusing L's ids would collide when two documents vendoring the same kit are pasted into each other.

**Variables and styles travel with the kit** (§5.3f). `kit::freeze` keeps every binding (a top's own visibility is frozen to what it shows) and freezes beside the mains the tables they read, closed over styles and aliases, with the kit's mode list (`frozen_tables`). A change to the tables alone is worth a publish (`Changes::tokens`). D holds what it vendors in its own tables, each variable and style minted D's id and carrying its origin (`VarOrigin`, `StyleOrigin`), and each kit's modes as a `KitModes` (never modes of D) with one per-kit mapping from D's modes, read by name, else the kit's first mode. One planner, `tokens::plan`, lands them for every door (`vendor`, `update_all`, the carrying paste): it reuses a held copy by origin whatever its version, reuses held kit modes when they cover the source's, refuses a source with a mode the held set lacks (`KitError::Modes`), and in the kit's own document maps to its own variables. A held kit record with no modes counts as absent and is minted afresh. A new kit variable or style whose name a held one of the same kit already has is `KitError::Modes` too (an update is owed first, or the commit would refuse the name twice). An update rewrites everything D holds of the kit and removes what the publish dropped (users detached keep their values), except a copy bound as its main is, which the commit's follow carries; an update whose publish reads none of the kit's variables removes the kit's record (`SetKitModes` with `None`) rather than leaving a mode-less one, which `variable::check` refuses beside any kit variable (`VarRule::NoKit`). The update's changed and removed variable and style lists name each entry once across kits (`update_in_order`).

## Publishing

- A kit's top bar carries a neutral *Kit* tag after the save dot and, hard against it, *Publish N* (the accent button), counting components changed since the last publish (added/changed/removed, in the hover). At zero it is disabled ("Nothing to publish · no changes since v8"). Never published: every component counts. *Publish kit...* is the document menu's row, a command-palette row and `Ctrl+Alt+P`, disabled with "No changes" when nothing is new.
- **The change count** is the kit frozen now against the kit frozen at its last publish, each top by id. A top is compared with the vault mains it reaches, leaving out every reached top's own place (transform, parent, insets, layout item, visibility: `propagate::is_placement`) and every origin's version (the frozen tables' variable and style origins included), since none of it reaches a consumer's instance. A move into another top-level frame is a change (the frame is the picker grouping). A kit rename or a new order of published mains is worth a publish (`Changes::renamed`, `reordered`, counted by `any()` not `count()`).
- **`kit::publish`** bumps the version, stamps the caller's date and a non-blank note, and stores the frozen copy. Not an operation, not undoable. A kit that has published and now holds no main publishes an empty state so consumers learn of the removal. The count is cached on the session's revision and the mark's version.
- **The dialog** (`kits/publish.rs`) is a modal card: a first publish lists the first six components and "+ N more"; a later one groups *Added* / *Changed* / *Removed* (removed ones "kept as copy where used", read from the last published state); an optional note; *Cancel* / *Publish*. Publishing saves; a failed save keeps its own status. A live text session is ended before counting and freezing so typed text is published (every kit verb that commits or saves does this). A toast follows.
- ***Stop sharing*** asks first (`OndinApp::stop_sharing_dialog`, one card for the document menu and the file card): documents using the kit keep their copies and stop receiving updates; making it a kit again continues from the last version. The dialog counts the documents using it on a worker that loads every library file but the kit's own and counts those whose vault holds a main from it (`kits/users.rs`); closing drops the count, and until it arrives the sentence stands without the number. It counts files on disk, so an open document's unsaved vault is not counted. The scan alone could not count (it reads a 4 KB prefix, `io::probe::meta_in_prefix`).
- **The kit mark** is `DocumentMeta::kit: Option<KitMark>`: last publish's version (0 before the first), date, note, and `sharing` (false after *Stop sharing*, keeping the version). It lives in `meta` so the scan's prefix answers "is this a kit" and "which version" without loading the file.
- **The published state** is a whole `Document` (`Document::published`, outside undo like `meta`) with one page, under the id of the kit's first page: every published main and set on it with the kit's own ids (so `Origin::node` names the same main across publishes), the other kits' mains those reach in its vault, and each top's top-level frame name. `kit::freeze` builds it; the file holds it one level deep.
- **What publishes.** The tops are every set and every main that is not a variant on every page that is not a draft, plus any set or main on a draft page that a published top reaches by link, swap or bound property, transitively (`draft_tops`): a draft keeps its own components out of a kit, never a piece the kit's components use. `kit::carried_from_drafts` names those for the publish message.
- **The dashboard**: a *Kits* row under *Starred* filtering the library's sharing kits; a *Kit* chip on the card cover (also on a conflict copy); file card ⋯ *Make a kit* (acts at once) or *Stop sharing as kit* (asks first). A conflict copy (it carries the original's id) gets no kit row unless it is the kit's only file; the row goes to whichever file `kit_file` answers. On the dashboard every file is closed, so the mark is written into the file (`library::store::set_kit`), the held copy patched to match, and the confirmation reads name and version from disk. A ⋯ row that opens a card gives up a file still loading. *Duplicate* leaves the mark and published state behind (`library::store::duplicate`).
- **The document menu** (`TopMenu::Document`, `OndinApp::document_menu`): the document name is its head (pulled left by `ui::HEAD_PAD`). It holds only rows with a verb behind them: *Publish kit...* (on a kit), *Kits used...* (while the vault holds anything), *Stop sharing as kit* or *Make this a kit*, *Show in library*. An unfiled document made a kit is given its `meta.id` by the verb (`make_kit`), since a kit without an id can never be found by the scan. Marking saves. The *Kit* tag (`kit_tag`, `theme::icon::PACKAGE`) is drawn by `top_bar`, not `document_menu`.

## Inserting

**The insert picker** (`kits/picker.rs`) is a floating panel beside the toolbar, opened from a hexagon at the foot of the vertical toolbar, `Shift+I` or the command palette's *Insert* row, bottom-aligned with the button; closed by `Escape` (a rung of `OndinApp::escape` after the colour picker's, so one press closes one thing) or the button. It opens with a library rescan. Search at the top, grouped by kit then by set; a click places at the viewport centre, a drag places on the canvas, inside the frame it is let go over.

- Browsing lists the kits D uses first, by last use (kept per machine and per document: `library::cache::LocalIndex::kit_use`), each opening to its sets and lone mains grouped by the top-level frame they sit in (outside a frame: under the kit's name). A set is listed once, its tile its default variant (`index::tile_subject`, `kit::default_variant`: first variant in reading order, topmost then leftmost, ties to the earlier child). Then "In your library, not used here" with counts.
- Search runs across every kit as a flat list with the kit on the right, best match first, `Enter` placing the highlighted one; a variant matches through its set.
- D's own mains lead as tiles under *This document* whenever it has any (pictured on a worker, `LocalTiles`, once a revision has stood 400 ms and only for a main whose subtree differs from the one drawn, its own translation ignored; every one again when a family the document names arrives). With no kits the picker says how a kit comes to exist and ends with *Open library*.
- A kit never published is listed "not published" with nothing to insert; a kit not found is *Unavailable* and offers only the copies D already holds, which still insert. A conflict copy of a kit (a second file carrying its `meta.id`) loses to the file that is not one, recognised by filename (§15 D375).
- *Used* means an instance on any page links or swaps to one of the kit's vault mains (`kits_on_the_page`, a walk from the pages that never enters the vault, following each link to the end of its chain), not that the vault holds copies. A vendored kit neither used nor in the library is still listed, unused. The update pill and *Kits used...* read the vault; the pill's waiting kits (`kits_waiting`) also take a kit held only through variables or styles another kit's main reads, since that kit's update and every insert from it wait on it.
- **Keyboard.** The search field takes focus once, on opening. `Shift+I` closes the picker only while the field does not hold focus; up, down and `Enter` act only while it does. The field has no `Escape` arm of its own deliberately: egui clears its focus before `input::resolve`, so the ladder's rung sees the press and a second arm would close the picker twice.
- **Pictures** are drawn as the main lands (`ondin_core::kit::as_placed`: a throwaway copy with the subject moved to the top of the first page, so no ancestor transform or layout, a variant at its stored size, a vault main resolved; subject chosen before the move). Tiles draw no scrollbar.
- **Placement** is one transaction: `kit::insert`, or `build::insert_subtrees` for a local main or an unavailable kit's vault copy, then a `SetTransform` centring the instance on the viewport, or on the release point for a drag (`OndinApp::place_kit_at`). Size is measured on a scratch document with the transaction applied and by the laid-out box for every kind; the world shift is converted into the parent's space (`centred`), so an instance dropped into a turned or scaled frame is centred on the release point. A click or `Enter` lands at the document top level. A drop lands in `drop_container_at`: the topmost unlocked frame or group with a layout (flex or grid) whose world box contains the release point and that shows there (no ancestor hidden, none clipping the point away), passing over any that is or sits inside a main, instance or set (the component rules could refuse an instance there) or inside a boolean; with none, the top level. In a layout container the instance joins the flow at its end. Releasing over the panel or a floating panel places nothing; a right-click cancels the drag. The drag draws the component under the pointer at its landing size, rendered on a worker at the canvas zoom, capped at half the canvas (re-rendered when zoom moves by a tenth); the tile's picture shows until it arrives. Every placement waits one painted frame with its tile at half opacity (`ask_place`, `OndinApp::kit_placing`) because it runs on the frame thread; a picker closed in the wait places at once.
- **Panel height** is fixed (460, or less where the canvas above the button is shorter; `panel_height`). An `Area` lays out in last frame's rect, so the list asks `min_scrolled_height` and does not shrink, and the area is placed by its top-left (a bottom pivot also reads last frame's size).
- **The library's kits** (`kits/index.rs`): `kits_in` lists them from the scan's `meta.kit`; whether a kit is sharing is asked of the file that won; `kits::index::kit_file` is the single answer also used by the dashboard filter and ⋯ row (ordinary file before conflict copy, then first by path). `KitShelf` loads each whole file and renders tile pictures on a worker, keyed by the mtime the scan read and recording the version the file said when read (a placement records that, not the scan's). The published state is sent ahead of the pictures so an accept never waits on a drawing; pictures decode once per kit (`index::prepared`, `png::raster_of_with`); a tile's pixels are dropped once uploaded; opening the picker drops shelves of kits the library no longer lists and every failed read (`KitShelf::refresh`). A font family a kit's text names arriving marks that kit for a fresh read (`KitShelf::fonts_changed`). Opening the picker loads every kit in the library.
- **Swap picker** (`panels/variants.rs`, `kits::index::kit_heading`): D's own mains first (headed *This document* only when a kit group follows), then one group per kit by name with one version for the group (the oldest D holds of that kit, the figure the update pill counts from; the library's for a kit D holds nothing of; or *unavailable*), the name-prefix filter across all of them. Groups are keyed by kit id so two kits of one name stay apart.
- **A swap to a kit main D has never used is offered and vendored at the swap.** Each library kit whose published state `KitShelf` holds at the file's current mtime adds its `kit::swap_offers` (mains of the copy's kind that `kit::find` says D does not hold) to its group. A pick is `kit::vendored` (`vendor` plus the document its ops leave), and the swap is built against that scratch (`variant::swap_carrying` for the copy's row, `variant::set_property` for a property's): one transaction, one undo step. A main vendored from a third kit is that kit's to offer.

## Kit instances and read-only copies

- A kit instance keeps the violet selection every instance has (`color::COMPONENT`); only the kit glyph is neutral. The Component card shows the kit, its name and version under the main's name ("· v9 waiting" when an update waits) and its ⋯ menu gains *Go to main in Atlas*, *Accept kit updates* (the instance's own kit; when one waits) and *Make local...*. The layers panel adds no mark; its tooltip names the kit. The canvas context menu on a kit instance's root gains the same three rows (*Accept kit updates* omitted when none waits; a recorded departure from `context-menus.md` §3, its §9.6 item 17), *Make local...* after *Detach instance*. A local instance's menus are unchanged.
- **A vendored main cannot be edited from D.** Read-only is the app's rule (no document rule can tell an edit from an update): a vault node is never resolved, so never drawn, picked or selected. *Go to main* opens L in its own tab (or brings L's tab forward) with the main selected, and L's top bar carries a "back to D" link, which brings D's tab forward; the link is kept with L's tab. *Detach* works as on any instance.
- ***Make local*** (`kit::make_local`, `Operation::SetOrigin`) reveals the hidden copy as an ordinary editable main of D, no longer following L, from the card (a dialog listing all N instances; overrides stay; undoable), from *Make all local*, and for a component the kit removed. No instance is promoted (promotion would make its overrides the main's values and re-base every other instance); every instance and override stays as it was. All origins in the main are cleared; the main is moved last onto the page the verb runs from (`kit::make_local`, `make_local_report`, `update` and `update_all` take that page), placed to the right of content (several stacked down, 80 apart, by laid-out boxes measured on the document the transaction leaves); the selection does not move. A kit main it nests stays vendored. A vault main that nests it keeps the kit's: the same transaction copies the revealed main back into the vault with origins kept and points the nesting copy there, so the revealed one is the user's fork and the vault never links out. The dialog counts only instances that will follow the revealed main (`OndinApp::make_local_reach`).
- **Make local forks the kit variables and styles the main reads** (`tokens::fork`): the revealed nodes' own bindings (not ones equal to their link source's, which a nested kit instance keeps; a fill or stroke matched to the source's by item id) are pointed at D's own copies, every mode given the cell the mapping read there, a fork already marked with the same kit variable or style (`Variable::forked`, `Style::forked`) reused. `kit::make_local_report` supplies the status line (how many were forked). An update makes the kit's removed mains local the same way, a top the publish no longer holds forked before the kit's tables are rewritten (`kit::update_in_order`), and whole: every top is classified before any is synced and no sync moves a layer out of one being made local (`Builder::keep_out`).

## Updates

D notices a newer publish of a kit it vendors from. A pill beside *Saved* ("2 kit updates") appears on open and, while D is open, at the next look at the used kits' files: `watch_kits`, only while the vault holds anything, every 45 seconds (`WATCH_EVERY`) and on the frame the window regains focus; each used kit's file is `stat`ed (mtime and size) against what the scan read and a difference rescans the library. A used kit the library cannot find is looked for on a focus only; a document using no kit watches nothing. No toast.

The popover lists per kit "v8 → v9" and what the update changes (component, variable and style counts, then *Changed* / *Added* / *Removed* rows with old-to-new values and how many layers a removal detaches), the publish note, the instance count ("Your overrides stay."), and *Later* / *Accept all*. Its summary (`kits::summary`) is read off a dry run of `update_all`'s operations, cached by the session's revision and waiting versions; a new value is read through the update's own kit-mode records, an old through the document's. *Later* shrinks the pill to glyph and count, kept per machine, per document, per version; a newer publish grows it back.

- **An update is a diff plus an ordinary commit.** `kit::update_all` rewrites each vendored main in place to its new publish, children first (matched by origin node: dropped, replaced where the kind changed, inserted, reordered), then its own fields and its origin at the new version, as one transaction across every accepted kit, undoable as one step. Each op is built against a scratch the earlier ones were applied to. It never touches an instance: the commit's main-edit passes carry the change (overrides survive by value comparison, instance structure by §5.3d's free-structure rules, an instance root's placement stays its own). A main the publish newly reaches is vendored first. Pictures a publish introduces come first in the transaction (`build::missing_image_ops` over every image the vault shows), or a changed fill would be saved with no bytes behind it. A node new to the publish is an empty shell filled by the same sync, never its published subtree copied whole, so a group the kit made around held layers moves them in rather than minting them again. A node's own fields are written only where its kind takes them (a group's paint ops, which `apply` refuses, are skipped).
- **It does not depend on vault order.** A link, swap or binding a sync cannot point yet is written empty and pointed once every kit's tops are synced (`Builder::later`); a missing node whose main is held at another version answers `NeedsUpdate`, not `Incomplete`. A node the kit only moved is moved, not deleted and re-copied: a published top held below the vault top level (a variant taken out of its set) is lifted; a top the kit put inside another waits for that top's sync, which reparents it in; every child a sync drops waits until the kit's tops are synced, deleted then only if no other sync moved it, so a layer moved between groups is a move and a group the kit ungrouped does not take the lifted layers with it.
- **Main-edit passes write no copy in the vault** (`propagate::follows_nothing`): a copy nested in a vault main takes values, children and order from the publish alone (through `sync` and `vendor`). A vault node is still a source (sync edits reach the page's instances).
- The toast counts mains whose sync changed more than their version (`Update::changed`; "no component you use changed" at zero; a layer deleted after every sync, or a reference pointed after them, counts to the main it lies in) and names each removed variant whose instances detach (`Update::removed`). A waiting kit that cannot be read applies nothing and says so. Toasts are text-only (the toast names `Ctrl+Z` instead of an Undo button; a revealed main's toast says where it went rather than offering Show).
- An accept uses a loaded publish only when it was read at the kit file's current mtime and at the version the scan read (`KitShelf::current`), else reads the file and records the version it says; an update writes the publish's name onto the kit's own vendored tops. A one-kit accept (card, canvas menu, *Kits used...* row) that meets a newer version of a third kit's main than D holds (`NeedsUpdate`) accepts every waiting update together when more wait than it took; otherwise it says the other kit is not in the library.
- ***Kits used...*** (document menu, while the vault holds anything): a row per kit with location, instance count and status ("v9 waiting", "Up to date · v16", "Unavailable"), each with *Open kit*, *Accept update*, *Make all local...* (a confirmation, one undo), and *Accept all* when any waits. There is no *Locate...*: a kit is found by `meta.id` through the library scan, and *Unavailable* means it is not in the library folder.

## Vault rules and kit operations (`kit.rs`)

- **`kit::check`** (after `component::check` in `apply` and the loader): the vault is a parentless `Root` (that it is not also a page is held by the loader and `OpenVault`); every node under it carries an origin naming a well-formed kit id, and none outside carries one; each child of the vault is a main or a component set; and no node in it links, swaps or binds to a node outside it (`LinksOut`). No rule makes a vendored main read-only.
- **`Operation::OpenVault` / `CloseVault`** are each other's inverse; a close is refused unless the vault is open, is `id` and is empty. The first insert that copies anything opens it, so its undo removes the vault and a document that never used a kit saves as before.
- **`remap_subtree` never carries `origin`**: every copy (duplicate, instance, paste) goes through it and none of them lives in the vault. Kit verbs write origin after minting.
- **Vendoring** (`kit::vendor`, `kit::insert`) brings a main, its whole set if a variant, and every main it reaches by link, swap or bound layer. A node held by its origin key is reused whatever its version (bringing it up to date is an update's job); a node a later publish added to a held main is refused as `KitError::NeedsUpdate`. A kit never vendors itself: `kit::find`, the lookup `vendor` and `adopt` share, lands an origin naming the document's own `meta.id` on the live node, so a kit's own main inserted or pasted into the kit links to the main and opens no vault; a pasted copy of a main the kit has since deleted is left out by `adopt` and lands detached. A kit built on this one is refused by `vendor`, an update and a paste alike with `KitError::Circular`. A main the kit itself vendored keeps the third kit's origin. Images are added if missing; the instance is placed under the given parent at the main's own transform, one transaction; centring is the app's.
- **A kit instance pasted into another document stays an instance**: the clipboard carries the vault mains a copy reaches (`kit::carried`, `io::clip`'s `kits`) and `kit::insert_carrying` vendors what the target lacks before inserting (§5.3d's paste rule, §9.4). An instance of the kit's own live main, copied inside the kit, carries nothing and detaches when pasted into a consumer (status "N instance(s) detached — its main is not in this document"). A carried main that nests one the target holds at an older version without a layer it links to is refused `NeedsUpdate` ("Accept the kit's update first"); one reaching a live main here is refused `Circular`. A carried main `adopt` leaves out (no origin, or this kit's own deleted main) leaves the fresh vault copies nesting it with that reference cut, detached as §5.3d's rule would, since no `settle_copy` runs on a vault insert; the status count is read off what landed.

## Not built / non-goals

- A per-component review table before accepting an update is the next phase, not a non-goal; the popover leaves room for its disclosure.
- Team publishing is not planned. Real-time collaboration is a non-goal (§12): a kit reaches another machine through the synced base folder (§5.11a), with no network code.

## Traps

- A reader that iterates `Document.nodes` instead of walking from the pages meets the vault; suspect it first when a kit's mains appear as artwork or in counts.
- Placement passes (`keep_insets`, `keep_flex_sizes`, `flex_holds`, `kept_flow_translations`) must leave every vault node alone: the vault is never resolved, so its stored transform is not where it is drawn.
- `propagate::follows_nothing` and `kit::sync` are two defences: a vault copy followed after a sync rewrites the publish and causes update defects.
- The `kit::vendor` reuse-by-origin rule ignores version; a node added by a later publish to a held main answers `NeedsUpdate`, so an insert can fail until the update is accepted.
- Deleting a main through the commit and a kit update both reach `propagate`; an update must never write instances directly.
- A conflict copy of a kit carries the original's `meta.id`; every door that asks "is this a kit" must go through `kits::index::kit_file`.
- `Origin::name` is written only where the top's origin is the kit being vendored; a third kit's main keeps its own kit's name or none.
- Make local must copy the revealed main back into the vault when a vault main nests it; otherwise the vault links out and `kit::check` refuses.
