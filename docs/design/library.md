# The library (§9.5)

The dashboard screen, the on-disk storage layout, saving, crash recovery and the library's modals and keyboard.

## 9.5 The library

### Two screens

`OndinApp::ui` calls `dashboard_ui` and returns before the font poll and `input::resolve`, so with the library up there is no tool, selection or canvas. Given up deliberately: the font poll, `disk_results` (the editor's save dot), and the two ticks (one of which `go_to_dashboard` compensates by hand). `handle_close_request`, `close_confirmation`, `recovery_modal` and the write of `OndinApp::chrome_focus` sit above the return (the window's close and focus are not editor machinery).

**Status.** `EditorSession::status` is one slot. **An error written this frame is never replaced**: a later `info` or `fail` in the same frame joins it with ` · ` (`session::STATUS_JOIN`; a sentence already there is not repeated, an empty write clears), so a handler's refusal survives the report that follows it. `OndinApp::ui` starts each frame with `next_status_pass`; a write in a later frame replaces, as a new action's report should, and an info is always replaced. The editor shows it in a floating status bar (`OndinApp::status_bar`): a non-interactable `Area` 12pt in from the central panel's bottom-left (to the minimap's right while it shows, `minimap_clearance`), in focus mode too, a `ui::menu_frame` card truncating at the smaller of 60% of the canvas and 560. It shows the mode whenever not `Normal`, and the last message for `app::status_hold` (`clamp(2 + 0.05 × chars, 3, 8)` s; failures ×1.5, at least 5), then fades over `STATUS_FADE`. The fade is the card's opacity when the message is alone, the label's colour when the mode is beside it; `age < hold` is what lets the bar go; the Area takes `.fade_in(false)`. *View > Show messages* silences messages, never the mode. The library draws `app::status_dot` instead (fixed 8pt mark in a 28pt hit box, whole message on hover, untimed). Only `app::status_color` is shared (what a failure looks like). Tests assert the dot's colour for the surface and `session.status().text` for the wording.

### Storage

One base folder, default `~/.ondin`, user-settable. Nothing asks where to save, open or what a file is called.

- `<root>/<slug>.ondin`, or `<root>/<project folder>/<slug>.ondin`. Names are slugged (`library::naming`), collisions take `-1`, `-2`, Windows device names too.
- `<root>/projects.json`: id, name, colour, optional folder, `archived` (written only when true).
- `<root>/.versions/<document id>/<unix seconds>[-n].ondin`: pinned versions, keyed on id, `-n` for a second pin in the same second. `store::versions` lists them newest first by `store::version_stamp`, numerically (a byte sort puts `S-1` before `S`).
- **Version history** (`versions.rs`): the Document menu's first row and a palette command open a card listing the open document's versions, newest first, each with *Restore*. A restore loses nothing: it writes and pins the current state first (whatever `prefs.version_history` says, since undo does not cross the restore), then adopts the copy at the same path with the file's id (`adopt_opened`) and saves it. A document outside the library (one `library.entry_at` does not list, whatever id it carries) gets no pins from `Ctrl+S`, so the card lists none for it, not even a library copy's under the same id, and says to save it to the library.
- `<root>/.trash/`: deleted documents. The retention window runs from an mtime stamp written on the way in (`store::trash` touches the moved file, `store::trashed` reads it). Swept at launch (`OndinApp::open_at_launch` → `store::purge_trash`) and on saving the library-settings card. The stamp temporarily clears a read-only attribute and restores the original permissions.
- `<root>/.recovery/<key>.ondin`: crash snapshots, keyed on document id or a minted key. Lives in the base folder so the library stays one directory to back up or sync.
- `<root>/.history/<document id>.json`: each document's kept undo history (`library::history`, below).
- `machine_dir::root()` (`cache_dir()/ondin`, `OndinData` on Windows because Setup deletes the installer's `ondin`): derived and local data (last-opened times, stars, covers, the page each document was left on). What a user would expect on another laptop goes in the document (§5.11a); the rest here.
- **Covers.** A cover draws the document's first page that is not a draft (the first page when every one is), framed on everything on it (`cover::rasterize`). One cache directory for all libraries; `Covers::sweep` runs once per dashboard entry and keeps only PNGs whose stem is `cover::key` (id plus mtime) of a current entry. An empty list sweeps nothing (an unlistable root must not delete every library's covers). Changing the base folder discards covers (cheap, they regenerate). `Covers::clear` is the renderer's teardown, called by `apply_library_settings` before `relocate` (drops the worker, joins the render in progress). Covers render on a worker thread and are requested only for cards on screen (`ui.is_rect_visible`; the grid and list are not virtualised, ~4 ms/frame at 1,000 documents); the list requests none; the project mosaic (up to `MOSAIC_MAX`) uses the same gate. `Covers::pass` runs once per dashboard frame before any card and drains the worker (an answer such as `Cover::Unreadable` is a fact, not just a picture). Past `MAX_RESIDENT_COVERS` = 128 textures the least recently asked-for `Ready` cover goes (aged by `Covers`' pass count; any asked on this or the previous pass is exempt).
- **`Project::folder` is one path component** (`library::project::is_folder_stem`, enforced in `Projects::read`, the single reader, also the door `relocate::merge_projects` uses). Checked via `Path::components` plus a refusal of any `\` on every platform. A bad value is dropped, not file-refusing (the project keeps its files at the root).
- **Dates are local, differences are not:** `clock::local_offset` asks Windows for the offset at that instant (`GetDynamicTimeZoneInformation` + `SystemTimeToTzSpecificLocalTimeEx`); Linux/macOS use `localtime_r`; other hosts get UTC. Relative labels ("2h ago") are instant differences.
- **The scan** walks two levels and skips dot-directories (`.versions` is also excluded by the depth limit; neither rule may change assuming the other covers it). A filename that is not valid Unicode cannot be an `Entry`; `scan::unnameable(root)` reports those (same `collect`), and `library::relocate` carries them by `OsStr` name (an occupied name is a failure, not a rename). A project folder whose name is not text is walked, not skipped. `Library::refresh` lists every folder each time but opens a document's prefix only when its full-precision modification time or size moved since the last refresh (`scan::scan_cached`, `scan::MetaCache`, keyed by path; a vanished file drops out), so a refresh over an unchanged library is a directory listing. It stays synchronous: callers read `entries` on the next line.
- **A scan that could not read the folder is not evidence it is empty.** `Library::root_unavailable` = the folder could not be listed AND the per-machine index is non-empty. It gates the sweep that drops per-machine rows (`LocalIndex::retain_known`), the empty-state sentence, and the three doors that create files (every write begins with `create_dir_all`, so without the refusal *New file* creates a fresh folder wearing the missing library's name). The index is keyed by document id, not folder. Settings creates the folder it is pointed at as the first thing in the branch, and a failure there is the refusal (only the base folder is refused; the card's other settings still apply).
- **Unreadable records are never overwritten by defaults.** `Prefs::unreadable`, `LocalIndex::unreadable`, `Library::projects_unreadable` are set when the file exists but cannot be parsed and are checked by every write; `OndinApp::report_unreadable_records` says so once with `fail` (naming `base_folder`). Each record has `load_from`/`save_to` against an explicit path. The global `LocalIndex::load`/`save` ask `library::cache::index_is_reachable()` (`!cfg!(test)`) on their first line so tests never touch the real cache; `Library::open_with_index` takes the index as a parameter, and a base-folder change hands the in-memory index across.

### Writes and migration

- **Every write is metadata first, path second** (rename writes the name inside the document then renames the file; move writes the project id then moves). A failure leaves a stale filename with correct contents, never the reverse.
- **Every open session is a third copy of the metadata** and is patched with it: `OndinApp::open_document_follows` (guard, clone, write-back with the field as a closure) is called from all four doors that move a library file, including *Delete project*'s transfer branch; otherwise the next save undoes the operation. It reaches parked tabs (`open_sessions`) and re-points tabs not yet read (`unloaded_paths`). Trashing a file (`open_file_trashed`) closes every tab of it — in front, parked or unread — dropping unsaved work, and takes it out of `Tabs::closed` so `Ctrl+Shift+T` cannot bring it back. Each session is unfiled before its tab goes, so no save in flight or on the way out writes the document back out of the trash.
- **Changing the base folder can migrate the library** (`library::relocate`); every open session and unread tab is re-pointed through the returned map of `(from, to)` pairs (`OndinApp::follow_moved_documents`, also `prefs.last_document`). It is a map, not a prefix swap, because `relocate` renames into a collision. `Moved::documents()` derives from the same pairs. Failures are named (`Moved::failed: Vec<PathBuf>` of source paths via `Moved::fail`), and `OndinApp::stranded {from, to, failed}` (cleared by a clean run and by a non-migrating folder change) feeds the *Library settings* card: count, old path, up to `STRANDED_ROWS` = 6 names, "…and N more", and *Try again* (`retry_migration`; not idempotent, which is why it is safe). It refuses and keeps the report if `to` is not the library root, if `from` cannot be listed, or if the library root cannot be listed. Rollback is deliberately not offered (`relocate` overwrites nothing).
- `relocate` keeps the name a file already has wherever free (re-slugging would erase the sync-conflict mark and merge ids); `naming::unique_stem` is the collision fallback. Collisions per dot-directory: `.versions` skip (same document instant); `.history` skip (either copy is vetted by its digest, and losing one costs only undo steps); `.trash` rename (unrelated documents), except an arrival with a non-text extension, which is counted a failure; `.recovery` left in place and counted a failure (a snapshot's stem is its document id).
- **Nothing in the library is undoable.** *Delete* moves to `.trash`. Deleting a project has no trash (it is a row in `projects.json`): its dialog moves the files first, and the row and the nav reset happen only when every member moved, so a partial failure leaves the project holding what could not move and a retry targets exactly those; the nav stays on that project.
- **Projects are edited and archived, not trashed.** *Edit project* (beside *Delete project*) reuses the New project card with *Create folder* replaced by an *Archive project* switch. A rename takes the folder with it; `library::project::rename_folder` returns the stem actually produced and the caller records that. `EditProject::differs_from` (name compared trimmed) is asked by `save_project` and by the footer, so an unchanged card writes nothing.
- **Archiving is a flag only.** An archived project still owns, counts and has a page for its files; it leaves every list (sidebar *Projects*, *Recent* cards, header filter, *Move to project*) and is reachable from the collapsible *Archived projects* group (collapsed each launch). Exceptions: search matches it by name, and *Move to project* shows the one a document is already in. `Projects::active` filters lists, `Projects::get` is unfiltered, `Projects::destination` answers "may a new document be filed here"; `dashboard::new_file_into`, `OndinApp::nav_project` and the import card's `start_copy` and `done_import` must answer alike (archived nav means unfiled).
- The editor's breadcrumb is `Project / Document`; the project half navigates to the library on that project; an unfiled document shows its name alone. The document half is the head of the document menu (§5.3e). The name shown is the typed one from the metadata (`library::scan::display_name`), never the file stem.

### Saving

- `Ctrl+S` writes the file and pins a version; autosave writes silently on an interval, never pins, never creates a file, and is gated on `is_dirty`. No *Save As* (use *Duplicate*, which mints a new document id).
- **Save state is a dot beside the document name** (`OndinApp::save_dot`; 7pt; `color::unsaved()` red until the file matches, `color::saved()` green). The sentence (*Unsaved*, *Saving…*, *Saved · 2m ago*) is its tooltip; *Saving…* keeps the dot red. The top bar has no open or save button (library via the library tab or `Ctrl+O`; save via `Ctrl+S`).
- **Autosave queues; `Ctrl+S` writes.** `autosave_tick` (four gates incl. `is_saving`) hands a `Document::clone` to the same worker the crash snapshot uses. The session goes clean from the worker's answer: `EditorSession::finish_save` refuses if the revision moved and returns whether the save counted (what `export_on_save` re-exports on). Undo/redo move the revision. `Ctrl+S`, walk to the dashboard, leaving or closing a tab, an open and the close-and-save arm stay synchronous (a pin is a file copy). The library's read and load on open are off-frame behind a save.
- **Every record is written atomically** (`atomic::write`): create the parent, write `<path>.<pid>-<counter>.writing`, `sync_all`, rename over the target. Covers the document, each pin, `projects.json`, prefs, the per-machine index and the crash snapshot. The directory entry is not synced. Covers, the font cache, exports and `ondin.log` deliberately do not use it (derived, re-run, or append-only). A save keeps the file's mode and symlink (temp gets the replaced file's permissions; links are written at the resolved target). Temp names are unique per write (a second Ondin is possible); debris is swept by stamp pattern (not extension) when older than an hour, once per directory per process. A failed write at any of the four steps removes its temp and leaves the old file intact. The destination is never unlinked first (`fs::rename` replaces; `remove_file` would clear read-only). `atomic::at` wraps each failure with a verb and path (create/write/flush/replace; the destination for the rename).

### Document tabs (`tabs.rs`)

Each open document is a tab in the strip (`app-chrome.md` draws it), after the library's, which is always first. `OndinApp::tabs` holds them in strip order.

- **One tab's editor state lives in `OndinApp`'s own fields** (`session`, the recovery key and times, `last_autosave`, `collapsed`, `kit_return`): the *active* tab, so every `self.session` reader reads the document in front. Every other loaded tab is `Body::Parked`, moved aside by `park_active` and back by `unpark`. A tab can also be only a path, `Body::Unloaded { path, failed }`: restored at launch and not shown yet, being read, or unreadable. The tool, the panes and the view switches are the window's, not a tab's.
- **`Tabs::shown`** is the tab in front while the editor is. It differs from `active` while the front tab is being read or could not be; the editor then draws `tab_placeholder` (*Loading X…*, or why with *Try again* and *Close tab*) and leaves the active state untouched.
- **A document is never open twice in one window** (`tab_of_file`, which also matches another spelling of the same file — a case difference, a `..`, a junction — through `canonicalize`; the per-frame readers keep the exact `tab_of_path`): two sessions saving one file would overwrite each other. A second Ondin process is not stopped from opening it (roadmap). `open_path` (on the frame) and `begin_open` (off it) put a document in a new tab at the end, or bring forward the tab already holding it. Nothing replaces an open document, so opening asks nothing.
- **Leaving a tab saves it** as `go_to_dashboard` does (`park_active`): finish the text session, save if filed and dirty, else bring the crash snapshot up to date, then settle the writer and swap. A tab behind is clean unless never filed or its save failed; no autosave or snapshot tick runs for it, and nothing is written behind the user's back while it waits. So a file import read for a tab behind waits until that tab is in front again (`poll_imports`), and a tab closed first takes its imports with it, unsaid.
- **Closing** (`close_tabs`, one tab or many: the ×, a middle-click, `Ctrl+W`, the tab menu's three *Close* rows, `context-menus.md` §6.9): a filed document saves and closes without asking; clean tabs close, the front one last so no tab about to close is brought forward and read. Every tab whose work cannot be saved stays open, and all of them are asked about on one *Unsaved changes* card (`closing_tabs`): *Save and close* brings each forward in turn and saves it, closing those whose save went through; *Discard* closes them all. The next tab to the right comes forward, else the left, else the library. `Ctrl+Shift+T` reopens the last closed at its old place (`Tabs::closed`).
- **Pinned tabs** (`Tab::pinned`, the tab menu's *Pin tab*) are always the leading run of `Tabs::list`. `Tabs::pin` puts a newly pinned tab right of the pinned ones and an unpinned one at the head of the unpinned, so the order stays put; a drag (`move_to`) and a new or reopened tab (`insert`) keep each tab on its own side. A pinned tab is spared by a middle-click, `Ctrl+W` (which says on the status line to unpin it), *Close others* and *Close all*, and its own menu's *Close* is dimmed: only unpinning lets it close.
- **Closing the window** (`handle_close_request` → `any_unsaved`) asks once on the same card, listing every unsaved tab with its project, *Unfiled* or *Not in the library*. *Save and close* brings each forward in turn and saves it (filing a never-filed one) and closes only if every save went through; ✕, Escape and the backdrop are Cancel.
- **Keys** (`tabs::read_keys`, both screens, before the keymap): `Ctrl+Tab` / `Ctrl+Shift+Tab` step, wrapping, the library counted; `Alt+1`…`Alt+8` that slot (the library is 1), `Alt+9` the last; `Ctrl+Shift+T` reopen. `Ctrl+W`, `Ctrl+O` and `Ctrl+N` are in `shortcuts.md` §8.
- **Next launch** (`open_at_launch`): the tabs open at the last quit come back in order (`Prefs::open_tabs`), each only a path; a file gone from disk drops its tab with a status message. `Prefs::pinned_tabs` counts how many of them, from the first, were pinned, and `restore_tabs` pins those again. `reopen_last` decides whether the tab that was in front (`Prefs::front_tab`) is in front again, else the library; a command-line document goes in front over both. `remember_tabs` writes the three once a frame. `prefs.last_document` is read only when `open_tabs` was never written (`Prefs::tabs_remembered` false, a preferences file from before tabs); an empty list written by `remember_tabs` means every tab was closed, and none comes back. A window launched while another Ondin runs (`instances::others() > 0`, a headless `ondin export` included) keeps its tabs private (`Tabs::private`): it restores none and writes none, since the other window may hold them open.

### Undo history

- **Kept in the library, not beside the file**, at `.history/<document id>.json` (`library::history`, `HISTORY_DIR`): it must not travel with a copy of the file (git, a USB stick, a shared folder), and the id survives renames and moves. It travels with the library, as `.versions` does. A document without an id, or saved outside the library root, keeps none (`OndinApp::kept_history`): a copy elsewhere carrying a library document's id would otherwise write over that document's history.
- **The record is `{ build, file, history }`**: the app version that wrote it (`CARGO_PKG_VERSION`), the SHA-256 in hex of the document's bytes as written (`history::digest`), and the `SavedHistory` (§5.8).
- **Written with every document write**, after the document lands and against the digest of the bytes written (`store::write_document_digest`): autosave on the writer thread (`writer::Job::Document` carries an optional `KeptHistory`, taken at queue time with the document clone) and `Ctrl+S` synchronously (`OndinApp::save_file`). A failed history write is not reported: the document is safe; only undo steps are lost. An empty history removes the record.
- **Read back on open only for the same bytes from the same version** (`read_opened`, on the open worker and in `open_path`; `history::for_opened`); any other record is dropped silently. A file can change while Ondin is not looking (sync, a git merge, a version restore), and replaying a history onto another document would corrupt it; the saved form follows the model's types. `EditorSession::resume_history` restores it with the top step *Saved*. Crash recovery and version restore adopt a document without reading one.
- **Library rewrites keep it.** *Rename*, *Move to project* and *Make a kit / Stop sharing* on a closed document go through `store::rewrite`, which carries the record to the new bytes' digest (`history::restamp`) when it was kept for the old bytes.
- **Removed with the document for good**: the trash purge (`store::purge_trash`) and the permanent delete from the trash (`trash_or_purge`). *Duplicate* mints a new id, so a copy starts empty. A record whose document was deleted outside the app is never pruned.
- **Size** is the library Settings card's *Undo history* (`prefs.history_size`, steps, default 100, field max 1000). It caps only what is written (`History::saved(keep)`), never the open session; memory is not the concern, since steps share image bytes through `Arc` and a property edit's inverse is tiny. A 16 MB ceiling on the record drops the oldest undo steps, then the farthest redo steps, since an undone image delete carries the picture's bytes. 0 keeps none: the next save removes the record, nothing is read back, and a warning caption says the history is cleared when a document is closed.

### Crash recovery

- **A snapshot, not a journal.** `library::recovery` writes the whole document to `.recovery/<key>.ondin` through `ondin_core::io::save`; a launch offers back what a previous run left. `OndinApp::recovery_tick` has three gates: `is_dirty`, the interval (`SNAPSHOT_SECS` = 10, a constant because `autosave_secs = 0` means off), and the revision having moved. No `path.is_none()` gate (it covers never-filed canvases).
- `library::writer::Writer` is one long-lived thread with an `mpsc` queue (started on first job), serving both snapshot and autosave in FIFO order, so a removal cannot be overtaken by the write it cancels. Results drain once at the top of the frame (`disk_results`) before both ticks, and the drain reads the channel's hang-up (a dead worker must not leave `saving` set). `recovery.at` is written from the worker's answer only. It is awaited by `on_exit`, both closing arms of `close_confirmation`, `Drop for Writer` (backstop), `apply_library_settings` (since `relocate` carries `.recovery/`), and `OndinApp::save_file`. *Discard* also removes temps (`atomic::forget`).
- **`pending` drops a snapshot the document already contains (strictly newer, or byte-identical) and no I/O sentinel may decide that.** An unreadable mtime is an `Option` (`Pending::written`; the card drops its "from N hours ago" clause); two unreadable files are not "identical" (both reads must be `Ok`).
- Recovering does not write the user's file: the snapshot loads with the original path and `mark_unsaved`; the snapshot recovered from is kept until save or *Discard*.
- The tick runs only on the front tab's editor frames, so whatever ends or parks a session sees to its snapshot itself: `close_confirmation`'s closing arms, `go_to_dashboard` (only when clean, after committing a live text session), `park_active` (drops it when clean, else writes it now), `discard_tab`, and `adopt_opened` and `recover` when they reload the file already in front.
- **`recover` opens the snapshot in a tab of its own** (`tab_for_adopting`: the tab already holding its target file, else a new one), parking the document in front with its snapshot; only a parked state of the same file is replaced, and its snapshot forgotten. A second *Recover* of a queue opens a second tab and keeps the first's work and snapshot (`a_second_recover_keeps_the_first`).
- **The unsaved-close card** is raised by cancelling the window close, re-armed on every request (a second ✕ must emit `CancelClose` again). `chrome::above_modal` makes the app's own ✕ clickable over the backdrop. The recovery card gives three answers behind two buttons: *Recover*, *Discard*, and `Later` for ✕, Escape and the backdrop. Only *Discard* deletes.

### Building the screen

- Built from `ui.rs`, not egui defaults (§9.4): a two-way switch is `ui::segmented`, a labelled action `ui::action_button` sized by `ui::action_button_w` to its longest word, a boolean `ui::switch_row`, free text `ui::text_field`. The body header's controls share `HEADER_CONTROL_H` = 28 (`settings::FIELD_H`). *Delete project* is a 32-wide icon button; hover is repainted in `theme::color::danger()` between face and glyph, rounded to `ui::BUTTON_R`; its words live only in a tooltip.
- **Project filter** (*All projects*): button plus `Area` (a `ComboBox` cannot hold a colour chip), using `ui::button_face`. `OndinApp::filter_applies` gates both the control and the `retain` in `visible_entries` (false on *Recent*, inside a project, or with no unarchived project). Archiving the filtered project clears the filter. The stale-id degrade runs above that early return. `sort_applies` is the same shape for the sort control; *Recent* keeps open order and offers no sort.
- Icons come from the icon font as a separate run (`icon::PLUS` in `theme::icon_font`), never a character in a prose font.
- `TextEdit::frame(Frame::NONE)` suppresses egui's focus ring and silently discards `TextEdit::margin`; supply the inset in the frame (`ui::text_field` gets it from `ui::field_row`; `OndinApp::rename_field` puts its own). The inline rename field asks for the caret once via a latch on `rename_entry`, lays out in a one-row-tall rect centred in the box, and is placed through `Ui::new_child`, never `Ui::put`. Ground and hairline are `ui::field_frame`'s.
- **A single click opens a document**; the outline is the keyboard's cursor (`OndinApp::pick_or_open`; no card reads a double-click). **A right-click on a card or list row opens its ⋮ file menu at the press** (`DashboardState::menu_at`; `anchored_menu` reads a zero-size anchor as a point and places it with `ui::menu_place`, top-left at the press, flipped off the screen's edges). `pick_or_open` reads it above the `menu_was_up` gate, so a second right-click moves the menu to its own card (`context-menus.md` §0 R4). A click on the ⋮ of a menu opened that way moves it under the dots rather than closing it. `DashboardState::selected` is written only by `OndinApp::dashboard_keys`. Cursored card: full `color::accent()` border (hover: `accent_700()`); cursored row: `accent_900()` wash. The body background is `ui.interact`ed before the cards (egui's hit test takes the last widget). `dashboard_body` clears a cursor matching no visible entry.
- **A click that dismisses one of the library's floating menus is spent doing so** (`context-menus.md` §0's R4). The ⋮ popup and the project dropdown dismiss on `any_click()` without consuming it, so the gate is on the act: `&& !self.dash.menu_was_up`, latched at the top of `dashboard_ui` (the live flag is false for cards drawn after the anchor); it counts the tab menu too, whose click-away is spent the same way. `OndinApp::library_menu_open` documents the list of doors (`pick_or_open`, `nav_row`, `project_row` (both hits), `new_file_card`, the sidebar *New file* button, *Recent*'s project cards, the body header's controls, the tab strip, the top bar's update chip); a new door must join by hand. The strip takes the latch as `tab_strip`'s `spent`, which stands down only its left-button doors, so a right-click on a tab still replaces an open ⋮ menu.
- **A document whose file is gone** (an `Act::Open` on a path that no longer exists and has no tab) raises *File not found* (`DashboardState::missing`, `missing_modal`), which however it closes reads the library again (`library.refresh()`), dropping the card.
- **Open is read off the frame** (`OndinApp::begin_open`, every other `Act::Open`): a document already in a tab has that tab brought forward; otherwise a tab is added at the end and shown at once, pulsing (`ui::pulse_alpha`, half-and-back, 1 s) while an `ondin-open` thread reads and loads. `poll_open` (above the dashboard return) lands the answer: adopted through `adopt_opened` if its tab is still in front, else dropped (the tab stays a path, read again when shown, so a slow file never pulls the window away). A failed read of a tab made for it removes the tab and reports on the library; of an existing tab, leaves it saying why. `dashboard_act` gives up a pending open before every act but `Act::Open`, as does `file_menu_chose` for the ⋯ rows that open a card (*Stop sharing as kit*, *Delete*, *Move to project*), or a trash, rename or move would see it adopted at its old path.
- **A state chip** (`dashboard::StateChip`, chosen by `OndinApp::state_chip`, drawn by `dashboard::open_chip`): a document that has a tab wears an accent *Open* (`icon::BROWSERS`), and a click brings that tab forward; else one imported on this machine and not opened since wears a green *New* (`icon::SPARKLE`). *Open* outranks *New*. *New* is per machine: `LocalIndex::imported` (doc ids, swept by `retain_known`) gains every copy `poll_import` writes, and `mark_opened` takes the id out. On a card the chip hangs at the cover's top left, and nothing else marks the card; on a list row it follows the name, after any mark, its width taken out of the *Name* column before eliding.
- **Library keys** (`OndinApp::dashboard_keys`, top of `dashboard_body`, reads `egui::Context` directly): arrows move the selection, `Enter` opens, `Delete`/`Backspace` opens the confirmation, `Escape` clears. Guard list: `OndinApp::library_keys_are_free` (the two confirmations, ⋮ menu, *Move to project*, *New project*, *Import files*, *File not found*, Settings, rename, search overlay, recovery card, the tab menu) plus `egui_wants_keyboard_input` and `modifiers.is_none()` asked separately by each caller (`search_field` reads its chord before drawing its field). Modifier discipline: `command` without Alt and Shift (`Ctrl+K`/`Ctrl+P` open search; `Ctrl+Alt+N`, `Ctrl+Shift+D` etc. stay unbound). The recovery card is drawn above the view branch and is the only modal a launch can put here; a new modal must be added by hand to both hand-maintained lists (the keyboard list and the editor's `modal_is_up`). The two floating menus are closed by `Escape` above the guard list, and take `context-menus.md` §8's other keys there (`read_nav` into `DashboardState::menu_keys`, which `anchored_menu` spends as it draws; each door that opens a menu clears it); the early return asks `library_menu_open()`. The tab menu's `Escape` is consumed in `dashboard_ui` before the strip, so `dashboard_keys` does not also clear the cursor. Arithmetic is the free fn `arrow_target` (reading order, clamps). `↑`/`↓` step a row using `DashboardState::grid_cols` as last laid (`file_grid` writes it; 0 reads as 1). `OndinApp::can_open` is one predicate for keyboard and click (a trashed document cannot open). `DashboardState::scroll_to_selected` / `follow_selection` scroll only when the keyboard moved the cursor.
- **Search dropdown:** arrows and `Enter` act on any row (recent query refills; project navigates; document opens). Arrows are `consume_key`'d above the `TextEdit`; `Escape` is `consume_key`'d too (that branch returns before the field is drawn, so otherwise `dashboard_keys` would also clear the cursor). `DashboardState::search_row` distinguishes `None` (default: first document match, recomputed) from `Some(0)`. File matches are most recently edited first, ties by name (`Library::sort_entries` with `Sort::Edited`, applied before the `SEARCH_MAX` cap).
- **Modal focus ring:** `ui::focus_ring` paints only after `Tab` moved focus (`:focus-visible`); every hand-rolled control is focusable by `Sense::click()`.
- An empty list names what is missing and nothing else (no base-folder path).
- **The grid fits columns to the window; no card wider than 300** (`dashboard::grid_cols`, `card_width`, `CARD_MAX_W`, `GRID_GAP`; fewest columns keeping cards at or below the max; *Recent*'s project row uses the same two functions). Never a fixed four columns.
- A project's grid ends in a dashed *New file in {project}* card (list: a *New file* row), gated on the project resolving (not on `Nav::Project`); `OndinApp::file_grid` counts slots, not chunks; an empty project shows the card instead of `empty_state`.
- **Sync conflict copies are marked** (`library::scan::conflict_marker`): *stated* patterns (Dropbox, Nextcloud, dated Syncthing) stand alone; *suspected* (`<base> (N)`, `<base> - Copy`) count only when the original sits in the same directory (`Library::conflict`). Every pattern is one `naming::slug` cannot emit. OneDrive's machine-name shape is a stated non-goal. Drawn as an amber `CONFLICT` pill (`color::warn()`).
- **Unreadable documents** wear the same chip in red: `dashboard::Mark` is `Unreadable | Conflict`, `OndinApp::mark_of` returns one, most severe first. Two sources: `scan::Entry::unread` (cheap, set via `MetaProbe::Inconclusive`, misses files whose first 4 KB parse) and `Covers::unreadable` (`io::load` over the whole file, from the cover worker, so only for cards that have been on screen).
- **A file dropped on the library opens *Import files* with it in the field** (`OndinApp::take_dropped_documents` → `fill_import`, below). It runs early in `dashboard_ui` when `library_keys_are_free` (deliberately not `modal_is_up`) or when the import card itself is up, since a drop on the card refills its field. Only dropped files with a `path` count; a bytes-only drop (from a browser) is refused on the status line. `OndinApp::library_drop_hint` draws a square `color::SELECT` outline and *Drop to import* on the rect `CentralPanel::show` returns (not `ui.max_rect()`).
- **Mosaic:** a project card on *Recent* shows up to `MOSAIC_MAX` covers newest first (newest takes a full-height column, the rest fill two at a time, a lone column runs full height); arithmetic in the free `mosaic_cells`. A project card shows only for a project with files. `Duplicate` stamps its copy as opened.

### Import files (`import_files.rs`)

The one door for bringing documents into the library: the sidebar's *Import files* (`OndinApp::open_import_card`) opens the card empty, a drop on the window opens it filled, and both reach the field through `fill_import`. Nothing is filed until *Import*.

- **The field, *Ondin, Sketch, Penpot file, or Figma link*.** It takes Ondin documents, Sketch's `.sketch` (which Lunacy saves too), Penpot's `.penpot` and a `figma.com` link. Filled by a drop, by *Browse…* (the native dialog: an *Ondin, Sketch and Penpot files* filter and *All files*), by a typed or pasted path once it names a file (`typed_path`, quotes trimmed as Explorer's *Copy as path* adds them), or by a typed or pasted link once `figma_in::file_key` finds its key (below). A file is known by its extension (`Kind::of`; `Kind::imports` is the one list of what the card takes), and the filled field wears its badge (ONDIN, SKETCH, PENPOT, LINK). A `.fig` (`Kind::Fig`) gets the notice *Figma files come in by link* with *Paste link*, which puts the clipboard's link in the field or says the clipboard holds none (`non-goals.md`). A PDF, SVG or picture is refused with a pointer to *Place image*, since those are placed on a canvas — Affinity and Illustrator work arrives that way, as SVG or PDF; any other file is refused as a kind Ondin does not import, naming the kinds and links it does; a document already in the library is refused, compared canonically so another spelling of the path is caught (`in_library`): one in `.trash` is told to be restored, one in `.versions` to be restored from history, any other to be duplicated there. Several `.ondin` together become one entry, "N documents". Another tool's file is only read, never written back, and comes in alone: a drop holding any `.ondin` takes those, else the first other tool's file; whatever is left out is named in a note under the field (`fill_import`). A drop while the copy runs is ignored.
- **A document dropped on a canvas is refused** with a pointer to *Import files* (`import::read_one`, by `Kind::is_document`: what the card imports, and `.fig`): another tool's file becomes a new library document, never layers in the open one.
- **One file is read on a worker for its options** (`read_source`: `io::load`, or `read_foreign` for another tool's file, then `take::census`). Options: Name (its own — for Penpot the file's name inside the export, for Figma the file's — else its de-slugged filename) and Project; Pages, a tick per page with its frame count; *Bring over* Components, Styles and Variables, each with a sentence on what turning it off does; Pictures, *Leave out its pictures* (image fills stay, drawn as missing). Another tool's file is offered the same options in its tool's words (`Kind::words`): for Sketch, pages counted in artboards, *Symbols as components*, *Shared styles*, *Colour variables* (off: each use keeps its colour as a raw value); for Penpot, pages counted in boards, *Components*, *Typographies* (as text styles; off: each text keeps its own type), *Colours* (as colour variables; off: each use keeps its colour); for Figma, *Components and variants*, *Styles*, *Variables* (Figma's API gives them to Enterprise plans only; the values they show come in). Several documents offer Project and Pictures only. For one file, a Components, Styles, Variables or Pictures row whose census count is zero is dimmed and takes no click (`check_row`'s `enabled`). *Import* needs a name and at least one page. The footer (`foot_text`) says nothing before a file is chosen, since the field already asks for one; while a file is read or a link fetched it carries a small spinner beside what is happening, the form's only one.
- **Another tool's file is unzipped on the worker** by one `Zip` (all entries together capped at 2 GiB inflated, `ZIP_LIMIT`; an entry that would pass it is not read at all) and read by `ondin_core::sketch_in::read` or `penpot_in::read`, both through `read_foreign`; its pictures are hashed and sized through `app::read_picture`, as a placed one is. A `.penpot` that is not a zip is Penpot's older binary export (`penpot_in::is_old_format`), which Penpot wrote until its zip export replaced it and which many published templates still are: one that opens as binfile v1 (`penpot_v1::is_binfile`: a mark, Penpot's magic number, version 1) has its zstd stream inflated by `ruzstd` within the same 2 GiB (`penpot_one`), and `penpot_v1::unpack` decodes its sections (Fressian-encoded Clojure data, the pictures as raw streams) into the entries the zip export would hold, keyword keys camelCased and keywords and ids as strings, so `penpot_in::read` reads it unchanged. Any other is refused (`PenpotError::OldFormat`: open it in Penpot and export it again). The font families its text names that `FontService::family_status` calls missing join the report when the read lands ("Not installed: drawn in Inter until it is"), on the frame because the font list is the frame's.
- **What the readers share is `ondin_core::foreign`**, so core holds no zip reader: the `Archive` trait (`entry`, and `names` listing every entry, empty unless the archive can say), the report row `Unmapped` with its `Part` (Layers, Components, Pictures), `Tally` (counts by kind; `into_report` gives one row per kind, the noun singular at one), `sniff` (a picture's format by its first bytes), `solid` and small JSON readers, and `Names<K>`: other tools let two styles or colours share a name, which a document refuses, so each reader gives its style and colour-variable names out through `Names::unique`, per kind, numbering a repeat apart ("Shadow", "Shadow 2"; an empty name reads "Style" or "Colour") and reporting "Names used twice · Numbered apart". Sketch keys styles by slot and swatches apart, Penpot text styles and colours, Figma styles by slot. `sketch_in` re-exports `Archive`, `Part` and `Unmapped`.
- **`sketch_in` builds in two passes, each through `Document::apply` with `propagate::owed`**, so the result passes every rule a loaded document does. The first writes pages, layers, shared styles and swatches, an empty group standing in for each symbol instance; the second replaces each with a copy of its master's captured subtree (`build::insert_subtrees`), masters holding no placeholder first so a nested symbol is whole before its holder is copied. It goes in rounds, each placing every instance whose master is ready in three transactions (copies, their styles, their overrides), since every commit costs in proportion to the whole document and one per instance took a symbol-heavy kit minutes. It writes text overrides (`<id>[/<id>]_stringValue`) onto the copy found by link chain.
  - Layers: artboard and symbol master → clipping frame, a master also a main component (an artboard without a background is filled white, as Sketch draws it; a master is filled only when its background shows in its instances, `includeBackgroundColorInInstance`, since main and copies look alike); a master's direct children take its resizing constraints as insets (`insets_of`: a pinned edge a px inset, a free size between free edges percentages, a pinned size between free edges centred by auto margins), an instance child's carried to its copy, so a resized instance stretches its layers as Sketch does, except inside groups, which take no insets; a mask with a fill or border turned on gets an unmasking copy just above it carrying that paint, since Sketch draws a mask's paint under what it clips and an Ondin mask paints nothing; group → group; shape group → its one shape carrying the group's style, a boolean of several (the op from the second child), or — when it holds other layers — a group whose layers keep their order, each shape wearing the group's paints; a rectangle whose points are its corners → rect with per-corner radii, oval → ellipse, any other shape → path with per-anchor radii (older files keep the points in a nested `path`, which `shape_kind` reads); text → text node (later runs as spans; a PostScript font name split by `font_face`; text in Sketch's older archived format, `archivedAttributedString`, is not decoded and comes in empty); bitmap → rect with an image fill; slice → slice. Fills, borders, shadows, inner shadows, gaussian blur, opacity, blend, winding and masks map.
  - Text Sketch archived before version 48 (`archivedAttributedString`, and the archived values in a text style's `encodedAttributes`, a layer's or a shared one's) is a base64 binary plist written by `NSKeyedArchiver`. `keyed_archive` reads it into the JSON later Sketch writes (the string, runs from `NSAttributeInfo`'s base-128 lengths and indices, font name and size, colour from `NSComponents` or `NSRGB`, kerning, alignment, line heights), so the text reader is one.
  - A layer left out (a hotspot, an unknown class) takes no index: `layer` answers whether it made a node, and `children` and the mixed shape-group loop count only those, so the next sibling's index never points past its parent's children.
  - Export presets → export settings (`Builder::exports`, from `create` and for each placed instance): png, jpg, webp, svg and pdf; the scale, or a width or height (`visibleScaleType` 1 or 2 with `absoluteSize`); Sketch's name as the suffix, or the prefix when `namingScheme` is 1, left empty when it equals the scale's own marker (`@2x`), which Ondin adds itself.
  - Swatches → colour variables in one mode, *Default*, and a fill naming a swatch is bound to it. A shared layer style → up to three styles (fills, strokes, effects) under its name; a shared text style → a text style. A layer is bound only when its values equal the style's, so one out of step stays as drawn. Library symbols land as local components on an added page, *Library symbols*; library styles are read as local.
  - What does not map is counted in `Read::report`, one row per kind, worded as `svg_in` reports: prototype links, export formats Ondin lacks, older-format texts whose archive does not read, smart layout, background blur, motion and zoom blur, mixed boolean ops, mask chains broken early, resized and masking instances, overrides other than text, missing, unplaceable or self-containing symbols, shape groups holding other layers, unreadable pictures, pages missing from the file, unknown layers. Each row names the part it is about (`foreign::Part`), and the card drops a row about components or pictures the import leaves out.
- **`penpot_in` reads Penpot 2's export** (its third format: a zip of JSON under a `manifest.json`). Of the manifest's files the one that is no other's library is read, its libraries' pages added after its own as "<library> · <page>" (reported as *Library pages*) so their mains are in the document; any other file is left out and reported. Pages come from `files/<file>/pages/*.json` in `index` order, shapes one JSON each, the page root `000…0` listing the top shapes. It builds in two passes, each through `Document::apply` with `propagate::owed`: pages, layers, colours and typographies first, then components and links.
  - Placement: every Penpot shape is in page space. A box shape sits at (x, y) turned by `transform` about its centre; a group, a boolean and a path sit at their selrect corner, a path's outline moved from page space into its own. Each node's transform divides out its parent's world placement.
  - A layer left out (an SVG layer, an unreadable path, a shape missing from the export) leaves no gap: its later siblings take the next index.
  - Layers: board → frame (clipping unless *showContent*); rect → rect (r1–r4); circle → ellipse; image → rect with an image fill (media id → `files/<f>/media/<id>.json` → `objects/<mediaId>.<ext>`); text → text node (paragraphs joined by line breaks, the first leaf the default, later leaves spans; camelCase or kebab-case keys; `sourcesanspro` read as Source Sans Pro; growType → sizing); group → group (a masked group's first shape its mask); bool → boolean; path → path (SVG data or a command list). Fills (colour, gradient, picture) and strokes (alignment, caps; dashed, dotted and mixed in Penpot's own pattern, which grows with the width), each list reversed since Penpot lists the topmost first; shadows, inner shadows, layer blur, opacity, blend and even-odd map.
  - Library colours → colour variables in one mode, *Default*, a fill naming one bound to it; typographies → text styles, a text bound when its first leaf names a typography it still matches.
  - Components: a main instance becomes a main component; an instance whose every shape's `shapeRef` resolves is linked node by node in one transaction, keeping its overrides. A link transaction the commit refuses falls back to the mains alone, the instances kept plain and reported.
  - Reported: svg-raw layers, arrow caps, background blur, gradient and picture library colours, mains inside other mains (kept plain), instances whose main is missing (kept plain), prototype interactions, export settings, flex and grid layout (kept at drawn positions), unreadable paths and pictures, unknown layers.
- **A Figma link is fetched, never a file** (`non-goals.md`). The link becomes `Field::Link` with the token row under it: *Personal access token* (a password field with show/hide), *Fetch*, a caption saying where the token is made, that it needs read access to file content and is sent to Figma only, and *Remember the token on this computer*. `Enter` on a link fetches. *Fetch* (`start_fetch`) runs `fetch_figma` on a worker: one `ureq` agent with timeouts; the file (`/v1/files/:key?geometry=paths`), then the `/images` addresses, then each picture without the token, since the picture storage wants none; 2 GiB in all (`FIGMA_LIMIT`); 403, 404 and 429 worded apart. `read_figma` reads it through `figma_in::read` into one document (`Kind::Figma`) named after the file, the message line "<name> · N pages · fetched just now". A test build's `fetch_figma` refuses at once, so no test reaches the network.
- **The token is kept only when asked** (`keychain.rs`), in the system's secret store: Windows Credential Manager through windows-sys, macOS `security -i`, Linux `secret-tool`, each given the secret on standard input so it never shows in a process listing. A fetch that worked stores it when *Remember* is ticked and forgets a remembered one that was unticked. The card reads a remembered token on a worker when it opens, since the store can block; a remembered token fills the row and a pasted link then fetches at once. Under `cfg(test)` the module keeps nothing, so no test touches the developer's keychain; an ignored test round-trips a separate account by hand.
- **`figma_in` reads what was fetched** through `foreign::Archive`: `file.json` and `images/<ref>`. `file_key` finds the key in `figma.com/design|file|proto|board/<key>/…`, a branch link giving the branch's key. It builds in two passes, each through `Document::apply` with `propagate::owed`: pages, layers and styles, then mains and links.
  - Placement: `relativeTransform` places a node in its parent, a group or a boolean included — the REST API's convention, not the Plugin API's, which places a group's children in the frame holding it. Each node's world is its parent's times its own; without a `relativeTransform`, its bounding box's corner, already on the page.
  - Layers: canvas → page (`backgroundColor` its ground); frame, component, component set, instance and section → frame (clipping from `clipsContent`, never for a section; radii, smoothing); group → group; boolean → boolean; rectangle → rect; ellipse → ellipse with its arc; line → line; vector, star and polygon → path from `fillGeometry`; one with nothing to fill (open, or without fills) → path from its `vectorNetwork`'s segments chained into runs, unfilled, so its stroke stays a stroke, or without a network its `strokeGeometry` drawn as the outlined stroke filled with the stroke paints; text → text node (its style the default, `characterStyleOverrides` runs as spans at byte offsets through `foreign::utf16_to_bytes`, shared with `sketch_in`; `textAutoResize` → sizing; line height in px or %); slice → slice. Solid paints, linear, radial and angular gradients (handles mapped onto the box), image fills (fill, fit, tile), strokes (weight, align, cap, join, miter angle, dashes), drop and inner shadows, layer blur, opacity, blend, masks, visibility, lock and export settings (`exportSettings`: PNG, JPG, SVG, PDF at a scale, width or height; a suffix that is only the scale's marker left to Ondin) map.
  - Styles: each style a node names (`styles.fill|stroke|effect|text`) is made from its first user under the file's style name; a later user is bound only while it shows the same values.
  - Components: a component becomes a main. An instance's nodes have ids `I<instance>;<source>`, the source (prefixed `I` again for a copy inside a nested instance) being Ondin's link. Every instance whose copies all find their source is linked in one transaction; a link transaction the commit refuses falls back to the mains alone, the instances kept plain and reported.
  - Variables cannot be read without Figma's Enterprise plan: bound values keep the values they show, reported.
  - Reported: open paths, variant sets (each variant its own component), diamond gradients (read as radial), arrow caps, per-side stroke weights, background blur and other effects Ondin lacks, frames used as masks (left unmasked), instances of components not in the file and instances whose layers are not their component's (both kept plain; a nested instance's root is linked as its outer instance's copy, never straight to its main), prototype interactions, export settings, auto layout (kept at drawn positions), video and emoji fills, pictures that could not be fetched, unknown layers.
- **Project** defaults to the one being viewed (`nav_project`, through `Projects::destination`, so an archived project's page files as no project); the dropdown lists *No project* and the active projects. `start_copy` asks `destination` again, so a project archived while the card is up files as no project.
- **The copy runs on a worker** (`import_one`, `import_many`): trimmed by `take::take` to the choices, then filed through `store::file_document` as a new identity (the meta id cleared so `file_document` mints one; the creation date kept; the name the card's). The card shows progress and *Cancel* in place of the options. Cancel sets a flag the worker checks before it writes, and the job moves to `DashboardState::import_abandoned`; whatever it wrote anyway is removed when it answers (`poll_import`). Closing the card cancels the same way. In a batch a file that cannot be read is reported and the rest go on.
- **The trim** (`ondin_core::take::take(&mut Document, &Keep)`) goes through `Document::apply` and `propagate::owed` with the editor's own builders, so a trimmed document passes every rule a loaded one does and what is left out leaves the layers drawn as they were. An unkept page goes as *Delete page* does (its guides and layers, `relink_for_delete`, `RemovePage`). Components off cuts every link, swap, main, set, variant and property in one transaction and empties and closes the kit vault; variables off removes every variable (`variable::remove_ops`) and mode (`remove_mode_ops`) and clears the kit modes; styles off is `style::remove_ops`; pictures off empties the picture table. A picture no layer or style shows any more is always dropped. At least one page must be kept (`TakeError::NoPages`). `take::census` counts what the options and the overview show (the vault's components excluded; pictures only those something shows, `images_shown`, since every copy drops the rest — an orphaned picture table is not offered as pictures to leave out).
- **The overview** (*Imported*): "<name> is in <project | the library>" (or "N documents are in…"), for another tool's file the subtitle "From <file>, which is unchanged" ("Read from Figma, which is unchanged" for a fetched one), six counts (pages, frames in the tool's word, components, styles, variables, pictures), a report of what did not come in as it was ("Nothing to report" when empty; a batch's unreadable files are listed) in a borderless box on the count cards' ground (`text_a(15)`, radius 8) with hairlines between rows, the rows scrolling with hidden bars past `REPORT_MAX_H` = 240 so a big document's overview stays short, *Copy report* (a `ui::icon_button`), *Done*, and *Open document* for a single document. *Done* (`done_import`) shows where the copies went: the chosen project's page (asked through `Projects::destination`) or *All files*, the single copy selected; ✕ and `Escape` only close. `Enter` imports on the form and opens on the overview.

### Modals

`crate::settings` owns the one form-in-a-modal card: `card_modal` (ground, hairline, corner, shadow, `PAD`, backdrop), `modal_title` (✕), `modal_footer`, `section`, `caption`, and the measurements. These modals use it: the editor's Settings, the dashboard's New project, Edit project, Delete project, Move to project, Delete file, *Import files*, *File not found* and library Settings, plus *Recover unsaved work?*, *Unsaved changes* and *Delete value*. In the editor every card centres on the canvas, as the command palette does (`settings::set_card_centre`, written each frame by `OndinApp::ui`), so a card opened from the palette does not jump sideways; on the library screen it centres on the window. All dismiss through `egui::Modal::should_close()` (Escape and backdrop mean the same everywhere). What a dismissal means is each card's own: on *Recover* it is `Later`; on *Unsaved changes* it is Cancel (never a destructive arm); *Discard* is a `FieldButton::Danger`. *New project* and *Edit project* hand-roll their footers and *Delete value* has its own Cancel/Delete; `modal_footer` carries the "lit only when the draft differs" rule. `ui::focus_ring` has exactly two production sites (its definition and `settings::card`), so any modal outside the vocabulary has no ring.

## Traps

- The library's early return in `OndinApp::ui` is the boundary; anything that must run on both screens (close handling, recovery modal, `chrome_focus`) belongs above it.
- A cover answer can arrive after the grid is left; `Covers::pass` runs first each frame and its position matters to the eviction recency guard.
- Two hand-maintained modal lists (library keys, editor `modal_is_up`) and seven hand-copied `menu_was_up` call sites: a new modal or door must be added to each by hand.
- An empty scan is indistinguishable from a missing drive; never run a membership sweep on an empty list.
- `Moved` must be kept as pairs; do not re-derive destinations.
- `recover` and `adopt_opened` call `drop_recovery` after `tab_for_adopting`, never before: before the park it deletes the snapshot of the document being moved aside, which is all an unfiled one has (`recovering_parks_the_document_in_front_with_its_snapshot`).
- Revisions come from one process-wide counter (`session::next_revision`): a per-session count lets a revision-keyed cache (`FrameIndex`, the drift cache, the export preview) answer for another tab's document (`no_two_sessions_share_a_revision`).
- `park_active` settles the writer before the swap, so every result lands on the session it is about.
- `close_tabs` does not check pins: every door that must spare a pinned tab (middle-click, `Ctrl+W`, *Close others*, *Close all*) leaves it out of the ids itself, so a new door must too (`closing_in_bulk_spares_pinned_tabs`).
- `read_dir` order differs per platform; sort anything user-visible (search matches).
- An import cancel has two halves that each look removable: the flag stops a worker that has not written yet, and `poll_import` removes what an `import_abandoned` job wrote before it saw the flag (`a_copy_cancelled_after_it_was_written_leaves_nothing_behind`).
- `take`'s components pass is one transaction on purpose: the rules are checked after its last op, so a main unmade before its instances are cut would leave them dangling.
- `foreign::Part::of` decides a report row's part from its words (*picture…* → Pictures; *symbol*, *component*, *instance* → Components; else Layers): rewording a row moves it to another part, and the card then keeps or drops it on the wrong option. No test pins it.
