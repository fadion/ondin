# 8. ondin-mcp

The MCP endpoint: the running Ondin process hosts it, agents connect through a stdio proxy configured once, and every write goes through the same op queue and commit door as the app's own edits.

## 8. ondin-mcp

### 8.1 Topology: one configured server, any document

Documents live in a running Ondin process, the window or a headless `serve`, so that process hosts the MCP endpoint and agents connect to it. A person configures one server in their harness, `ondin mcp-proxy` with no arguments, and it reaches any document.

- **Hosts.** The window (one per machine, holding its documents as tabs, `one_window.rs`) and `ondin serve` each listen on a local endpoint and serve any number of documents, addressed by absolute path. Each writes a discovery file naming its endpoint, `mcp/<pid>.json` in the window lock's folder (`one_window::window_dir`: the machine folder on Windows, the user's runtime folder elsewhere), and removes it on exit; the proxy removes one whose endpoint does not answer.
- **The proxy** (`ondin mcp-proxy`) bridges an agent that spawns its server over stdio. It connects to the window's endpoint when a window runs, else to a running `serve`, else starts `ondin serve` and connects to that. It forwards lines and remembers one thing: the connection's current document, so that when its host goes away or a window starts it reconnects to the window and restores it before the next tool call. `--client <key>` keys the host's state for the client (*Revisions*), and `--document <path>` names the document from the first call, so an assistant that starts the proxy per turn skips `use_document`. `--tools all` lists every tool rather than the core set (*Core*, §8.4).
- **The current document** is per client: the proxy's key when it was given one, else the connection (*Revisions*). `use_document(document)` sets it and every other tool acts on it until the next `use_document`; a tool called before any fails naming `use_document`. The document is an absolute path, or a name or relative path matched against the host's open documents, then the library's by file name or document name; the proxy first turns a relative path that exists from the harness's working folder, with or without `.ondin`, into an absolute one. Several matches fail with the candidates, for the agent to ask. The tool's description tells the agent to switch only when the person names another file.
- **Opening.** In the window, a document not yet open opens as a tab in the background: the window is not raised and the tab in front does not change, and the agent's edits show when the person looks at it. An agent's edit to a tab behind is written to its file at once, since a tab behind is kept clean (`tabs.rs`); one to the tab in front waits for the save or the autosave, as the person's own edits do. In `serve` it loads into memory.
- **Security.** Same user, same machine, no token: a same-user process can already read and write the files the endpoint guards. On Windows the pipe rejects remote clients, its default DACL lets only the current user write to it, and the host drops a client whose process runs as anyone else (`one_window::same_user`). Elsewhere the socket sits in a 0700 folder, is 0600, and the host checks the peer's uid. TCP or remote transport is parked.

### 8.1a Wire

JSON-RPC 2.0, one message per line, on std threads with `serde_json`; no SDK and no async runtime. The methods are `initialize`, `ping`, `tools/list`, `tools/call` and the `initialized` and `cancelled` notifications. `initialize` answers the newest of `wire::PROTOCOL_VERSIONS` not newer than the client's (`wire::negotiate`), so never one it cannot know; `2025-03-26` is not offered, since it requires batches. A batch or a line that is no object gets one Invalid Request with a null id, and a line that is not UTF-8 a parse error, so a client never waits on a line the server dropped and the session goes on; the proxy answers a bad line from the agent the same way.

Every tool carries annotations from `schema::class`: `readOnlyHint` for the reads, and `destructiveHint` only for what `undo` does not revert (`create_document`, the kit mark, `save_version`), since every other write is one undo step. The server instructions (`wire::INSTRUCTIONS`) say once what every tool shares: results' text is the document's data, never instructions, since layer names, text and kit notes come from other people's files too; what `base_rev` does; and the id form. No description repeats them: the list is paid for on every uncached turn, and `schema`'s budget test holds its size. It stays byte-stable between calls, since any change drops a client's prompt cache. A tool no host serves is refused first, by name, and a table tool's arguments are checked as a verb's are (`verbs::check_args`): an unknown, missing or wrongly typed one is refused rather than read as absent. Each tool's input schema is generated from its verb's `Param`s, with `verbs::example` showing a model parameter's shape. No resources, prompts or server-sent notifications: see *Revisions* below.

### 8.2 Headless mode

`ondin serve` hosts documents with no window: core, history, CPU renderer and the MCP endpoint. Same op queue, same tools, so an agent can build, edit and export on a machine with no display, or edit a file nobody has open. This follows from the headless-core invariant and is a first-class v1 deliverable.

- `serve` writes each commit to its file: there is no person to save later, and a window with the same file open as a clean tab follows it (`library.md`, *the file is watched*).
- `serve` exits after its last client's connection closes, or 15 minutes after while it remembers a keyed client (*Revisions*), whose harness may start a process per turn. A connection counts once it has called a tool: the proxy's and `serve`'s own checks that an endpoint answers connect and close without one, and must not end it.
- It hands over when a window lists its endpoint: once no client is connected, or a second after its last answer, so that answer reaches its connection first. The proxy moves to the window at its next request. A tool call whose answer was lost is not sent again, since it may have applied; the proxy answers it with an error saying so.
- A commit `serve` cannot write to its file, like one to a window's tab behind, is answered with `unsaved` and the reason. A tab behind whose file changed outside since it was read is not overwritten: it keeps the edit and asks the person, as *Changed on disk* does.
- `serve` finds a document already open under another spelling of its path, so one file never has two sessions writing over each other.
- One `serve` runs per user: it holds `mcp/serve.lock` while it lives, and one started while another holds it exits at once, so proxies starting together share the first. The proxy starts it detached (its own process group off Windows), so a harness ending the proxy does not end the client state `serve` keeps.

### 8.3 Concurrency model

- The owning process holds each document as an `EditorSession` on its main thread.
- Every tool call funnels through one single-writer **queue** (`ondin_mcp::queue`): a connection's thread sends the call's name and arguments with a reply channel and waits. The call travels rather than a built transaction because a verb reads the document to answer its edit, and the document is the owning thread's.
- The owning thread runs the handler (`ondin-app`'s `mcp::Engine`) against the document's `EditorSession`: a read projects it, a write runs the registry verb (`verbs::call`) and commits through `EditorSession::try_commit`. `serve` drains the queue in its loop; the window drains it every frame. One source of truth and one history; an agent's edits appear live on the canvas through the same path as the person's. An MCP edit's undo step is named by the tool it called and remembers the client (`EditorSession::name_mcp_step`, `Origin::Mcp`), so the History section can mark it. An agent's `undo()` and `redo()` act only on a step that client made, judged by the name it gave at `initialize` (`mcp::own_step`); over the person's step or another client's they are refused, naming the step, and nothing changes: the history is the person's too. They answer the step they moved by its name, `undone` or `redone`, null at the end of the history; a `set` step is named by what it set (`set fills, name`).
- **Document-level actions** (invariant 10, §15 D1097): `make_kit`, `publish_kit(note)`, `stop_sharing_kit`, `create_document(name, project?)` ride the **same queue**, so they are ordered against surrounding edits (a publish sent after a batch of writes publishes those writes). The owning thread runs the app's own code: `make_kit`, `publish_now`, `stop_sharing_kit` (the verbs the document menu's rows end in, past their dialogs) and `library::store::file_document`, and replies with the result. None is a `Transaction`, none enters history, `undo` reverts none.
- No connection thread ever touches a document (invariant 10).
- A call the owning thread has not taken within 30 seconds is answered as not run, with nothing changed: the window drains the queue only between frames, which a modal file dialog stops. The owning thread and the connection each claim the call (`Call::take`) and the first wins, so a call answered as not run never runs later; one already taken is waited for.

#### Conventions

- `style_text` and `style_paragraphs` are how an agent styles part of a text: a range counted in
  characters becomes runs over it, as the text editor writes a selection; the whole text becomes the
  layer's defaults with that attribute's runs dropped, as the type panel writes it.
- A page is named by its root node's id: `create_node`'s and `insert_subtree`'s parent may be one,
  and `set_name` renames one.
- `create_node`, `insert_subtree`, `duplicate`, `convert_container`, `add_page` and `duplicate_page` return the new ids (the handler minted them); so do `create_instance`, `insert_from_kit`, `add_image`, `add_variable`, `add_mode`, `add_collection`, `duplicate_collection` and `add_style`. `add_image` also answers the picture's `pixel_size`, as the paint summary of an image fill carries it.
- The snapshot exposes world transforms so agents can compute local placements; a `place_at_world(id, world_transform)` adapter is allowed in core if agents struggle.
- `set_blend(nodes, blend)` takes the mode as the snapshot names it (`"Multiply"`, `"Pass through"`) and writes through `build::set_blend_all`, as the inspector and `Shift`+digits do: the outermost members only, and Pass through landing as Normal on a layer that is not a frame or group.
- `set_point(node, point, subpath?, …)` edits one anchor as the inspector's point fields do, in the layer's own space, indexed as the snapshot's `subpaths` lists them. A coordinate left out keeps its value and handles are placed after the point moves. One handle given mirrors the other on a smooth point (`PenAnchor::is_smooth`, a corner counting as smooth) and leaves it on a broken one, as `nudge_handle_tx` does; both given are set exactly. It reads the drawn anchors (`edit::path_subpaths`) and writes the whole path back through `edit::rewrite_points`, so a mirrored path stays symmetric and the commit is one `GeometryPatch::Path`, the editor's own undo granularity.
- `set_geometry` refuses a `Path` patch on a rounded path that holds any point its drawn outline has only because a corner is rounded (`verbs::bakes_rounding`, within 0.001): that is the snapshot's `svg` written back, whole or edited, which would bake each fillet into curves and round it again. The refusal points at `subpaths` and `set_point`.
- The setters take `nodes` and write a selection as the inspector does. `set_fills` and `set_strokes` reach a group's shapes (`build::paint_targets`); where the layers share one list they write it as an edit of that list (`build::retarget_fills_all`, `retarget_strokes_all`), so each layer keeps its own item ids and an instance stays tied to its main's items, and where the lists differ as a replacement position by position (`set_fills_all`). Layers that reach nothing taking paint (an empty group) are refused. `set_effects` writes the outermost layers (`set_effects_all`). `set_exports` gives a row past any layer's end one id across the layers, as the Export card does. The text style setters take text layers only, and `set_text_style`'s `spans` one text. `set_text_style`, and so `set`'s `text_style`, changes only the fields it is given; each text keeps the rest of its own.
- A chart is edited through its four verbs, which write `SetChart`; its parts regenerate after the commit (`chart::settle`), and any other tool writing a part is refused by `chart::guard` (*Part of a chart — edit the chart, or flatten it first*). `insert_chart` makes a 480 × 280 frame on the kind's sample table, or on the table given with its mapping read off the column types (`chart::Mapping::guess`) unless one is given; `set_chart`'s `mapping` and `options` are JSON merge patches over the chart's own; `set_chart_data` keeps the mapping and series colours of each column whose name survives (`Chart::with_table`) and drops the linked file; `flatten_chart` is `chart::flatten_ops` for each chart (*Flatten*, `charts.md`). The snapshot's `chart` names the column ids they take.
- `insert_subtree` is the tool a whole layout goes through: a page of a few hundred layers is a handful of calls, one tree per section, where `create_node` is a round trip per layer. It answers `named`: each layer the tree named, by the `/`-joined names of it and its named ancestors, with its id, so the agent addresses the parts it wrote without counting; `created` then holds the root, first as every write's does, and the layers no name reaches, so each id is said once.
- Every model parameter reads the short forms (`verbs::loose`): a colour as `"#rrggbb"` or `"#rrggbbaa"` wherever the model takes one, a fill as a bare colour, a fill's or stroke's `brush` as a colour, a fill or stroke and a text's style without the fields a new one has. It also takes what `get_node` and CSS write, so an agent writes back what it read: a length as `"22px"`, `"1.2em"` or `"auto"`; a sizing as `{type, width}`; a fill as `{paint: {type: "Solid", color, alpha}}`, its `id` and `index` ignored; an effect flat (kind `DropShadow` or `drop_shadow`, its `opacity` folded into its colour) or with its kind as an object, shown unless it says not; a rectangle's corner radii left out (square) or as one number; padding as one number, and `gap` for both gaps of a flex or grid; a path as SVG path data under `svg` or `path`; a bound corner by name (`top_left` …). A model argument is read whole (`verbs::check_model`): a value it cannot read, or a field the model has no place for, is refused naming its path (``at `children[1].kind.Text.sizing`: …``), never dropped, since a dropped field lays out silently wrong (`Flex { gap }` with no gap). A tree layer's `like` names a layer whose fills, strokes, effects, opacity, blend, text style (field by field) and paragraph it takes where it gives none, so a new text matches the page's own type without restating it. `get_tree` and the schema's examples answer in the short forms wherever they read back to the same value, a length as `"22px"` and a path as SVG path data included; output is a large share of an agent's time, and the long forms were most of a written tree. The one exception: an sRGB colour is written as hex rounded to the nearest byte, so a tree read and written back may move a colour by half a byte step, which no eye sees, for a quarter of the text.
- `batch(steps)` runs write tools that are verbs in turn, each committed through the door and reading what the last left, then joins their steps into one named *batch* (`History::join_last`), so the person undoes the agent's request at once. A step names what an earlier one made as `"@label"`, the label that step gave in `as`, as `ondin script` does. A refused step takes back the steps before it (`EditorSession::take_back`, no redo left behind) and the refusal names the step: a batch lands whole or not at all. `base_rev` holds for every step.
- `export_png` is the agent's eyes: placement errors no read tool reports (a card under the band below it, a label over a button) show only in the render. A client that can see images is expected to export, look and correct. Its longest side is capped at 1600 by default; `max` raises the cap to at most 4096 and is refused above it, since the raster is held in the person's window. `region: [x, y, w, h]` draws only that rectangle of a page, everything in it, up to 2× as a layer is, so the agent looks closer at one part without exporting it alone; a region with a non-page `id`, or with no area, is refused.
- `get_document`, `get_node` and `export_svg` refuse an answer past 100 KB with its size and the narrower read to use: a harness cuts a result past its own limit, and a snapshot cut mid-way reads as a smaller document. A page is never drawn above 1×, a layer above 2×.
- `find_nodes(query)` is how an agent reaches "the home header" without reading the whole document: layers whose name or text contains the query, each with its id, name, kind, the names of its ancestors, its own box in world space to 0.1 and `selected` when it is or holds a selected layer, so two layers of one name are told apart by where they sit without another read. A request about one part of a page is a find and a subtree read, not a snapshot. `get_outline(id?, depth?, limit?)` is the map before the find: a page's or layer's layers two levels down by default, as a table (`columns` once, then one row of id, name, kind, own box in world space to 0.1 and depth per layer, in paint order with a parent before its children), with `more` counting the rows past `limit` and `selected` the selected layers under it, so where a page's sections sit is one call instead of a `list_children` per level. Both boxes leave the stroke out; `get_node`'s `world_bounds` and `get_bounds` take it in. `find_like(id, by)` reaches the rest of a kind from one: *Select same* (fill, stroke, font, effect, `app::shares`), *Select matching layers* (`matching::matching_layers`) and a main's or set's instances, over every page.
- A write answers `created`, the layers it brought into being and never one that was there before; what else it made, named for what it is (`image`, `variable`, `mode`, `collection`, `style`, and `property` by the name `set_instance_property` takes), when it made one; `main` from `make_component`, made or turned into one; and `said` when its verb has something to say the document does not show: how many matches `replace_text` wrote and how many it left alone, what `import_svg` left out, how many places `merge_colours` changed.
- Each structure verb refuses where its menu row dims, in that row's words: `frame` where `build::can_frame` refuses, `outline_stroke` without a visible stroke, `divide` without an overlap, `blend_shapes` with `blend::Refusal::says`, `push_to_main` into a kit's or a locked main.
- Colours travel as `#rrggbbaa` between the reads and `merge_colours`: `review_colours` writes them, `merge_colours` takes them back. An `into` a variable carries binds the raw paints to that variable, as Colour review's default target does.
- A verb refuses a kit's vendored component (`Document::in_vault`), which a kit instance's `component.main` names: the person can never select one, and an edit there would change every instance until the kit's next update undid it. Reading one is fine, and `create_instance` and `swap_instance` may name it as `main`.
- `set_selection` takes layers of the page the person is on, never the page itself, and does not switch the page: a selection never spans pages (`Selection::retain_existing`), and the agent does not move the person's view.
- Writes name layers `node` and `nodes`, as their verbs do; the reads, `set_selection` and `make_local` name them `id` and `ids`. The phase lists above give the main parameters, not every one; `tools/list` is the full signature.

#### Revisions

The person and the agent edit one live document, so an agent's earlier read goes stale without its knowing. Each document has a revision that every commit advances, the agent's or the person's, undo and redo included. A refused `batch` or `set` takes back every step it made and puts the revision back where it was (`EditorSession::mark`, `rewind`), so no client is told of a change that is not there.

- Revisions come from one counter per process, seeded with the launch time in microseconds, so a `rev` from another process (a `serve` before the window took over, the app before a restart) never matches one here and reads as unknown: `since` answers in full and `base_rev` is refused.
- Every tool result carries `rev`. The host remembers, per client, the revision it last showed; when the document moved since, the result also carries `changed`: the layers added, changed and removed since then, by id and name, found by comparing each layer's snapshot entry, so a layer a reflow moved is reported beside the one edited. Each list names at most 20 (`CHANGED_LISTED`); past that, `left_out` counts the rest of each list and names in `in` the top-level layers holding them, since one deleted frame listing every layer in it buried the answer it rode on.
- `get_document`, `get_node` and `list_children` take `since: rev` and answer `unchanged`, or only the layers changed and removed since. Nothing is withheld unless the agent passes `since`: a harness may have summarised its earlier read away.
- A registry verb takes `base_rev`. If a layer it writes changed after that revision the write is refused and the refusal lists them; without `base_rev` it applies. The client's own writes since are not changes against it, so several writes off one read each pass that read's `rev`; each remembered revision records whether the client's own call made it. The kit tools and `import_tokens` take none.
- **A client** is the key `ondin mcp-proxy --client <key>` (or `ONDIN_MCP_CLIENT`) puts in `initialize`'s `_meta` under `io.github.fadion.ondin/client`, else the connection. A keyed client's document and revisions outlive its connection, so a harness that starts a process per turn finds them on its next connection, with `changed` reporting what the person did in between; the host keeps the 32 most recently used keys. `use_document` of the document a client already uses keeps its history and answers `changed`; the proxy's own restore after a reconnect passes `restore` and answers none, leaving it for the agent's next call. "Never told of its own write" holds per client.

Server-sent notifications would be the protocol's own channel for this, but harnesses do not put them in front of the model mid-turn; a tool result always reaches it.

#### The commit door

Every write goes through the commit door the app's edits use (`EditorSession`), so the same passes run for an agent's transaction: `keep_insets` and `keep_flex_sizes`, the eight `keep_*_bindings` passes, then `propagate::owed`, which runs `style::settle`, `swap::settle`, `propagate_structure`, `component::settle_links`, `variant::settle`, `propagate`, `style::settle` once more, `keep_size_bindings` again and the inert-spacing clear, in that order (pinned by core tests). An agent never has to know a copy exists to keep it in step with its main.

That sequence lives in `EditorSession::commit_inner`, in `ondin-app`, which has no lib target (§15 D786's wall), so `ondin-mcp` cannot call it. It never needs to: the handlers hand transactions to the owning thread, and `serve` is the same `ondin` binary as the window, so both own an `EditorSession` per document and commit through it. The door also reads an edit of a styled layer as an edit of the style while the style browser's *Edit* is open (`style::edit_through`, first in `commit_inner`, §15 D1063). An agent's transaction skips that step: the same call does the same thing whatever is open on screen, and an agent changes a style with `set_style_value`.

#### Phase 3: verbs, not ops

Phase 3 names verbs because the raw ops are refused or wrong alone:

- Binding a field writes a canonical literal beside the binding (`build::bind_*_ops`: 0 for a number, empty for a string, `true` for a visibility), so a main and a copy bound to one variable compare equal whatever either held. A colour binding replaces the paint's brush outright, keeping its alpha percentage (`BrushSource::Bound`, `build::bind_brush_at_all`).
- Removing a variable or style detaches its users to what they drew in the same transaction (`variable::remove_ops`, `style::remove_ops`); removing a mode returns its frames to *Inherit* for its collection (`variable::remove_mode_ops`). Each is refused at the commit otherwise (§15 D1038). A bare `RemoveStyle` or a bare `SetCornerVars` over a non-canonical literal would be refused or wrong.
- Renaming a mode keeps every kit column it reads (`variable::rename_mode_ops`); a bare `SetModeName` re-maps a kit by the new name.
- Making an instance writes a linked copy (§15 D978).
- `bind_variable`'s `field` names any bindable field: corner radii, gaps and padding, width and height, a layout item's min/max width and height, visibility, opacity, a text's content, family, size, weight, line height, letter spacing and paragraph spacing, a fill's or stroke's colour, a stroke's width, and a shadow's X, Y, blur and spread or a layer or background blur's radius. An effect's colour and a filter's numbers bind nothing. It is one tool over the six `Set*Vars` ops plus the bindings a fill, stroke, effect and layout item carry in their own items (`BrushSource`, `LayoutItem::limit_vars`); an absent `variable` detaches to the value drawn. An item's binding names its item: the core verbs take a stroke's or effect's `ItemId`, and a paint's colour its index in the list.

#### Reads must grow with Phase 3

A bound field's stored literal is a placeholder, so the snapshot reports the **drawn** value of every bound field. It does that for a paint's colour, a stroke's width, an effect's numbers, size and corners (through `Resolved`'s used kind), visibility, opacity, a text's content and family, and a layout's gaps, padding, flow and limits. Beside the drawn values each node names what it reads, in the terms the Phase 3 tools take: `bindings` lists each bound field as `bind_variable`'s `field` with its variable, `styles` the style per slot by `apply_style`'s slot names, `modes` the modes a frame sets, and `component` its part (main, set, instance with the main it shows, or copy with the layer it is linked to), a variant's values, an instance's `properties` (each value as `set_instance_property` takes it, and whether it differs from the main's) and an instance's or copy's `overrides` (the fields `reset_overrides` would put back, `"fills"`, `"geometry.size"`, `"swap"`, from `reset::overrides`). The fill, stroke and effect lists stay visible entries only, so each carries its item id and a fill or stroke its index in the whole list. A text reads back as written too: `paragraph` and `block` in the shapes `set_paragraph_style` and `set_block_style` take, and `runs` and `paragraphs` as `style_text`'s and `style_paragraphs`' arguments, counted in characters, so a run's colour and a list item's marker and level are there; a family a run sets that the host lacks warns as the default's does. Where layout draws a node otherwise than authored, `specified` carries its stored transform and geometry beside the used ones. The snapshot is what is drawn, which a whole-list write cannot be built from: `get_tree(id)` answers the model instead, in `insert_subtree`'s `Tree` shape (`verbs::tree`), with every fill and stroke including the hidden ones, a gradient's and an image's framing, a stroke's align, dash, cap and join, the effects and exports, a text's runs and a mask's mode, each field only where it differs from a new layer's and no item ids. A binding a fill, stroke, effect or layout item carries travels in it; any other bound field (size, corners, a text's content, family and type numbers, gaps, padding, flow, visibility, opacity) is written as drawn and unbound, since `Tree` has no place for its binding and the stored literal is a placeholder. A tree carries nothing `Tree` does not hold: no applied styles, frame modes or width queries, pivot, element or link, description, or component state (a main, an instance's link, properties and variant values), so inserting one makes a plain copy drawn as the original is drawn. Layout reads back as written: `display`, `item` and `insets` carry the shapes `set_display`, `set_layout_item` and `set_insets` take, so an agent edits one by changing the field it read; the item is the authored one, not the width a frame with width queries is laid at. `list_variables` returns every mode's cells (aliases unresolved and resolved) in the short forms `set_variable_value` takes, and a kit variable's `kit`: the kit's id and name, its kit collection's name when the kit has several, that collection's modes, the document collection it is read from (`read_from`), the kit mode each of that collection's modes reads (`mapped`) and the one read where no frame sets a mode (`default`); `list_styles` returns each style's slot, name, value (in the short forms) and users' count. `list_components`, `list_variables` and `list_styles` also carry each main's or set's, variable's and style's description (`Node::description`, `Variable::description`, `Style::description`), read from the model, and `list_components` each main's or set's documentation link (`Node::doc_link`); the snapshot carries neither.

#### Phase 4: building and using a design system

An agent builds a design system by filling a document through Phases 2 and 3 with mains, variables and styles, then `make_kit` and `publish_kit`; it uses one by listing the library's kits, reading a kit's published mains, variables and styles with `get_kit`, placing a main with `insert_from_kit`, and taking later publishes with `accept_kit_updates`. The tools are the app's verbs:

| Tool | Backing |
| --- | --- |
| `insert_from_kit` | `kit::insert`: vendors the main and every nested main it reaches into the vault; variables and styles carried by `tokens::plan` into the document's own tables |
| `accept_kit_updates` | The app's accept, per kit or all kits, never per main; transaction built by `kit::update_all` |
| `make_local` | `kit::make_local`, forking the kit variables and styles the main reads |
| `map_kit_modes` | The variables browser's mapping row (`panels/variables.rs`): a `SetKitModes` carrying the kit's held record with only its hand-set `map` changed |
| `swap_instance` | Takes a kit main too, vendoring it first (`kit::swap_offers`, `kit::vendored`) |

The raw kit ops (`OpenVault`, `CloseVault`, `SetOrigin`, a `SetKitModes` rewriting the kit's name or modes, `SetStyleOrigin`, whole-variable `SetVariable`) stay behind those verbs, where the planner keeps them consistent.

**Outside undo.** The kit mark is document metadata, not an operation (§5.11a), so `make_kit`, `publish_kit` and `stop_sharing_kit` save the file and `undo()` reverts none (`make_kit` mints the document id first when it has none). `publish_kit` is the only outward write: it changes what every consuming document is offered (an open one's update pill within the watch's 45 seconds or on regaining focus; a closed one's when next opened).

**No dialog (§15 D1097).** The agent publishes, stops sharing and files documents on request: the request is the person's ask, the publish note is the tool's argument, and a dialog would hang the agent on a window it cannot see. The person instead gets the status line saying the agent did it: the app's own line for the act (`kits::made_kit_said`, `stopped_sharing_said`, `publish::published_said`), or *Filed Landing* for a new document, followed by *· by* and the name the client gave at `initialize` (*Published Atlas v4 · 3 components · by Claude Code*). The window puts it on its status line whichever tab the document is in; `serve` logs it.

**Documents by path (§8.1).** `create_document` files a new document in the library (`library::store::file_document`) and returns its path, which the agent passes to `use_document`; opening it never changes the tab in front of the person. Renaming, moving, duplicating and trashing documents stay with the person on the dashboard.

**Any document, either host (`mcp::kits`).** The app's kit actions are `OndinApp` methods on the tab in front, but an agent's document may be a tab behind or a `serve` session. So Phase 4 runs on that document's session and the library the host lends (`Documents::with_library`, a scan read again for each call), through the core verbs the app's own run on (`kit::insert` by way of `kits::picker::build_placement`, `update_all`, `make_local_report`, `publish`) and the app's functions that read a library (`kits::index::kits_in`, `kits::updates::waiting`). A kit's published state is read from its file at each call, with the version that file says it published (§15 D1023), never from the window's `KitShelf`. The mark's changes are written at once (`Documents::save`): the person's own save for the tab in front, a direct write for a tab behind or in `serve`. `list_documents`, `list_kits` and `create_document` need no current document. A kit is named by its id or its name; `insert_from_kit`'s `x` and `y` are the left and top of the instance's box in its parent, as `create_instance`'s are (`build::cornered_at`), and an edge not given stays at its main's own place.

#### Exports

`set_exports` writes a layer's export list (the *Export* card's rows: format, scale, prefix and suffix, background, quality, trim, square padding; `ExportSpec`, see export.md §7). `run_exports` renders the listed layers' files through `ondin_export::plan` and `plan::render` (the path `ondin export --all` takes) and **returns bytes with their names** rather than writing them, each file an embedded resource (text for SVG, base64 otherwise); where files land is the client's and the person's call. With no `ids` it takes the layers *Export all* takes (`panels::exportable_layers_of`); the CLI keeps its own copy of that walk, held to the same answer by `build::all_in_document_order`.

`export_code` writes layers as HTML/CSS, React or Vue through `code::Target::export` (export.md, *Code export*), the CLI's `--html`, `--react` and `--vue` path, and returns the files with the three report lists (`approximated`, `positioned`, `inlined`) beside them, never writing to disk. `ids` defaults to the selection, as *Export as HTML / React / Vue…* takes it, and with nothing selected (always, in `serve`) to the layers of the person's page, the first page's in `serve` as the CLI takes them. It is the door the deterministic translation exists for: the snapshot carries used values, so CSS an agent writes from it is absolute positions, where `export_code` keeps the specified layout, the variables and the components for the agent to build on.

#### Checks, tokens, fonts and versions

- `check_contrast` is `ondin_export::contrast::check_with`, the check *Check contrast* and `ondin check contrast` run, on the host's thread with the faces the canvas uses; `ids` narrows it to the subjects under them. It counts what it measured and what fails, and lists the failing findings only unless `all` asks for every one. `fix_contrast` is its fix. `review_colours` is *Colour review*'s census and groups (`color_review`).
- `design_context` answers what a frame, group or page already uses, so an agent adding to it matches it without reading every tree: the distinct text styles (each layer's default style with its ink, a sample per style), the colours seen in fills, strokes and text, corner radii, shadows and blurs, families, the bound variables' and styles' names, the sections (the root's shown children and their world boxes) and the content column. The column is the most common rounded left and right edge of what the sections hold, a child spanning its section's width being a background and left out. Only what is seen counts: hidden layers and paints, masks and image fills are left out, and lists stop at 24 with a count of the rest. A page holding one frame is read as that frame, the usual shape of a web page.
- `check_layout` lints placement from what the session has laid out, without a render: text cut at its box or line limit (`TextLayout::truncated`) and lines whose baselines leave a fixed box; a layer partly or wholly outside the frame that clips it; a flex or grid child past its frame's box; a shown layer with no width or height; and two unrotated texts whose boxes share more than a sliver. Edges get one unit of slack, so a hairline stroke on a frame's edge is not a finding, and a layer found clipped or overflowing answers for its descendants. Overlapping shapes, text over a busy ground and spacing rhythm are not checked: they are too often meant.
- `export_tokens` and `import_tokens` are the DTCG file the *Export tokens* and *Import tokens* doors read and write, as text: the agent hands the file over and takes it back, and nothing is written to disk or linked. An import applies every row the review starts ticked (`dtcg_in::Review`), removals only with `removals`, as one undo step named by the tool.
- `list_fonts` answers the families the host can set text in: the window's font service (installed, and web fonts it fetches on first use), `serve`'s installed families (`mcp::system_fonts`). `replace_font` is the one tool held to that list: its `to` must be a family `list_fonts` answers, written in the host's spelling, and not the family it replaces, since a replacement drops each match's axis and feature settings. A family an agent names is loaded as one the person picked: the window loads the tab in front's families after an agent's commit, a tab behind's when it comes to the front, and `serve` registers the installed faces of each family its document names on opening it and after each commit, then lays the text out again.
- `save_version(name?)` saves the document and pins it (`library::store::pin_version`), as *Save named version…* does, for a library document only; `undo` does not revert it. `list_versions` reads them back, and `compare_version(version)` answers what changed since one, named by its `at` or its name: `ondin_core::diff` of the version against the document now, as *Compare with now* reads it, with each value before and after, refused past the read budget. Restoring one stays with the person, in *Version history*.

#### set_pivot

`set_pivot` is for the person who comes after the agent. An agent can already rotate about any point with `set_transform` and an affine it computes, since the pivot is baked by the gesture that reads it and never composed into the world transform (§15 D55). The stored pivot decides where a person's later turn goes (canvas rotation, the inspector's rotation and skew fields, a flip; resize and skew drag ignore it, §15 D60): a needle about its hub, a door about its hinge.

#### Not exposed, on purpose

Guides, layout grids, a page's ground, the fill rule and the proportions lock (visual only, irrelevant to an agent; §15 D1095, D1096). Paragraph spans travel inside `style_paragraphs`. *Warp* and *Trace image*, cards whose settings are tuned by eye on the canvas. Restoring a version, which replaces the document outside undo, and linking a tokens or chart data file, which watches a path on the person's disk: both stay with the person.

## Traps

- **The four phase paragraphs above are parsed by a test.** `ondin-mcp/src/tools.rs` holds the same names as `PHASE_1` to `PHASE_4`, and a `#[cfg(test)]` module `include_str!`s the architecture document and diffs every phase in order. The parser anchors on each phase's opening sentence, takes the paragraph up to the first blank line, and reads **every backticked token in it as a tool name**, dropping any signature at the `(`. Do not reword a phase's opening sentence, do not merge a phase paragraph into the next, and do not put a backticked aside inside one; put asides after the last phase. A rename fails at the comparison, a moved heading fails loudly at the parse. **When the architecture file is split, `tools.rs` must point its `include_str!` at this file (`docs/design/mcp.md`) or it will read the old path.**
- Phase 3 tools wrap verbs; writing the raw op (`RemoveStyle`, `SetCornerVars`) hands the commit a transaction it refuses or a non-canonical literal.
- Kit actions and document creation are not `Transaction`s: they bypass history, so `undo()` is not a safety net for them.
- A write applied to the `Document` anywhere but `EditorSession::commit` skips the `keep_*` passes and the propagation, and every gate stays green.
