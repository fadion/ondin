# Rendering (`ondin-render`)

The renderer crate: layout of the crate, the `ScenePainter` boundary and `RenderOverrides` (how gestures are drawn), and the CPU and GPU backends with the shared scene walk. Effect pixel passes are in effects.md (§6.4); image decoding is in images.md.

## 6.1 Layout

```
ondin-render/src/
├─ lib.rs
├─ renderer.rs     # Viewport, RenderOverrides
├─ gpu.rs          # VelloGpuRenderer (vello + wgpu) - interactive canvas
├─ cpu.rs          # VelloCpuRenderer (vello_cpu) - PNG export, CI, headless
├─ scene.rs        # trait ScenePainter + the one document->scene walk, culled
├─ effects.rs      # the effect passes, read by both backends (§6.4)
├─ fx_gpu.rs       # the same passes as compute shaders (fx.wgsl) for the GPU backend
├─ images.rs       # the decode cache: encoded bytes to peniko::ImageData, once per image
└─ color.rs        # the ONLY color conversion point
```

## 6.2 The boundary

```rust
pub struct Viewport { pub view: kurbo::Rect, pub pixel_size: (u32, u32) } // zoom is derived

pub trait ScenePainter {
    fn has_image(&self, id: &ImageId) -> bool;
    fn fill_path(&mut self, transform: Affine, path: &BezPath, brush: &peniko::Brush,
                 framing: Option<Framing>);
    fn stroke_path(&mut self, transform: Affine, path: &BezPath, stroke: &StrokePaint<'_>);
    fn draw_text(&mut self, transform: Affine, run: &TextRun<'_>);
    fn push_layer(&mut self, transform: Affine, clip: Option<&BezPath>, rule: ClipRule,
                  opacity: f32);
    fn push_mask_layer(&mut self);   // DestIn: the enclosing layer survives in proportion
                                     // to the alpha drawn in this one
    fn push_erase_layer(&mut self);  // DestOut: survives in proportion to the alpha NOT drawn
    fn push_add_layer(&mut self);    // Plus: fills an erased hole in proportion to how far
                                     // it was erased. Both defaulted to a plain layer;
                                     // both backends override them.
    fn push_effect_layer(&mut self, transform: Affine, bounds: Rect, effects: &[Effect]);
                                     // `bounds` = node's INK box in `transform`'s space.
                                     // Defaulted to push_layer; both backends override it.
    fn push_shadow_layer(&mut self, transform: Affine, bounds: Rect, effects: &[Effect]);
                                     // an effect layer keeping only the shadows it casts.
                                     // Defaulted to push_effect_layer; both backends override it.
    fn push_blend_layer(&mut self, mode: BlendMode);
                                     // unclipped, composited by `mode` (peniko `Mix`, `scene::mix`);
                                     // Normal = isolation group. Defaulted to a plain layer;
                                     // both backends override it.
    fn pop_layer(&mut self);         // closes an effect OR ordinary layer; a painter keeping
                                     // effect frames must count which
    fn ground(&self) -> Option<Color>;   // the opaque colour the target holds before the
                                     // walk draws: the GPU canvas's clear colour; None
                                     // (the default) wherever a ground is laid after
    fn paints_backdrops(&self) -> bool;  // false for BoundsPainter and OutlinePainter
    fn backdrop_box(&mut self, transform: Affine, local: Rect);  // the glass's box, for those
}
```

- `Viewport` stores `view` + `pixel_size`; zoom is their ratio.
- **A render draws one page.** `scene::build`, `gpu::build_scene`, `VelloGpuRenderer::render` and `VelloCpuRenderer::render_to_rgba` take the page whose root the walk starts from; the vault is never walked.
- **A slice is never drawn** (§5.3): `scene::paint_node` returns for one before pushing any layer, so it owes no pop. `svg::emit_node` and the code export skip it the same way (§7).
- **One world unit is one pixel at 100% zoom.** `grid.rs` (a one-unit lattice) and `snap::to_pixel` (one-unit multiples) both rely on it (§9.4); a different unit is a change to this rule, not a local one.
- **Brushes, not colours.** Paths carry `peniko::Brush`. Gradient points are stored in the node's local px, against its **paint box** (`paint_box::paint_box`): the stored box, with each bound axis read as its variable's number in the default mode, since a bound axis's literal is a placeholder 0. `GradientBrush`'s affine carries an elliptical radial's squash and the paint box's scale after a resize (`paint_box::keep_gradients`, at the commit and preview doors and again at the end of `propagate::owed` for the sizes copies follow; a line or path is carried by the resize tool, `tools::carry_gradients`, since a point edit also moves a path's box). Binding or detaching an axis carries only by what the paint box changes. A fill or stroke list bound to a style is left to its style. Layout, insets and a bound size read in another mode draw another box, so `scene::paint_node` maps gradients from the paint box (of a preview's kind, else the node's) onto the used one (`paint_box::drawn_paint`); the exporters ask `paint_box::node_paint` for the same answer. A variable's default-mode number changing moves the paint box with the drawn one, so the gradient keeps its px there. Text has no stored box and is not carried. Both backends set a brush transform from `color::brush_to_backend`'s second answer for every variant. Stop offsets are made monotonic there (`image::make_stops_monotonic`), and a sweep is turned to start at 0 with its start angle moved into the transform (`color::sweep_from_zero`): both backends measure a sweep's angle in `0..2π` without wrapping, so a sweep starting anywhere else would pad its first colour over the turn before its start. An image is the other exception: its coordinates are its own pixel grid, so each draw carries a `Framing` beside the brush (`StrokePaint` and `TextRun` carry one too). It is `None` for a solid, a gradient, and an image with no table entry (the fill is diverted to the placeholder first).
- **Resolution is the one thing the backends disagree about**: `color::Resolution { Source, Atlas }` is a parameter on `brush_to_backend`. The GPU painter asks for `Atlas` (`ImageStore::atlas_pixels`, shrunk to vello's 8192 atlas); the CPU painter asks for `Source` (`ondin export --png` writes the picture as placed). Both are correct.
- **`has_image` is the one question the walk asks the painter**: the pixel store belongs to the backend, the geometry to the walk, so a picture that cannot be drawn is answered here and *drawn* in `scene.rs` (one placeholder description, §6.3).
- **Layers, not folded alpha**: overlapping half-transparent children must not show through each other. A layer is pushed only when a node clips, is below full opacity or blends (below); opacity under 100%, a clip and a mask run isolate whatever the blend mode. `clip: None` means the render target's own pixel box; vello demands a shape, so the GPU backend substitutes `gpu::layer_shape` (the target box), never a big rectangle in node space (an ancestor scale would shrink it into a real clip). `push_mask_layer` and `push_luminance_mask_layer` use the same function.
- **A mask run is a layer nested inside whatever the parent pushed** (`scene::MaskRun`): a parent has one clip for all children, a mask has one for a run of them. It closes and reopens with the parent's layer, like `escape_clip` (mask first out, last in). `scene::mask_geometry` mirrors `Resolved::mask_path` override-aware (so a dragged mask clips under the pointer); ghosts carry `GhostNode::mask` and `mask_mode`.
  - Two arrangements, `MaskRun::kind`: `RunKind::Clip(BezPath)` is a shape mask (one layer clipped to the outline; the mask never drawn). `RunKind::Ink(NodeId, bool)` is an alpha or (the `bool`) luminance mask: it carries the node, arrives at the *end* of the run (it composites over what it masks), and its run layer has no clip (an isolation group). `push_ink_mask` opens the composite: `push_mask_layer` is one `BlendMode::new(Mix::Normal, Compose::DestIn)` taken by both backends' `push_layer`; `push_luminance_mask_layer` defaults to it, and both shipping backends override it.
    - **GPU**: vello's `Scene::push_luminance_mask_layer`, clipped to the unbounded `gpu::layer_shape`. The clip must stay unbounded: vello leaves a pixel outside it unmasked, where everywhere else no ink means erased.
    - **CPU**: `vello_cpu` has no drawn-layer luminance mask, so the mask's drawing goes into an `FxFrame` (`Pass::Luminance`) the size of the enclosing target, pixel for pixel, `base` unchanged. On pop, `luminance_to_alpha` turns each premultiplied pixel into black at alpha = the weighted sum of its premultiplied rgb (lum × a), painted back inside a `Compose::DestIn` layer. The backends agree within 2/255 (`gpu_effects::both_backends_draw_the_same_luminance_mask`, on-device).
  - No mode reads the mask node's own opacity (shape: outline decides which pixels survive; alpha and luminance: opacity already in the ink). A shape mask with no geometry masks nothing; an ink mask with no ink erases the run. A hidden mask masks nothing in any mode: both arms ask `scene::visible`.
- **A blend layer is the outermost layer of a node**, outside even the effect layer, so a layer's shadow blends with it (`push_blend_layer`). It is pushed when `BlendMode::isolates(kind)` (any mode but Normal and Pass through, or Normal on a frame or group), and with Normal for a **page** and a **top-level frame** (parent a page root) that hold a blended descendant — a mode or a visible shadow's mode, ghosts included (`scene::holds_blend`): what is inside then blends with the page's or the frame's content, never the canvas ground, so the canvas looks the same as an export, and a frame the same as exported alone. The answer is `Resolved::blends_within`, kept with the ink children first, so the walk asks one lookup per child; a preview that blends anything (`RenderOverrides::blends`) answers yes, since an isolation group around artwork that does not blend changes no pixel. `scene::blend_layer` decides; `NodeOverride::blend` and `GhostNode::blend` carry previews, and `paint_ghost` takes a `top` flag for the top-level rule. GPU matches CPU within 2/255 (`gpu_effects::both_backends_blend_alike`, on-device).
- **An effect layer sits just inside the blend layer**, both positions load-bearing (`push_effect_layer`). Outside the clip, so a clipping frame's drop shadow falls outside the frame (the SVG writer needs a wrapper element for the same reason). Outside the opacity, so a half-transparent layer casts a half-transparent shadow. It is pushed only when `effects::any_ink` says a pixel could change (not `!effects.is_empty()`) and only when the node has cached bounds (a node in its creation frame draws unfiltered rather than not at all).
  - **`Filters` fold into solid inks** (`scene::folded_filters`), in every walk, screen or export: a colour matrix is affine, so recolouring each ink draws what filtering the layer's pixels draws, and the shadows are cast from an alpha it never changes. The rows then leave the stack, and a layer with nothing else needs no buffer. Refused, keeping the buffer: a container (its children are not its inks), a non-solid ink, a visible layer blur (list order decides whether its mixing comes before or after the filter), a failed boolean's placeholder, and a clamp on any ink while the layer holds more than one colour (clamping does not commute with mixing). `effects::matrix_colour` is `apply_matrix`'s arithmetic on one colour; `tests/effects.rs · filters_folded_into_the_inks_match_the_filtered_pixels` holds the two within 2/255 premultiplied.
  - **Under level of detail the stack is cut first** (`scene::detail_effects`): a drop or inner shadow, or a layer or background blur, whose reach (a shadow's |offset| + blur reach + |spread|) times the largest stretch of the node's local-to-device transform is under one device pixel is dropped, since it moves an edge by less than a pixel and costs an offscreen buffer. `Filters` recolour every pixel and always stay. A layer left with nothing that inks draws plain, with no buffer. The cut can lose a shadow tucked wholly under a translucent layer.
  - **A blending shadow takes the node out of the one effect layer.** A shadow's mode (§5.3a) blends with what lies under the layer, or for an inner shadow with the layer and what shows through it, and the effect buffer holds neither. So when a visible shadow of the stack blends, `scene::shadow_passes` splits the node into `FxPass`es, drawn bottom to top by `paint_node_pass` (and `paint_ghost`'s `pass`): each drop shadow alone in reverse list order (`effects::run` stacks a later drop shadow behind an earlier), then the layer with its appearance effects and no shadow, then each inner shadow alone in list order. A shadow's pass keeps the appearance effects, which shape its silhouette, and goes through `push_shadow_layer` inside its own blend layer; every pass sits inside the node's blend layer (`scene::draw_passes`) but for the shadow passes of a node whose layer only isolates (Normal), which are drawn outside it so they blend with what lies under the node rather than with an empty group; under any other mode the node's mode composites its shadows too. Each pass sizes its buffer from the whole stack so all passes read the same silhouette box. The cost is a redraw of the subtree per pass, so a stack with no blending shadow keeps the single effect layer. GPU matches CPU within 2/255 (`gpu_effects::both_backends_blend_a_shadow_alike`, on-device).
  - A ghost gets its own effect layer in `paint_ghost`, measured by `scene::ghost_ink` (not `Resolved`, which has not seen it); otherwise an Alt-drag copy of a shadowed layer draws flat until release. `ghost_ink` mirrors `effect_bounds`' three arms: a container's box is its children's, each grown by that child's stack; a boolean's is `GhostNode::path`; other kinds use `geometry::world_bounds_of_parts` (stroke included); growth is `effect::escaped`.
  - Pushed at the top and popped at the end of `paint_node`, so every early return owes a pop. The `Boolean` arm returns from the middle (operands are not artwork) and unwinds the clip/opacity layer, the mask run, the effect layer and the blend layer; `paint_ghost`'s twin arm unwinds the same way and is load-bearing. Not folded into `close`, which is also called inside the children loop. (A comment in `scene.rs` still says the ghost unwind cannot fire; fix the comment.)
- **A background blur is drawn by `scene::paint_backdrop`** (a layer with one is a *glass*), from `paint_node_pass` before the node's blend layer, so behind its own shadows and blend. It erases the node's outline from the current target at the node's opacity (`push_erase_layer`); then, inside an add layer (`push_add_layer`), a clip layer to the outline at that opacity holds an effect layer carrying `[LayerBlur { radius }]` (`effect::backdrop_radius`), whose content is a repaint of what lies behind. Erase-then-add is `(1 − o)·under + o·blurred` at any coverage; drawing the blurred copy over instead fades what is under twice.
  - **What lies behind** is everything the walk drew before the node inside the nearest enclosing container that draws its children into a layer of its own (a blend, effect or opacity layer: CSS's backdrop root), or from the walk's origins when none does; a layer exported alone has nothing behind it. A `Walk` threaded through `paint_node` keeps the origins, the containers open above the node (`Open`, with whether each isolates), a count of shadow passes, and while repainting a `Backdrop`. The repaint draws the root container bare (without the layers that isolate it, keeping its clip), stops on reaching the node (an ink mask's composite and a frame's stroke after it are left out), does not stop inside a shadow pass (a shadow is cast from the whole layer), and culls to the outline's box grown by the blur's reach. Under a clipping frame the backdrop ends at the nearest one's edge (`scene::clip_box`, the snapped device box, when the frame is axis-aligned): the repaint is clipped to it and, past it, repainted again mirrored about each edge the read box crosses, as a browser's backdrop filter mirrors its edges. Read through the edge, a glass along a frame's side would blur in what lies outside it — the ground on the canvas, transparency in an export. A layer met inside a repaint draws without its own backdrop, so each glass costs one repaint and glass behind glass is seen unblurred, then blurred.
  - A repaint from the walk's origins is first filled with `ScenePainter::ground()`, so a glass over bare canvas does not erase through to nothing. Exports answer `None`: their background is laid after the drawing, and erase-then-add over transparency is exact under it by linearity.
  - **The outline** (`backdrop_shape`) is the kind's path, a boolean's result, text's glyph outline, or a group's children's outlines united as a mask's are; a snapped box uses the fill's snapped transform.
  - **Limit**: where a clip layer (a clipping frame, a shape mask run) sits between the root and the node, the erase reaches only into the clip layer, so a translucent backdrop lets what is under it show through. Exact wherever the backdrop is opaque.
  - No backdrop is drawn through a painter answering `paints_backdrops() == false` (outline view traces no backdrop, and `BoundsPainter` would measure it twice); such a painter is handed the outline's box instead (`backdrop_box`), which `BoundsPainter` counts, so a fill-less glass is damage where it moves. Nor is one drawn for a ghost: an Alt-drag copy of a glass draws without its blur until release.
- **`RenderOverrides` is how a gesture is drawn** (invariant 5): per-node patches (transform, kind, paint, effects, opacity, blend, visibility, re-shaped text), *ghosts*, a page's ground being dragged (absorbed from `SetPageGround`, read back by `RenderOverrides::ground(page)`; the backdrop is the clear colour, handed to the renderer separately), and a per-parent child order (`children_of`, for `Reorder`). All count towards `is_empty`.

### Ghosts

A ghost is a subtree: `Ghost { parent, index, node }`, with `GhostNode` carrying everything the walk reads off a `Node` (transform, kind, paint, effects, text, opacity, blend, visibility, clip, mask, mask mode, `children`, and `path` for a boolean ghost's combined outline evaluated once at build). `scene::paint_ghost` handles a ghost's clip, opacity and stops at a `Boolean` like `paint_node`. `InsertSubtree`'s `index` is honoured: `paint_node` interleaves ghosts among their parent's real children by index.

Every setter looks in the ghost forest *before* the node map (a transaction that adds artwork and then places it names a node the document has never seen). Readers owe the same order (`transform_of` for a ghost id).

### Readers, layout and the preview

- After the override, a reader falls back to *used* geometry, not the document's: `transform_of` = ghost, override, used local; `drawn_kind` the same; `scene::paint_node` and `mask_geometry` = override, used, document. **Except `current_kind`** (ghost, override, document), because it is what an op is applied to (`absorb`'s `SetGeometry`, `patch_text`); patching a laid-out size would write it back as typed. Empty overrides reduce the walk to the committed document exactly, which holds under layout only because the fallback is the used local (`Resolved` composes used locals). The one deliberate difference is pixel snapping (below).
- **`relayout`** re-places what the preview moves by insets: after `absorb`, before booleans, it runs `container::place` for every pinned child of a frame the preview resizes and every layer whose insets it sets (`NodeOverride::insets`), parents first, writing ordinary transform/kind overrides. It skips a layer the transaction itself places (`SetTransform`, or `SetGeometry` whose patch `resizes()`). A non-resizing patch (e.g. a radius) places nothing; a pinned layer carrying a kind override is re-placed from that override kind. A layer with no insets is left alone unless the preview unpinned it. A pinned layout root it re-places is laid again first via `lay_out` over the preview, items written by `apply_laid`.
- **`flex_relayout`** runs before it: `absorb` records `SetDisplay` and `SetLayoutItem` (`NodeOverride::display`, `item`) and every layout root a touched node chains to (through plain groups, so a laid group behind one is its own root) is laid over a `PreviewView`, the same `container::lay_out` `Resolved` runs. Results become transform and kind overrides plus `NodeOverride::frame` (a group's box), so a pinned child is placed against the box its container has just been given. `set_preview` appends `build::flex_holds` (growth, `align-self`, size keyword that `keep_flex_sizes` writes), otherwise a stretched item dragged shorter stretches back each frame.
  - Where `item_placed` answers `local: None`, the item's transform is the preview's own override, then the document's. It skips only a layer dragged with `SetTransform`; a resized item (even with a left/top-handle `SetTransform`) or turned item (linear part differs) is re-laid. A skipped item's slot is kept in `RenderOverrides::landings` (world transform and box), composed through the container's world transform in this preview after both passes; the canvas outlines only the item the release will reorder (§9.4). A layout the preview takes away puts its items back at stored transforms. Ghosts are not in the view's tree: a copy dragged into a flex row or grid is laid out on release (flex verified; the grid release is measured, the grid preview is not).
- **Bindings in the preview**: each arm reproduces the commit pass's judgement through a shared function, never a copy. Gaps and padding resolve via `Document::spacing_drawn_in` with `build::kept_spacing_vars`; `SetSpacingVars` kept on `NodeOverride::spacing_vars`; `SetGeometry` over bound corners via `build::kept_corner_vars`/`corners_drawn_in`; `SetCornerVars`; visibility (`SetVisibleVar`, `shown_in`; no visibility arm marks moved because `flex_relayout` lays from every node with an override); width/height (`Document::resolved_kind`, `build::kept_size_vars`, `SetSizeVars`); size limits (`SetLayoutItem`'s item through `build::kept_limits`, which `PreviewView::item` resolves with `Document::limits_drawn_in`); text bindings (`patch_text`: a bound family or type number written as its literal draws its variable, as `keep_text_bindings` keeps it; a content written empty does not; `SetTextVars`); opacity (`SetOpacity`, `SetOpacityVar`); stroke width (`SetStrokes` via `build::kept_stroke_widths`; `resolved_paint_in` clears `width_var` on output or the scene double-resolves; the arm marks the node moved); effects (`SetEffects` via `build::kept_effect_vars`, marked moved); and `SetVariableCell` is patched (variables table cloned with the one cell, `Variables::with_cell`; every bound node re-resolved; one cell per transaction). `SetMode` is refused. The ghost reads `opacity_drawn_in` over the captured node's own literal and binding, never `drawn_opacity`. A ghost's kind (`ghost_kind`) and the specified kind a preview patches or draws a layer the layout lets go with (`specified_kind`) resolve bound corners as well as size and text: `Document::resolved_kind` leaves corners to `Resolved`, which a preview's kind never passes through. The preview runs no binding keep pass as such (`set_preview` and `preview_follows` run `keep_insets` and `keep_flex_sizes`, and `set_preview` `paint_box::keep_gradients`).
- **`SetEffects` is patchable** (whole stack) and its arm marks the node moved, since an effect reaches outside the layer and cached bounds no longer cover its ink.

### Preview properties

1. **Built from the pending transaction**: `RenderOverrides::from_transaction` projects the exact `Transaction` the gesture commits. A differential test builds the scene both ways and requires identical draw-call streams. Text sessions use `from_transaction_shaped` (the already-shaped `TextLayout`). `set_preview` projects the gesture's transaction plus `build::flex_holds`, through `paint_box::keep_gradients` so a resize draws its gradients carried. Beside it, `propagate::propagate`'s follows (§5.3d) are run over the door-rewritten transaction (`keep_flex_sizes(keep_insets(...))`) and passed to `from_transaction_following`, which lays follows out rather than treating them as drags; the structural pass is not run. The raw differential commits a raw transaction; its twin `assert_preview_matches_commit_through_the_doors` uses the door-rewritten one and asserts the flex hold held.
2. **It refuses what it cannot represent.** Ops that only add artwork are ghosts (`CreateNode`, `InsertSubtree`). Ops that move or remove an existing node (delete, reparent), and a page added or removed, cannot be patched and return `None` (no preview). Values `apply` would reject return `None` (including invalid layout values via `is_valid_over`). A `Reorder` is representable: a patch on the parent's child order (`children_of`), read by the scene walk, `PreviewView` and the boolean evaluator's `operand_children`. `SetClip`, `SetMask`, `SetMaskMode` refuse (they change which other nodes the walk clips). `SetFillRule` refuses for lack of a `NodeOverride` field (not structural). A missing preview is recoverable; a lying one is not.
- **Guide ops** are absorbed as no-ops returning `Some` (the app previews a guide from its own state, `OndinApp::shown_guide`), so they do not blank the rest of the transaction. `SetPivot` is in the same arm (pivot is baked by the gesture reading it); field-driven pivot edits use `EditorSession::pivot_preview`/`preview_pivot`.
- **No-op arms**: `AddImage | RemoveImage` (no image table in `RenderOverrides`; a previewed image appears at commit), the chrome ops (`SetComponent`, `SetLink`, variant ops, `SetSwap`, `SetPageDraft`, `MovePage`), the variables-table ops (`AddVariable`, `RemoveVariable`, `SetVariableName`, `AddMode`, `RemoveMode`, `SetModeName`, `SetVariable`, `SetKitModes`; the walk reads the table off the document) and the styles table and bindings (a style draws through the lists its users hold). `overrides.rs · every_no_op_of_absorb_is_a_no_op_and_two_of_them_still_change_ink` pins the lists and their lengths; a new `Operation` variant must be added to both this fixture and `op.rs`'s list.

## 6.3 Backends

- **GPU (`vello`)**: owns `vello::Renderer`; the app supplies the `wgpu` device and queue (shared with egui). The walk is z-order, culling a node whose *ink* bounds miss the viewport (not `world_bounds`; three readers: `paint_node`, `plan::raster_size`, `plan::raster_opts`), which also skips its subtree when those bounds cover it: a group, a clipping frame, or a boolean (children are operands, so the walk stops there). Under a node that pushes an effect layer, the children are culled against the view grown back by the stack's escape (`effect::stack_escape`, sides swapped), since a shadow or blur carries a child's ink past the child's own box. A frame with `clip` off is not skipped; a moving node and a node holding a ghost are never culled. A screen also culls by **level of detail** (`RenderOverrides::set_level_of_detail`): a node whose world ink maps under half a device pixel on both axes (`scene::sub_pixel`) is skipped, with its subtree under the same rule and exemptions, and so is not a node a preview patches or holds something it patches (`Walk::grown`), whose cached ink is the committed size. Each leaf is judged on its own: a dense pattern of sub-pixel layers (dots, hatching) that inks a visible area together draws nothing at that zoom, a loss the decision accepts. Under it, too, a glyph run set under four device pixels (`scene::GREEK_BELOW`) is **greeked** (`scene::greeked`): one bar per span of glyphs on a baseline, from 0.15 to 0.45 of the font size above it, filled in the run's inks at 0.7 of their alpha (`scene::GREEK_INK`, the share of the bar that glyphs that small actually ink; outlined type in its first stroke's, and its glyph outline is not stroked). Type that small cannot be read, and its glyphs were most of vello's CPU time on a zoomed-out page. Type on a path and rotated glyphs always draw as glyphs. The flag is a view, not an edit: `OndinApp::draw_canvas` and the presentation view install it every frame, as outline mode is, because `set_preview` replaces the overrides wholesale. It is off by default, so every export and thumbnail draws what the document holds. Opacity and artboard clipping use layers; text uses the glyph-run API from cached parley layouts, and shapes fill and stroke their cached outline (`Resolved::shape_path`) unless a preview changes their kind.
- **The canvas draws only on change.** `CanvasRenderer::render` keeps its texture while its `DrawnKey` equals the one the texture was drawn from: `EditorSession::revision` (document and `Resolved`), `EditorSession::drawn`, `EditorSession::shaped`, `ImageStore::generation`, camera, pixel size, backdrop, page, and the view fields of `RenderOverrides` that are re-installed every frame (outline ink, level of detail, the chrome ghost), compared by value. egui still repaints for a caret blink or a hover; only the scene walk and render are skipped. A failed draw clears the key. The presentation view uses the same renderer and key.
  - `drawn` moves in `set_preview`, `set_session_preview` and `clear_preview`: a preview or a landed font changes what is drawn without moving `revision`, which other caches read as "the document changed". `fonts_changed` re-shapes `Resolved`'s text, moves `shaped` and calls `clear_preview`; `shaped` is how the canvas tells a re-shape, which changes `Resolved` with no preview, from a preview changing. All three stamps come from one global counter, so they are unique across sessions and tabs.
  - `generation` moves when a decode lands (`ensure`, `adopt`), an entry is evicted, the atlas factor changes or a preview is promoted; a first ask of an adjustment does not, since the frame that asked drew the answer. While `ImageStore::wants_frame()` is true the canvas draws whatever the key, because promotion needs the picture asked for on consecutive frames.
  - **A pan moves the last frame.** `Camera::viewport` rounds the view's corner so the world origin sits on a whole device pixel; the centre stays exact, so the rounding (under half a pixel per axis) never accumulates over a pan, and a zoom step's anchor holds only to within a device pixel (`Camera::zoom_by` reads both of its world points through rounded views). When only the camera centre changed, `DrawnKey::pan_to` gives the whole-pixel shift and `Gpu::pan` draws `Region::exposed` into a spare texture with `VelloGpuRenderer::render_regions`, copies the kept part of the last frame over it (`gpu::copy_shifted`) and swaps the two. It draws the whole frame instead when the shown frame is pinned, when half the canvas or less would be kept, or while `wants_frame()` holds.
  - **A preview redraws only its damage.** `CanvasRenderer` keeps `shown_preview`, a clone of the `RenderOverrides` its texture was drawn under. When `DrawnKey::previews_to` holds (only `drawn` and the chrome ghost differ), the damage is `scene::damage(doc, res, vp, page, before, after)`; `patch_regions` grows each box by `DAMAGE_MARGIN` (2 device px) into a `Region` (`Region::covering`), and `Gpu::patch` draws them into the spare texture with `render_regions` and copies them into the target (`gpu::copy_regions`). It draws whole when the damage is unbounded, the regions cover half the canvas or more, the frame is pinned, or `wants_frame()` holds.
  - **An edit redraws only its damage.** `EditorSession` keeps an `InkLog` of its last `InkLog::KEPT` document changes, keyed by the revisions either side. At every commit, undo and redo, after the document is applied and before `Resolved::update`, `InkLog::record` takes the dirty set and records the top-level layers holding a dirty node (children of a page or of the vault) and the old world `Resolved::ink_bounds` of each of them, of each deleted node, and of each dirty node itself — the tops are the document's after the change, so a layer wrapped into a new group would otherwise leave its old ink out. A node the old `Resolved` never placed (new, or in the vault) drew nothing; an existing node with no ink box, or more than 64 separate boxes once nested ones are dropped, makes the step unbounded. When `DrawnKey::edits_to` holds (only `revision`, `drawn` and the chrome ghost differ, outline mode off, since outline draws a clipping frame's children past the box `Resolved` keeps for it) and `InkLog::between` joins an unbroken chain of bounded steps from the shown revision to the new one, `edit_damage` redraws the recorded old ink (`scene::device_box`), the ink the shown frame's preview had (`shown_ink`), and what every top-level layer the edit or either preview touched draws now (`scene::top_level_ink` under the current preview). It then patches as a preview does, with the same refusals.
    - `shown_ink` is kept beside the texture: `scene::preview_ink` after a whole draw or an edit's patch, moved with a pan, a preview patch's damage after one. It is `None` when the shown frame had a mask among the page's layers, as `top_level_ink` is when the page has one now, so an edit adding or removing a mask draws whole. So do images landing, re-shaped text and camera moves (the key differs in more than `edits_to` allows) and a canvas further behind than the log keeps.
    - `RenderOverrides::touched` names every document node whose drawing a preview can change: the patched, moved, escaping, the reshaped booleans, the reordered parents and their children, the ghosts' and the chrome ghost's parents, and the chrome's glued layer. The walk reads nothing else off a preview but the view fields, so every other node draws as committed.
    - `scene::damage` is top-level: each touched node stands for its ancestor among the page's children, and that item is measured under both previews by `scene::top_level_ink`, which walks it into a `BoundsPainter` (through `OutlinePainter` in outline view). Ghosts hanging off the page are always measured. `BoundsPainter` errs large: clips are not applied, a stroke grows by its widest mitre or cap, a glyph run by three ems, and an effect layer counts its whole buffer box. `damage` is `None` when the page's children do not draw independently (a mask among them clips those after it; a preview reordering them changes which covers which). The walk up is `scene::tops_of`, shared with `edit_damage`; it skips a node the document does not hold, whose old ink an edit records instead.
  - **Damage spreads through glass** (`scene::spread_through_backdrops`, on a preview's or an edit's damage before `patch_regions`): a change behind a glass shows in the glass as far as its blur reaches, so each damage box grown by a glass's device reach and cut to the glass's ink is damage too, followed one glass further each round for glass behind glass, and given up once the boxes cover half the canvas, which `patch_regions` draws whole anyway. The glass is found through `Resolved::glass_within` (a node's subtree holds a visible background blur, kept children first as the ink is), so a page with none walks nothing, and among the nodes the preview gives effects.
  - **`render_regions`** walks with the full viewport's device transform, effect limit and budget, culled to the regions grown by `REGION_CULL_MARGIN` (2 device px) through `scene::build_within`, and renders into a full-size target in the frame's one page pass (§15 D344). Inside the regions it draws the full frame within a level or two, but for a few pixels: an effect layer packs at another offset in its pass's texture when fewer layers share the pass, and vello's stroke expansion can then place an edge ~0.05 px apart, up to ~14 levels on one edge column. A full frame varies the same way with what is in view. Kept pixels are the last frame bit for bit (moved, after a pan), and differ from a fresh full frame only as two full frames a pan apart do (vello's antialiasing at another whole-pixel offset). Nothing is approximated, stale or stretched.
  - **A pinned frame is never moved or patched.** `VelloGpuRenderer::pinned` says the last frame's pixels depended on where the canvas sat: an effect buffer whose escape was trimmed to the page budget (`buffer_box_within` short of `buffer_box`), resampled into the size cap (`effect_buffer` grew `k`), or cut by the canvas while filtered on a coarse grid anchored at the buffer's corner (a downscaled buffer or a block-blurred shadow, `gpu::coarse`). `render_regions` returns `Ok(false)` when its own walk comes out pinned.
- **GPU glyphs come from outlines.** vello draws every glyph of a font that holds any bitmap strike through its emoji path, taking the strike's bitmap wherever one exists at the size, and draws a monochrome one blank: the ClearType faces Windows ships (Calibri, Cambria, Consolas and the like) carry such strikes for screen sizes, and lost most of their letters on the canvas. `GpuScenePainter::draw_text` hands vello `outline_only::outline_only(font)` where it answers: the face written out alone without `EBDT`/`EBLC`/`EBSC`, made once per blob and face and kept (so its blob id, and vello's glyph cache, holds across frames; the cache starts over past 256 fonts). A font with colour strikes (`CBDT`, `sbix`) is emoji and left alone. `vello_cpu` ignores monochrome strikes, so the CPU backend needs none of it (`gpu_bitmap_strikes.rs`, on-device, Windows' Calibri).
- **CPU (`vello_cpu`)**: the same walk, no GPU, deterministic; used by PNG export and `ondin serve`. `cpu.rs`'s `export_settings` pins `Level::baseline()` via `RenderContext::new_with` because a stroked path rasterizes differently under AVX2 vs SSE4.2/scalar; the pin is export-only (`rasterize_glyph_run` keeps the detected level). `raster_settings` spells out all four rasterizer settings at every call site so no upstream default moves a raster. It declines (returns `Option<Vec<u8>>`) rather than truncating past `MAX_RASTER_SIDE` (`u16` dimensions). Byte-comparability holds per architecture and per pinned `vello_cpu` version.
- **Effects, both backends, one specification** (§5.3a, §6.4).
  - **CPU**: `CpuPainter::push_effect_layer` renders the layer into an offscreen `RenderContext` sized from the ink box, clamped to the enclosing target grown by the escape (`effect::buffer_box_within`; shadows of scrolled-out layers still cast in), never past the page's own pixel count (the escape grows with zoom), and at a coarser resolution when the layer's blur has destroyed the detail (`effect::buffer_downscale`). It runs `effects::run` over its premultiplied `Pixmap` (borrowed) and composites back via `ImageSource::Pixmap`. It keeps a stack of `FxFrame`s and `base` is the current target's, saved on push and restored on pop. The offscreen route is used even for the two effects `vello_cpu` could serve, so every effect goes through one mechanism, a background blur's backdrop included.
  - **Buffer size** comes from `effects::effect_buffer`, capped at `effects::MAX_EFFECT_BUFFER_SIDE` = 8192 by resampling (growing `k`), not truncation (truncating cuts the silhouette a shadow is cast from; a larger buffer aborts wgpu validation). The fixed cap, not the device's, so both backends choose the same buffer; it also equals vello's `MAX_ATLAS_SIZE`.
  - **GPU**: a `vello::Scene` is a recording, so `GpuScenePainter::push_effect_layer` redirects drawing into a sub-scene with the same clamped box, rounding and scale; `pop_layer` closes it into an `EffectJob` and draws an atlas image slot into the enclosing scene. After the walk, `VelloGpuRenderer::resolve_effects` rasterizes jobs, runs `fx_gpu` compute passes (one batch per vello pass: `fx_gpu::run_batch`, one encoder and one `queue.submit`), and points each slot at the result with `Renderer::override_image`, deepest nesting level first. Slots are unregistered at frame end, whichever pass failed (they are keyed by blob id and minted per frame; `resolve_effects` pushes each onto the caller's list as it registers it).
  - **Pooling**: `fx_gpu::FxPool` pools scratch textures by size class (`fx_gpu::size_class`, two steps an octave), usually larger than asked, so no pass may read past `Params::size`. A pass's source and scratch return after its submit; its result is held to `end_frame`. Pool trims to the largest working set of the last eight frames; bind groups are cached per texture triple.
  - **Register on the renderer that draws the slot**: a nested layer's result is drawn by its parent's sub-scene, which belongs to a level-above pass with its own atlas. Passes are planned before any runs; `Holder` records where each slot went.
  - **One vello pass per renderer is a correctness rule**: vello's image atlas evicts images not drawn for two resolve passes, so a renderer doing N passes loses a picture appearing in only one. Sibling layers pack into as few textures as possible (`Scene::append` at each slot's origin, inside a clip to the slot) and every pass takes the next renderer, built on demand. Renderer count = nesting depth for nested effects, and = total effect-buffer area / page area for siblings. Nothing caps the pass count; a renderer costs a one-time ~6-8 ms build (more under contention). A renderer pool was declined.
  - **Pass budget**: `pack` starts a new chunk rather than let a pass exceed the page's pixel area (vello's fixed intermediate buffers cannot report overflow; past it the fine shader hangs and Windows resets the GPU).
  - **Alpha**: `vello_cpu`'s `Pixmap` is premultiplied; vello GPU output and its atlas are straight, so `fx_gpu` brackets the stack with `premul`/`unpremul`.
- GPU output is not byte-identical to CPU in general (antialiasing differs); the on-device suite runs with `cargo test -p ondin-render --release -- --ignored`, at the default thread count: each `gpu_effects` and `fx_gpu` test holds its binary's adapter lock while it has a device (re-entrant on its thread in `gpu_effects`, where a test makes a second device to compare against), since devices made side by side hung the suite. The effect passes are the exception: shaders quantise on the same 8-bit ladder with the same host-built kernel. `tests/fx_gpu.rs` allows one channel of error; `gpu_effects::both_backends_draw_the_same_shadow` asserts exact equality on integer-pixel fixtures.
- **Axis-aligned edges are rounded onto whole device pixels.** vello blends each path's coverage independently (no MSAA mode helps: it collapses coverage to a scalar per path first), so shapes sharing a fractional edge leak a lighter seam, and where one shape's edge is rounded and a coincident one is not, a sliver of the shape beneath shows. With the world origin on a whole device pixel (`Camera::viewport`), an edge's phase depends on zoom only, so such a sliver stays put. Every snapped edge rounds by one rule on one global grid, `scene::device_base` (the same affine `cpu::CpuPainter::base` and `gpu::GpuScenePainter::base` apply; the three must agree), so abutting and coincident edges land on the same pixel. Only where the device transform is a pure scale and translate; `scene::SNAP_BOXES_TO_DEVICE_PIXELS` switches both arms.
  - **Boxes** (`Rect`, `Artboard`): `scene::snapped_box_world` adjusts the world transform so both device edges are integers; a box thinner than a pixel keeps one. Every snap rounds through `scene::snap_round`, a tie always up and decided past floating-point noise, so a whole-pixel pan rounds each edge as a fresh frame does (`tests/seam.rs · a_whole_pixel_pan_moves_every_snapped_edge_by_the_pan`). It applies to the node's own ink only (background, clip, stroke), never its children. A box already on the grid is returned untouched (round-tripping perturbs the matrix, and `assert_preview_matches_commit` compares exactly).
  - **Centred strokes** of every other kind but text (`scene::strokes_snap`; not in outline mode, which traces the centre line): `scene::snapped_stroke` builds the ink as one rectangle per segment, reaching over a join by half the width and past an end by its cap, rounds each edge as a box edge is rounded, and fills it in the stroke's brush. Only when every segment is a horizontal or vertical line, the device transform scales both axes alike, and the stroke is undashed, not per-side, butt- or square-capped and, where the path turns, mitred with a limit of at least √2; anything else is stroked as stored. A stroke under a pixel wide keeps its width, centred in the one row its edges round into, so a zoomed-out hairline grid does not turn bold; when both edges round to one pixel boundary, it is laid against that boundary on the side of it that every box edge rounding there, alongside the segment, puts it (`scene::Edges`: the walk's snapping boxes, on the device before rounding, gathered from `Resolved` on first use and leaving out what a gesture moves or reshapes), so a box over it covers it and a box beside it does not hide it whatever the box's opacity; with no such edge, or two that disagree, it stays where it lies.
  - Image editing's chrome ghost and the layer it is glued to are exempt from both together (`RenderOverrides::unsnapped`): their different rounding made the ghost slide.
- **Paint order**: `paint_shape` draws visible `fills` in `Vec` order then `strokes` in `Vec` order. Text paints the same shaped runs per visible fill (falls back to black when none); a `Line` skips fills. A frame's fill loop is separate (fills behind children, strokes over them and outside its clip), so a rule added to one of the two loops is owed to the other.
- **Stroke alignment is built in `scene.rs`** (no backend has it): stroke at twice the width and clip away the unwanted half. Inside clips to the shape by its own fill rule; outside clips to the shape plus an enclosing box, even-odd. A non-zero path or glyph outline may cross itself, where that complement counts the overlap as outside, so its outside stroke is drawn whole in a layer and the shape's non-zero fill erased from it (`ScenePainter::push_erase_layer`, `Compose::DestOut`); the SVG writer does the same with a `<mask>`, and the PDF follows its SVG. The box must clear the ink: `scene::outer_bounds` takes `reach = scene::miter_reach(width, limit) = width * limit.max(1.0)`. That is why `push_layer` has a `ClipRule` and `StrokePaint` has no alignment. `geometry::stroke_align_applies` gates alignment to closed outlines (renderer, SVG writer, inspector all ask it); a `Boolean` is answered by kind.
- **Per-side strokes are one call per edge** along open paths: `geometry::side_path(kind, side)` splits corner arcs at their 45 degree midpoints (as CSS `border-top` with `border-radius`). Radii come from `RoundedRect::from_rect(...).radii()`. `closed` is asked of the kind, not the path.
- **One alignment clip per run** of consecutive same-aligned strokes (`scene::paint_strokes`), not a sort (list order is z-order). All four sides of a per-side stroke ride one clip.
- **Type strokes** use `ondin_core::text::outline` from the cached layout, built only when a visible stroke exists, then the same `paint_strokes`. Frame is the text box (`layout.bounds()`), passed explicitly.
- **Dashes** reaching a backend are resolved: `geometry::resolved_dashes(stroke, width, path)` takes the width actually laid down. A zero-length dash under `Cap::Butt`/`Square` becomes a square dot one width long with the gap shortened (period preserved). `dash_fit` scales the pattern via `geometry::fitted_dashes` to the *nearest* whole period count, measured per subpath (`geometry::dash_fit_pieces`; `None` when there is nothing to fit).
- **Very wide strokes are filled, not stroked**: `scene::lay_stroke` (past the gate `width >= min(bbox)`, closed, solid) expands with `kurbo::stroke`, drops inner contours (`outermost_subpaths`), appends the outline, winds alike (`wound_alike`) and fills. The SVG writer lacks this, so very wide strokes may differ between canvas and export (§7).
- **The mitre limit** passes through as the stored ratio (`kurbo::Stroke::with_miter_limit`); degrees belong to the panel.
- **Image fills**: `scene::framing_of` resolves one `Framing` per draw, reading intrinsic size from the document's image table (not the decode cache), so a picture mid-decode frames at its final size. vello takes the transform per call as `brush_transform` (so framing is computed in local space); `vello_cpu`'s paint transform is context state, so `apply_paint` sets it on every call (the framing for an image, `brush_to_backend`'s second answer otherwise), else an image's framing would transform the next shape's gradient. The extend belongs to the fit and is applied at the boundary (`color::apply_framing`, `color::framed_sampler`), never written to the model. Pixels come from `ImageStore::pixels`; `color::framed_transform` composes the framing over the buffer's own grid and neither backend may set a brush transform without it. `scene::clipped` wraps the single draw a letterboxing `Fit` asks for. `paint_strokes` takes its frame as an explicit `Rect`.
- **A missing picture is a drawing**: `scene::fill_or_placeholder` is the one place a fill becomes ink (shape fills and artboard backgrounds); where `has_image` says no pixels it calls `scene::paint_missing` (`ondin_core::missing_placeholder` ground, then a layer clipped to the shape's own path with the cross and rim). Strokes and text with a missing picture draw nothing, as a `return`; the CPU backend must also return (it once drew text in the previous node's colour because `vello_cpu` paint is context state).
- **Colour (`color.rs`)** is the single conversion point from document colours (sRGB straight alpha) to each backend's contract, verified by a pixel test.

## Traps

- Layer order, outermost first: blend, effect, then the opacity and clip layers. Each is popped at the end of `paint_node`, so every early return owes a pop.
- A page and a top-level frame isolate when they hold a blended layer even at their default Pass through; dropping that rule makes the canvas mix a Multiply layer with the ground while every export (drawn alone) does not. Pinned by `tests/blend.rs · a_top_level_frame_isolates_what_blends_inside_it` and `a_blending_shadow_isolates_the_page_and_its_top_level_frame`, and on device by `gpu_effects.rs · a_loose_blended_layer_does_not_mix_with_the_ground`.
- `push_effect_layer`'s default is a plain layer; a backend overriding must count frames in `pop_layer`.
- A backdrop is erased and then added, never drawn over: drawn over, a faded glass fades what is under it twice (`tests/backdrop.rs · a_faded_glass_shows_its_blur_at_its_opacity`). Its repaint starts at the nearest isolating container, not the walk's origins (`the_backdrop_stops_at_the_nearest_container_that_isolates`).
- `shadow_passes` draws drop shadows last first, matching how `effects::run` stacks them; list order looks natural and swaps which shadow covers which. Pinned by `tests/blend.rs · drop_shadows_keep_their_stacking_when_one_blends`.
- Preview fallbacks: readers fall back to used geometry; `current_kind` falls back to the document. Merging them passes every test.
- `render_regions` culls one full-canvas walk to the regions; it never draws a smaller viewport per region. The effect limit, budget and coarse-grid anchors are the canvas's, and a region-sized viewport would draw effect buffers the kept pixels were not drawn with. `tests/gpu_regions.rs · a_canvas_kept_across_pans_draws_the_full_frame_where_it_draws` compares the regions with a full frame; `a_frame_shaped_by_where_the_canvas_sits_is_pinned` pins the refusal.
- Two defences: a moved flex item's copies stay in their slots because the door drops the move's follow *and* the layout passes take no follow for a drag; either alone suffices, so either looks removable.
- `RenderOverrides` is not exercised by the raw differential for commit-door passes; use the "through the doors" twin.
- Pixel snapping, `device_base`, `CpuPainter::base` and `GpuScenePainter::base` must stay in step.
- `snapped_stroke` rounds each stroke edge on its own, as `snapped_box_world` rounds a box edge. Rounding the centre line and the width instead looks equivalent but puts one edge a pixel off whenever the width rounds, leaving a sliver of stroke under a box that ends there; `tests/seam.rs · a_stroke_ending_where_a_box_over_it_ends_stays_covered` pins it at zoom 1.5.
- Level of detail stays off in `RenderOverrides::default()` and is turned on per frame by the screens that want it; defaulting it on makes exports and thumbnails drop sub-pixel ink and small shadows. Pinned by `tests/render.rs · level_of_detail_skips_ink_under_half_a_device_pixel` ("drawn without the flag").
- Anything that changes what the canvas draws must move one of the `DrawnKey` inputs, or the canvas keeps a stale texture: a new `RenderOverrides` setter moves `EditorSession::drawn` or joins the key by value, and a new way pixels change in `ImageStore` moves `generation`. Pinned by `canvas.rs · each_change_to_what_is_drawn_draws_once` and `a_decoded_picture_draws_the_page_again`; `frames_that_change_nothing_draw_nothing` pins the skip. No headless test reaches the `wants_frame` term (the headless canvas never walks the page).
- A preview is patched, not redrawn, so a new `RenderOverrides` field the walk reads must be named by `touched()`, or its node's old pixels stay. Anything else that changes `Resolved` without moving `revision` needs a stamp of its own in `DrawnKey`, as `shaped` is: folded into `drawn`, a font re-shape passes `previews_to`, and with no preview on either side the damage is nothing and the old glyphs stay. `tests/gpu_regions.rs · a_frame_patched_where_a_preview_changed_is_the_full_frame` pins the damage for a drag on device; `canvas.rs · only_a_preview_changing_is_patched` pins that a re-shape is no preview, edit or pan, and `an_edit_redraws_only_where_it_changed_the_page` runs the preview kinds through the headless canvas.
- An edit is patched from its dirty set, so an operation that changes what a node draws must dirty it, or its old pixels stay. `InkLog::record` runs after the document is applied (the walk up to the tops reads the new tree) and before `Resolved::update` (the old ink it reads would be gone). `canvas.rs · an_edit_redraws_only_where_it_changed_the_page` pins the recorded ink.
- Atlas failures are silent in vello and invisible to `has_image`.
- Never substitute a "big rectangle" for `clip: None` on the GPU.
- One vello pass per renderer; splitting a level without splitting renderers brings back the vanished-image bug.
- A new `Operation` variant needs adding to the no-op fixtures in both `overrides.rs` and `op.rs`.
- Gradients on a line or path are carried by the resize tool, never by `paint_box::keep_gradients`: a path's box also moves on a point edit, which must leave its gradients where they are. Widening `keep_gradients` past `NodeKind::box_size` carries them on every point drag.
