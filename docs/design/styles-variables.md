# Styles and variables (§5.3f)

Variables (named, typed, per-mode values that fields bind to) and styles (reusable per-slot sets of values), how kits carry both, the binding chrome, and the commit-time passes that keep bindings honest. Text styles and the text node are in `text.md`; components and overrides are §5.3d.

## 5.3f Styles and variables

### Variables

A **variable** is a named, typed value — **colour, number, string or boolean** — with **one value per mode**. An **alias** is a per-mode cell naming another variable of the same type (not a fifth type). CSS custom properties are the model.

**Modes**
- One mode list per document, no collections (`roadmap.md`); the default mode is the first.
  `variable::move_mode_ops(doc, mode, index)` reorders: a `RemoveMode` then an `AddMode` of the same
  mode (same id and name) with its whole column at the new index, so frames set to it and kit mappings
  keyed by its id hold. Index 0 makes it the default every unset frame reads.
- Only a **frame** (an `Artboard`, never a group) sets a mode, exactly one: `Node::mode: Option<ModeId>`; `None` inherits from the nearest ancestor frame that sets one, else the default.
- On an instance, a mode set on the copy is an override like any field (§5.3d).
- Deleting a mode returns every frame set to it to inherit, in one undoable transaction.
- A kit's variables use the kit's own modes, mapped onto the document's by one per-kit mapping (below). A frame may be set to a kit's own mode (a kit main's, carried to its instances); it governs only that kit's variables, and `mode_at` passes over it.

**What binds**
- **Numbers**: W, H, a layout item's min/max width and height (as px), corner radius, layer opacity (a percentage 0–100), stroke width, an effect's X/Y/blur/spread, layout gaps and padding, and a text's size, weight, line height, letter spacing and paragraph spacing (the node's defaults, never a run's or paragraph's own). **Not** X, Y or rotation (placement, which an instance keeps as its own — `reset::placement_is_own`). W/H bind only where the user set them (never a hugging frame's, a text box's, or a size a flex/grid layout deals out or stretches). Stroke width and effect numbers bind in the item, one at a time; a stroke drawing per-side widths takes none, and an effect binds only the numbers its kind has (a layer blur's radius is the blur).
- **Colours** bind a whole solid paint, never a gradient stop (a reusable gradient is a fill style). The variable carries its own alpha; the fill's `%` stays a separate unbindable field and what draws is the variable's colour times it.
- **Booleans** bind visibility.
- **Strings** bind text content and font family. Binding the content clears its spans; binding a default clears the runs or paragraphs that hold their own value for it. A text style holds plain values, so the family and the character numbers never bind under one; the paragraph spacing, which no text style holds, does.
- A field that is also a component property's needs no rule: the property is a view over the field (§5.3d).

**A bindable field stores its binding and resolves it at read.** The binding is a sidecar beside the field's literal (`Node::corner_vars`, `size_vars` and the rest of the table below), the literal a placeholder while bound; only paint is an enum (`BrushSource::{Literal, Bound}`). The value drawn is found against the mode in force at that node. So:
- Overrides compare the binding: a main rebinding *brand* → *accent* reaches a copy still bound to *brand*; a copy bound elsewhere keeps an override. So the main's literal writes do not follow onto a field the copy binds otherwise: a content write (`SetText`, span writes) skips a copy whose content binding differs, and a size or corner follow keeps the copy's own literal on each axis or corner it binds otherwise (`propagate::keep_own_bound_geometry`) — its literal 0 would otherwise read as the main's old value and take the new one.
- Editing a variable writes no node, so nothing propagates. §12's "resolved value is in no node" holds, where §5.3d's copies bend it.
- Every reader must resolve (`container::lay_out`, `scene::build`, the SVG writer, the snapshot, the inspector); one that skips it draws the fallback silently. Code export alone keeps the binding: it writes `var()` against a `tokens.css` with one block per mode, every alias redeclared in each (`export.md`, *Code export*). Paint is guarded by a type with no `Deref`; other fields by `Document` resolve readers.

**Deletion and leaving a document**
- Deleting a variable in use **detaches** every field bound to it to the value it resolved to, as ops in the deleting transaction (as a deleted main, §5.3d). Deleting a style detaches its users likewise.
- A paste into another document rebinds to a variable of the same name and type, else detaches to the resolved value; within a document the binding is kept. *Paste properties* uses the same rule through `variable::rebind`; presets hold nothing bindable.
- A ghost (drag preview) resolves in the default mode; the snapshot reports the resolved value.

### The table and the readers

`ondin_core::variable`: `Variables { modes, vars, kits }` — modes in order, variables by `VarId`, per-kit modes by kit id; `ModeId`/`VarId` are `NodeId` newtypes from the session's `IdSource`. Each variable is a name, a kind (`Color`, `Number`, `Boolean`, `String`), one `Cell` (value or `Alias`) per mode and a `description` (free text, empty is none). `Document::variables` reads it. `SetDescription { of: Described::Variable(id) | Described::Style(id), text }` writes a variable's or a style's description (a main's too, §5.3d); it draws nothing and dirties nothing.

Readers built on `mode_at` (which counts the node itself): `resolve_var`, `resolve_brush`, `resolved_paint`, `resolve_corners`, `resolved_display`, `shown`, `resolved_kind` (applies `text_drawn_in`), `resolved_item` (applies `limits_drawn_in`), `drawn_opacity`, `stroke_width_drawn_in`, `resolved_effects`.

**`variable::check` is a post-condition of every transaction and a check of the loader**; it refuses a dangling binding rather than repairing it. Save format v7–v9 (§5.11); operations, invalidation and the paste rule are in §5.7, §5.11, §5.9.

### The binding shapes

Each "keep" pass runs in `commit_inner` and judges a write over a bound field so no door has to know about bindings.

| Field | Storage | Literal while bound | Reader | Commit pass |
| --- | --- | --- | --- | --- |
| Paint | `Fill::brush`/`Stroke::brush` = `BrushSource::{Literal(Brush), Bound{var, alpha}}` | n/a (`%` rides in `alpha`) | `resolved_paint`, then `BrushSource::drawn` (bound = transparent; use only below a resolve) | decided at the write |
| Corners | `Node::corner_vars: [Option<VarId>;4]` beside `Rect`'s radii | 0 | `resolve_corners`; `Resolved`'s used kind | `keep_corner_bindings` |
| Gaps/padding | `Node::spacing_vars: [Option<VarId>;6]` (col gap, row gap, pad T/R/B/L) | 0 | `Document::resolved_display` (a `Cow`) behind `LayoutView::display` | `keep_spacing_bindings` |
| Visibility | `Node::visible_var` beside `visible` | `true` | `Document::shown` (layer's own eye, not ancestors') | `keep_visible_bindings` |
| Opacity | `Node::opacity_var` (percent, clamped 0–100) | 0 | `Document::drawn_opacity` | `keep_opacity_bindings` |
| Stroke width | `Stroke::width_var` in the item | 0 | `resolved_paint_in` substitutes and clears `width_var` | `keep_stroke_width_bindings` |
| Effect numbers | `Effect::vars: EffectVars` (X, Y, blur, spread) in the item | 0 | `resolved_effects(_in)` substitutes and clears bindings | `keep_effect_bindings` |
| W/H | `Node::size_vars: [Option<VarId>;2]` for `Artboard`, `Rect`, `Ellipse`, `Polygon`, `Star` | 0 | `LayoutView::kind` via `Document::resolved_kind`; `resolve::with_bound_size` for unlaid layers | `keep_size_bindings` |
| Size limits | `LayoutItem::limit_vars: LimitVars` (`[Option<VarId>;4]`: min W, max W, min H, max H, `LayoutItem::limit(k)` order) in the item | `Px(0)` | `Document::resolved_item` (`limits_drawn_in`) behind `LayoutView::item` | `keep_limit_bindings` |
| Text | `Node::text_vars: TextVars` (`[Option<VarId>;7]`, `Text` only): content and family to string vars, then size, weight, line height, letter spacing, paragraph spacing to number vars; `variable::check` asks each slot's kind of `text_slot_kind` | content empty with no spans; family empty; a number 0 in its unit (weight 0) | `resolved_kind` (`text_drawn_in`); `with_bound_size` | `keep_text_bindings` |
| Frame mode | `Node::mode` | — | `mode_at` | — |

Passes run in table order, `keep_size_bindings` after `keep_flex_sizes`, `keep_limit_bindings` after size, `keep_text_bindings` after the limits; all before `propagate::owed`. `paint_box::keep_gradients` (§6.2) runs between the last and `owed`, because a detached size binding's literal is a size write its gradients must follow; it measures both boxes through the size bindings, so the placeholder 0 is never a size it carries to. `owed` runs it again last, for the sizes copies follow.

Per-shape rules. The **two-half rule** (corners, gaps, stroke width, effects, W/H, size limits, text): a write over a bound field leaves it bound if it writes what the field draws *or* its own literal; either half alone detaches fields nobody edited (a field reads drawn values and writes them back; Scale, reorder and per-corner reset rebuild from literals).
- **Corners.** Readers of the document's own kind see 0, so the inspector reads corners as drawn. Price: a 0 typed into the field detaches nothing; the chip's retype (which detaches first) is 0's door. Only `Rect` corners bind; a `Path`'s per-anchor radii don't, by decision (indexed by anchor, which point editing inserts/deletes).
- **Gaps/padding.** A layout taken away clears its bindings (on a copy whose layout a follow takes, `propagate::owed`'s last step); a binding on a layout-less node is inert, and deleting its variable (`variable::remove_ops`) or a paste that cannot rebind it (`variable::land`) clears it, having nothing to detach it to. The spacing and corner judgements are functions the preview shares (`build::kept_spacing_vars`, `kept_corner_vars`) so a write the commit detaches previews where it lands.
- **Visibility.** Everything that draws, picks, lays out or exports asks `shown`, so a layer its variable hides leaves its layout's flow. **One half only**: written what it shows stays bound; anything else detaches. The literal half would excuse the `true` the eye and *Bring back into flow* write to show a hidden bound layer, keeping it bound and hidden.
- **Opacity.** One half only (the drawn value), because 0% typed over a bound layer means "make it invisible"; no writer builds an opacity from the literal. The chip is on one layer's Appearance card only; the several-layer row writes the outermost members' shared value and takes no binding, detaching in the edit itself.
- **Stroke width.** Preview bounds, hit test, snapshot and ghost all read through `resolved_paint_in`; clearing `width_var` on output matters because a preview override holding a resolved paint is resolved again by the scene against the committed table. `kept_stroke_widths` is shared with the preview; a binding the write changes (bind, detach, reset, new stroke) is left as written. A `Custom`-sides stroke on a **box** (`build::draws_own_sides` via `geometry::effective_sides`) takes no binding: `bind_stroke_width_ops` refuses it and `kept_stroke_widths` detaches a bound one at the width it drew, whoever wrote it (checked before the "binding the write states" exemption, so a pasted bound `Custom` stroke lands detached). On an ellipse or path `Custom` draws whole at `width` and binds normally. The shared weight row clears bindings it writes, except a stroke whose bound width already draws the typed one. The pass rewrites lists in place.
- **Effect numbers.** `resolved_effects` reads a bound blur within `0..=effect::MAX_BLUR` (`Effect::number_read`), the range `Document::apply` holds a typed one to, so a detach never writes a blur the operation refuses; offsets/spread as they are. `kept_effect_vars` is shared with the preview; a binding on a number the effect's kind no longer has (shadow retyped to layer blur) is dropped whoever wrote it. Chip on one layer's own effect; popover fields over several layers stay plain and clear the slot's binding in their write, except on a layer whose bound number already draws the typed one; a number equal to the committed one writes nothing. The write is retargeted onto each layer's own item ids. The retype range is the card's own (blur `0..=MAX_BLUR`, offsets/spread `±MAX_OFFSET`). The pass rewrites in place.
- **W/H.** Only a hand-set axis binds (`build::size_axes_authored`): not `%`/`fit-content`, not pinned at both ends, not a flex item's main axis with growth/basis, not a stretched flex cross axis or grid axis sized `auto` (shrink, min-, max- don't count). In `kept_size_vars` the resized axis detaches and the other stays bound; "what it draws" includes the *used* size a layout's shrink or min/max squeezes it to (given `Resolved`), which the H field and top/bottom handles carry forward on the other axis. An axis an edit makes computed (keyword, second pin, growth, basis, stretch, reparent into a layout, a layer shown or unmasked into the flow, a bound layer an `InsertSubtree` brings into a layout, judged by the bindings it arrives with) detaches to the size drawn before; that half judges the tree the transaction leaves on a scratch copy built with `apply_unchecked` (a member moved out of its instance fails `component::check` until `settle_links` runs). `propagate::owed` runs the pass again over the whole transaction after the follows, so a copy's own size binding that a followed layout write makes computed detaches too. `keep_insets` reads sizes from the document this pass leaves, and its scratch copy is unchecked for the same reason. Binds on one layer's Transform card only; text boxes' W/H don't bind.
- **Size limits.** A bound limit is px: its variable's number floored at 0, its literal `Px(0)` (`build::bind_limit_ops`). The bindings sit in the item beside the values, as an effect's do, so every door that writes the item from the stored one (propagation, reset, a variant's merge) carries them with no arm of its own. `build::kept_limits`, which the preview's `SetLayoutItem` arm shares, keeps a binding on a write of the literal or the drawn px and detaches on any other value, a mode or unit picked to `auto` or `%` included; a binding the write itself sets is left alone. A detach (`detach_limit_ops`, `variable::remove_ops`, `detached`) writes the drawn px. The limits bind to number variables only (`variable::check`). The pass rewrites in place.
- **Text.** Binding writes the bound literals empty or 0 (`build::bind_text_ops`); the slots a text style holds (`variable::TEXT_STYLED`, family to letter spacing) don't bind under one. A number reads its variable as the number its field shows, in the literal's unit (`variable::set_text_slot_number`): size in px floored at `MIN_FONT_SIZE`, weight rounded into 1–1000, line height (floored at 0), letter spacing and paragraph spacing in px or, where the literal is an em, in % (hundredths of an em); an Auto line height binds as px. Binding a default clears the runs or paragraphs with their own value (see *Traps*). A `SetText` of the drawn string with no spans stays bound (`""` is what a deliberately emptied text writes; one half); anything else detaches. Spans written over a bound content become a `SetText` of the drawn string, detaching. A family or number that a `SetTextStyle` (for the paragraph spacing, a `SetParagraphStyle`) writes drawn or as its literal stays bound, its literal put back; any other value detaches, the same number in another unit too. Applying a text style detaches the `TEXT_STYLED` slots and leaves the paragraph spacing bound. A run or paragraph given a value is a span, the default staying bound under it. A copy's `TEXT_STYLED` bindings under its main's text style are cleared by `style::settle`, since the copy receives the `SetTypeStyle` by propagation, after the pass. A bound content draws with no spans (`text_drawn_in`): the passes keep spans off it, and this second defence stops a byte range cutting a string whose length is the mode's. `keep_insets` reads the document both passes leave.

**Saying what was cut.** `session::variables_detached` names every variable a slot loses (*Detached size/w*, *Detached N variables*) from the `Set*Vars` ops appended between `asked_ops` (after `keep_flex_sizes`, before the first pass) and `propagate::owed`; `said_detached` merges it with `styles_detached`. The stroke-width and effect passes rewrite in place, so `commit_inner` notes the bound widths/numbers before and the cut ones after (`stroke_widths_bound`/`_cut`, `effect_numbers_bound`/`_cut`). Edits whose own ops set a binding, and inspector doors, say nothing; the layers panel's eye and the hide chord leave it to the pass. A paint's binding is decided at the write, so `replace_image_fill` (the one canvas door overwriting a bound paint) reads the fill's variable first and folds it with `EditorSession::last_detached` into its *Replaced with ‹file›* status; *Replace image…* and *Paste properties* report likewise (`OndinApp::replaced_status`). The image card is read-only under a styled Fill card.

### Styles

A **style** is one slot's isolated set of values (an isolated CSS class, not the cascade). **Slots: fills, strokes, effects, text, layout.** A node holds at most one style per slot; styles don't stack. A style's values may be variables.

- **A card is styled or not as a whole**: editing any field of a styled card detaches it; no partial override, no inheritance.
- **The inspector is read-only on a styled card** (fully or partly); a style's values change only through the browser's *Edit*, live to every user. Every other door (canvas gesture on a styled or bound value, *Paste properties*, MCP) detaches, and the floating status says what — refusing would leave canvas handles dead.
- **A layout style** carries the container's whole `Display` (flex or grid, tracks included) and gap/padding bindings — never an item's grow or `align-self`.
- **A text style** holds the character defaults less colour and language (colour is the Fill card's, language the words'), neither the paragraph nor block scope, and a plain family. Spans stay the text's own marks over the style: styling a selection keeps the style; only a write of the defaults detaches.
- **A style is not resolved at read.** A styled layer's own list holds a copy of its style's values, which the commit writes; readers of fills, strokes, effects or type never ask the style table (the opposite of variables).

#### Table and ops

`ondin_core::style`: `Styles` by `StyleId` (a `NodeId` newtype) on `Document`; `Style` = name + `StyleValue` + `description`. Names are slash paths, unique within a slot, not across slots. Bindings: `Node::styles: StyleRefs { fills, strokes, effects, text, layout }`. Binding ops per slot (`SetFillStyle`, `SetStrokeStyle`, `SetEffectsStyle`, `SetTypeStyle`, `SetLayoutStyle`) write the binding alone. `AddStyle` and `SetStyleValue` refuse a value holding a non-finite number (`OpError::NonFinite`, asked of the save format itself by `style::survives_save`).

`StyleValue`:
- `Fills`/`Strokes`/`Effects`: the card's whole `Keyed` list (a stroke style carries width, join, cap, dashes, alignment).
- `Text(Box<TextStyle>)`: the type part (`style::type_part`: defaults with `color` and `locale` cleared). The commit writes it as `SetTextStyle { spans: None }` over the layer's own colour and language, compares type parts, and re-states spans against the new defaults (a span the new defaults equal is dropped; only `Ctrl+Z` brings it back). `SetTextSpans`/`SetText` are not the slot's writes; `SetTextStyle` is but detaches only when it moves the type part. `style::check` refuses a text style on a non-text layer.
- `Layout(Box<LayoutStyle { display, spacing_vars }>)`: the only slot written by two ops (`SetDisplay`, `SetSpacingVars`; `StyleValue::write_ops`, `writes_slot` maps both). A layout-less layer has no layout value (`StyleValue::of` → `None`), so no style is made from one; **applying a layout style to a plain frame gives it the layout**. Only frames and groups bind one. `edit_through` builds the edited value from the user's display and bindings with each write applied, judging a `SetDisplay` by `kept_spacing_vars` as the commit's spacing pass would (that pass never sees a write folded into the style), except where the same edit states that user's `SetSpacingVars` (a bind or a detach): there the display is taken as written, as the spacing pass leaves a stated binding as stated.

#### `style::settle`

`style::settle` is the whole of "styled or not as a whole". Run by `propagate::owed` **first and last**, it finds every bound slot not holding its style's look (values compared, item ids not) and:
- **rewrites** it from the style when the transaction edited the style or set that binding, or when no op of the user's edit or the doors' rewrites wrote the slot (a component follow, a paste rebound by name);
- **detaches** the layer (values kept) when one did.

So canvas, *Paste properties* and MCP detach with no door knowing. Both runs matter: the first lets a main's rewrite/detach reach copies, the second restores a copy on another style that a follow drifted. When the first `settle` writes a `SetDisplay`, `propagate::owed` runs `keep_size_bindings` again over the whole transaction before the copies follow, so a child's bound W/H that the style's layout makes computed detaches and the copies follow that; it runs once more, always, after the second `settle` (§5.3d's pass order).

`style::check` (post-condition of `apply` and the loader): names unique per slot; no item id twice in a style; paints bound to colour variables only; stroke width, effect numbers and layout gaps/padding to number variables only (an effect's numbers only where its kind has them, since `settle` could never write the rest onto a user); every binding names a style of its slot; **no vault node bound to a style of the document's own** (a vault node's styles are kits', and a kit's style reads only kits' variables).

Deletion: a bare `RemoveStyle` of a style in use is refused; `style::remove_ops` detaches users first. Deleting a variable a style's paint reads detaches the style to its colour **in the default mode** and rewrites the users from it (they stay styled; a user in another mode changes colour). A paste rebinds a style by id, else by name+slot, else detaches.

### Chrome

**Binding chrome rules**
- A fully rounded **capsule means a reference** (a bound field's chip, a collapsed styled card, an alias); nothing else in the inspector is round. No hue; the accent still means selected.
- A bound field is a **chip** at the field's own width showing the variable name (elided by whole groups from the left), tooltip *name · value · Mode*; a typed literal, `Backspace`, or the chip's hover × detaches; it does not scrub (a bound number draws the unbound field's own prefix, `ui::prefix_strip`/`paint_prefix`).
- *Mixed* is a capsule only when every target is bound to different variables (`field_mixed_vars`; tooltip lists names, no hover × or field menu); some bound, some not stays the plain grey *Mixed*. Sits beside §5.3d's override dot.
- **Binding is by typing `--`** into the field; it takes the whole field (`--x * 2` is refused: `expr.rs` is a calculator with no names). `--` opens the one shared list (`panels/binding.rs`), filtering by substring, previewing live (a corner's as the radii it will draw via `absorb` patching a `SetCornerVars`), and is a rung of `Escape`. **Refusal**: a whole name with more after it (`binding::refused`, asked only once nothing matches) turns the list into one sentence and dims the refused tail with a dotted underline (`refusal_galley`, `underline_refusal`). A refused `Enter` leaves the field as typed and focused.
- Field right-click (`context-menus.md` §6.7): *Bind to variable…*, *Extract into variable…* (value into every mode, disabled when bound), *Detach variable* (omitted unbound). *Extract* is one transaction (variable + a first mode if none + bind), then the browser renames it; solid files at full alpha, `%` staying the bind's.
- Focused, a chip consumes `Backspace`/`Delete` as detach (so the keymap never deletes the layer) and hands any other key to the field's buffer as the start of a literal. A hex typed over a binding writes the literal outright (`build::set_brush_at_all`), not through `edited_brush`'s as-drawn reading.
- A colour swatch popup gains a **Variables** tab (4th paint kind; picker width 272). `OndinApp::variables_face`: search plus every colour variable under group headers (the document's own first, then each kit's), row = swatch, elided name, hex in the layer's mode, current checked; click binds keeping `%`. A bound paint opens on it. *Solid* over a binding detaches (`detach_field`); *Linear*/*Radial* convert the drawn brush, which detaches. Where the face can't be named (selection rows whose targets disagree; the *All* row) *Solid* writes as drawn, which is kept: it changes nothing drawn and a `%` ≤ 100% can't draw more opaque than its variable.
- Styled card: collapses to one 28-high capsule (preview, name, summary, *Detach* on hover); the five slot cards' headers gain a `⋯` after the `+` (`ui::HEAD_MORE_W`): *Apply style…*, *Create style…* (*as a copy…* when styled, *…from these N layers…* over several; off over *Mixed*, a partly styled card, or disagreeing lists), *Detach style*. The `+` hides while any target is styled, except under an edit. A popover opened from a locked row (an effect's, a stroke's) takes the lock itself (`styles::lock`), since an `Area` inherits none; an undo or redo that lands a style under an open picker closes the picker.

**Per-field doors**
- **Paint row / corners** (`FieldKey::Paint`, `Radius`, `Corner`): swatch shows the resolved colour and its `%` is the binding's alpha. Each corner binds alone in the per-corner disclosure (`FieldKey::Corner` in `CornerVars` order; `build::detach_corner_ops` leaves the other three); the all-corners field is the chip only while all four share a variable. The radius `DragValue` lays out its own text, so it hands `--` to the chip's retype buffer, which detaches before its write only if a chip was typed over. On an instance a corner binding is an override of the radius field (mark joins binding and literal via `OverrideMark::and`; ↺ writes the main's `SetCornerVars` beside its radii).
- **Gaps/padding** (`panels/layout.rs`, `FieldKey::Spacing { id, slots }`, a bit per `SpacingVars` place; `number_chip`, `number_retype`, `binding.rs`'s `bound_field_ui` and `field_doors`, which every bindable number field draws through): a bound gap field's CSS name gives way to the chip; opposite sides bound apart open per-side padding rows; a value typed over a *Mixed* capsule detaches every slot it covers; on instances the binding's mark joins the literal's.
- **Visibility** (`FieldKey::Visible`, never typed): bound, the identity card's eye sits in a 22×18 capsule, click writes the other value (commit detaches), right-click is the field menu. The Properties card's Boolean switch is a 38×22 capsule when every layer it views is bound; the layers panel draws a bound layer's eye at rest in a 22×18 capsule.
- **W/H** (`FieldKey::Size { id, axis }`, only on axes `build::bindable_size_axes` calls hand-set; the multi card's W/H take none). ↺ on an instance writes the main's `SetSizeVars` beside its size.
- **Size limits** (`FieldKey::Limit { id, slot }`, a `LimitVars` place): the Item card's *Min / max* rows (`limit_rows`, through `dimension_row`'s `key`) take the chip, `--` and the field menu on one layer only. On an instance the row's mark compares the binding with the literal and its ↺ writes the main's binding with it. *Extract* files the px the limit lays out at, a `%` limit as px of the parent's content box; an `auto` limit has no number to extract.
- **Type numbers** (`FieldKey::Type { id, slot }`, a `TextVars` slot): the Type card's size, line height and letter spacing fields and the popup's Paragraph spacing field take the chip, `--` and the field menu. The weight is the variant picker, never typed, so its binding is the field menu's (right-click on the variant combo); bound, the chip takes the variant field's place. They bind on one layer only, not over a live session's selection (the paragraph spacing not while a live session names paragraphs, a bare caret's included: `para_partial`), and the `TEXT_STYLED` ones not under a text style (`type_key`). On an instance `binding_mark` marks a slot bound apart from its main, its ↺ writing the main's binding beside its literal. *Extract* files the drawn number, an Auto line height as the px it was laid at.
- **Text** (`FieldKey::Content` typed, `FieldKey::Family` never typed): the *Content* row (`OndinApp::type_content_row`) is in the Type card's live tail beside alignment, so a text style leaves it live; read-only over multi-line text or while the canvas edits the layer (field menu still binds). On an instance, `family_mark`/`content_mark` join binding and literal; ↺ writes both. The canvas session opens on the drawn string. The Properties card's Text row is the chip while every content it views is bound (`variants::bound_chip`; × or `Backspace` detaches each to its drawn string).
- **Frame mode row** (`OndinApp::frame_mode_row`, identity card, `Artboard` only, only in a document with a mode): set → mode name bright; inherited → dim with *· from ‹frame›* or *· default*. Click opens `mode_menu_ui` (*Inherit*, naming what it would inherit, then each mode), one `SetMode` per pick, a rung of `Escape`. Every frame tag appends *· ‹mode›* when the frame sets one (never inherited); eliding the tag is not built, by decision. A copy's own mode is an override marked on the row (label bright with the dot; ↺ restores the main's). Modes have no glyph.

**The browser** (`panels/variables.rs`)
- Opened by `Shift+S` or the rail's swatches button above the hexagon; opening it or the insert picker closes the other (same anchor); fixed height 460; width 340/436/532 by mode count (scrolls sideways past three modes). `Escape` takes an open menu/field first, then the browser. *Variables* and *Styles* tabs, an *In selection* filter, usage counts that select.
- Groups = everything before a name's last `/` (`variable::split_name`), each distinct path one flat header; renaming a group onto one holding a same-named leaf is refused, else merged. `Alt`-click opens/closes all; collapsed groups are kept per root id for the process (not saved). A usage count is layers whose own fields read the variable, not through an alias (`variable::users`), leaving out vault nodes (a kit's frozen mains read its variables by rule and can't be selected); *Select* takes the same set. A document group's menu acts on the document's own variables only.
- A mode header's menu: *Rename mode*, *Duplicate mode*, then with two or more modes *Make default*, *Move left*, *Move right* (`move_mode_ops`; each disabled where it would not move), then *Delete mode…*.
- **Descriptions**: a variable's and a style's row menu has *Description*, typed in the rename field's place — past a style's preview, across a variable's cells (`Edit::Describe`, committed trimmed as one `SetDescription`); a variable row's name and a style row hover the description, as do the `--` list's rows and the *Apply style…* picker's.
- Cells edit in place (`Enter`/defocus commits, `Escape` abandons, `Tab` next mode, scrolled into view); an alias is typed `--name` (so a literal string starting `--` can't be typed), resolving to the cell's current target first when it has that name (an alias of a kit's variable shows its name unqualified, and the document may hold its own of that name). A colour cell takes any colour text a colour field reads (`variables::parse_colour`, through `colour_text`), opaque unless an alpha is typed. Colour cells open the colour popup (`PaintSlot::VarCell`); its Variables tab makes the cell an alias and greys rows that would loop. Picker drags preview in the picker and browser cell (`OndinApp::var_cell_preview`) and on every layer reading the variable through `absorb`, which re-resolves every bound node against the table with one cell changed (`Variables::with_cell`) each frame; kept at 3.7 ms a frame over 200 content-bound texts rather than narrowed to the variable's readers.
- Deleting goes through core verbs putting detaches in the deleting transaction (`variable::remove_ops`, `remove_mode_ops`); the commit refuses a bare removal. A first variable brings the document's first mode; the last mode can't be deleted while the document has variables of its own (kits' variables read their own modes). Refusals show as one sentence above the table, refused text dim over dots.
- Boolean variable: `true` in every mode; click on the box toggles, on the word types (`true/false`, `yes/no`, `on/off`, `1/0`). String variable: default "Text" in every mode; cell drawn quoted, line breaks as spaces, typed bare and untrimmed.
- *Styles* tab groups by card, then, under each slot's header, by the path before a name's last `/` as the variables tab does: the top level first with no header, then one flat header per full path, `GROUP_STEP` (14) in from the slot, its rows in by as much; row = preview, leaf name, count. A style group's fold is keyed `\u{1}`-prefixed (`style_group_key`) in the same collapsed set as the variable groups; `Alt`-click folds/opens every style group (`Act::ToggleAllStyles`); a search opens them. The document's own groups double-click to rename and right-click for *Rename group*, *Select N layers*, *Delete group* (`Menu::StyleGroup`); a kit's only fold. A rename runs `style::rename_group_ops(doc, slot, from, to)`: the slot's own styles in the group and its subgroups move, another slot's style of the same path stays, and a landing on a name held outside the group is refused with that name (*‹name› already exists.*). *Delete group* removes its styles in one commit (`Act::DeleteStyles`, `style::remove_ops`), the status counting the distinct layers that keep their values. Style row menu *Rename*, *Description*, *Edit*, *Select N layers*, *Delete*. **Edit is an edit mode, not a card in the browser**: it selects the style's users and sets `EditorSession::style_edit`; their card opens live under an *editing* capsule; `style::edit_through`, first in `commit_inner`, turns a write of the slot on a user into one `SetStyleValue`, which `settle` writes onto every user. A style with no users can't be edited; the edit ends with *Done*, `Escape`, the style's removal, or a selection holding a non-user. A door-made detach says *Detached X* on the floating status (`session::styles_detached`). **No preview runs `settle`**: the picker's and an edit's previews write the lists themselves, and a preview carries the style's `write_ops` beside the binds, which `absorb` no-ops. *Create* names the new style in the capsule, `Escape` undoing it (`escape_styles`) only while the create is still the last step (the naming records its commit count), so it never undoes another edit.

**Type card as a style card.** *Ag* preview, `Family · size` summary. ### Kits' variables and styles

A vendored kit's variables and styles sit **in the consumer's own tables**, each minted the consumer's id and carrying `origin: Option<VarOrigin | StyleOrigin>` (kit, id in the publish, version) — the key an update and second insert match on (`by_origin`). The document's own are `Variables::local`.

- **Kit modes**: `Variables::kits` holds `KitModes { name, modes: [KitMode { id, name, from }], map }` per kit; a kit's variable has a cell in each mode of its kit and no other; `Variables::mode` never answers one.
- **Which column a layer reads** (`Variables::kit_mode`, via `Document::mode_for_in`, at every step of an alias walk): the kit's own mode if the nearest mode-setting frame sets one, else the hand-set map entry for the document's mode in force, else the kit mode of that mode's name (a document mode's, or, where another kit's variable aliases this kit's, that kit mode's), else the kit's first.
- **A mode renamed or copied keeps the kit columns it reads.** `variable::rename_mode_ops` and `copy_mode_ops` (the browser's rename, *Duplicate mode* and *New mode*) write a mapping entry (`SetKitModes`) in every kit where the new name would match a different kit mode: a rename relabels a mode, it does not repoint what its layers draw. A bare `SetModeName` still re-maps by name, so it dirties every bound node while a kit is held and counts as ink.
- **Rules**: a vault node binds only kits' variables and styles and sets no document mode; a kit's variable aliases only a kit's (its own or another's), never the document's own (`check_table`); a kit's style reads only kits' variables; names unique per kit; mode ids unique across the document and every kit.
- **One planner, `tokens::plan`**, lands what a set of nodes reads for `kit::vendor`, `kit::update_all` and the carrying paste (`Carried::tokens`, matched by **origin, never by name**; `plan_carried` points it at the vendored copy). A kit's variables and styles land with their descriptions. `update_all` with `sync` rewrites the kit's whole holding (`SetVariable`, `SetKitModes`, `SetStyleName/Value/Origin`, and `SetDescription` for a style's description; a changed description counts as a change), keeps hand-set entries while their target survives, removes what the publish dropped (detaching its users), and resets frames on a removed kit mode. A live copy bound as its main is **not** rewritten — the commit's follow carries it, or it would read as an override (`tokens::reads_as_its_source`, `tokens::alike`: fills/strokes matched by item id, a vault main's binding to the document's fork counted alike, styles likewise).
- A held kit's record is reused when it covers the source's modes (a new variable fills extra columns from the source's default); `KitError::Modes` when it lacks one, or when a new kit variable or style takes a name a held one of the kit has; a record with no modes counts as absent, an update leaving one removes it, and `variable::check` refuses a kit variable under one (`NoKit`); the kit's own document maps to its own variables, never copies. *Accept all* retries with a `Modes`-named kit moved ahead.
- **A publish freezes a top's and variant's own visibility** to what it shows, so a main root's binding there carries no variable. A kit's frozen copy keeps its other bindings and carries their table.
- ***Make local*** forks what the revealed main's bindings read: document-owned copies named `Kit/name`, keeping the description, marked `forked` with the kit variable/style they came from (so a second *Make local* reuses them); each document mode gets the cell `kit_mode` read there (a document with no modes takes the first forked kit's by name; every other held kit's default is pinned to its first mode); the main's bindings are rebound and the follow carries them to its instances; a nested kit instance keeps the kit's.
- Saved in v8 (`VariablesDto::kits`, optional origins and fork marks).
- **Chrome**: the `--` list, the swatch Variables face, the browser and *Apply style…* list kits' last, each under its mark and name. The browser's kit header carries the mapping per mode column (a click opens the kit's modes and *Match by name*); kit groups fold under `\u{2}kit\u{2}path`; rows are inert (count selects users; no rename, cells, menu or *Duplicate*); a kit's style offers *Select* only. The update toast and popover count variables and styles updated/removed (old → new, with a removal's detach count); a kit header reads *· v8 → v9* while an update waits. Not built: a kit variable no held main reads can't be bound.

### Traps
- **Every reader must resolve.** A reader of the document's own kind (not `Resolved`'s used kind, `resolved_*`, `shown`, `drawn_opacity`) sees the bound literal (0, `true`, empty) and silently draws wrong.
- **Resolved outputs clear their bindings** (`resolved_paint_in`, `resolved_effects_in`): previews hold resolved values that the scene would otherwise resolve again against the committed table.
- **Two-half rule for "keep" passes**: drawn value *or* own literal stays bound. Either half alone detaches fields nobody edited (Scale tool, per-corner ↺, whole-list rebuilds). Visibility and opacity deliberately use one half.
- **`style::settle` runs first and last** and is the only place "styled or not as a whole" lives; no preview runs it.
- **`commit_inner`'s no-op test also drops a bound release's identical commit**, so a guard added only there looks removable but isn't.
- **Style vs variable resolution differ on purpose**: variables resolve at read; styles are copied into the layer at commit.
- **Corner slot order**: `Corner::var_slot` maps the inspector's TL,TR,BL,BR to `CornerVars`' TL,TR,BR,BL — never a cast.
- **`inherited_mode` vs `mode_at`**: `variables::inherited_mode` starts at the parent (what the frame would read unset); `Document::mode_at` counts the node itself.
- **Kit variables are never matched by name** in the carrying paste or update: match by origin.
- **Two defences keep spans off a bound content**: `propagate` skips a content write onto a copy whose content binding differs, and `text_drawn_in` draws a bound content with no spans. Either alone looks removable; without both, a byte range cuts a multi-byte string and the shaper panics (`string_vars.rs`: `a_mains_span_edit_skips_a_copy_bound_to_its_own_string`, `a_bound_content_draws_without_spans_it_should_not_hold`).
- **`bind_text_ops` clears the runs before it zeroes the literal.** A span list canonicalizes against the defaults it is given, so clearing against a 0 size or weight leaves a run of the smallest size or weight over the whole text (`type_vars.rs`: `a_bound_size_and_line_height_draw_in_the_mode_in_force`).
