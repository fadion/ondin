# Styles and variables (§5.3f)

Variables (named, typed, per-mode values that fields bind to) and styles (reusable per-slot sets of values), how kits carry both, a design-tokens file read into both, the binding chrome, and the commit-time passes that keep bindings honest. Text styles and the text node are in `text.md`; components and overrides are §5.3d.

## 5.3f Styles and variables

### Variables

A **variable** is a named, typed value — **colour, number, string or boolean** — with **one value per mode of its collection**. An **alias** is a per-mode cell naming another variable of the same type, in any collection (not a fifth type). A variable's **scope** is the fields it may bind. CSS custom properties are the model.

**Collections and modes**
- A **collection** (`Collection { id: CollectionId, name, modes, breakpoints }`) is a named set of variables with its own mode list, the first mode its default. A document always has at least one: it starts with `Collection::first()` (`CollectionId::FIRST`, a fixed id no session mints, named *Variables*, no modes). Collection ids and names are unique (`VarRule::NoCollection`, `DuplicateCollection`, `DuplicateCollectionName`).
- **A variable's collection is the one owning its cells' modes** (`Variables::collection_of`); a variable records no collection of its own, so the cells cannot disagree with it. Names are unique per collection, not across (`by_name_in`; `by_name` answers the first collection's first).
- *Move to* (`variable::move_ops`) is a `SetVariable` with the cells re-keyed: each target mode takes the source's mode of the same name, else the source's default. The id stays, so bindings and aliases hold. A name the target already holds is refused.
- `variable::move_mode_ops(doc, mode, index)` reorders within the mode's collection: a `RemoveMode` then an `AddMode` of the same mode (same id and name) with its whole column at the new index, so frames set to it and kit mappings keyed by its id hold. Index 0 makes it the default every unset frame reads. In a collection picked by width it moves nothing: the widths order the modes. `remove_mode_ops`, `copy_mode_ops` and `rename_mode_ops` work within the mode's collection too.
- Only a **frame** (an `Artboard`, never a group) or a **page** sets modes: `Node::modes: Vec<ModeId>`, in id order, **at most one per collection** (`VarRule::TwoModes`). Each collection inherits on its own: one with no mode set here reads the nearest ancestor frame's that sets one of it, else the page's, else its default. `Operation::SetModes { id, modes }` writes the set whole; `variable::with_mode(t, set, owner, mode)` writes one pick, keeping every other collection's mode (`ModeOwner::{Collection(id), Kit(kit, collection_name)}`). A page is its root node, so the walk needs no case for it. A page's root may set only document modes, never a kit's, since no kit's variables live on a page (`variable::check`).
- **A collection picked by width** lets a top-level frame, the one CSS calls the viewport, pick its mode from its width. `Collection::breakpoints: Option<Breakpoints>` holds each mode's minimum width in px, keyed by mode id; `None` is not picked by width. At most one collection is (`VarRule::TwoByWidth`); its widths are one per mode, the first 0, strictly ascending and finite (`VarRule::BadBreakpoints`), so the default is the narrowest. `Collection::mode_for_width` is the mode with the largest minimum the width reaches, inclusive; `Variables::by_width()` finds the collection. Only a frame `Document::picks_by_width` accepts picks: an `Artboard` whose parent is a page and that is no component main, set or instance, none of which is a viewport; a component picks by its own width through a width query instead (below). `Operation::SetBreakpoints { id, breakpoints }` writes the widths whole, refuses a non-finite one and dirties every bound node; a mode added or removed beside it needs its own, which the verbs below emit.
- **Width verbs**: `by_width_ops(doc, c, on)` is *Pick mode by width*. Ticked, the modes start at 0, then `FIRST_WIDTHS` (768, 1200), then `WIDTH_STEP` (400) past the one before; refused with *‹Name› already picks its mode by width.* Unticked, the modes stay, the widths go, and every frame that picked by width is set to the mode it drew (`SetModes`), so nothing on the canvas changes. `breakpoint_ops(doc, mode, width)` refuses the first mode (*‹First› starts at 0.*) and a width at or past a neighbour's, naming where that one starts (*Desktop starts at 1200.*). In a collection picked by width `copy_mode_ops` gives the copy a width halfway to the next mode's (whole px when one fits between) or `WIDTH_STEP` past the last, `remove_mode_ops` drops the mode's width and gives the new first 0, and `columns_for_new` gives a first mode 0. `variable::px` writes a width.
- **Width queries** (CSS's container query) let a frame's contents pick a collection's mode from the frame's own width, so each instance of a main picks by its own. `Node::queries: Vec<Breakpoints>` holds each mode's minimum width in px, one query per collection, the document's or a kit's (the owner is read from the mode ids: `Node::query_of`). `variable::check` holds them to a frame, one per collection, none empty, every width finite and ≥ 0 (`VarRule::BadQuery`); order and a first 0 are what the verbs write, not a rule. `variable::query_mode` answers, of the modes the table still holds, the one with the largest minimum the width reaches (the later mode on a tie, as the later `@container` block wins in the export), else the narrowest. `variable::query_order` lists a query's modes narrowest first by its own widths, whatever the collection's order: a mode moved in its collection keeps its place among the widths, and the verbs and the *Widths* fold read that order. A key naming a mode the table no longer holds is passed over, not refused: a kit update can take a kit mode away under a vendored main. `Operation::SetQueries { id, queries }` writes the set whole and dirties the frame and every variable-reading layer under it. Set on a main; its copies follow it as one field (§5.3d).
- **Query verbs**: `query_ops(doc, frame, owner, on)` is *By width*. On, the owner's modes start at 0, then `QUERY_STEP` (320) past the one before, in mode order, and a mode the frame pins of that owner is let go, since a pin beats the width; refused with `why_no_query`'s sentence (*Only a frame picks by its width*; *Picks by width only when its width is set from outside — not Fit content*); empty while the query is held or the owner has fewer than two modes. Off, the query goes. `query_width_ops(doc, frame, mode, w)` is `breakpoint_ops`' rule on the frame's own widths in `query_order` (*Compact starts at 0.*, *Wide starts at 640.*). The document's mode verbs keep every frame's keys in step (`queries_ops`): `remove_mode_ops` drops the mode's width, gives the narrowest held mode 0 when the removed one held 0, and drops a query left with one mode; `copy_mode_ops` gives the copy a width between its neighbours, as a collection picked by width does, or `QUERY_STEP` past the last; `remove_collection_ops` drops the query.
- `NodeId::NOWHERE` (seq 0, never minted) sits under no frame and on no page, so asked as a place it reads every variable in its collection's default; the style previews read through it.
- On an instance, the copy's mode set is one field, an override like any other (§5.3d).
- Deleting a mode returns every frame set to it to inherit for that collection, in one undoable transaction.
- **Collection verbs**: `new_collection_ops` (one mode, *Mode 1*, not picked by width), `duplicate_collection_ops` (fresh ids, not picked by width; an alias inside it points at the copy, one outside kept), `remove_collection_ops` (its variables removed as `remove_ops` removes them — users detach, aliases from elsewhere resolve — frames return to *Inherit* for it, kit mapping entries naming its modes go; empty for the last collection), `collection_reach` (variables, layers and frames, for the confirmation). `columns_for_new` gives the modes a new variable of a collection takes, adding its first mode when it has none; every door that files a value into a variable starts from it. `rename_group_ops(doc, collection, from, to)` works within one collection.
- A kit's variables use the kit's own collections and modes, mapped onto the document's (below). A frame may be set to a kit's own mode (a kit main's, carried to its instances); it governs only that kit collection's variables. A kit's collection is never picked by width (`KitMode` carries no width).

**Resolution**
- `Document::modes_at(id)` is the modes in force at `id`, nearest first, one per collection (the document's or a kit's): walking up from `id`, each node gives its own pins, then its width queries' picks (`query_pick_in`), then its viewport width pick (`width_pick_in`). So a pin on an instance beats its width, its width beats anything around it (a page pin, a top-level frame's width), and layers inside inherit. `Document::mode_at(id, collection)` picks one collection's from it, else its default.
- **A frame's width queries never answer for the frame itself**: its own fields read the mode around it, as in CSS, where a container cannot query itself. That keeps the width it picks by independent of what it picks, and lets code export write it as a container query.
- **A frame's kit query beats its document query's mapping**: when a frame queries a document collection and a kit collection mapped onto it, the kit's own pick answers for the kit's variables, whatever the queries' order, as a frame's kit pins come before its document pins (`Document::modes_at`). The export writes kit query blocks after the document's so they win the same way. A pin on the frame still beats its kit query, a document pin read through the mapping, since a frame's pins answer before its queries; the export writes those mapped pin blocks after the kit query's blocks and before the kit's own pins.
- **The query width** (`query_width_in`) is the frame's **content box**, as `@container (min-width)` reads it in the export: its width less its side padding, of a resize preview's width (`Variables::with_width`), else the laid-out width the document was last settled with, else its own — its padding alone where its width is fit-content (so 0 inside), else its width, a bound one read in the frame's own pins, then the modes in force at its parent. **Containment**: `limits_drawn_in`, and so `resolved_item` behind every layout view, gives a querying frame with a fit-content width its padding as width, so layout never sizes it by the contents its queries pick (`layout.md`). *By width* is refused on such a frame; one set to fit-content afterwards keeps its query and is laid at its padding.
- **Laid widths.** `Document::settle_widths(&Resolved)` stores every querying frame's used width (the vault's excepted) and answers the variable-reading layers under each frame whose pick moved. A frame's width never depends on its own pick (the two defences under *Traps*), but a querying frame nested in another can be widened by the outer one's pick, so the settle repeats, laying out what moved, until nothing moves (`Resolved::settle`, at most `MAX_SETTLE_ROUNDS`, 8). The session does so after every resolve (commit, undo, redo); `Resolved::settled` does the same for a loaded document (session adopt, the CLI's export and check, the history compare). A reader that only `Resolved::rebuild`s (thumbnails, kit previews) reads each frame's own width, so an instance stretched by its parent picks by its stored width there. `apply_one` compares a querying subject's picks before and after each op and dirties its readers when they move, but in a settled document the laid width stands until the next settle, so a resize's new pick reaches the canvas through `settle_widths`. The renderer's resize preview redraws the layers under a querying frame in the mode the dragged width picks (`redraw_reading` against `with_width`), the frame itself excluded.
- **The width pick.** `Document::width_mode(id)` is the mode a top-level frame's width reaches, pinned or not; `width_pick(id)` is that mode where neither the frame nor its page sets one of the collection picked by width. `modes_at` pushes a frame's width pick after its own modes, so a pin on the frame beats a pin on the page, which beats the width, and nested frames inherit the pick as any mode. A bound frame width is read in the modes the frame and its page set: a frame's own width cannot be read in the mode the width picks. `Document::apply_one` compares the subject's `width_pick` before and after every op (`overwrites()`, or a `Reparent`'s id) and, when it moves, dirties every variable-reading layer under it: a resize across a breakpoint, making the frame a component, moving it to or from the top level. A resize preview reads through `Variables::with_width(frame, w)`, whose `previewed_width` is never saved (`width_pick_in` is its door): the renderer's `SetGeometry` arm redraws a dragged top-level frame's bound contents in the mode the new width picks (`redraw_reading`, shared with the cell preview).
- `Variables::resolve_at(var, set)`: **each alias step reads its own collection's mode in force**, else that collection's default, so an alias may cross collections. `resolve(var, mode)` is that one mode set, every other collection at its default.
- `would_loop` is exact across collections: a step into a collection no step has read yet tries each of its modes, and a later step into it reads the one chosen, since a layer reads one mode per collection. A chain that loops only with one collection in two modes is no loop; reading every column of every other collection would refuse chains no layer can walk.

**Scope**
- `Variable::scope: Option<Scope>`; `None` is every field of its kind but the flex direction and wrap (below), including any made bindable later. A scope is a set of `Field` families: `Size`, `Limits`, `Spacing`, `Corner`, `StrokeWidth`, `Opacity`, `Effect`, `Type` (text size, line height, letter and paragraph spacing), `Weight`, `Fill`, `Stroke`, `Content`, `Family`, `FlexDirection`, `FlexWrap`, `Visible`. `Field::kind` is the variable kind each binds; `Field::is_length` marks the px families; `text_slot_field` maps a `TextVars` slot to its family. A boolean has no scope (`VarRule::BooleanScope`): visibility is its one field.
- **A flex direction or wrap binds only a string scoped to it** (`Field::needs_scope`): `Variable::binds` with no scope leaves them out, so an unscoped string (a label's *Continue*) never lands on a direction. Their words are `Field::words` (*Row, Column, Row reverse, Column reverse*; *No wrap, Wrap, Wrap reverse*); `Field::takes` and `FlexDirection::from_word`/`FlexWrap::from_word` accept the CSS keyword too, in any case. **A string scoped to flex families alone holds only their words** in every literal cell (`variable::holds_its_words`, else `VarRule::NotAWord`).
- **`variable::check` refuses a binding outside its variable's scope** (`VarRule::OutOfScope`). A style's bindings are not checked against it; they are held to it by `scope_ops`' detach (style families: fills → `Fill`, strokes → `Stroke` and `StrokeWidth`, effects → `Effect`, layout → `Spacing`, `FlexDirection` and `FlexWrap`).
- `variable::scope_ops(doc, var, scope)` detaches every field of a family the new scope drops to the value it drew, then writes the scope with `SetVariable`: one step, so a bound field never sits outside its scope. Its detach is `detach_ops`, the first half of `remove_ops`. Narrowing a string to flex families alone sets each cell naming none of their words to the first family's first word, and a variable of the same collection aliasing it in that mode takes the value it read. A variable of another collection aliasing it refuses the narrowing (`variable::scope_held_by`, named on the status line): it reads the string in whichever of that collection's modes is in force, so no literal of its own could keep its text. `users_by_field` counts the layers bound per family.

**What binds**
- **Numbers**: W, H, a layout item's min/max width and height (as px), corner radius, layer opacity (a percentage 0–100), stroke width, an effect's X/Y/blur/spread, layout gaps and padding, and a text's size, weight, line height, letter spacing and paragraph spacing (the node's defaults, never a run's or paragraph's own). A run or paragraph holding the value a bound default draws keeps it: the text editor and the Type card keep span lists against the literal (`variable::span_defaults`, `TextEdit::keep_spans_against`), never the drawn value, which differs by mode. **Not** X, Y or rotation (placement, which an instance keeps as its own — `reset::placement_is_own`). W/H bind only where the user set them (never a hugging frame's, a text box's, or a size a flex/grid layout deals out or stretches). Stroke width and effect numbers bind in the item, one at a time; a stroke drawing per-side widths takes none, and an effect binds only the numbers its kind has (a layer or background blur's radius is the blur).
- **Colours** bind a whole solid paint, never a gradient stop (a reusable gradient is a fill style). The variable carries its own alpha; the fill's `%` stays a separate unbindable field and what draws is the variable's colour times it.
- **Booleans** bind visibility.
- **Strings** bind text content, font family, and a flex container's direction and wrap (only a string scoped to them, above). Binding the content clears its spans; binding a default clears the runs or paragraphs that hold their own value for it. A text style holds plain values, so the family and the character numbers never bind under one; the paragraph spacing, which no text style holds, does.
- A field that is also a component property's needs no rule: the property is a view over the field (§5.3d).

**A bindable field stores its binding and resolves it at read.** The binding is a sidecar beside the field's literal (`Node::corner_vars`, `size_vars` and the rest of the table below), the literal a placeholder while bound; only paint is an enum (`BrushSource::{Literal, Bound}`). The value drawn is found against the modes in force at that node. So:
- Overrides compare the binding: a main rebinding *brand* → *accent* reaches a copy still bound to *brand*; a copy bound elsewhere keeps an override. So the main's literal writes do not follow onto a field the copy binds otherwise: a content write (`SetText`, span writes) skips a copy whose content binding differs, and a size or corner follow keeps the copy's own literal on each axis or corner it binds otherwise (`propagate::keep_own_bound_geometry`) — its literal 0 would otherwise read as the main's old value and take the new one.
- Editing a variable writes no node, so nothing propagates. §12's "resolved value is in no node" holds, where §5.3d's copies bend it.
- Every reader must resolve (`container::lay_out`, `scene::build`, the SVG writer, the snapshot, the inspector); one that skips it draws the fallback silently. Code export alone keeps the binding: it writes `var()` against a `tokens.css` with one block per mode per collection, every alias redeclared in each of its collection's, and the collection picked by width in media queries and a frame's width queries in container queries (`export.md`, *Code export*). Paint is guarded by a type with no `Deref`; other fields by `Document` resolve readers.

**Deletion and leaving a document**
- Deleting a variable in use **detaches** every field bound to it to the value it resolved to, as ops in the deleting transaction (as a deleted main, §5.3d). Deleting a style detaches its users likewise.
- A paste into another document rebinds to a variable of the same name and type whose scope takes the field, the namesake in the collection of the same name first (`CarriedVar::collection`), else detaches to the resolved value; within a document the binding is kept. A copied frame's modes map by name within the collection of the same name, else the first (`CarriedMode`), else *Inherit*; a kit mode is kept, one of the target's own kit becomes the document mode it maps from. Its width queries map their keys the same way, each keeping its width; a query left with no mode, spanning two collections, or over a collection already queried goes. `variable::detached` drops queries with modes. *Paste properties* uses the same rule through `variable::rebind(t, carried, v, field)`; presets hold nothing bindable.
- A ghost (drag preview) resolves in the default mode; the snapshot reports the resolved value.

### The table and the readers

`ondin_core::variable`: `Variables { collections, vars, kits }` — collections in order (never empty), variables by `VarId`, per-kit modes by kit id; `CollectionId`/`ModeId`/`VarId` are `NodeId` newtypes from the session's `IdSource`. Each variable is a name, a kind (`Color`, `Number`, `Boolean`, `String`), one `Cell` (value or `Alias`) per mode of its collection, a `scope` and a `description` (free text, empty is none). `Document::variables` reads it. `SetDescription { of: Described::Variable(id) | Described::Style(id), text }` writes a variable's or a style's description (a main's too, §5.3d); it draws nothing and dirties nothing.

Readers built on `modes_at` (which counts the node itself): `resolve_var`, `resolve_brush`, `resolved_paint`, `resolve_corners`, `resolved_display`, `shown`, `resolved_kind` (applies `text_drawn_in`), `resolved_item` (applies `limits_drawn_in`), `drawn_opacity`, `stroke_width_drawn_in`, `resolved_effects`.

**`variable::check` is a post-condition of every transaction and a check of the loader**; it refuses a dangling binding rather than repairing it. Save format v7–v9; collections, scope, a collection's widths and the flex direction and wrap bindings in v13, width queries in v15 (§5.11); operations, invalidation and the paste rule are in §5.7, §5.11, §5.9.

### The binding shapes

Each "keep" pass runs in `commit_inner` and judges a write over a bound field so no door has to know about bindings.

Passes run in table order, `keep_size_bindings` after `keep_flex_sizes`, `keep_limit_bindings` after size, `keep_text_bindings` after the limits; all before `propagate::owed`. `paint_box::keep_gradients` (§6.2) runs between the last and `owed`, because a detached size binding's literal is a size write its gradients must follow; it measures both boxes through the size bindings, so the placeholder 0 is never a size it carries to. `owed` runs it again last, for the sizes copies follow.

Per-shape rules. The **two-half rule** (corners, gaps, flex direction and wrap, stroke width, effects, W/H, size limits, text): a write over a bound field leaves it bound if it writes what the field draws *or* its own literal; either half alone detaches fields nobody edited (a field reads drawn values and writes them back; Scale, reorder and per-corner reset rebuild from literals).
- **Corners.** Readers of the document's own kind see 0, so the inspector reads corners as drawn. Price: a 0 typed into the field detaches nothing; the chip's retype (which detaches first) is 0's door. Frames, rects, polygons and stars bind corners (`VarRule::BadCorners` refuses a binding on any other kind). A polygon's or star's one radius is held as four corners, the same variable in every slot, and `GeometryPatch::CornerRadii` on it takes the top left; nothing new reaches the file. A `Path`'s per-anchor radii don't bind, by decision (indexed by anchor, which point editing inserts/deletes).
- **Gaps/padding.** A layout taken away clears its bindings (on a copy whose layout a follow takes, `propagate::owed`'s last step); a binding on a layout-less node is inert, and deleting its variable (`variable::remove_ops`) or a paste that cannot rebind it (`variable::land`) clears it, having nothing to detach it to. The spacing and corner judgements are functions the preview shares (`build::kept_spacing_vars`, `kept_corner_vars`) so a write the commit detaches previews where it lands.
- **Flex direction and wrap.** The bindings ride in the layout, as an effect holds its bound numbers, so layout styles, propagation, resets and pastes carry them with no op of their own. `spacing_drawn_in` reads them in the mode in force and **keeps the bindings in what it returns**: layout reads only the literals, and a door writing the drawn layout back keeps the binding by the two-half rule, where a cleared one would read as a detach. `build::kept_flow` (shared with the preview; `keep_flow_bindings` runs it on every `SetDisplay`, rewriting in place): a write keeping the same variable stays bound when it states the drawn word or the literal (the literal put back), any other value detaches; a binding the write changes or clears is left as written. **A binding to a string that names no direction or wrap in some mode** (any cell, through aliases: `variable::names_one_everywhere`) is then cut: `keep_flow_bindings` judges the tree the transaction leaves, for every flex it writes or inserts and, when it writes a cell, a variable or a mode, every bound flex, and detaches such a slot to the word drawn (the mode in force's, else the literal) in the transaction's last `SetDisplay` of that layer, else an appended one; the session's `flows_cut` names the cuts on the floating status. The `--` list leaves such strings out (`binding::matches_for`). A document that holds one anyway (a loaded file) draws the literal where a mode names none. `bind_flow_ops(doc, id, slot, var)` binds, or with `None` detaches, writing the drawn word as the literal. `variable::check` refuses a flow binding to anything but a string; `detach_ops` detaches spacing and flow in one `SetDisplay`; `land` rebinds a pasted one or falls back to its twin's drawn word. A child's bound W/H is judged under every direction a bound direction can take (*W/H*).
- **Visibility.** Everything that draws, picks, lays out or exports asks `shown`, so a layer its variable hides leaves its layout's flow. **One half only**: written what it shows stays bound; anything else detaches. The literal half would excuse the `true` the eye and *Bring back into flow* write to show a hidden bound layer, keeping it bound and hidden.
- **Opacity.** One half only (the drawn value), because 0% typed over a bound layer means "make it invisible"; no writer builds an opacity from the literal. The chip is on one layer's Appearance card only; the several-layer row writes the outermost members' shared value and takes no binding, detaching in the edit itself.
- **Stroke width.** Preview bounds, hit test, snapshot and ghost all read through `resolved_paint_in`; clearing `width_var` on output matters because a preview override holding a resolved paint is resolved again by the scene against the committed table. `kept_stroke_widths` is shared with the preview; a binding the write changes (bind, detach, reset, new stroke) is left as written. A `Custom`-sides stroke on a **box** (`build::draws_own_sides` via `geometry::effective_sides`) takes no binding: `bind_stroke_width_ops` refuses it and `kept_stroke_widths` detaches a bound one at the width it drew, whoever wrote it (checked before the "binding the write states" exemption, so a pasted bound `Custom` stroke lands detached). On an ellipse or path `Custom` draws whole at `width` and binds normally. The shared weight row clears bindings it writes, except a stroke whose bound width already draws the typed one. The pass rewrites lists in place.
- **Effect numbers.** `resolved_effects` reads a bound blur within `0..=effect::MAX_BLUR` (`Effect::number_read`), the range `Document::apply` holds a typed one to, so a detach never writes a blur the operation refuses; offsets/spread as they are. `kept_effect_vars` is shared with the preview; a binding on a number the effect's kind no longer has (shadow retyped to layer blur) is dropped whoever wrote it. Chip on one layer's own effect; popover fields over several layers stay plain and clear the slot's binding in their write, except on a layer whose bound number already draws the typed one; a number equal to the committed one writes nothing. The write is retargeted onto each layer's own item ids. The retype range is the card's own (blur `0..=MAX_BLUR`, offsets/spread `±MAX_OFFSET`). The pass rewrites in place.
- **W/H.** Only a hand-set axis binds (`build::size_axes_authored`): not `%`/`fit-content`, not pinned at both ends, not a flex item's main axis with growth/basis, not a stretched flex cross axis or grid axis sized `auto` (shrink, min-, max- don't count). Under a parent whose flex direction is bound, `size_axes_authored_everywhere` asks that of every direction the variable names in any mode, since a frame set to another mode lays the axis out that way; `bindable_size_axes`, `bind_size_ops` and the commit pass all ask it. In `kept_size_vars` the resized axis detaches and the other stays bound; "what it draws" includes the *used* size a layout's shrink or min/max squeezes it to (given `Resolved`), which the H field and top/bottom handles carry forward on the other axis. An axis an edit makes computed (keyword, second pin, growth, basis, stretch, reparent into a layout, a layer shown or unmasked into the flow, a bound layer an `InsertSubtree` brings into a layout, judged by the bindings it arrives with, a parent's direction bound, or a cell, variable or mode written so that some mode of a bound direction lays it out) detaches to the size drawn before; that half judges the tree the transaction leaves on a scratch copy built with `apply_unchecked` (a member moved out of its instance fails `component::check` until `settle_links` runs). `propagate::owed` runs the pass again over the whole transaction after the follows, so a copy's own size binding that a followed layout write makes computed detaches too. `keep_insets` reads sizes from the document this pass leaves, and its scratch copy is unchecked for the same reason. Binds on one layer's Transform card only; text boxes' W/H don't bind. A bound axis draws its variable's number within `0..=build::GEOMETRY_LIMIT` (`Document::size_drawn_in`).
- **Size limits.** A bound limit is px: its variable's number floored at 0, its literal `Px(0)` (`build::bind_limit_ops`). The bindings sit in the item beside the values, as an effect's do, so every door that writes the item from the stored one (propagation, reset, a variant's merge) carries them with no arm of its own. `build::kept_limits`, which the preview's `SetLayoutItem` arm shares, keeps a binding on a write of the literal or the drawn px and detaches on any other value, a mode or unit picked to `auto` or `%` included; a binding the write itself sets is left alone. A detach (`detach_limit_ops`, `variable::remove_ops`, `detached`) writes the drawn px. The limits bind to number variables only (`variable::check`). The pass rewrites in place.
- **Text.** Binding writes the bound literals empty or 0 (`build::bind_text_ops`); the slots a text style holds (`variable::TEXT_STYLED`, family to letter spacing) don't bind under one. A number reads its variable as the number its field shows, in the literal's unit (`variable::set_text_slot_number`): size in px floored at `MIN_FONT_SIZE`, weight rounded into 1–1000, line height (floored at 0), letter spacing and paragraph spacing in px or, where the literal is an em, in % (hundredths of an em); an Auto line height binds as px. Binding a default clears the runs or paragraphs with their own value (see *Traps*). A `SetText` of the drawn string with no spans stays bound (`""` is what a deliberately emptied text writes; one half); anything else detaches. Spans written over a bound content become a `SetText` of the drawn string, detaching. A family or number that a `SetTextStyle` (for the paragraph spacing, a `SetParagraphStyle`) writes drawn or as its literal stays bound, its literal put back; any other value detaches, the same number in another unit too. Applying a text style detaches the `TEXT_STYLED` slots and leaves the paragraph spacing bound. A run or paragraph given a value is a span, the default staying bound under it. A copy's `TEXT_STYLED` bindings under its main's text style are cleared by `style::settle`, since the copy receives the `SetTypeStyle` by propagation, after the pass. A bound content draws with no spans (`text_drawn_in`): the passes keep spans off it, and this second defence stops a byte range cutting a string whose length is the mode's. `keep_insets` reads the document both passes leave.

**Saying what was cut.** `session::variables_detached` names every variable a slot loses (*Detached size/w*, *Detached N variables*) from the `Set*Vars` ops appended between `asked_ops` (after `keep_flex_sizes`, before the first pass) and `propagate::owed`; `said_detached` merges it with `styles_detached`. The stroke-width and effect passes rewrite in place, so `commit_inner` notes the bound widths/numbers before and the cut ones after (`stroke_widths_bound`/`_cut`, `effect_numbers_bound`/`_cut`). Edits whose own ops set a binding, and inspector doors, say nothing; the layers panel's eye and the hide chord leave it to the pass. A paint's binding is decided at the write, so `replace_image_fill` (the one canvas door overwriting a bound paint) reads the fill's variable first and folds it with `EditorSession::last_detached` into its *Replaced with ‹file›* status; *Replace image…* and *Paste properties* report likewise (`OndinApp::replaced_status`). The image card is read-only under a styled Fill card.

### Styles

A **style** is one slot's isolated set of values (an isolated CSS class, not the cascade). **Slots: fills, strokes, effects, text, layout.** A node holds at most one style per slot; styles don't stack. A style's values may be variables.

- **A card is styled or not as a whole**: editing any field of a styled card detaches it; no partial override, no inheritance.
- **The inspector is read-only on a styled card** (fully or partly); a style's values change only through the browser's *Edit*, live to every user. Every other door (canvas gesture on a styled or bound value, *Paste properties*, MCP) detaches, and the floating status says what — refusing would leave canvas handles dead.
- **A layout style** carries the container's whole `Display` (flex or grid, tracks included, with the direction's and wrap's bindings riding in it) and gap/padding bindings — never an item's grow or `align-self`.
- **A text style** holds the character defaults less colour and language (colour is the Fill card's, language the words'), neither the paragraph nor block scope, and a plain family. Spans stay the text's own marks over the style: styling a selection keeps the style; only a write of the defaults detaches.
- **A style is not resolved at read.** A styled layer's own list holds a copy of its style's values, which the commit writes; readers of fills, strokes, effects or type never ask the style table (the opposite of variables).

#### Table and ops

`ondin_core::style`: `Styles` by `StyleId` (a `NodeId` newtype) on `Document`; `Style` = name + `StyleValue` + `description`. Names are slash paths, unique within a slot, not across slots. Bindings: `Node::styles: StyleRefs { fills, strokes, effects, text, layout }`. Binding ops per slot (`SetFillStyle`, `SetStrokeStyle`, `SetEffectsStyle`, `SetTypeStyle`, `SetLayoutStyle`) write the binding alone. `AddStyle` and `SetStyleValue` refuse a value holding a non-finite number (`OpError::NonFinite`, asked of the save format itself by `style::survives_save`).

`StyleValue`:
- `Fills`/`Strokes`/`Effects`: the card's whole `Keyed` list (a stroke style carries width, join, cap, dashes, alignment).
- `Text(Box<TextStyle>)`: the type part (`style::type_part`: defaults with `color` and `locale` cleared). The commit writes it as `SetTextStyle { spans: None }` over the layer's own colour and language, compares type parts, and re-states spans against the new defaults (a span the new defaults equal is dropped; only `Ctrl+Z` brings it back). `SetTextSpans`/`SetText` are not the slot's writes; `SetTextStyle` is but detaches only when it moves the type part. `style::check` refuses a text style on a non-text layer.
- `Layout(Box<LayoutStyle { display, spacing_vars }>)`: the only slot written by two ops (`SetDisplay`, `SetSpacingVars`; `StyleValue::write_ops`, `writes_slot` maps both). A layout-less layer has no layout value (`StyleValue::of` → `None`), so no style is made from one; **applying a layout style to a plain frame gives it the layout**. Only frames and groups bind one. `edit_through` builds the edited value from the user's display and bindings with each write applied, judging a `SetDisplay` by `kept_spacing_vars` and `kept_flow` as the commit's passes would (that pass never sees a write folded into the style), except where the same edit states that user's `SetSpacingVars` (a bind or a detach): there the display is taken as written, as the spacing pass leaves a stated binding as stated.

#### `style::settle`

`style::settle` is the whole of "styled or not as a whole". Run by `propagate::owed` **first and last**, it finds every bound slot not holding its style's look (values compared, item ids not) and:
- **rewrites** it from the style when the transaction edited the style or set that binding, or when no op of the user's edit or the doors' rewrites wrote the slot (a component follow, a paste rebound by name);
- **detaches** the layer (values kept) when one did.

So canvas, *Paste properties* and MCP detach with no door knowing. Both runs matter: the first lets a main's rewrite/detach reach copies, the second restores a copy on another style that a follow drifted. When the first `settle` writes a `SetDisplay`, `propagate::owed` runs `keep_size_bindings` again over the whole transaction before the copies follow, so a child's bound W/H that the style's layout makes computed detaches and the copies follow that; it runs once more, always, after the second `settle` (§5.3d's pass order).

`style::check` (post-condition of `apply` and the loader): names unique per slot; no item id twice in a style; paints bound to colour variables only; stroke width, effect numbers and layout gaps/padding to number variables only, a layout's direction and wrap to strings (an effect's numbers only where its kind has them, since `settle` could never write the rest onto a user); every binding names a style of its slot; **no vault node bound to a style of the document's own** (a vault node's styles are kits', and a kit's style reads only kits' variables).

Deletion: a bare `RemoveStyle` of a style in use is refused; `style::remove_ops` detaches users first. Deleting a variable a style reads detaches the style to the colour, number or word it draws **in the default mode** and rewrites the users from it (they stay styled; a user in another mode changes colour). A paste rebinds a style by id, else by name+slot, else detaches.

Footer *Cancel* / *Bind N*, disabled at none with *Tick a field to bind it*.

The status line reads *Bound ‹name› to N more fields · K layers use it · Ctrl+Z to undo*, K counting users outside the vault, with *· its scope now takes ‹families›* before the undo hint when it widened.
- Groups = everything before a name's last `/` (`variable::split_name`), each distinct path one flat header. **A group belongs to its collection** (`GroupOf`): it folds apart from a same-named group in another collection or a kit (`group_key` prefixes the collection's or kit's id), and its rename and menu act on its own collection (`rename_group_ops`), also in a search spanning collections. A usage count is layers whose own fields read the variable, not through an alias (`variable::users`), leaving out vault nodes (a kit's frozen mains read its variables by rule and can't be selected); *Select* takes the same set. - In a collection picked by width each mode header past the first is followed by its minimum (`≥768`, faint, at `ui::CAPTION_PT`, as the frame mode menu shows it as an accelerator); the first's 0 is not written.
- A mode header's menu: *Rename mode*, then, for a mode past the first of a collection picked by width, its minimum as a `ui::value_field_suffixed` (prefix `icon::DEVICES`, suffix *px*, whole-unit scrub, tooltip *‹Mode› from this width up*): a drag holds a draft (`Browser::width_draft`) committed when it ends, a typed number lands on `Enter` or defocus, one step *Breakpoint*, a refusal shown as the browser's refusal sentence. Then *Duplicate mode*, then with two or more modes *Make default*, *Move left*, *Move right* (`move_mode_ops`; each disabled where it would not move, and in a collection picked by width with the tooltip *Ordered by width*), then *Delete mode…*.

A colour cell takes any colour text a colour field reads (`variables::parse_colour`, through `colour_text`), opaque unless an alpha is typed. - Deleting goes through core verbs putting detaches in the deleting transaction (`variable::remove_ops`, `remove_mode_ops`); the commit refuses a bare removal. A first variable brings its collection's first mode (`columns_for_new`); a collection's last mode can't be deleted while it holds variables (kits' variables read their own modes). Refusals show as one sentence above the table, refused text dim over dots.
- Boolean variable: `true` in every mode; click on the box toggles, on the word types (`true/false`, `yes/no`, `on/off`, `1/0`). String variable: default "Text" in every mode; cell drawn quoted, line breaks as spaces, typed bare and untrimmed. - *Styles* tab groups by card, then, under each slot's header, by the path before a name's last `/` as the variables tab does: the top level first with no header, then one flat header per full path, `GROUP_STEP` (14) in from the slot, its rows in by as much; row = preview, leaf name, count. The document's own groups double-click to rename and right-click for *Rename group*, *Select N layers*, *Delete group* (`Menu::StyleGroup`); a kit's only fold. A rename runs `style::rename_group_ops(doc, slot, from, to)`: the slot's own styles in the group and its subgroups move, another slot's style of the same path stays, and a landing on a name held outside the group is refused with that name (*‹name› already exists.*). *Delete group* removes its styles in one commit (`Act::DeleteStyles`, `style::remove_ops`), the status counting the distinct layers that keep their values. **Unused** (`Browser::unused`, `icon::FUNNEL` after *In selection* on the search row, tooltip *Unused: only this document's styles no layer uses*) lists only the document's own styles, never a kit's, whose usage count is zero (`unused_styles`); with *In selection* both filters apply. An empty list's hint names *In selection* when it is on, else *Turn off Unused to see them all.* A line under the search row counts the unused styles the list shows, the search and *In selection* applied (*N unused styles*, or *No unused styles here*), with *Delete unused* on its right, dim with *No style here is unused* when there are none, which deletes exactly those through `Act::DeleteStyles` as one step *Delete style*, the status reading *Deleted N unused styles* (and the layers that keep their values when a kit's frozen main used one). Style row menu *Rename*, *Description*, *Edit*, *Select N layers*, *Delete*. **Edit is an edit mode, not a card in the browser**: it selects the style's users and sets `EditorSession::style_edit`; their card opens live under an *editing* capsule; `style::edit_through`, first in `commit_inner`, turns a write of the slot on a user into one `SetStyleValue`, which `settle` writes onto every user. A door-made detach says *Detached X* on the floating status (`session::styles_detached`). **No preview runs `settle`**: the picker's and an edit's previews write the lists themselves, and a preview carries the style's `write_ops` beside the binds, which `absorb` no-ops. *Create* names the new style in the capsule, `Escape` undoing it (`escape_styles`) only while the create is still the last step (the naming records its commit count), so it never undoes another edit.

### Kits' variables and styles

A vendored kit's variables and styles sit **in the consumer's own tables**, each minted the consumer's id and carrying `origin: Option<VarOrigin | StyleOrigin>` (kit, id in the publish, version) — the key an update and second insert match on (`by_origin`). The document's own are `Variables::local`.

- **Kit modes**: `Variables::kits` holds `KitModes { name, modes: [KitMode { id, name, from, collection }], map }` per kit. Kits keep their collections: each `KitMode` names its kit collection (empty for a kit with one), and a kit's variable has a cell in every mode of one kit collection and no other; `Variables::mode` never answers one.
- **A kit collection maps from the document collection of its name, else the first** (`Variables::kit_onto`). `tokens::plan` carries a kit's collections into its `KitModes`, naming them only when the kit has two or more.
- **Which column a layer reads** (`Variables::kit_mode_at(kit, collection, set)`): the nearer of the kit collection's own mode and the mode in force of the document collection it maps from — on one frame the kit's own first — the latter through the hand-set map entry, else the kit mode of that mode's name, else the kit collection's first. With none in force, that document collection's default maps the same way. **The walk carries the mode it started in** (`resolve_at`): a walk from a document variable reads every kit step in the document's modes alone; a walk from a kit variable reads every later kit step in the one mode that chose its first column, so another kit reads a kit's frame-set mode only along an alias, by name.
- **A mode renamed or copied keeps the kit columns it reads.** `variable::rename_mode_ops` and `copy_mode_ops` (the browser's rename, *Duplicate mode* and *New mode*) write a mapping entry (`SetKitModes`) in every kit where the new name would match a different kit mode: a rename relabels a mode, it does not repoint what its layers draw. The entries are written for every kit collection that maps from the mode's collection; a kit holds one entry per document mode, so where two of its collections map from the same one, the first that needs an entry gets it. A bare `SetModeName` still re-maps by name, so it dirties every bound node while a kit is held and counts as ink; so does `SetCollectionName`, since kit collections map by name.
- **Rules**: a vault node binds only kits' variables and styles and sets no document mode; a kit's variable aliases only a kit's (its own or another's), never the document's own (`check_table`); a kit's style reads only kits' variables; names unique per kit; mode ids unique across the document and every kit.
- **One planner, `tokens::plan`**, lands what a set of nodes reads for `kit::vendor`, `kit::update_all` and the carrying paste (`Carried::tokens`, matched by **origin, never by name**; `plan_carried` points it at the vendored copy). A kit's variables and styles land with their descriptions. `update_all` with `sync` rewrites the kit's whole holding (`SetVariable`, `SetKitModes`, `SetStyleName/Value/Origin`, and `SetDescription` for a style's description; a changed description counts as a change), keeps hand-set entries while their target survives, removes what the publish dropped (detaching its users) except what a main held back from the update reads (`tokens::Kept`, `kit::update_holding`), and resets frames on a removed kit mode. A live copy bound as its main is **not** rewritten — the commit's follow carries it, or it would read as an override (`tokens::reads_as_its_source`, `tokens::alike`: fills/strokes matched by item id, a vault main's binding to the document's fork counted alike, styles likewise).
- A held kit's record is reused when it covers the source's modes (a new variable fills extra columns from the source's default); `KitError::Modes` when it lacks one, or when a new kit variable or style takes a name a held one of the kit has; a record with no modes counts as absent, an update leaving one removes it, and `variable::check` refuses a kit variable under one (`NoKit`); the kit's own document maps to its own variables, never copies. *Accept all* retries with a `Modes`-named kit moved ahead.
- **A publish freezes a top's and variant's own visibility** to what it shows, so a main root's binding there carries no variable. A kit's frozen copy keeps its other bindings and carries their table.
- ***Make local*** forks what the revealed main's bindings read: document-owned copies named `Kit/name`, keeping the description, marked `forked` with the kit variable/style they came from (so a second *Make local* reuses them); a fork goes into the document collection its kit collection maps from, each of that collection's modes getting the cell `kit_mode_at` read there (a document with no modes takes the first forked kit collection's into its first collection, by name; every other held kit's default is pinned to its first mode); the main's bindings are rebound and the follow carries them to its instances; a nested kit instance keeps the kit's.
- Saved in v8 (`VariablesDto::kits`, optional origins and fork marks); `KitMode::collection` in v13.
- **Chrome**: the `--` list, the swatch Variables face, the browser and *Apply style…* list kits' last, each under its mark and name; in the browser a kit lists under the document collection it maps from. The browser's kit header carries the mapping per mode column (a click opens the kit's modes and *Match by name*); kit groups fold under `\u{2}kit\u{2}path`; rows are inert (count selects users; no rename, cells, menu or *Duplicate*); a kit's style offers *Select* only. The update toast and popover count variables and styles updated/removed (old → new, with a removal's detach count); a kit header reads *· v8 → v9* while an update waits. Not built: a kit variable no held main reads can't be bound.

### Design tokens

A DTCG `tokens.json` (`dtcg_in::parse`, `export.md`, *Design tokens (DTCG)*) is reviewed against the document and applied to its own variables and styles; `tokens_import.rs` draws the review.

- **Collections** (`dtcg_in::review(doc, &file, into, &mut IdSource)`): a top-level group carrying the collection extension lands in the document collection of its name, else in a new collection, made only when one of its modes is ticked; the root's tokens land in `into`, the browser's collection on show — for a linked file's review, the collection the link was applied into (`TokensLink::into`) while it exists. A matched variable whose file collection differs moves there, keeping none of its old cells. Removals are offered only among the collections landed in.
- **Matching**: a token is the variable or style whose id its extension carries, else the one at its path (a variable's path is `dtcg::token_path(name)`, so a name the export made legal keeps its name), else new, its id minted here so aliases between new tokens name real ids. A rename made in code is therefore a rename that keeps its bindings, not a delete plus a create. A variable token whose match is of another kind is left out.
- **Modes** match **by name within a collection**. A file mode the collection lacks is an added mode, a row of its own; a document mode the file lacks keeps its values and is named in the note (`Review::kept_modes`). A file with one unnamed mode fills the collection's default mode, or an added *Mode 1* in one with none. A new variable takes the `$value` mode's value in every mode the file gives it none for. The review's columns are each landed collection's modes, labelled *Collection · Mode* when there are two collections. **Widths**: a collection whose widths the file changes has a row of its own under *Modes* (*Breakpoints of ‹collection›*, old struck beside new per mode, *each frame picks its mode by its width* when the collection is not yet picked by width), ticked; ticked, the file's `minWidth`s land after the `AddMode`s (`Review::breakpoint_ops`) when they cover every mode the collection will have, ascending from 0, and no other collection is picked by width; otherwise a collection already picked by width keeps its widths, each mode the file adds starting `WIDTH_STEP` past the last.
- **Scope**: a new number takes its scope from the extension, else from its `$type` (`dimension` → the length families, `fontWeight` → weight). A held variable keeps its scope unless the extension gives one; a narrowed scope detaches through `scope_ops` in the same transaction. A scope change is a *Changed* row (*scope changed*).
- **Rows** (`Change`): *Added*; *Changed*, old struck beside new per mode, colours compared within the export's six-place rounding so a round trip is no change, and a cell for an added mode alone not a change (the mode's row writes it); *Renamed*, *was ‹old path› · N bindings kept*; *Removed*, a document variable the file lacks, unticked, *read by N layers and M styles*; *Kit*, a token whose id or path is a kit's variable or style, listed dim and never applied, since a kit changes through its update. An import never removes a style.
- **References** resolve to a file token, else to a document variable by path, which is then not offered for removal. A dangling reference, a kind mismatch, a self-reference or a loop refuses the file.
- **A style is built over the held one**, so item ids and what the token cannot carry (blend mode, gradient geometry, italic) stay, and typography's letter spacing and line height keep the held unit when the value is the same. A shadow number or a border width given as a reference to a number variable binds it (`Effect::vars`, `Stroke::width_var`), and a fill colour by reference binds the colour variable; other colours in a style are literals in the file's first mode.
- **Apply** (`Review::ops(doc, ticked)`) is one transaction, one undo step named *Import tokens*: removals first (`variable::remove_ops`, detaching users), then each new `AddCollection` with a ticked mode, each ticked `AddMode` (every variable of its collection given the file's value for it, else its default-mode cell), `AddVariable`/`SetVariable` (a narrowed scope's detaches before its `SetVariable`), then `AddStyle`, `SetStyleName`, `SetStyleValue`, `SetDescription`. It is refused with a sentence when a ticked row reads a new variable left unticked (*a.b reads c.d, which is not ticked*) or one ticked for removal, when a variable would have no mode, and when the result fails a scratch apply.
- **A linked file** is `Document::tokens_link` (`meta::TokensLink { path, applied, into }`): its path, the file as last applied, and the collection its root tokens landed in. Outside undo, as `meta` and `published` are, because an undo of the apply does not make "this is what was last applied" untrue; saved as the DTO's `tokens_link` (`io.md`). `Review::since(&file, &old)` keeps only the rows whose token differs between the file now and as last applied (by id, then path), a removal only if the old file had that token, an added mode only if the old file's collection landing in the same place lacked it, and a widths row only if that collection's widths changed, so what the document changed since is left alone.
- **The path is the document's, so untrusted**: it is looked at only when it is absolute and on a local drive (`tokens_import::local_path`; never a `\\host\share`, a `\\?\` or `\\.\` path, or a Windows device name), and read only when it is a regular file, at most 16 MB. A file linked from a network share is therefore never watched. Opening a compare refuses the link's doors (`app-compare.md`).

**Chrome**
- **Doors**: the browser's `+` menu, after a separator (*Import tokens…*, *Export tokens…*, *Unlink ‹file›* while linked); the palette's *Import tokens…* and *Export tokens…* (aliases *tokens*, *dtcg*, *json*, *variables*) and *Unlink tokens file* (dim with *No tokens file is linked*); a lone `.json` dropped on the window. A file that does not read is refused on the status line with the first reason and its path.
- **The review** is a modal like batch rename's: centred over the canvas column, `TOP_GAP` 56 from its top, 620 wide, a clear backdrop; `Escape` or a click outside cancels, `Enter` applies (`ui::card_enter`: with nothing focused or in a text entry; on a focused button or box it is that control's click). Head: the import glyph, *Import tokens*, *tokens.json · ‹two parent folders›*, ✕. Filter chips (*All*, then *Changed*, *Added*, *Renamed*, *Removed*, *Kit’s*, each with its count, only the non-zero). A *TOKEN* column and one value column per mode (at most 150 wide); rows under group headers (the token's parent path joined ` / `, *Modes* first; a caret and the count of rows on show, a click closes or opens the group and Alt-click every group, as in the variables panel), in a list that scrolls with no bar shown, each a box, a tag (+ added `#4f8fe6`, − removed `#e8964a`, ~ changed `#c9b458`, → renamed neutral, K kit), the name and a second line; a name, line or value cut short shows the whole of it in a tooltip under the pointer. An info note names the left-out tokens (the first three, *and N more*) and the kept modes. Foot: *Keep this file linked* (on when the document is linked to nothing or to this file; absent for a browser drop, which has no path), *Cancel* (*Later* when opened from the link), *Apply N changes* (*Done* with nothing ticked, which still records or drops the link), with the refusal beside it while Apply is off. Applied with the box ticked, the file's path and contents become the link and the document is unsaved; unticked on the linked file, it unlinks.
- **Watching** (`watch_tokens`): the linked file is `stat`ed every `kits::updates::WATCH_EVERY` (45 s) and on the frame the window regains focus; a change in path, mtime and size, or the applied copy, recounts `since` against the document with throwaway ids. A pill before the kit-update pill, on the same `ui::button_face` at toolbar scale, reads *tokens.json · N changes* (lit, the *on* state) and opens the review of only what changed; *Later* shrinks it to glyph and count until the file changes again, held in memory for the session, not per machine as the kit pill's is. The browser shows the link in a line under the search row (link glyph, path elided from the left, *N changes* in accent), a click opening the same review.

### Traps
- **Every reader must resolve.** A reader of the document's own kind (not `Resolved`'s used kind, `resolved_*`, `shown`, `drawn_opacity`) sees the bound literal (0, `true`, empty) and silently draws wrong.
- **Resolved outputs clear their bindings** (`resolved_paint_in`, `resolved_effects_in`): previews hold resolved values that the scene would otherwise resolve again against the committed table.
- **`spacing_drawn_in` keeps the flex direction's and wrap's bindings**, unlike the other resolved outputs. Layout reads only the literals, and doors write the drawn layout back; with the bindings cleared there, `kept_flow` would read every such write as a detach. No test pins this on its own.
- **A width pick reads a bound frame width in the modes the frame and its page set, never through `modes_at`** (`Document::frame_width`). Through `modes_at` the width would be read in the mode the width picks, and the pick would recurse into itself; the frame's own pins of other collections are what it draws, so the pick reads them too.
- **Two defences keep a query's width independent of its pick**: `modes_at_in` skips a frame's own queries when the walk starts at that frame, and `limits_drawn_in` holds a querying frame's fit-content width at its padding. The first stops a frame's bound width or padding reading the mode its width picks; the second stops its contents sizing it. Without either the pick can move the width it picks by, and the settle chases a frame's own width round its pick instead of descending (`queries.rs`: `a_pin_on_the_instance_beats_its_width_and_its_width_beats_the_page`, `the_laid_out_width_picks_and_fit_content_is_held_at_the_padding`).
- **Two-half rule for "keep" passes**: drawn value *or* own literal stays bound. Either half alone detaches fields nobody edited (Scale tool, per-corner ↺, whole-list rebuilds). Visibility and opacity deliberately use one half.
- **`style::settle` runs first and last** and is the only place "styled or not as a whole" lives; no preview runs it.
- **`commit_inner`'s no-op test also drops a bound release's identical commit**, so a guard added only there looks removable but isn't.
- **Style vs variable resolution differ on purpose**: variables resolve at read; styles are copied into the layer at commit.
- **Corner slot order**: `Corner::var_slot` maps the inspector's TL,TR,BL,BR to `CornerVars`' TL,TR,BR,BL — never a cast.
- **`inherited_mode` vs `mode_at`**: `variables::inherited_mode(doc, id, collection)` starts at the parent (what the frame would read unset); `Document::mode_at` and `modes_at` count the node itself.
- **Kit variables are never matched by name** in the carrying paste or update: match by origin.
- **Two defences keep spans off a bound content**: `propagate` skips a content write onto a copy whose content binding differs, and `text_drawn_in` draws a bound content with no spans. Either alone looks removable; without both, a byte range cuts a multi-byte string and the shaper panics (`string_vars.rs`: `a_mains_span_edit_skips_a_copy_bound_to_its_own_string`, `a_bound_content_draws_without_spans_it_should_not_hold`).
- **`bind_other_uses` builds each field's bind on a scratch document that has taken the ones before it.** Two fills of one layer are one list, so a second bind built against the document would write the first one back unbound. No test pins this.
- **`bind_text_ops` clears the runs before it zeroes the literal.** A span list canonicalizes against the defaults it is given, so clearing against a 0 size or weight leaves a run of the smallest size or weight over the whole text (`type_vars.rs`: `a_bound_size_and_line_height_draw_in_the_mode_in_force`).
